# AGENTS.md

## 1. 文件目的

本文件是 Mamep2026 项目中 AI 编程代理的工作手册。

所有 AI 代理在分析、编写、修改、测试或审查代码前，必须阅读并遵守本文件。AI 生成的代码必须经过类型检查；自动化测试（尤其耗时较长的 e2e / acceptance）的执行时机由用户决定，用户未要求时 AI 不得擅自长时间跑测试，也不得谎报已执行。不能仅凭界面看起来正常就判定任务完成。

本文件适用于：

- 浏览器端
- Electron 桌面客户端
- VSCode 插件
- Monorepo 中的共享包
- 内置插件和受信任插件
- 测试、构建、文档及工程配置

> 工程已迁移为 monorepo（2026-08-13，ADR-013）：网页端在 `apps/web/`，分层共享包在 `packages/`，测试在 `tests/`。根目录 [AGENTS.md](../AGENTS.md) 提供入口速览、当前实际命令与环境要点；本文件是完整规范。

## 4. 项目概述

Mamep2026 是一款面向设备开发人员和嵌入式开发人员的轻量化、现代化、可扩展 Modbus 开发调试工具。

产品支持：

- 浏览器在线工具
- Electron 桌面客户端
- VSCode 插件

平台协议能力如下：

| 平台     | Modbus RTU | Modbus TCP |
| -------- | ---------: | ---------: |
| 浏览器   |       支持 |     不支持 |
| Electron |       支持 |       支持 |
| VSCode   |       支持 |       支持 |

> 实现状态（2026-08-21）：上表为三端产品规划。浏览器侧 MVP 已落地（Web Serial RTU，能力矩阵 `serialPorts: "browser-picker"`）；Electron MVP 串口已落地（2026-08-21，ADR-017 扩展：与浏览器一致复用 Web Serial API——Renderer `navigator.serial` 走既有路径，主进程 `select-serial-port` 最小授权并把端口列表转发给渲染进程、由用户在 antd Select 下拉框中选择，能力矩阵翻转为 `modbusRtu:true`/`serialPorts:"enumerated"`；TCP/文件持久化仍未实现）；VSCode 侧（含 Modbus TCP）为规划目标，当前仅保证编译与路径引用不破坏（见 §7 与根 [AGENTS.md](../AGENTS.md)）。

核心产品价值：

- 使用一张表管理任意不连续保持寄存器
- 每行独立读取和写入
- 支持全表读取和周期轮询
- 三端共享相同的核心业务规则
- 修复 COM10 及以上串口兼容问题
- 使用插件隔离厂商私有功能
- 使用现代界面替代老式 Windows 菜单和控件
- 使用 TDD 和 ATDD 保证协议与通信质量

产品面向开发和测试场景，不是工业生产控制、功能安全、SCADA 或无人值守监控系统。

## 5. MVP 功能边界

### 5.0 MVP 交付形态

MVP 交付形态为三端运行骨架加核心调试闭环：

- 浏览器、Electron 和 VSCode 三端均能启动并加载同一套共享 UI 页面，页面显示一致；
- 三端功能完整度按 PRD 优先级逐步补齐，骨架阶段不要求串口、TCP 等能力生效；
- 三端骨架必须符合各自安全边界：Electron 为 Main、Preload、Renderer 隔离，VSCode 为 Extension Host 与 Webview 隔离。

> 当前状态（2026-08-21）：浏览器侧 MVP（P0）已实现并验收；Electron 骨架已落地（2026-08-21，ADR-016：Main/Preload/Renderer 三层 + 版本化安全 IPC，Renderer 即 apps/web 共享 UI）且 MVP 串口已复用 Web Serial 打通桌面端 RTU 调试闭环（2026-08-21，ADR-017 扩展：Renderer `navigator.serial` + 主进程 `select-serial-port` 最小授权、端口列表转发 + 渲染进程 antd Select 下拉框选择，能力矩阵翻转为 `modbusRtu:true`/`serialPorts:"enumerated"`，TCP/文件持久化仍未实现）；VSCode 端骨架已落地（2026-08-23：`apps/vscode-extension/` 命令打开 Webview 加载共享 UI——生产 `asWebviewUri` 打包资源 / dev `MAMEP_DEV_URL` iframe，Extension Host ↔ Webview 复用 HostMessage v1 类型化 RPC，能力矩阵如实声明，`tests/e2e-vscode` 真实 VSCode 集成测试）；Node 串口原型已通过（2026-08-23，ADR-020：`packages/platform-node` 落地 Node Serial Adapter，serialport@13 选型，Layer 1 Fake 57 用例 + Layer 2 com0com COM4/COM5 虚拟串口 7 用例全绿，Electron/VSCode 独立探针就绪，能力矩阵未翻转，见 docs/node-serial-prototype-验证记录.md）。

### 5.1 当前核心协议范围

MVP 的保持寄存器表只支持：

- 功能码 03，读取一个 16 位保持寄存器
- 功能码 0x10，写入一个 16 位保持寄存器

即使只写一个寄存器，也必须使用功能码 0x10。

每行独立发送请求。不得自动合并连续地址。

### 5.2 当前明确不支持

未获得明确需求和架构决策前，不得自行实现：

- 线圈表
- 离散输入表
- 输入寄存器表
- 自定义功能码
- 广播写入
- 多寄存器组合数据类型
- 32 位整数或浮点数
- 多活动连接
- 每行独立从站地址
- 每个标签页独立连接
- 浏览器直接 Modbus TCP
- RPN Calculator
- 任意第三方 JavaScript 插件执行
- 插件市场
- 完整 Memory Access 模式

### 5.3 插件功能边界

以下功能不得硬编码到通用核心：

- Enter ROM
- Enter RAM
- 厂商私有协议
- 厂商专用寄存器规则
- 特殊校验算法
- BCC 和 CHECK-SUM
- 厂商专用参数生效逻辑
- 厂商寄存器手册
- 私有报文封装
- 专用调试小工具

Address Adjust 已于 2026-08 确认为核心功能（Connection Settings 配置项，ON 时发送地址 = 用户地址 − 1，默认 OFF），不属于插件边界。

安川公开协议可以作为示例插件，但不得与核心 Modbus 模块耦合。

## 8. 架构强制规则

### 8.1 依赖方向

推荐依赖方向：

    apps
      -> ui
      -> register-table
      -> communication
      -> protocol-modbus
      -> domain

平台依赖通过以下方向进入：

    apps
      -> platform adapter
      -> platform-api

禁止以下依赖：

- domain 依赖 React、Zustand、Electron、VSCode、浏览器或 Node.js API
- protocol-modbus 依赖通信调度或平台实现
- communication 依赖 UI 或寄存器表组件
- 共享 UI 依赖具体平台适配器
- 浏览器应用依赖 Node.js 内置模块
- Electron Renderer 依赖串口库、net、文件系统或 Main 内部模块
- VSCode Webview 依赖文件系统、串口库或 Extension Host 内部模块
- platform-node 依赖 Electron 或 VSCode
- 插件依赖核心未公开的内部模块
- 包之间形成循环依赖

注：MVP 阶段 Electron Renderer 通过 Web Serial API（`navigator.serial`）连接串口（ADR-017），不属于上述「依赖串口库」禁止项；Node 串口库替换阶段由 Main / Node Serial Adapter 承载。

出现双向依赖时，必须重新划分契约或将共享类型下沉，禁止用循环导入临时解决。

### 8.2 Ports and Adapters

外部能力必须通过 Port 接入，包括：

- 串口
- TCP
- 工作区持久化
- 日志存储
- 时钟
- ID 生成
- 文件选择
- 平台能力
- 通知
- 插件运行时

Domain 和 Application 层只依赖接口，不依赖具体平台实现。

### 8.3 UI 边界

React 组件不得：

- 解析 Modbus 字节流
- 计算 CRC
- 管理请求队列
- 直接访问串口或 TCP
- 直接读写文件
- 直接调用 Electron IPC
- 直接调用 VSCode Extension API
- 通过 userAgent 判断平台能力
- 通过错误字符串判断错误类型
- 把复杂业务规则散落在事件处理函数中

UI 应通过应用服务、Host API、ViewModel 和 Store 获取状态及执行操作。

### 8.4 平台能力

平台差异必须通过 PlatformCapabilities 或 Adapter 表达。

不得：

- 调用不存在的 API 后再通过异常判断能力
- 在浏览器端显示可以操作但必然失败的 TCP 入口
- 为界面一致性显示底层明确不支持的参数
- 对不支持的能力进行静默降级
- 用散落的环境判断形成多套业务行为

必须启用并保持：

- strict
- noUncheckedIndexedAccess
- exactOptionalPropertyTypes
- useUnknownInCatchVariables

- 对外接口必须明确返回值和错误模型
- 第三方库对象不得成为领域模型或持久化格式

### 9.3 命名

- 类型、类和 React 组件使用 PascalCase
- 函数、变量和实例使用 camelCase
- 常量根据项目现有规范使用 camelCase 或 UPPER_SNAKE_CASE
- 布尔值使用 is、has、can、should、supports 等明确前缀
- Port 接口使用清晰的能力名称，并以 Port 结尾

- 错误代码使用稳定的大写下划线形式
- 持久化字段名称不得依赖当前界面语言
- 避免无上下文的 data、info、temp、obj 等模糊命名

### 9.4 函数和文件

- 一个函数只承担一个明确职责
- 复杂业务分支应拆成可命名、可测试的单元
- 避免超大文件、超大组件和超大 Store
- 不得为了复用而创建没有明确边界的通用工具集合
- 纯函数优先放入可独立测试的核心包
- 平台副作用必须集中在 Adapter 或 Host
- 注释解释设计原因、边界和风险，不重复代码表面行为
- 删除无用注释、调试日志、临时代码和已失效的 TODO

### 9.5 格式化和静态检查

- 使用仓库统一的 Prettier 和 ESLint 配置
- 禁止为单个文件创建冲突的格式规则
- 禁止通过大面积禁用规则让检查通过
- 必须解释必要的规则例外，并将例外范围控制到最小
- 格式化修改不得与无关功能修改混在同一次变更中

## 10. Modbus 协议规则

### 10.1 核心协议职责

protocol-modbus 负责：

- RTU ADU 编解码
- TCP ADU 编解码
- PDU 编解码
- 功能码 03
- 功能码 0x10
- CRC-16
- MBAP Header
- Modbus 异常响应
- 报文长度校验
- 地址、功能码和事务一致性校验

不得在该包中加入：

- UI 状态
- 寄存器表状态
- 自动重试
- 轮询
- Address Adjust（由 register-table 应用层处理，协议包只接收最终发送地址）
- 厂商私有功能码
- Enter RAM 或 Enter ROM
- 厂商寄存器业务语义
- BCC 或 CHECK-SUM

### 10.2 响应校验

RTU 响应至少校验：

- 最小长度
- CRC
- Slave Address
- 功能码
- 异常功能码
- 字节数
- 数据长度
- 写入起始地址
- 写入数量
- 多余或缺失字节

TCP 响应至少校验：

- Transaction ID
- Protocol ID
- MBAP Length
- Unit ID
- 功能码
- 异常功能码
- 字节数
- 数据长度
- 写入地址
- 写入数量

不得因为设备返回了“类似正确”的数据就跳过一致性校验。

### 10.3 字节流处理

串口和 TCP 都是字节流，不得假设一次数据事件就是一个完整响应。

必须处理：

- 半包
- 粘包
- 分片响应
- 多响应连续到达
- 部分帧超时
- 非法长度
- 噪声或多余字节
- 迟到响应
- 连接中断

RTU 不得仅依赖固定延迟判断帧结束。

TCP 必须根据 MBAP Header 中的 Length 分帧。

### 10.4 Transaction ID

Modbus TCP Transaction ID：

- 在 16 位范围内递增并回绕
- 由当前连接会话维护
- 必须与响应匹配
- 超时重试使用新的 Transaction ID
- 迟到响应不得被后续请求接收
- 不得写入工作区持久化数据

---

## 11. 传输和连接规则

### 11.1 Transport 边界

Transport 只处理：

- 打开和关闭
- 字节写入
- 字节事件
- 错误事件
- 关闭事件
- 连接状态
- 传输能力

Transport 不理解：

- 寄存器表
- 数据类型
- Data 单元格
- 工作区
- 轮询业务
- 厂商寄存器含义

### 11.2 串口路径

系统串口路径必须视为不透明字符串。

禁止：

- 假设 COM 名称只有一位数字
- 把 COM10 解析为 COM1
- 根据显示文本重新拼接端口路径
- 在 Domain 层解析 Windows、macOS 或 Linux 端口格式
- 使用数组索引作为端口标识
- 缓存已经失效的端口对象

COM10 及以上属于发布前必须通过的重点场景。

### 11.3 连接配置快照

连接建立时必须创建不可变配置快照。

已入队请求使用创建时的配置，不得读取之后被 UI 修改的可变对象。

以下配置变更需要重新连接：

- 串口
- 波特率
- 数据位
- 停止位
- 校验位
- 流控
- TCP 主机
- TCP 端口

以下配置只对后续请求生效：

- Slave Address 或 Unit ID
- 请求超时
- 重试次数
- 请求间隔

### 11.4 连接状态机

连接状态必须通过受控状态机管理，禁止任意写入状态字符串。

至少支持：

- disconnected
- selecting-device
- connecting
- connected
- disconnecting
- reconnect-waiting
- reconnecting
- interrupted
- failed

用户主动断开后，不得被自动重连逻辑再次连接。

### 11.5 资源释放

关闭操作必须幂等，并完成：

1. 禁止新请求进入
2. 取消未执行请求
3. 停止轮询
4. 停止自动重连
5. 取消超时、重试和延迟
6. 释放 Reader 和 Writer
7. 关闭串口或 Socket
8. 删除数据、错误和关闭监听器
9. 清理帧缓冲
10. 更新连接状态

断开后不得继续发送新请求。

---

## 12. 请求调度规则

### 12.1 统一队列

同一活动连接只有一个 RequestScheduler。

以下所有请求必须进入同一队列：

- 手动读取
- 手动写入
- 全表读取
- 周期轮询
- 写后回读
- 插件请求

任何模块和插件均不得绕过调度器直接调用 Transport。

### 12.2 并发限制

同一连接在任意时刻只能执行一个设备请求。

不得以提高速度为理由在 RTU 或当前 TCP 会话中引入不可控并发。

### 12.3 优先级

默认优先级：

1. connection-control
2. manual-write
3. manual-read
4. write-verify
5. batch-read
6. polling
7. plugin-background

优先级只影响尚未开始的任务，不得中断已经发送的设备请求。

调度器必须具备公平性，避免低优先级任务永久饥饿。

### 12.4 取消语义

取消已经发送的请求，只表示软件停止等待，不能保证设备没有执行操作。

取消后到达的响应必须：

- 被识别为迟到响应
- 不更新当前请求或新连接状态
- 根据日志策略记录或丢弃

UI 和错误信息不得把“请求已取消”描述为“设备一定未执行”。

### 12.5 快速重复操作

- 同一行尚未开始的重复手动读取可以合并
- 正在读取时可禁用按钮或合并后续读取
- 写入不得自动合并
- 写入进行中默认禁用同一行再次写入
- 不得因快速点击创建无上限的重复请求

---

## 13. 超时、重试和请求间隔

### 13.1 超时

请求超时从完整请求实际发送后开始，不从入队时开始。

必须区分：

- 连接超时
- 队列等待时间
- 写入耗时
- 响应耗时
- 请求总耗时

连接超时和请求超时不得使用同一个错误代码表达。

### 13.2 重试

retryCount 表示首次失败后允许的额外尝试次数。

以下情况不得重试：

- 输入校验失败
- 用户取消
- 用户主动断开
- 默认策略下的明确 Modbus 异常响应
- 未声明为可重试的私有写入操作

以下情况可以由明确策略决定是否重试：

- 请求超时
- 临时传输错误
- CRC 错误
- 可恢复连接错误

每次尝试必须有独立 attempt 编号和日志。

### 13.3 请求间隔

内部统一使用 interRequestDelayMs，界面名称为 Rx Delay（Connection Settings 配置项）。

其语义为：

- 相邻请求之间的最小附加间隔
- 从上一请求结束后开始计时
- 同时作为 WP 行周期轮询的重复间隔（不设独立的全局轮询间隔）
- 默认值为 50 ms（2026-08 确认）
- 不用于判断帧结束
- 不代替请求超时
- 必须可取消
- 必须记录实际应用的延迟

---

## 14. 周期轮询规则

- 每行通过 WP 开关独立决定是否加入轮询
- 轮询间隔使用 Connection Settings 中的 Rx Delay（interRequestDelayMs，默认 50 ms），不设独立的全局轮询间隔配置
- 不提供全部行持续轮询（ALL Polling）功能；全表读取为一次性批量操作
- 每行使用独立的功能码 03 请求
- 不合并连续地址
- 轮询优先级低于用户手动操作
- 实际刷新周期可以大于配置周期
- 不承诺实时控制精度
- 浏览器后台状态下不承诺精确轮询周期

每个轮询行最多存在：

- 一个正在执行的轮询任务
- 一个等待执行的轮询任务

下次触发时如果旧任务尚未完成，不得继续积压。应记录 skipped tick 或 lag 指标。

以下情况必须使行的 generation 失效：

- 地址变化
- 行删除
- 标签页关闭
- 停止轮询
- 切换连接
- 修改影响请求目标的配置

旧 generation 的响应不得更新当前行。

工作区恢复时可以恢复 pollingEnabled 配置，但应用启动保持离线，不得自动发送轮询请求。

切换标签页默认不停止其他标签页的轮询。关闭标签页必须停止该标签页的轮询。

---

## 15. 全表读取规则

全表读取必须：

1. 获取当前标签页的不可变行快照
2. 按表格顺序处理
3. 跳过空地址和非法地址
4. 每行独立发送功能码 03
5. 不合并连续地址
6. 单行失败后继续
7. 支持取消尚未执行的任务
8. 汇总成功、失败、跳过和取消数量
9. 将每次请求记录到通信日志
10. 不修改轮询配置

全表读取优先级高于普通轮询。

不得因为一行失败而中止整个批次。

---

## 16. 数据和地址转换规则

### 16.1 原始值

寄存器原始值统一表示为 0 至 65535 的整数。

创建原始值时必须验证：

- 是整数
- 不小于 0
- 不大于 65535

通信层只处理原始值，不处理用户界面格式化文本。

### 16.2 支持的数据类型

MVP 支持：

- HEX
- Unsigned Dec.
- Unsigned 0.1
- Unsigned 0.01
- Unsigned 0.001
- Unsigned 0.0001
- Signed Dec.
- Signed 0.1
- Signed 0.01
- Signed 0.001
- Signed 0.0001
- Binary

Type 只改变数值解释、输入和显示，不改变寄存器原始值和通信报文。

### 16.3 定点数

定点转换必须使用确定性的十进制算法。

禁止：

- 无提示四舍五入
- 无提示截断
- 依赖浮点误差容忍判断精度
- 默认接受科学计数法
- 让本地化小数格式直接进入协议转换

精度或范围不合法时必须返回结构化错误。

### 16.4 HEX

- 显示为四位大写十六进制
- 不显示 0x 前缀
- 输入可接受可选的 0x
- 提交时去除首尾空格
- 最多四位有效字符
- 非法输入不得被清空
- 不得静默截断

### 16.5 Binary

- 显示为固定 16 位
- 只包含 0 和 1
- 默认不接受 0b 前缀
- 不接受中间空格
- 最多 16 位
- 不足 16 位可在提交后补零显示

### 16.6 地址

内部地址范围为 0 至 65535。Register 列进制按表独立设置（ADR-014，2026-08-14）：

- 默认 DEC：仅接受十进制数字，值域 0~65535，超范围报错；提交保留去空格后的原文本（不补零）。
- HEX：仅接受 1~4 位十六进制字符（不接受 0x 前缀）；提交后自动补全为 4 位大写（不足四位前补 0）。
- 切换进制不重排已提交的 addressDraft（仅影响列头与后续输入解析）；设置随工作区按表持久化，复制表继承源表进制。

地址编辑必须区分：

- addressDraft
- addressValue
- addressValidation

校验失败时：

- 保留用户输入
- 展示明确错误
- 不发送请求
- 不自动清空或替换为默认地址

Address Adjust 由核心实现：Connection Settings 中配置（ON 时发送地址 = 用户地址 − 1，默认 OFF，2026-08 已确认）。日志必须同时记录用户地址和最终发送地址。

---

## 17. 读取值和待写值

Data 单元格采用单一当前值模型：

- 单元格内容即当前值，用户编辑直接改值
- 读取成功后按当前 Type 格式化，强制覆盖单元格内容，包括用户正在输入时
- 读取失败时不改变单元格内容；操作结果经 Data 列状态点展示（成功/失败/编辑完成三态），失败原因经状态点 Tooltip 呈现
- 写入失败时不清空单元格内容
- Type 切换不改写单元格文本
- 禁止为读取值和待写值维护两份独立文本

---

## 18. 写入和写后回读

### 18.1 写入规则

写入必须：

1. 使用不可变行快照
2. 校验连接状态
3. 校验地址
4. 根据 Type 解析单元格当前文本
5. 校验精度和范围
6. 转换为 16 位原始值
7. 使用功能码 0x10
8. 进入统一调度队列
9. 记录请求和响应
10. 保留失败时的用户输入

### 18.2 写后回读结果

必须严格区分：

- write-failed
- write-succeeded-no-verify
- write-succeeded-verify-matched
- write-succeeded-verify-mismatched
- write-succeeded-verify-failed
- cancelled-before-verify

回读失败不得把已经成功的写入显示为写入失败。

### 18.3 与轮询的关系

写入任务提交后：

- 暂缓同一行的普通轮询
- 其他行轮询可以继续
- 写入及回读结束后按当前配置恢复
- 用户已停止轮询时不得自动重新启用
- 旧地址请求的结果不得覆盖修改后的行

标准写入重试必须遵循明确策略。插件私有写入默认不得假设幂等。

---

## 19. 工作区和持久化

### 19.1 必须持久化

工作区至少包括：

- Schema 版本
- 标签页及顺序
- 标签页名称
- 寄存器行
- 名称和地址
- 数据类型
- 轮询配置
- Trace 配置字段
- 通信参数
- 超时和重试
- 请求间隔
- 写后回读配置
- 备注
- 面板布局
- 主题和用户偏好
- 插件启用状态和配置

### 19.2 不得持久化

不得把以下运行时状态写入工作区：

- 串口或 Socket 句柄
- Promise
- Timer
- Reader 和 Writer
- 当前请求对象
- 当前连接 ID
- 当前 Transaction ID
- CancellationToken
- 运行时错误实例
- 正在运行的轮询任务
- 自动重连计时器

最近成功读取值如果被持久化，恢复后仅作为普通单元格文本展示，不视为当前设备实时值。

### 19.3 串口恢复

串口路径不是必须恢复项。

允许保存不用于自动连接的最近端口提示，但不得：

- 自动选择并连接旧串口
- 因旧串口不存在阻塞应用启动
- 假设浏览器仍保留设备授权
- 将端口路径作为稳定设备身份

### 19.4 启动行为

应用启动时必须保持离线。

工作区恢复不得自动执行：

- 连接
- 读取
- 写入
- 轮询
- 插件设备命令

### 19.5 保存规则

- 连续编辑使用 debounce
- 结构性操作应及时安排保存
- 同一时刻只执行一个保存任务
- 保存中发生新修改时，后续保存最新快照
- 保存失败不清除内存状态
- 自动保存静默执行，不展示保存状态；仅手动保存场景展示保存中、已保存或失败
- Electron 文件保存使用临时文件、备份和原子替换
- 工作区必须包含 schemaVersion

### 19.6 数据迁移

迁移必须：

- 单向
- 可重复测试
- 不直接覆盖原始文件
- 按版本顺序执行
- 保留未知插件配置
- 在迁移前或迁移后创建可恢复备份
- 无法完整迁移时尽可能部分恢复
- 记录迁移历史

---

## 20. 错误处理

所有可识别错误必须使用结构化 MamepError 或等价领域错误。

错误至少包含：

- code
- category
- severity
- retryable
- userMessageKey
- technicalMessage
- cause
- context

错误类别包括：

- validation
- capability
- permission
- connection
- transport
- timeout
- protocol
- modbus-exception
- cancellation
- persistence
- plugin
- internal

禁止：

- UI 通过错误字符串判断类型
- 吞掉异常以维持表面运行
- 只记录控制台错误而不更新业务状态
- 把未知异常堆栈直接作为主要用户提示
- 将权限不足误报为端口不存在
- 将回读失败误报为写入失败
- 将取消误报为设备未执行

用户提示应包含：

- 简短原因
- 可执行建议
- 相关字段
- 是否可以重试

诊断信息可以包含底层错误码和堆栈，但不得泄漏不必要的敏感信息。

---

## 21. 日志规则

日志分为：

- ApplicationMessage
- CommunicationLogEntry
- DiagnosticLog

通信日志至少记录：

- 时间
- 连接 ID
- 协议
- 请求来源
- 方向
- Slave Address 或 Unit ID
- Transaction ID
- 功能码
- 用户地址
- 实际发送地址
- 寄存器数量
- 原始报文
- attempt
- 队列等待时间
- 执行耗时
- 成功、失败、超时或取消状态
- Modbus 异常码
- 结构化错误代码
- 相关 batch、polling、plugin 或 operation group ID

原始字节显示为：

- 大写十六进制
- 字节之间使用空格
- 不进行本地化

日志必须有保留上限，不得无限增长。

默认不得记录：

- 操作系统用户名
- 完整个人目录
- 环境变量
- 插件私有凭据
- 与调试无关的文件内容

## 22. 平台安全规则

### 22.1 Electron

必须保持：

- contextIsolation 开启
- nodeIntegration 关闭
- 在可行范围内开启 sandbox
- Renderer 不获得通用 ipcRenderer
- Preload 只暴露白名单 API
- Main 校验所有输入
- Renderer 不得指定任意路径进行文件读写
- Renderer 不得执行任意命令
- Renderer 不得加载任意 Node.js 模块
- 外部链接通过受控方式打开
- 配置明确的 Content Security Policy

### 22.2 VSCode

必须：

- 使用严格 Webview CSP
- 使用 nonce
- 使用安全资源 URI
- 对所有 Webview 消息进行 Schema 校验
- 遵守工作区信任状态
- Webview 销毁时释放订阅
- Extension 停用时释放连接
- 不向 Webview 暴露任意文件系统和串口能力
- 长时间任务支持取消
- 不阻塞 Extension Host

### 22.3 浏览器

必须：

- 使用 Web Serial 授权模型
- 在连接前检测能力
- 不直接实现 Modbus TCP
- 不打包 Node.js polyfill
- 不模拟文件系统或 TCP 能力
- 页面刷新后保持离线
- 浏览器不支持 Web Serial 时仍允许查看工作区
- 不显示虚假的连接成功状态

### 22.4 CSP 和脚本

Browser、Electron Renderer 和 VSCode Webview：

- 不使用 eval
- 不执行不受控 inline script
- 不从不受信任远程地址加载脚本
- 图标和字体优先随应用打包
- 插件 UI 不得注入共享页面 DOM

## 23. 跨平台消息协议

Electron 和 VSCode 的跨边界消息必须使用版本化 Envelope，至少包含：

- protocolVersion
- messageId
- kind
- payload

消息类别：

- request
- response
- event
- error

规则：

- 每个请求具有唯一 ID
- 响应引用原请求 ID
- payload 使用 Zod 或等价 Schema 校验
- 未知消息类型被拒绝
- 不允许任意方法名调用
- 长任务支持取消
- 错误使用结构化对象
- 字节数组使用明确可序列化格式
- 消息协议版本与应用版本、插件 API 版本、工作区 Schema 版本相互独立

## 24. 插件开发规则

### 24.1 插件原则

- 插件不得直接修改核心源代码
- 插件通过稳定贡献点扩展
- 插件必须声明平台支持和权限
- 插件失败不得导致核心应用无法启动
- 插件不得直接取得串口或 Socket 句柄
- 插件请求必须进入统一通信队列
- 插件通信必须记录 plugin ID 和完整日志
- 插件配置使用独立命名空间
- 插件 API 必须版本化

### 24.2 插件类型

UI-safe 插件适用于：

- 文档
- 寄存器手册
- 纯计算工具
- 受控工具按钮
- 显示扩展
- 受控数据类型或地址显示

Host 插件适用于：

- 厂商私有协议
- 特殊报文封装
- 本地文件处理
- 受控设备操作

浏览器不得加载 Host 插件。

### 24.3 MVP 插件来源

MVP 优先支持：

- 随应用构建的内置插件
- 开发模式下的受信任本地插件
- Manifest 驱动的启用和禁用
- 插件加载错误隔离
- 平台能力检查

不得默认开放从互联网下载并执行任意第三方代码。

### 24.4 厂商危险操作

Enter ROM 和 Enter RAM 等厂商操作只能存在于专用插件中。

已知设备专用信息不得进入通用核心，包括：

- Enter ROM 相关地址和写入规则
- Enter RAM 相关地址和写入规则
- 禁止读取的设备专用地址
- 参数写入 EEPROM 或 RAM 的厂商语义

插件必须提供必要提示，并通过统一权限、调度和日志机制执行。

## 25. UI 和产品交互规则

### 25.1 设计方向

UI 必须：

- 现代、简洁、专业
- 保持较高信息密度
- 支持深色和浅色主题
- 支持键盘高效操作
- 状态和错误清晰可见
- 三端保持核心视觉语言一致
- 遵守浏览器、桌面和 VSCode 的平台规范
- 连接后进入调试阶段时，尽量减少让用户选择的弹窗，调试中的修改优先内联完成，避免类似 Modbus Poll 的「右键选择 + 弹窗修改」方式

### 25.2 禁止复刻的旧设计

不得复刻：

- File、Edit、View 等老式顶层菜单
- Win32 灰色立体控件
- 立体凸起按钮
- 原软件 Logo、品牌区和版权装饰
- Access Counter
- User ID 和 User Name 授权区
- 原始浅绿与白色交替行样式
- 含义不清晰的笑脸和缩写图标
- 固定尺寸且不可缩放的旧式对话框

### 25.3 连接配置

连接配置使用 Modal（浏览器非 Mock 模式启动时自动弹出；dev Mock 传输模式 `?mockTransport=1` 下自动连接模拟设备、不弹出，见 [浏览器端自动化测试方法指南](浏览器端自动化测试方法指南.md)；浏览器端仅提供 Modbus RTU 配置）。Connection Settings、Plugin Manager、Settings 的入口统一放在顶部应用栏，不放在侧边栏。

连接失败时必须：

- 保留用户配置
- 保持配置界面可继续编辑
- 显示可理解的失败原因
- 提供重试入口
- 不清空寄存器表
- 不自动反复连接

### 25.4 寄存器表

表格应支持：

- 虚拟滚动
- 单元格编辑（可编辑单元格的输入控件宽度铺满单元格，点击单元格任意空白区域即可进入编辑）
- 多行选择
- 复制、剪切和粘贴
- 新增、插入、删除和移动
- 键盘导航
- 右键上下文菜单
- 撤销和重做
- 地址及数据错误提示（在对应单元格内展示，不设独立 Status 列）
- 读取结果强制覆盖单元格内容
- 轮询和操作状态展示
- READ / WRITE 按钮必须包含完整文字，不得只使用图标
- 列序固定：No / TM / Name / Register[HEX] / WP / READ / Data / WRITE / Type / Comment

领域模型不得依赖 Ant Design Table 的内部数据结构。

> **已确认行为（2026-08-15，见 [ADR-015](adr/ADR-015-行编辑交互与剪贴板决策.md)）**：行编辑（新增/插入/删除/上移/下移/复制/剪切/粘贴/多行选择/键盘快捷操作/右键上下文菜单）已在浏览器 MVP 完整实现。多选用 Ant Design Table `rowSelection` 原生能力（复选框列、表头全选、Shift 范围选择、Ctrl 多选），领域层只持有 `selectedRowIds: RowId[]`；行级右键菜单用 `Dropdown trigger={['contextMenu']}`；删除（含多选）直接执行不弹确认、不引入撤销；键盘快捷键 Alt+↑/↓、Delete、Ctrl+C/X/V、Ctrl+I 仅在焦点不在文本输入控件时生效；系统剪贴板经 `AppHost` 端口（`navigator.clipboard`）。

### 25.5 可访问性

必须保证：

- 图标按钮有辅助文本
- 键盘可完成核心任务
- 焦点状态清晰
- 错误与对应输入控件关联
- 状态不只依赖颜色
- 动态读取不抢夺焦点
- 轮询不使用持续闪烁表达状态
- 对话框关闭后恢复原焦点
- 虚拟化不破坏基本键盘导航

## 27. 测试驱动工作流

测试（尤其耗时较长的 e2e、acceptance）的执行时机由用户决定：不要求每次变更后都跑测试；用户未要求时 AI 不得擅自长时间执行测试。用户要求测试先行时遵循 TDD / ATDD 流程（见 27.1）；用户要求执行某类测试时，按 27.4~27.6 的覆盖要求准备用例。AI 必须如实报告实际执行过的测试，不得谎报。

### 27.1 标准步骤（当用户要求测试先行时）

1. 阅读需求、技术设计和现有测试
2. 写出可验证的验收条件
3. 确认测试层级
4. 先新增或修改失败测试
5. 运行测试并确认因目标行为缺失而失败
6. 编写满足测试的最小实现
7. 运行相关测试
8. 重构，保持测试通过
9. 运行类型检查和静态检查
10. 运行受影响包和客户端的回归测试
11. 检查架构边界和跨端一致性
12. 清理临时代码
13. 报告完成情况和未解决风险

禁止先写完整实现，再补充只验证当前实现细节的测试。

### 27.2 测试层级

根据风险选择：

- 领域单元测试
- 协议编解码测试
- 通信调度测试
- 持久化测试
- React 组件测试
- 平台适配集成测试
- 跨端契约测试
- 浏览器端到端测试
- Electron 端到端测试
- VSCode 集成测试
- 真实设备验收测试

### 27.3 测试原则

- 纯函数测试不得依赖真实设备
- 调度测试使用 Virtual Clock
- 不得使用真实等待时间测试超时和轮询
- 组件测试使用 Application Service Fake
- 协议测试使用固定向量
- 平台适配测试覆盖资源释放
- 协议和转换测试覆盖正常值、边界值和错误值
- 测试名称应描述条件、行为和预期结果
- 测试不得依赖执行顺序
- 测试不得静默忽略未处理 Promise
- 不得通过增加任意 sleep 掩盖竞态问题

### 27.4 协议必测场景

当用户要求执行协议测试时，修改 Modbus 协议代码至少覆盖：

- 功能码 03 正常请求和响应
- 功能码 0x10 正常请求和响应
- CRC 正确和错误
- 响应地址不匹配
- 功能码不匹配
- 字节数错误
- 数据长度错误
- Modbus 异常响应
- TCP Transaction ID 不匹配
- TCP Unit ID 不匹配
- 半包
- 粘包
- 部分响应超时
- 迟到响应

### 27.5 调度必测场景

当用户要求执行调度测试时，修改调度、轮询或通信会话至少覆盖：

- 同一时刻只有一个请求
- 手动操作优先于轮询
- 公平性
- 轮询不无限积压
- 超时
- 重试
- 取消
- 断开
- 迟到响应
- 写后回读
- 全表读取单行失败后继续
- 插件请求进入统一队列
- 修改地址后旧结果被丢弃
- 删除行后不再发送请求

### 27.6 持久化必测场景

当用户要求执行持久化测试时，修改工作区或持久化至少覆盖：

- 保存和加载
- Schema 迁移
- 损坏 JSON
- 缺失字段
- 未知插件字段
- 保存中断
- 从备份恢复
- 保存失败后内存状态保留
- 串口恢复规则
- 启动保持离线
- 轮询配置恢复但不自动执行

### 28.1 最小检查范围

当用户要求执行测试时，参考范围：

- 普通局部变更：相关单元或组件测试、受影响包的类型检查、受影响包的 Lint、格式检查
- 共享核心变更：相关包全部测试、三端类型检查、三端构建或等价契约检查、跨端共享验收测试
- 协议、调度、持久化、Host API、插件 API 和安全边界变更：对应专项测试

## 29. 跨端修改检查清单

修改共享核心或共享 UI 时，必须检查：

### 29.1 Browser

- 构建中没有 Node.js 内置模块
- 没有 TCP 功能入口
- Web Serial 不支持时有能力提示
- 页面刷新后保持离线
- IndexedDB 数据仍能加载

- IPC 输入经过校验
- Main 能正确释放连接

- Webview RPC 向后兼容或已版本化
- 工作区信任限制有效
- 主题适配正常
- Extension 停用时释放连接
- Webview 不直接访问 Host 能力
- VSIX 打包不遗漏原生依赖和静态资源

### 29.4 共享行为

- 地址格式一致
- 数据类型解释一致
- 错误分类一致
- 日志核心字段一致
- 超时和重试语义一致
- 工作区 Schema 一致
- RTU 请求和响应行为一致

## 30. 依赖管理规则

新增依赖前必须检查：

1. 当前仓库是否已有等价能力
2. 是否真的需要第三方依赖
3. 维护状态
4. 发布频率和问题响应
5. TypeScript 类型质量
6. 许可证
7. 浏览器、Electron 和 VSCode 兼容性
8. Node.js 和 ABI 要求
9. 包体积影响
10. 安全历史
11. 是否可以通过 Adapter 封装
12. 是否容易被 Fake 替代和测试

关键依赖包括：

- 串口库
- Electron
- VSCode API
- 表格和虚拟化库
- IndexedDB 库
- Zod
- 状态管理
- 插件加载器
- 构建工具

关键依赖升级必须：

- 独立于普通功能变更
- 阅读迁移说明
- 记录破坏性变更
- 更新锁文件
- 按用户要求执行专项回归
- 检查许可证和漏洞
- 必要时新增或更新 ADR

不得自动接受关键依赖的主版本升级。

### 30.1 第三方库使用规则

涉及第三方库（如 antd、react、zustand、serialport、Playwright 等）的用法实现或修改前，AI 必须：

1. 优先通过工具、MCP、插件（如 Context7、库官方文档站）查阅该库的官方文档、API 参考和示例，再动手编码
2. 仅在官方文档无法覆盖具体行为时，才查看库源码作为补充说明
3. 只使用库公开、稳定（非 internal / private、非下划线前缀、非实验性）的 API
4. 不得修改或补丁第三方库内部未公开的属性、方法或内部实现
5. 需要库不具备的能力时，通过封装 / Adapter / 组合实现，而不是改动库本身
6. 涉及库用法的实现需说明文档依据；不得在未查文档的情况下声称“库就是这么做的”

## 31. ADR 规则

以下变化必须创建或更新 ADR：

- 核心技术栈变化
- 模块或包边界变化
- 请求调度策略变化
- 工作区存储格式变化
- Modbus 协议实现策略变化
- 表格技术替换
- 串口库最终选型（后续版本替换阶段，ADR-017；MVP Electron 用 Web Serial）
- 插件隔离或权限模型变化
- Electron 进程边界变化
- VSCode Webview RPC 变化
- 新增远程后端或数据库
- 新增 Modbus 功能码或表类型

ADR 应包含：

- 背景
- 决策
- 备选方案
- 选择理由
- 正面影响
- 负面影响
- 复审条件

不得仅在代码注释或提交信息中记录架构决策。

## 32. AI 禁止行为

AI 代理不得：

1. 擅自扩展产品范围
2. 猜测未确认的协议规则
3. 把原 M@MEp2006 行为直接当成新产品规格
4. 在浏览器端模拟直接 TCP Socket
5. 绕过统一请求调度器
6. 让 UI 直接操作串口、TCP 或文件系统
7. 将厂商私有规则写入核心
8. 关闭严格类型检查以通过构建
9. 使用 any、类型断言或非空断言掩盖问题
10. 吞掉异常
11. 通过错误字符串判断业务逻辑
12. 用固定 sleep 修复竞态
13. 使用无限重试
14. 使用无限内存日志或 Trace 缓冲
15. 在工作区保存运行时句柄和任务
16. 应用启动后自动连接或写入设备
17. 让插件直接访问底层 Transport
18. 在未获得授权时加载第三方代码
19. 无测试保护地大范围重构
20. 同时修改大量无关文件
21. 为三端复制三套核心业务逻辑
22. 通过模拟成功掩盖平台能力缺失
23. 在校验失败时清空用户输入
24. 在读取失败时修改或清空 Data 单元格内容
25. 在写入失败时清空 Data 单元格内容
26. 静默截断或舍入寄存器数据
27. 声称执行了未实际执行的命令或测试
28. 删除用户数据、迁移文件或测试以让检查通过
29. 修改生成文件、锁文件或构建产物而不说明原因
30. 提交调试凭据、设备私密信息或未经授权的协议资料
31. 用户未要求时擅自长时间执行全套测试（如 e2e、acceptance）代替用户决策
32. 不通过工具、MCP、插件查阅库官方文档，直接翻阅库源码来实现第三方库用法
33. 修改或补丁第三方库未公开（内部 / 私有）的属性或方法

## 33. 单次变更范围

允许同一任务包含：

- 目标实现
- 对应测试
- 必要类型调整
- 必要文档更新
- 与目标直接相关的局部重构

不得顺带进行：

- 无关格式化
- 无关重命名
- 无关目录迁移
- 未要求的依赖升级
- 未要求的 UI 重设计
- 未要求的新功能
- 大范围“顺便优化”

如果发现独立问题，应记录为后续事项，不要扩大当前任务。

## 35. 不得自行决定的事项

以下事项仍待最终确认，AI 不得在普通实现任务中自行拍板：

- 是否彻底禁止广播写入（从站地址 0 允许配置，按标准无应答，MVP 不实现广播写入）
- Node.js 串口库最终选型（后续版本替换阶段，ADR-017；MVP Electron 使用 Web Serial）
- 三端对 1.5 位停止位的支持
- XON/XOFF 和 RTS/CTS 的实际能力矩阵
- 工作区公开交换格式
- 插件第三方代码隔离机制
- 表格组件原型后的最终结论
- 插件命令是否可以触发轮询
- 是否在 MVP 开放工作区导入导出
- VSCode Webview 关闭后是否保持连接的最终产品策略

遇到这些事项时：

- 使用可替换策略或接口预留边界
- 不实现未经确认的具体行为
- 在代码、测试或任务报告中明确标记待确认
- 不得使用原工具行为作为默认答案

## 36. TM、WP 和 Trace 特别说明（2026-08-13 已确认）

TM 与 WP 的最终定义已于 2026-08-13 确认：

- TM = 轨迹追踪（Trace）：勾选后弹出 Memory Trace 追踪窗口，对当前行寄存器持续采样并保留历史数据；字段为 traceEnabled
- WP = 周期轮询开关：控制当前行是否加入周期轮询；字段为 pollingEnabled
- pollingEnabled 与 traceEnabled 为两个独立字段，不得复用

Trace 实现要求：

- 完整 Trace 属于浏览器端 MVP 核心范围（PRD §6.5.4）
- Buffer Size 的 `Continue` 档不得真正无限，使用环形缓冲区硬上限（10000 条）
- 追踪窗口标题为 `M@MEp2006 Advance [Memory Trace]`，含 Play / Stop / Save、Buffer Size、Speed、No./Data 列表与 Average
- 追踪采样必须经过统一调度器

WP 实现要求：

- WP 列使用现代开关控件，不复刻原工具的笑脸锁定交互
- 写入禁用由明确的编辑、轮询和操作状态控制

## 37. Git、提交和 Pull Request

    feat(scope): add holding register read flow

1. 变更目标
2. 对应需求或问题
3. 主要实现
4. 测试结果
5. 受影响的平台
6. 架构和安全影响

10. 待确认事项

## 38. 失败处理和回滚

当实现、构建或测试失败时：

1. 保留原始错误信息
2. 确认失败是否由当前变更引起
3. 优先修复根因
4. 不删除失败测试
5. 不降低断言强度
6. 不扩大超时掩盖问题
7. 不禁用类型或 Lint 规则
8. 不修改无关模块尝试碰运气
9. 不能安全完成时回滚当前局部变更
10. 报告失败原因和未完成内容

如果数据迁移失败：

- 保留原始数据
- 不覆盖有效备份
- 提供恢复或重置路径
- 不把部分迁移结果伪装为成功

如果资源释放失败：

- 尽可能清理本地引用
- 记录诊断错误
- 避免 UI 永久停留在中间状态
- 不继续接受新设备请求

## 39. 任务完成前自检

AI 在声明任务完成前必须检查：

### 39.1 功能

- 验收条件是否全部满足
- 是否存在未要求的功能扩展
- 正常和失败路径是否均处理
- 用户输入是否在失败时保留
- 连接和设备状态是否准确

### 39.2 架构

- 模块职责是否清晰
- 依赖方向是否正确
- 是否绕过 Port、Adapter 或 Scheduler
- 是否产生跨平台业务分叉
- 是否将厂商规则写入核心
- 是否引入循环依赖

### 39.3 类型和错误

- 是否存在新的 any
- 是否存在不安全类型断言
- 外部输入是否经过校验
- 错误是否结构化
- 是否吞掉异常
- 用户信息与诊断信息是否分离

### 39.4 通信

- 请求是否进入统一队列
- 是否支持取消
- 是否正确处理超时和重试
- 断开后是否停止新请求
- 迟到响应是否被隔离
- 资源是否释放
- 日志是否完整

### 39.5 数据

- 是否存在无提示截断或舍入
- Type 切换是否保持原始值
- 读取失败是否不改变 Data 单元格内容
- 写入失败是否保留单元格内容
- 恢复后是否保持离线

### 39.6 测试

- 是否按用户要求新增或修改测试；用户未要求时不擅自跑测试
- 用户要求执行的测试是否执行并通过；未执行的测试是否如实说明
- 类型检查是否通过
- Lint 和格式检查是否通过（按用户要求时）
- 受影响客户端是否完成检查
- 是否存在未处理异步错误
- 是否使用真实等待时间掩盖问题

### 39.7 清理

- 是否删除调试日志
- 是否删除临时文件
- 是否删除未使用的导入和依赖
- 是否更新必要文档和 ADR
- 是否留下需要说明的 TODO
- 是否意外修改无关文件

## 41. 发布阻断条件

存在以下任一情况时，不得建议发布：

- COM10 及以上仍不能正常使用
- 功能码 03 或 0x10 存在已知转换错误
- 写入地址与用户目标地址不一致
- 数据可能被无提示截断或舍入
- 断开后仍发送请求
- 迟到响应污染新请求或新连接
- 核心通信错误导致应用崩溃
- 工作区恢复稳定丢失用户配置
- 浏览器错误宣称支持直接 Modbus TCP
- 插件失败阻止应用启动
- 三端对相同原始值解释不一致
- Electron Renderer 获得不必要的 Node.js 权限
- VSCode Webview 可以绕过 Host 能力边界
- P0 验收用例未全部通过
- 存在阻断级或严重级数据丢失缺陷
- 连接无法可靠释放
- TypeScript、Lint、测试或构建检查未通过且无明确批准

## 42. 默认技术参数

在产品没有进一步决策时，可以使用以下技术设计初始默认值：

- RTU 波特率：9600
- 数据位：8
- 停止位：1
- 校验位：None
- 流控：OFF
- 从站地址允许范围：0~255（默认 1；不实现广播写入）
- Address Adjust：默认 OFF（ON 时发送地址 = 用户地址 − 1）
- 请求超时：1000 ms
- 重试次数：1
- 请求间隔（Rx Delay）：50 ms（兼作 WP 轮询间隔）
- TCP 端口：502
- TCP 连接超时：5000 ms
- 自动重连：关闭
- 应用启动状态：离线
- 应用启动时自动弹出 Connection Settings Modal
- 同一连接并发请求数：1
- 通信日志默认上限：10000 条
- 应用消息默认上限：2000 条
- 普通编辑自动保存 debounce：500 ms
- Trace Buffer 环形缓冲硬上限：10000 条

这些值必须集中管理，不得散落在组件、Host 和 Adapter 中。

如果产品决策或 ADR 确认了不同值，应更新统一配置及相关测试。

## 43. 关键不变量

任何实现和重构都必须保持以下不变量：

1. 三端共享相同的 Modbus 核心规则
2. 浏览器不直接支持 Modbus TCP
3. 同一连接在同一时刻只执行一个设备请求
4. 所有请求进入统一调度器
5. 轮询任务不会无限积压
6. 断开后不再发送新请求
7. 迟到响应不污染后续请求
8. 读取失败不修改 Data 单元格内容
9. 写入失败不清空 Data 单元格内容
10. Type 切换不改变原始寄存器值
11. 地址校验失败不发送请求
12. 地址转换可以在日志中追踪
13. 工作区恢复后保持离线
14. 工作区不保存运行时资源
15. 插件不能绕过权限、调度和日志
16. 厂商规则不进入通用核心
17. UI 不直接访问系统能力
18. 所有跨边界消息经过 Schema 校验
19. 平台不支持的能力不会被静默模拟
20. 所有 P0 行为都有可重复的验收测试
