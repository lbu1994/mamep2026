# 崩溃后的状态恢复

> 日期：2026-09-04　状态：完成
> 关联决策：docs/adr/ADR-049-崩溃后的状态恢复.md

## 需求摘要

应用异常退出/崩溃后重新打开时，恢复关闭前的工作区状态，并保证最新编辑在关闭/崩溃场景下尽量不丢失（依赖已落地的工作区持久化：浏览器 IndexedDB / Electron `filesystem:"full"`（ADR-036）；§21.2「状态恢复依赖工作区持久化」）。

## 边界条件

- 空工作区：首次启动 / 重置后，`load()` 返回空工作区，`getRecoveryInfo()` 为 `source:"none"`，不显示恢复横幅。
- 主数据完好：`load()` 返回正常结果，`recoveryInfo.recovered=false`，不显示横幅。
- 主数据损坏、备份有效：从备份恢复，`recoveryInfo.source="backup"`，显示「已从备份恢复」横幅。
- 主数据与备份均不可用：`recoveryInfo.source="fresh"` + `errorCode`，应用以空工作区保持可操作，显示「恢复失败已重置」横幅（无按钮）。
- 关闭时机：`visibilitychange→hidden` 触发 flush（关闭窗口/切后台时页面先进入 hidden、仍存活，写入可靠完成）；`pending` 被清空故幂等。`pagehide` 不用（卸载会中断异步 IndexedDB 写入，且 reload 也触发 pagehide，会破坏「清工作区→reload」测试隔离）。
- 崩溃：无优雅关闭，flush 不生效；autosave（debounce 500ms）已周期性落盘，崩溃最多丢最后 500ms 编辑（best-effort，不区分崩溃/正常关闭，无 dirty 标记）。

## 异常场景

- 保存失败：`AutoSaveCoordinator` 保持内存状态、下发 `failed`，UI 可观察 `SaveStatus`；不清空内存。
- 损坏恢复：主损坏→备份恢复并自愈写回；双损坏→结构化错误 + `fresh` 恢复横幅。
- 浏览器存储不可用 / 配额不足：`load`/`save` 返回 `category:"persistence"` 结构错误，走既有加载失败路径。
- 版本不一致：`parseWorkspace` 迁移后校验，迁移失败尽可能部分恢复（既有迁移链）。

## 性能与安全

- 性能要求：关机/隐藏时 flush 仅落盘一次最新快照，不阻塞 UI 线程（fire-and-forget）；`visibilitychange` 在无 pending 时为零开销。
- 安全/权限：UI 不直接触碰文件系统/IndexedDB；桌面端仍经主进程 `WorkspaceFileRepository`（原子保存 + .bak）；跨边界 HostMessage v1（`workspace-load/save/clear` + 新增 `workspace-create-backup`，全部 Zod 校验 + 白名单）。

## 计划（Plan 摘要）

1. `WorkspaceRepositoryPort` 扩 `reset/export/import/createBackup/getRecoveryInfo`，新增 `WorkspaceRecoveryInfo`。
2. 各仓储 `load()` 记录恢复元数据（`none`/`backup`/`fresh`），`getRecoveryInfo()` 旁路返回（不动 `Result<Workspace>` 契约）。
4. `AppHost.flush()` + `getWorkspaceRecoveryInfo()`；`App.tsx` 组合根注册 `visibilitychange`→hidden flush。
4. `RecoveryBanner`（antd Alert banner，无按钮）+ store `workspaceRecovery`。
5. HostMessage v1：`workspace-load` 响应含 `recoveryInfo`，新增 kind `workspace-create-backup`；`ipc.ts` 两处穷尽守卫 + preload/vscode-bridge 同步。
6. i18n 双语 `recovery.*`。

## 测试策略

- 新增/修改测试：`workspace`（端口/`WorkspaceRecoveryInfo`）、`packages/platform-web`（IndexedDB 新方法 + 恢复元数据）、`ui`（RecoveryBanner 三态 + app-store）、`platform-api`（响应含 `recoveryInfo` + 新 kind）、`apps/web`（FileWorkspaceRepository 新方法 + getRecoveryInfo）、`apps/electron`（主进程新方法 + ipc/preload）、`apps/vscode-extension`（新 kind 能力错误 + bridge）。
- e2e：浏览器 `crash-recovery.spec.ts`（关闭丢数据：编辑后关闭/重载不丢数据（autosave 兜底 + flush best-effort）；损坏恢复：损坏主记录+合法备份→reload 恢复 + RecoveryBanner），Electron `workspace-persistence.spec.ts` 损坏恢复用例补 `RecoveryBanner` 断言。**「模拟崩溃」未做**（进程杀伐/强制中止基建成本高，且 flush 为 best-effort，见 ADR-049 决策点 3）。
- 回归：`pnpm typecheck`（27/27）、`pnpm lint`（0）、受影响包单测全绿、浏览器新 e2e 2/2、**Electron e2e 30/30**（含 `workspace-persistence` 损坏恢复 + `RecoveryBanner` 断言、`tcp-reconnect` 开关显式化、`electron-smoke` 白名单）。
- 执行时机：**由用户决定**（docs/AGENTS.md §27）；不得谎报。

## 风险与回滚

- 风险：三端仓储行为不一致、HostMessage 契约波及多端 arm 分支、`visibilitychange` flush 切后台额外写一次、Electron 关闭时 IPC 可能在 flush 完成前拆除（best-effort）。
- 回滚：以新增方法/字段为主，不动 `load/save/clear` 语义与 `load` 成功返回类型；移除新增方法与 `RecoveryBanner` 即可回滚。
