# Android 端构建产物代码分割验证（2026-09-13）

> 待办来源：`ToDoList.md` 阶段一 `[verify] 四端构建产物代码分割的 Android 端验证`（关联 2026-09-11「构建产物代码分割」与 ADR-050 Android 端接入）。
> 本次改用**无线调试**（用户指定），并在验证过程中顺带修复/加固了若干测试基建与一处产品缺陷（能力不支持时的静默无操作）。

## 1. 目标

确认四端共用的「懒加载 + rolldown 默认分包」方案在 **Capacitor WebView（生产产物 `https://localhost`）** 下无回归：

1. 入口与多个 chunk 加载正常、React 挂载正常（无 `Class extends value undefined` 类循环依赖症状）、单 chunk 不超过 Vite 的 500 kB 告警阈值；
2. 懒加载覆盖层**按需加载**、无 console 错误；
3. `ConnectionSettingsModal` 启动自动弹出、TCP 闭环不回归（USB-RS485 闭环无硬件，保持门控跳过）。

### 3.1 分包与启动（新增 `code-splitting.spec.ts` 用例①）

| 指标                                              | 实测                                                                                   |
| ------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 首屏已加载 JS chunk 数                            | **22**（单文件时代为 1 个大 chunk）                                                    |

| 最大 chunk                                        | `jsx-runtime-D49eeqJg.js` = **484721 B**（< 500 kB，与 `pnpm build:android` 输出一致） |
| React 挂载                                        | `#root` 有子节点、`.register-table-tabs` 可见 ✓                                        |
| 启动自动弹出 Connection Settings                  | ✓                                                                                      |
| 类循环依赖症状（`Class extends value undefined`） | 无 ✓                                                                                   |

> **度量方式（重要）**：Android WebView 的 resource timing **不填充** `decodedBodySize` / `encodedBodySize`（恒为 0），若直接用它做「< 500 kB」断言会**平凡通过**（假通过）。本次改为在页面内 `fetch(url) → blob.size` 实测，并补 `bytes > 0` 守卫。首屏 chunk 名字经 `performance.getEntriesByType("resource")` 获取（同一 chunk 可能因 `<script>` + `<link rel=modulepreload>` 留下重复条目，需去重）。

### 3.2 懒加载覆盖层按需加载（用例②）

- 首屏 **不含** 4 个懒加载 chunk：`HelpDrawer-*` / `SettingsDrawer-*` / `TraceWindow-*` / `WorkspaceImportModal-*`；

## 4. 本次顺带修复/加固

### 4.1 测试基建：支持无线调试

`tests/e2e-android/helpers/adb.ts`

- `MAMEP_ANDROID_ADB_TARGET=<ip:连接端口>`：`requireDevice()` 先幂等 `adb connect` 并轮询等待就绪（未设置时**行为完全不变**）；
- 建链后设官方 `ANDROID_SERIAL` 环境变量固定目标设备 —— 无线调试下同一设备会出现**两个 transport**（`ip:端口` + mDNS 自动连接别名），裸 `adb` 命令会报 `more than one device/emulator`；
- 设备缺失错误文案覆盖 USB / 无线两种方式，并提示用 `adb mdns services` 拿准确 IP:端口（避免连错地址）。

### 4.2 测试基建：动作超时（消除「无限挂起」）

`tests/e2e-android/playwright.config.ts` 增 `use: { actionTimeout: 30_000, navigationTimeout: 60_000 }`。

Playwright 默认**无动作超时**：一旦定位器匹配不到（如界面语言变化导致按钮名不匹配），用例会一直等到 test timeout —— 表象就是「卡住」。本次两度出现该现象，加固定上限后可快速失败并定位。

### 4.3 测试基建：屏幕唤醒

`helpers/adb.ts` 新增 `ensureScreenAwake()`（`KEYCODE_WAKEUP` + `wm dismiss-keyguard`），`installApk()` 复用；`mobile-ui.spec.ts` 在返回键用例前调用。

实测：**息屏时 Activity 无法获得前台焦点**（`mCurrentFocus` 变成 keyguard / `NotificationShade`），此时 `am start` 也不能把应用拉回前台 —— 前台/输入相关断言会全部失真。

### 4.4 既有用例修正：`mobile-ui.spec.ts` 硬件返回键（首次真机运行暴露）

该用例写于 2026-09-10（Phase 3）但**从未在真机跑过**，首次运行暴露两处不可用断言：

1. **不能用 `document.visibilityState` 判定后台**：Playwright 经 CDP（DevTools）附着时，Chromium 会把页面**强制视为 visible**，最小化后仍为 `visible`。改用**系统层面前台窗口**判定（`dumpsys window` 的 `mCurrentFocus`）：
   - 返回键关抽屉 → 前台窗口仍是本应用 ✓（复位了原 `visibilityState === "visible"` 的弱断言）
   - 再无覆盖层按返回键 → 前台窗口变成 launcher ✓（应用确实最小化，用 `dumpsys window` 直接确认产品行为正确）
2. **去掉「唤回前台」脚手架**：该 ROM 上应用退后台后 `am start` 会回 `intent has been delivered to currently running top-most instance` 而不重排任务，前台焦点不回归（属环境行为，非产品缺陷）。本用例是该文件最后一个，且每个 spec 的 `beforeAll` 会重装/清数据/重启应用、`afterAll` 会 force-stop，故无需唤回 —— 已在文件头写明「该用例必须放在文件内最后」的约束。

### 4.5 产品缺陷修复：能力不支持时不再「静默无操作」

`packages/ui/src/workspace-transfer.ts`

Android 上 `workspaceImport/workspaceExport` 均为 `"unsupported"`，原实现两个分支都不命中 → **点击 Import/Export 毫无反应**（用户会当成 bug）。现改为弹出 warning 级能力提示：

- 复用此前未被引用的 `errors.workspaceImportUnsupported`（en/zh 早已存在）；
- 新增 `errors.workspaceExportUnsupported`（en/zh）；
- `WorkspaceFileActions.test.tsx` 增 2 个单测（unsupported 时给提示且不调用 `openTextFile` / `saveTextFile`）。

### 4.6 Android 版本号改为取根 `package.json`

`apps/android/android/app/build.gradle`：Capacitor 模板占位值 `versionCode 1` / `versionName "1.0"` → 读仓库根 `package.json`（ADR-050 决策 7「版本取根 package.json」）：

```gradle
def rootPackageJson = new groovy.json.JsonSlurper().parse(file("$rootDir/../../../package.json"))
def appVersionName = rootPackageJson.version.toString()   // 0.4.2
// versionCode = major*10000 + minor*100 + patch → 402
```

实测安装后：`versionName=0.4.2`、`versionCode=402`。

## 5. 无线调试踩坑（已写入 `apps/android/README.md`）

1. **配对端口 ≠ 连接端口**：`_adb-tls-pairing` 只在「使用配对码配对设备」弹窗打开时存在；连接用「无线调试」主界面的 `_adb-tls-connect` 端口。**配对码约 1 分钟失效**，迟到会报 `error: protocol fault (couldn't read status message)`。
2. **不要凭肉眼用 IP**：本次用户给的 IP 与设备实际地址不同（连错表现为 `10061 拒绝` / `10060 超时`）；`adb mdns services` 可直接列出正确的 `_adb-tls-pairing` / `_adb-tls-connect` 的 IP:端口。
3. **两个 transport** → 裸 `adb` 报 `more than one device/emulator`（见 4.1）。
4. **未插电时 `svc power stayon true` 不生效**，须调长息屏超时（见 §2）；**息屏还会让前台焦点断言失真**（见 4.3）。
5. 无线链路下 `adb reverse`、`adb shell`、APK 安装（`--no-streaming`）均实测正常。
