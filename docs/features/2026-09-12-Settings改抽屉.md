# Settings 由 Modal 改为 Drawer

> 日期：2026-09-12　状态：完成
> 关联决策（如适用）：无新增 ADR（纯 UI 容器替换，无架构/产品级决策）；关联 ADR-033（工作区导入导出入口位于 Settings）、ADR-037（`Ctrl+,` 快捷键）、ADR-047/048（主题色预设选项）、ADR-049（重置工作区）、ADR-050 Phase 3（移动端布局与覆盖层）

## 需求摘要

将 Settings 界面由居中模态框（antd `Modal`）改为右侧抽屉（antd `Drawer`，侧滑展开），内容与行为保持不变，为后续「插件管理并入 Settings」预留更大的纵向空间。

## 边界条件

- **空值 / 极小 / 极大**：抽屉宽度固定 420px，窄屏（含手机竖屏）由 CSS `max-width: 100vw` 兜底，不会超出视口；内容为定长配置项，无空值分支。
- **并发**：抽屉为单实例（store `settingsModalOpen` 布尔），重复点入口/重复按 `Ctrl+,` 只是置 `true`，无重复挂载。
- **与其它覆盖层并存**：移动端左侧栏抽屉、底部面板抽屉与 Settings 抽屉可同时存在（三个独立 `Drawer`，各自遮罩）；不在本轮做互斥/层级特殊处理。
- **不改变的行为**：入口（顶栏 `Settings` 按钮 / 窄窗口 `More` 下拉 / `Ctrl+,`）、打开期间快捷键抑制（`keyboard/guards.ts#isAnyModalOpen`）、内容区块（主题、主题色预设、语言、重置工作区、工作区导入导出、插件 settings 分区、关于）、`data-testid="plugin-settings"`、懒加载与挂载门控（`React.lazy` + 各自 `<Suspense>` + `useOpenedOnce`）。

## 异常场景

- **失败时如何表现（UI / 通信 / 持久化）**：无新增失败路径。抽屉内的重置工作区（Popconfirm）、工作区导入/导出（`useWorkspaceTransfer` + antd message）沿用既有错误处理与提示，未改动任何调用。
- **容器层风险**：若误用 antd v6 已弃用的 `width`/`height`（或传入非纯数字字符串 `size`），会产生 console 警告/错误，进而打爆全仓 e2e 的「无 console 错误」断言——本轮以「数值 `size` + CSS `max-width`」规避，并由新增 e2e 断言守门。

## 性能与安全

- **性能**：抽屉与弹窗同为 portal 渲染，无额外重渲染；懒加载分块大小不变（产物文件名由 `SettingsModal-<hash>.js` 变为 `SettingsDrawer-<hash>.js`，四端相对说明符解析不受影响）。
- **安全/权限**：无变化。抽屉内的隐藏 `<input type="file">`（浏览器端工作区导入）与主机能力调用（导出下载 / 桌面端保存对话框）沿用既有能力矩阵与 HostMessage v1，未新增 kind、未改动能力位。

## 风险与回滚

- 风险：①弃用属性 / 非法 `size` 字符串 → console 警告（已规避 + e2e 守门）；②`.ant-drawer-section` 选择器歧义（已用 `.settings-drawer` 限定）；③移动端与侧栏抽屉并存的层叠表现（本轮不处理，记录为已知限制）；④懒加载 chunk 改名（无影响）。
- 回滚：纯 UI 容器替换 + 测试定位器改动，无工作区 schema / 数据迁移 / 协议契约变更，`git revert` 单次即可回退。

- 静态回归（已执行）：`pnpm typecheck` **32/32**、`pnpm lint` **EXIT=0**、`pnpm --filter @mamep2026/ui test` **388/388**（含新增抽屉容器断言；定向复跑 `src/MamepApp.test.tsx` 16/16）。
- e2e（已执行，定向 4 个 spec，**14/14 全绿**）：`pnpm --filter @mamep2026/e2e-web exec playwright test tests/settings-drawer.spec.ts tests/theme-color-presets.spec.ts tests/workspace-import-export.spec.ts tests/sidebar-rename-dark-theme.spec.ts`（3.2m）；全量 `test:e2e:web` / 三端 e2e / `pnpm test:all` 执行时机由用户决定。
- 已知限制（未处理，非缺陷）：Android 硬件返回键对 Settings 抽屉不生效（未注册 `overlay-close` 栈，现状所有 Modal 亦然）；移动端「侧栏抽屉 + Settings 抽屉」并存的层级与遮罩未做互斥。
- 实现要点（踩坑记录 1：类名归属）：antd v6 的 `className` 落在内容面板 `.ant-drawer-section` 上，而开合类 `.ant-drawer-open`、`.ant-drawer-mask`、`.ant-drawer-content-wrapper` 都在根元素 `.ant-drawer` 上 → 根级类必须用 `rootClassName`，否则 `.settings-drawer.ant-drawer-open` / `.settings-drawer .ant-drawer-content-wrapper` 全部匹配不到（Help 抽屉的 `className="help-drawer"` 只用于面板内后代选择器，故此前未暴露该差异）。
- 实现要点（踩坑记录 2：关闭后的 DOM 与动画）：抽屉关闭后**根元素仍在 DOM**（仅内容 `.ant-drawer-content-wrapper` 加 `ant-drawer-content-wrapper-hidden` → `display:none`）——故①不能对根元素断言 `toBeHidden()`（必须用 `.ant-drawer-open` 计数或对 wrapper 断言）；②关问后若还需继续操作页面，必须等**离场动画跑完**（开合类即时移除，动画期间点击会被仍在收起的遮罩/抽屉吞掉）——首轮 5 个 `workspace-import-export` 用例即因只等开合类而失败，助手改为「点关闭 → 等 wrapper hidden → 断 `.ant-drawer-open` 计数 0」后全绿。
