# 测试结果日志收集（轻量版）

> 日期：2026-09-07　状态：完成
> 关联：ToDoList「[test] 保存各种测试的结果作为测试报告」/ `pnpm test:all` 全量测试编排

## 需求摘要

把 `pnpm test:all` 的各测试步骤（单测 / acceptance / 三端 mock e2e / 真实端口 e2e / 虚拟串口 / lint / typecheck）的终端输出，**逐步骤落盘为独立日志文件**；每个单独测试脚本单独运行时也各自输出到对应日志文件。不做逐用例/逐包解析、不做 HTML 报告，保持轻量、机器可读。

> 背景：此前尝试过解析 turbo/playwright/stdout/stderr、逐用例表格等复杂方案，用户反馈「太复杂」已回撤，改采用本轻量方案。

## 边界条件

- 报告粒度仅到**步骤级**：每步 `name / command / exitCode / durationMs`，外加总体 `status`。
- 不解析单个用例 / 单测各包 / playwright 用例级的通过数。
- 不保存 stdout/stderr 全文到 JSON（完整原始输出在 `.log` 文件里）。

## 异常场景

- 真实端口 e2e 缺环境：由 `e2e-real.mjs` 按既有语义 `SKIP`（退出码 0），报告中记为通过（与 `test:all` 原语义一致）。
- 任一步失败：fail-fast 中止后续步骤，报告 `status:"failed"` + `failedStep`，退出码非 0。
- 日志写入失败：best-effort，不影响测试本身退出码。

## 性能与安全

- 性能：只是把输出 tee 到日志，额外开销可忽略。
- 安全：日志文件为本地生成产物，已加入 `.gitignore`（不提交）。

## 计划（Plan 摘要）

1. `run-logged`：`spawn(command, {shell:true})`，stdout/stderr tee 到终端 + `<logDir>/<name>.log`（文件侧去除 ANSI），并在 `summary.json` 追加步骤结果。
2. `test-all`：按固定顺序跑 `pnpm <script>`（`MAMEP_TEST_REPORT_DIR` 指向共享 run 目录），fail-fast，写 `result.json`，打印日志目录。
3. 单独脚本：`package.json` 中把 `test` / `test:acceptance` / `test:e2e:*` / `test:*:real` / `test:serial:virtual` / `lint` / `typecheck` 包一层 `run-logged`。
4. `MAMEP_TEST_ALL_STEPS`（逗号分隔）可只跑部分步骤，便于子集验证。

## 测试策略

- 新增测试：`scripts/lib/test-report.test.mjs`（node:test）：`stripAnsi`、`timestamp`、`runLogged` 成功/失败/去 ANSI/写 summary。
- 已人工冒烟：`run-logged` 单命令、`cmd /d /s /c` 下外层引号包裹 `&&` 的单参数行为、`test-all` 用 `MAMEP_TEST_ALL_STEPS=lint` 全链路（共享目录 / summary / result.json / fail-fast / 退出码；lint 曾因 `tests/e2e-web/tests/app.spec.ts:312` 既有 `err` unused 报错而失败，该错误已一并修复，全仓 lint 通过）。
- 回归重点：`pnpm test:all` 各环节仍按原顺序执行、失败中止、`test:e2e:vscode` 的 `&&` 引号不破坏。
- 执行时机：**由用户决定**（docs/AGENTS.md §27）；全量 `pnpm test:all` 未在本功能内执行。

## 风险与回滚

- 风险：`test:e2e:vscode` 的 `&&` 通过外层引号作为单参数传给 `run-logged`，已用 `cmd /d /s /c` 验证可靠；若个别 shell 环境异常，可退回「构建与测试分两条 `&&` 串联」写法。
- 回滚：恢复 `package.json` `test:all` 为原链式命令、去掉各测试脚本的 `run-logged` 包装即可；`scripts/` 新增文件可独立删除。
