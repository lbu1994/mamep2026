# 删除 Modbus RTU 设置中的 Rx Delay（`interRequestDelayMs`）

> 日期：2026-09-06　状态：完成
> 关联：ADR-013（「WP 轮询间隔 = Rx Delay」语义翻转）、TECH_DESIGN §12.3 / §13、docs/AGENTS.md §13.3 / §14。

## 需求摘要

删除 Connection Settings 中 RTU「Option」分组的 **Rx Delay (ms)** 输入项及其功能（内部字段 `interRequestDelayMs`，默认 50ms、范围 0–5000ms）。删除后两重作用均去除：

1. 相邻请求之间最小附加间隔为 0（上一请求结束后立即开始下一请求）；
2. WP 轮询的重复读取不再有间隔（读完一个立即读下一个，轮询间隔恒为 0）。

## 边界条件

- **范围**：**全局删除**（用户决策 1A）——RTU 与 TCP 均移除 `interRequestDelayMs`（TCP 侧原为「内部字段，不入表单」，兼作其 WP 轮询间隔）。
- **字段处理**：**完全移除**（决策 2A）——domain 模型 / workspace schema / platform-api payload / config 均删除该字段。
- **工作区 schema 版本**：**不 bump**（决策 3A）——zod 默认 `strip` 未知键，旧工作区数据仍可解析（向后兼容），旧 `interRequestDelayMs` 在解析时被静默丢弃、重存时消失。
- **WP 轮询间隔**：**恒定 0**（决策 4）——`PollingCoordinator` 的 `getIntervalMs` 由 application 层固定 `() => 0`，即「读完一个立即读下一个」。
- **i18n**：`connection.rxDelay` 删除；`wpHint` → "Poll this register continuously while online."；`pollingActive` → "Polling continuously"（zh-CN 同步）。
- **明确不做**：不用于判断帧是否结束 / 不替代请求超时 / 不影响已收到响应的解析（TECH_DESIGN §12.3）。

## 异常场景

- 旧工作区含 `interRequestDelayMs`：解析时被 zod strip，重存后消失；无迁移、无版本 bump（决策 3A）。
- 旧连接设置表单（若缓存过 `rxDelay` 值）：字段已从 `settingsSchema` 移除，提交不包含该字段、不校验。
- TCP 轮询：`getPollingIntervalMs` 固定 0，TCP WP 轮询同样「读完一个立即读下一个」。

## 性能与安全

- 轮询间隔 0 可能产生较高的轮询/读取频率（对设备较激进），已按决策 4 接受；所有请求仍经统一调度器串行执行（单连接同一时刻一个请求），inFlight/跳过机制防积压。
- 零协议/跨端 HostMessage v1 改动（仅 payload 字段删除）、零安全影响。
