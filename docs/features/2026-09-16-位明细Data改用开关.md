# 位明细 Data 单元格改用开关（去掉输入框）

> 日期：2026-09-16　状态：完成（实现 + 单测 + 定向 e2e + typecheck/lint 全绿）
> 关联决策：docs/adr/ADR-052-寄存器位明细展开.md（本变更以「修订（2026-09-16）」小节记录，不新增 ADR）

## 需求摘要

Type 为 **Binary** 的寄存器行展开出的位明细子行（bit15 → bit0），其 Data 列**不再提供输入框**，
只保留一个带文字 `1`/`0` 的 antd `Switch`（`checkedChildren="1"` / `unCheckedChildren="0"`），
让位值操作只走「开关」一种交互。

## 边界条件

- **未读取（`registerValues === null`）**：开关显示为关，并在开关左侧显示 `—` 占位，用于与「读到 0」区分；
  开关**仍可点击**（ADR-052 决策 4「未读取按父行 `cellText` 派生、失败全 0 的基准可操作」），
  代价是未读取时首次点击只能得到 `1`（再点回 `0`）。
- **只读表**（`discrete-input` / `input-register`）：可展开查看，开关 `disabled`（与位名称/位注释编辑禁用一致）。
- **范围行两层嵌套**（范围行寄存器子行再展开位明细）：同一渲染路径，行为一致。
- **位值语义不变**：只改当前值（`registerValues[i]` + 父行 `cellText` 重算），**不写设备、不入撤销栈**（ADR-052 决策 3/6）。

## 异常场景

- 去掉输入框后不存在「非法输入」路径（原来的 `0`/`1` 校验、错误提示与草稿保留逻辑一并移除）。
- 只读表点击开关：antd `Switch` 为 `disabled`，无 `onChange`（与改造前一致，无新失败面）。
- 未读取时点击开关：按全 0 基准写入当前值（不涉及设备、持久化仅经既有自动保存）。

## 性能与安全

- 位行渲染由「`EditableCellValue`（本地 editing/draft 状态 + 输入框）+ Switch」简化为「div + Switch」，
  减少每行一个受控 `Input` 与本地状态，虚拟滚动/长表渲染开销略降。
- 安全边界零改动：不写设备、不新增 HostMessage kind、不涉及 CSP / 能力矩阵 / 协议层。

### 视觉微调（同日，用户反馈）

用户实测后提出三点：① 开关要居中；② `0`/`1` 文字偏大、快超出开关边界；③ 开关长度稍微长一点。
均为 `apps/web/src/index.css` 纯样式调整（无组件/逻辑改动）：

| 需求     | 做法                                                                                                                                                                              | 实测（1600×900，系统 Edge）                                                                  |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 居中     | `.register-table__bit-value` 加 `justify-content: center`；未读取占位改 **绝对定位**（`inset-inline-end: calc(50% + 23px)`），否则会参与 flex 布局把开关整体推离中心              | 开关中心 **759.5** vs 单元格中心 **760**（±0.5px，未读取/已读取两态一致）                    |
| 文字变小 | 字号必须写在两个文字 span 上（antd 直接给它们设了 `font-size`，父级继承无效），选择器用 4 个类压过 antd 的 3 类                                                                   | **12px → 10px**；文字可用宽度 **7px → 13px**；`overflow:hidden` 无裁剪（可见文字均在开关内） |
| 开关加长 | `.register-table__bit-value .ant-switch.ant-switch-small { min-width: 34px }`（antd small 默认 `min-width` = 滑块 10×2 + padding 2×2 = **24px**；选择器 3 个类压下 antd 的 2 类） | 开关 **34×14px**；文字与滑块/边缘留 **4–5px**                                                |

验证方式：临时 Playwright 脚本测量 `getBoundingClientRect` / `getComputedStyle`（已于验证后删除），
并用 Qwen 视觉代理复核 3× 高清裁切截图的观感（“无拥挤、未超出开关边界、水平居中”）。
若还要更紧凑/更宽，只需改 `min-width`（如 32/36px）与 `font-size`（如 9/11px）两个值。

### 2026-09-17：改用 antd **默认尺寸**（开关做高，行高不变）

用户问“开关能不能做高而不撑大行高”。实测行高构成与边界（真实浏览器注入不同高度、等 `transition` 结束再量）：

| 开关高度 | 14  | 18  | 20  | 22  | **24** | 25  | 26  | 28  |
| -------- | --- | --- | --- | --- | ------ | --- | --- | --- |
| 表格行高 | 29  | 29  | 29  | 29  | **29** | 30  | 31  | 33  |

- 行高 29px = 单元格上下 `padding` 2px×2 + 底边框 1px + 内容区 **24px**；那 24px 由固定 24px 高的
  `.register-table__editable-cell-value-wrap`（Name/Comment 编辑单元格）决定，**与开关无关**；
- 因此开关高度 ≤ **24px** 不撑高行（>24px 时 行高 = 开关高 + 5px）；⚠️ 若真要超过，必须同步改
  `RegisterTable.tsx` 的 `ROW_HEIGHT = 29`（移动端 `MOBILE_ROW_HEIGHT = 44`），否则虚拟滚动错位。

**实现（用户选定方案 A）**：删除 `size="small"`，回到 antd 默认尺寸 —— 高度由 `fontSize × lineHeight`
计算（small 为 `controlHeight / 2` = 14px）。实测：

| 项           | 改前（small）           | 改后（默认尺寸）                        |
| ------------ | ----------------------- | --------------------------------------- |
| 开关尺寸     | 34 × 14px               | **44 × 21px**                           |
| 滑块         | 10×10px                 | **17×17px**                             |
| 行高         | 29px                    | **29px**（未变）                        |
| 水平居中     | 中心 759.5 / 单元格 760 | **中心 759.5 / 单元格 760**（未变）     |
| 文字可用宽度 | 13px                    | **12.5px**（无 `overflow:hidden` 裁剪） |

**为什么宽 34px 维持不住**：默认尺寸的内边距随滑块一起变大（`innerMaxMargin = 滑块 + padding×3`、
`innerMinMargin = 滑块 / 2`），若仍用 34px，文字可用宽度只剩 ≈ **3px**，会被 `overflow: hidden` 裁掉；
故 `min-width` 同步改为 **44px**（antd 默认 ≈ 40.9px），占位偏移改为 `calc(50% + 28px)`（44/2 + 6）。
未选方案 B（保留 small + 纯 CSS 抬高）：需手工同步 handle 尺寸、选中态 `inset-inline-start`、文字
`min-height` 与 antd 内置的固定像素滑动 margin（如 `calc(-100% + 14px - …)`），且 antd 给 Switch 加了
`transition: all`（**测量/断言时必须等过渡结束**，否则读到起始值）。

**同日追加：`1`/`0` 字号改为与 Data 列普通数据一致（13px）**（用户要求）。实测 Data 列普通数据单元格
`font-size` = **13px**（继承主题 `fontSize: 13`，`td` 与 `.register-table__editable-cell-value-wrap__text` 同值），
故把开关文字从 10px 改为 **13px**。实测（两态一致）：字形宽 **7.02px**、文字框 **12.5px**、
单侧余量 **2.74px**（无 `overflow:hidden` 裁剪，优于 antd 默认尺寸自带的 ≈1.75px）、行高仍 **29px**、居中不变；
视觉代理复核 3× 高清裁切：“数字未越界、开关水平居中、比例协调不拥挤”。未改 `min-width`（仍 44px）。

**同日再追加：未读取的「—」改为显示在开关内部（替代 `0`）**（用户要求）。实现：直接改 props——
`unCheckedChildren={value === null ? "—" : "0"}`（读到 0 时仍为 `0`），**删除**开关外侧的
`.register-table__bit-value-placeholder` 占位与其 CSS（含 `position: absolute` / `inset-inline-end`）。
好处：不新增 DOM 节点、不需绝对定位去避免推偏居中，未读取与「读到 0」的区分也落在开关内部。实测（未读取态）：

| 项                       | 值                                    |
| ------------------------ | ------------------------------------- |
| 开关内文字               | `—`（字形宽 13px，13px 字号）         |
| 字形到开关左边（旋钮侧） | 23px                                  |
| 字形到开关右边           | 8.5px                                 |
| 字形是否越界             | 否（完全落在开关内部，与 `0` 同位置） |
| 开关尺寸 / 行高          | 44.5 × 21px / 29px（未变）            |
| 开关中心 / 单元格中心    | 759.5 / 760（居中不变）               |

回归：单测 `RegisterTable.test.tsx` **43/43**、定向 e2e `bit-detail.spec.ts` **5/5**（50.4s）；
e2e 断言助手改为按「当前该显示哪一侧」的 span 断言文字（`1` / `0` / 未读取 `—`），状态仍以 `aria-checked` 为准。

回归：单测 `RegisterTable.test.tsx` **43/43**；定向 e2e `bit-detail.spec.ts` **连续 5 次 5/5 全绿**

## 风险与回滚

- 风险：① 未读取态的区分依赖 `—` 占位（读成功后消失，可区分，但视觉需实测确认）；
  ② 失去键盘直接输入（用户已确认接受 antd Switch 原生键盘能力）；
  ③ e2e 断言依赖 antd Switch 的 `aria-checked`（语义属性，版本敏感度低）。
- 回滚：`BitDataCell` 单点渲染回退 + 恢复 i18n 两键；无数据模型/schema/协议影响。

## 踩坑（antd v6 Switch）

- `checkedChildren` / `unCheckedChildren` 渲染为**两个恒在 DOM 的兄弟 span**（`.ant-switch-inner-checked` /
  `.ant-switch-inner-unchecked`，由 `@rc-component/switch` 渲染、靠 CSS margin 滑动切换），因此
  **e2e 不能用可见文本判断开关状态**（`textContent` 恒为 `10`），必须断言 `aria-checked`（或 `.ant-switch-checked`）；
  单测则可直接断言两个 span 各自的文本（已验证 `size="small"` 同样渲染这两个 span）。
- 去掉输入框后不再需要 `stopPropagation`（原为阻止点击开关时同时触发外层 `EditableCellValue` 进入编辑），
  已在实现中一并移除。
