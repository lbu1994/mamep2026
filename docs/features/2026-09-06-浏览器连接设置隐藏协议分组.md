# 浏览器端连接设置不显示「协议」分组

> 日期：2026-09-06　状态：完成
> 关联：ADR-022 协议门控 / ADR-046 浏览器兼容性检测。纯 UI 打磨，无新增 ADR。

## 需求摘要

浏览器仅支持 Modbus RTU（`browserCapabilities.modbusTcp:false`），连接设置里的「协议」`Segmented` 只有单选项「Modbus RTU」，冗余。目标：浏览器端隐藏整个「协议」分组（label + Segmented）；Electron/VSCode（`modbusTcp:true`）保留 RTU/TCP 切换。

## 边界条件

- 判定：按能力矩阵「可用协议数 > 1」决定是否显示协议分组（`supportsRtu && supportsTcp` 才显示）；浏览器 rtu-only 隐藏，比仅判 `modbusTcp` 更通用。
- 隐藏后 `protocol` 值：保留 `<Controller name="protocol">` 注册，隐藏分支渲染一个 `<input type="hidden">` 承载字段，保持 `protocol="rtu"` 稳定；submit 走 `values.protocol === "rtu"` → RTU 连接路径不变。
- `sheetProtocol`（活动表类型对应 codec 协议）照常传给 `host.connect`，与是否显示协议组无关。
- 不改动：`BottomPanel`「通信属性」协议显示、Header、能力矩阵数值、HostMessage v1、调度器。

## 异常场景

- 假设未来某平台仅支持 TCP（`supportsRtu:false`）：>1 条件会隐藏分组，但 `protocol` 默认仍 `"rtu"` 会错误；当前三端矩阵无此平台，如需要另设默认协议，本次不做。
- 能力矩阵异常（无 rtu 亦无 tcp）：协议组隐藏、`protocol` 回退 `"rtu"`；由能力矩阵自身负责。

## 性能与安全

- 纯 UI 显示与能力矩阵门控联动，零协议/跨端改动，无安全影响。

## 影响模块

| 包/端 | 文件 | 改动原因 |
|------|------|---------|
| packages/ui | `src/components/ConnectionSettingsModal.tsx` | 新增 `showProtocolSwitcher`（可用协议数>1）；协议分组按此渲染，隐藏分支用隐藏 input 注册字段 |
| packages/ui | `src/components/ConnectionSettingsModal.tcp.test.tsx` | 浏览器用例改为断言「协议分组隐藏」（无 Protocol/Modbus RTU/TCP），并断言 RTU 通信组仍显示 |

## 计划（Plan 摘要）

1. `ConnectionSettingsModal` 计算 `showProtocolSwitcher`。
2. `<Controller name="protocol">` render：显示分组（Form.Item + Segmented）或隐藏（`<input type="hidden" {...field}/>`）。
3. 更新浏览器单测断言。

## 测试策略

- 回归：typecheck（ui 通过）、lint 0、相关单元测试 14/14。e2e-web `app.spec.ts`（仅断言无 Modbus TCP、Connection Settings 存在）不受影响，未重复跑（执行时机由用户决定）。

## 风险与回滚

- 风险：隐藏协议组时 `protocol` 值依赖 Controller 注册；已用隐藏 input 保字段，避免 RHF 未注册字段边界问题。
- 回滚：删除 `showProtocolSwitcher` 分支、还原协议组显示即可；改动集中在 `packages/ui`，不涉协议/跨端。
