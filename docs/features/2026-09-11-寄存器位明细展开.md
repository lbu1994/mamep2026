# 寄存器位明细展开（Binary 行 → 一行一 bit）

> 日期：2026-09-11　状态：完成（含同日需求追加）
> 关联决策：docs/adr/ADR-052-寄存器位明细展开.md（ADR-030 范围行 / ADR-031 子行可编辑化 / ADR-032 撤销边界 / ADR-051 二进制分组）

## 需求摘要

单寄存器（或范围行寄存器子行）Type 为 Binary 时，可展开为 16 行位明细（Register 列「寄存器地址 + Bit 序号」+
位名称 + 0/1 + 位注释），逐位查看、置位与标注，提升寄存器表的位级可读性。

## 需求追加（2026-09-11）

- **Name 列可自行编辑**（与 Comment 列同处理）：新增 `RegisterRow.bitNames` + 工作区 schema **v9→v10**（纯补 null，位注释不丢）。
- **Register 列显示寄存器号 + Bit 序号**（如 `2000 Bit 15`）：按本表 HEX/DEC 进制格式化地址；原掩码改为 hover 提示。

## 边界条件

- 空值：寄存器尚未读取（`registerValues === null`）时位行显示 `—`；切换/输入以「父行 `cellText` 派生、
  失败全 0」为基准（与 `commitChildCellText` 同语义），**不禁用**。
- 极小/极大：bit0 掩码 `0x0001`、bit15 掩码 `0x8000`；位注释长度无上限（与行 Comment 一致）。
- 并发：位行是派生虚拟行，不落 store、不进设备请求路径；位值改动只改当前值，不影响在途请求。
- Type 切走/切回：位子行随之消失/重新生成（无持久化展开态）。

## 异常场景

- 位值输入非法（非 `0`/`1`）：保留输入 + 红框/Tooltip（既有 `EditableCellValue` error 分支），不写坏当前值。
- 越界调用（`registerIndex` / `bit` 超范围）：`bit-register.ts` 返回结构化错误（`BIT_INDEX_OUT_OF_RANGE` 等）。
- 只读表（`discrete-input` / `input-register`）：位明细可展开查看，切换与注释编辑禁用。
- 持久化：旧工作区（v8 及更早）经迁移补 `bitComments = null`；缺陷数据（长度不匹配）按索引裁剪/补齐。
- **范围行位值编辑**：必须经真实父行 rowId + `registerIndex` 路由（寄存器子行 id 是派生虚拟 id、不入 store）；
  该缺陷由 e2e `bit-detail.spec.ts`「范围行两层嵌套」用例捕获并修复（单寄存器行不可复现，需范围行用例守护）。

## 性能与安全

- 性能：位子行仅在展开时生成（惰性 `children`）；位行单元格组件全部 `memo`；
  「存在范围行或 binary 行」时禁用虚拟滚动（antd tree + virtual 不兼容，ADR-030 先例，阈值 > 500 行）。
- 安全/权限：位切换**不写设备**（设备写入仍需用户按 Write 触发），不新增 HostMessage kind、
  不改能力矩阵、不触碰协议层与调度器。

## 计划（Plan 摘要）

1. 文档（ADR-052 + 本记录）。
2. 数据模型：domain 字段 + workspace schema/迁移 + platform-api payload。
3. 纯逻辑：`bit-register.ts`（位值读写、注释、掩码、范围裁剪）+ 撤销字段扩展。
4. UI：`tree-rows.ts` 位子行（两层递归）、`RegisterTable` 位行渲染与交互、`app-store` 动作、i18n/样式/帮助。
5. 测试：受影响包单测（TDD 红→绿）+ e2e-web 位明细闭环。
6. 回归：受影响包单测 + `pnpm typecheck` + `pnpm lint`，界面/传输相关提醒冒烟或 e2e。

## 风险与回滚

- 风险：两层树行数放大、手势冲突（点击切换 vs 点击编辑）、schema v9 影响面、
  **范围行位值路由误用虚拟行 id**（已发生并由 e2e 捕获，见上方异常场景）。
- 回滚：`buildTreeRows` 停止为 binary 行生成 `children` 即恢复原行为（字段/迁移无害）；
  完整回滚 revert 提交，v9 为纯增字段，旧版本 zod strip 后仍可读取。
