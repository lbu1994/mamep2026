# App 装配按运行时平台懒加载三端 Host（含启动骨架屏）

> 日期：2026-09-13　状态：完成
> 关联：ToDoList「构建产物代码分割」（2026-09-11 已完成）／ADR-016 Electron 骨架与安全 IPC／ADR-021 VSCode RTU 接线／ADR-022 两端 TCP 接线／ADR-050 Android 端接入与 Capacitor 方案／ADR-054 删除随包插件机制与同进程执行
> 说明：本改动为**纯装配层重构**，无工作区 schema / HostMessage v1 / 能力矩阵 / 协议层 / 调度器变更，故不新增 ADR。

## 需求摘要

`apps/web/src/App.tsx` 此前**静态 import** 三端宿主实现（`ElectronAppHost` / `VscodeAppHost` / `AndroidAppHost`）与 `@mamep2026/platform-android` 的两个 Capacitor 子路径，导致四端渲染器首屏都加载并执行 `@capacitor/core`（浏览器构建中该 chunk 还被 `<link rel="modulepreload">` 预加载）。本改动把宿主实现改为**按运行时平台动态 `import()`**，并补齐由此引入的异步装配语义（启动骨架屏 + 装配失败兜底 + 取消竞态守卫）。

## 边界条件

- 平台判定顺序保持既有行为：`window.mamepHost` 存在 → 按 `bridge.platform` 分 VSCode / Electron；无桥且 `Capacitor.getPlatform() === "android"` → Android；否则浏览器。**宿主桥优先**（宿主内嵌 WebView 不得误判 Android）。
- **浏览器路径保持静态装配**（`BrowserAppHost` 同时是 Electron / Android 的 inner：Web Serial + IndexedDB 路径三端共用），因此浏览器/Android 首屏不增加异步跳；只有 Electron / VSCode / Android 各自成为懒 chunk。
- `vscode-dev-bridge.ts` **不动态化**：它在 `main.tsx` 中先于 `createRoot().render()` 同步安装 `window.mamepHost`，动态化会推迟挂载（用户决策）。
- 启动骨架只覆盖「Host 装配中」（模块加载 + 宿主构造）：接线完成即切真实外壳，工作区加载、Connection Settings 自动弹出仍由外壳承担（`loaded` 语义不变）。
- `hostStatus` 默认 `"ready"`（组件隔离渲染/单测不受影响）；真实启动由 `apps/web/src/main.tsx` 在渲染前置 `"assembling"`（起点必须早于首帧）。

## 异常场景

- **懒 chunk 加载失败 / 宿主构造抛错**：捕获后置 `hostStatus: "failed"`、发 `messages.hostLoadFailed` 错误消息（含原因），应用以「无 Host」状态保持可操作（连接等入口依 `host === null` 自然禁用）——**不再白屏**（改前静态 import 失败即整页不可用）。
- **取消竞态**（StrictMode 双挂载 / 页面卸载）：装配用 `AbortSignal`，在 `await` 后与工厂调用后**各查一次 `aborted`**；已取消则丢弃（已构造的 host 立即 `dispose()`，**不接线**）——否则旧 host 订阅与新 host 并存会让通信日志一条变两条（2026-08-23 已修 bug 的回归防护）。
- 释放由装配编排的 abort 监统一负责：退订 `visibilitychange` + `host.dispose()`；Android 前后台订阅（`@capacitor/app`）挂同一信号退订。

## 性能与安全

### 实测（`pnpm --filter @mamep2026/web build`，2026-09-13）

| 指标                                       | 改造前                                                         | 改造后                                                                  |
| ------------------------------------------ | -------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 入口 chunk                                 | 384.54 kB（gzip 113.19）                                       | **7.78 kB**（gzip 3.08）——应用代码重新分入共享 chunk                    |
| **首屏 JS 合计**（入口 + `modulepreload`） | 1663.21 kB / gzip 518.16（16 文件）                            | 1630.45 kB / gzip 513.91（20 文件）= **−32.76 kB（−2.0%）/ gzip −0.8%** |
| `@capacitor/core`                          | 7.74 kB，**首屏预加载并执行**（顶层挂 `globalThis.Capacitor`） | 7.74 kB，**仅 Android 按需加载**                                        |
| 平台宿主 chunk                             | 全在首屏                                                       | `electron` 9.81 / `vscode` 11.67 / `android` 9.23 kB（懒）              |
| chunk 总数                                 | 22                                                             | 33（首屏 +4 个同源并发请求）                                            |

- **门槛结论（实施前约定：入口收益 < 5% 则不做）**：字节收益 **低于门槛**（首屏 gzip −0.8%）。实施前的桩替换对比构建预测「入口 −49.9 kB（−13%）」高估了净收益——基线首屏早已包含几乎全部代码（真正懒加载的仅 4 个弹窗，74 kB），被移出的平台专属代码本身约 38 kB。**经用户确认后保留**，理由为下述非字节收益（平台隔离、失败兜底、可测性），并在 `ToDoList` 如实标注字节收益低于门槛。
- **保留的实际价值**：① Capacitor 运行时不再在浏览器 / Electron / VSCode 加载与执行（平台隔离 + 少一个第三方全局副作用）；② 装配失败从白屏变为可读提示 + 可操作；③ 启动骨架屏（深色主题下不闪白，骨架在 `ConfigProvider` + `AntApp` 内）；④ 装配编排从 0 测试变为 9 个单测；`App.tsx` 由 345 行降至约 130 行。
- 安全边界零改动：能力矩阵 / HostMessage v1 / 工作区 schema / CSP / 插件机制（含同进程授权）均不变；懒 chunk 为同源脚本，`file://`（Electron）、`vscode-webview://`（VSCode）、`https://localhost`（Android）解析路径与既有懒加载弹窗一致。

## 风险与回滚

- **风险 1｜启动时序**：装配整体后移一个 chunk 加载耗时（同源本地文件），可能踩 e2e 固定等待窗口。缓解：浏览器路径不懒加载；骨架替换外壳不改变 DOM 就绪顺序；三端 e2e 已全绿。
- **风险 2｜懒加载路径的产物级验证**：dev 不打包，`e2e-web` 覆盖不到 → 以 Electron（`file://`）与 VSCode（`vscode-webview://`）生产产物 e2e 为准（已验证）。
- **风险 3｜首屏请求数 +4**：均为同源小 chunk（0.6–50 kB），可接受。
- **回滚**：改动集中在 `apps/web/src` + `packages/ui` 少量文件 + i18n，`git revert` 即可完全恢复（无数据/协议迁移）。
