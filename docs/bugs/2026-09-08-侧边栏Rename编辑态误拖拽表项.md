# 侧边栏 Rename 编辑态下误拖拽表项（无法选中输入框文本）

> 日期：2026-09-08　状态：已验证

## 现象

侧边栏对某 sheet 项右键菜单选择 **Rename** 进入重命名编辑态后，想在输入框内用鼠标按住拖动**选中全文**，结果却把整个 sheet 项**拖拽移动**了；期望能正常选中输入框内容、sheet 不被拖走。

复现步骤：

1. 侧边栏右键某个 sheet 项 → **Rename**（`.sheet-item__input` 出现）；
2. 在输入框内按住鼠标左键并左右拖动（意图选中文本）；
3. 观察：sheet 项被拖拽移动，文本未被选中。

## 根因分析

`packages/ui/src/MamepApp.tsx` 中，侧边栏表项通过一个 `useEffect`（无依赖数组、每次渲染后执行）把**所有** `li[data-sheet-id]` 设为 `draggable = true`，用于启用拖拽排序：

```js
useEffect(() => {
  sidebarListRef.current?.querySelectorAll <
    HTMLLIElement >
    "li[data-sheet-id]".forEach((el) => {
      el.draggable = true;
    });
});
```

当某个 sheet 进入重命名编辑态时，`<SheetNameEditor>` 的 `<input>`（`.sheet-item__input`）渲染在**同一个可拖拽的 `li`** 内部。因为整个 `li` 是 `draggable`，用户在输入框上按下鼠标并移动，会被浏览器判定为「拖拽该表项」（触发 `dragstart`），而不是「文本选择」，故无法选中文本且 sheet 被拖走。

**对比**：页签头重命名走 antd `Tabs` 结构，不经过上述「li 设 draggable」链路，因此无此问题。

## 复现测试（强制）

- 测试文件：`tests/e2e-web/tests/sidebar-rename-drag-select.spec.ts`
- 断言：正在 Rename 的 `li[data-sheet-id]` 的 `draggable` 为 `"false"`（可正常选中文本），其余 sheet 项仍为 `"true"`（拖拽排序不受影响）。
- **红**（修复前）：`expect(renamingLi).toHaveAttribute("draggable", "false")` 失败，实测为 `"true"`。
- **绿**（修复后）：`1 passed`。

## 修复方案

- 方案：让「正在重命名的那个表项」在编辑态下**不 draggable**，其余项仍可拖拽排序。将上述 effect 改为按 `sidebarRenamingSheetId` 条件化：

  ```js
  el.draggable = el.dataset.sheetId !== sidebarRenamingSheetId;
  ```

  `sidebarRenamingSheetId` 是组件作用域状态，该 effect 无依赖数组、每次渲染后执行，会随编辑态进入/退出自动重应用 draggable。

- 影响文件：`packages/ui/src/MamepApp.tsx`（仅一处 effect 逻辑，组件 JSX 零改动）。
- 兼容处理：编辑态退出（提交/取消/Escape）后 `sidebarRenamingSheetId` 置空，对应 `li` 恢复 `draggable = true`，拖拽排序行为不变；其余 sheet 项始终可拖拽。

## 影响范围与回归

- 受影响模块：`packages/ui`（侧边栏拖拽与重命名交互）。
- 回归测试：`pnpm --filter @mamep2026/e2e-web test`（确认 `sidebar-menu.spec.ts` 拖拽排序、重命名用例无回归）+ `@mamep2026/ui` 单测 + `pnpm typecheck` / `pnpm lint`。
- 执行时机：**由用户决定**（docs/AGENTS.md §27）。
