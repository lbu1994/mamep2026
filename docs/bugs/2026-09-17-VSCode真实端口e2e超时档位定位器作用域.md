# VSCode 真实端口 e2e：RTU 超时档位选择器定位作用域错误

> 日期：2026-09-17　状态：已修复（已回归）
> 关联：[ADR-024 三端真实端口 e2e](../adr/ADR-024-三端真实端口e2e测试.md)、
> [2026-09-11-VSCode真实端口e2e移动布局回归.md](2026-09-11-VSCode真实端口e2e移动布局回归.md)、
> [2026-09-17-刷新后外壳界面状态首帧闪烁.md](2026-09-17-刷新后外壳界面状态首帧闪烁.md)（本次 `test:all` 首次暴露该缺陷）

## 现象

`pnpm test:all` 首轮在 `test:e2e:vscode:real` 中止（`real-rtu.spec.ts` 的「连接：自动选择 COM4 → Online」步骤）：

```
TimeoutError: locator.waitFor: Timeout 10000ms exceeded.
  waiting for locator('.ant-select-dropdown:visible .ant-select-item-option')
    .filter({ hasText: /^100 ms$/ }) to be visible
```

浏览器（15/15）与 Electron（29/29）同款用例通过，仅 VSCode 失败。

## 根因

`tests/e2e-vscode/real/real-rtu.spec.ts` 的 `setRtuTimeoutSelect` 用 `frame.page().locator(...)` 定位 antd 下拉选项：

```ts
const option = frame.page().locator(".ant-select-dropdown:visible .ant-select-item-option")...
```

VSCode webview 是**两层嵌套 iframe**（窗口 → 容器 `index.html` → 内容 `fake.html`），共享 UI 与其渲染的
下拉 portal 都在**最内层 frame** 内；`page.locator()` 只查**顶层窗口文档**，因此永远命中不到 → 超时。

该缺陷是 2026-09-16「超时档位增补长档位（1000 ms）后，键入 `100` 会同时匹配 `100 ms` 与 `1000 ms`，
Enter 落点不保证 → 改为精确点选」那次改动引入的：同文件里的 Port 下拉一直用 `frame.locator(...)`（正确），
只有新改的这个助手误用了 `page` 作用域。浏览器 / Electron 无嵌套 iframe，所以两套 suite 一直绿，
VSCode suite 直到本次 `pnpm test:all` 首次完整执行才暴露。

失败快照佐证：下拉**已打开且已过滤**（listbox 内只有 `100 ms` / `1000 ms` 两项），说明点击与搜索都正常，
唯一的问题就是「在错误的 frame 里找元素」。

## 修复

`setRtuTimeoutSelect` 改回 **frame 作用域**：

```ts
const option = frame
  .locator(".ant-select-dropdown:visible .ant-select-item-option")
  .filter({ hasText: new RegExp(`^${timeoutMs} ms$`) });
```

同时把「收窄下拉列表」的方式由键盘输入改为**元素级 `locator("input").fill(...)`**（不依赖窗口 / iframe
键盘焦点，避免同类焦点竞态），并在点选前加 `waitFor({ state: "visible", timeout: 10_000 })` 提升可诊断性。

- **改动文件（仅测试代码）**：`tests/e2e-vscode/real/real-rtu.spec.ts`；
  另同步加固 `tests/e2e-electron/tests-real/real-serial.spec.ts` 与
  `tests/e2e-web/tests-real/real-serial.spec.ts` 的同名助手（作用域本身合法，仅统一为 `fill` 写法）。
- **产品代码零改动**：无协议 / 状态机 / UI 行为变化。

## 教训

- **e2e-vscode 里禁止用 `frame.page().locator(...)` 找 webview 内元素**——一律用 `frame.locator(...)`
  （`frame` = `waitForWebviewFrame()` 返回的最内层 frame）。键盘类调用（`frame.page().keyboard`）仍可用，
  但输入文本优先用元素级 `fill()`。
- 三端 real spec 有同名助手（`setRtuTimeoutSelect`），改一处要检查另两处的一致性。
- 新增 / 修改 e2e 用例后必须进一次**全量 suite**：本次缺陷在定向运行里不会暴露（浏览器 / Electron 路径
  本就正常）。
