# VSCode 真实端口 e2e 未适配移动布局（ADR-050 Phase 3 回归）

> 日期：2026-09-11　状态：已验证
> 关联：ADR-050（Android 第四平台，Phase 3 移动布局）/ ADR-024（三端真实端口 e2e）

## 现象

`pnpm test:all` 首次完整执行时，在第 3 步 `test:e2e:vscode:real` 中断：

- `real/real-rtu.spec.ts`「真实串口 RTU（UI 级）：连接 + 全场景矩阵」与 `real/real-tcp.spec.ts`「真实 Modbus TCP（UI 级）：连接 + 全场景矩阵」均在**第一个 `test.step`（连接）末尾**失败：
  `TimeoutError: locator.evaluate: Timeout 30000ms exceeded. waiting for locator('.table-toolbar__radix .ant-segmented-item').filter({ hasText: 'HEX' }).first()`（`setRadixHex`）。
- 连接本身是成功的（顶栏 `data-conn-state='connected'` 断言已通过、弹窗已关闭），`real-theme.spec.ts` 通过（3 例中 2 例失败）。

## 根因分析

1. **移动布局按宽度生效**：ADR-050 Phase 3（2026-09-10）统一了 1023px 断点（`packages/ui/src/layout/breakpoints.ts` 的 `useIsMobileLayout()`）——视口 `< 1024px` 时工具栏次要控件（地址进制 / 从站地址(Unit ID) / 写后回读 / Address Adjust / 恢复列布局 / 行数）收进工具栏「更多」`Popover`（`RegisterTable.secondaryToolbarGroup`），底部面板改为底部 `Drawer`，侧栏改左 `Drawer`。
2. **VSCode webview 恰是窄窗口**：实测 Explorer + Chat 两侧栏同时展开时编辑区 `< 1024px`（既有用例注释亦记录「VSCode webview 为窄窗口，Header 连接按钮文字隐藏」）。故应用在 VSCode 内**走移动分支**：`.table-toolbar__radix` 不在工具栏 DOM 中（仅在「更多」面板展开后出现）→ 定位 30s 超时。
3. **回归来源**：ADR-050 Phase 3 落地时回归了浏览器（`mobile-layout.spec.ts`）与 Electron（窗口够宽仍为桌面布局），**VSCode real 套件未重跑**，两 spec 仍按桌面布局定位（工具栏直取 radix、直接点常驻底部面板页签）。
4. **证据**：失败 run 的 Playwright trace 内截图（经 Qwen 视觉代理读取）显示应用工具栏存在「More」按钮、无可视底部页签面板、无应用侧栏 —— 确认移动分支。

## 复现测试（强制）

- 测试文件：`tests/e2e-vscode/real/real-rtu.spec.ts`、`tests/e2e-vscode/real/real-tcp.spec.ts`
- 复现命令：`pnpm test:e2e:vscode:real`（需 com0com COM4↔COM5 + `config/connections.json`；runner 自动拉起 RTU/TCP 从站）
- 预期失败（红）：连接步骤在 `setRadixHex` 处 30s 超时（`.table-toolbar__radix` 未渲染）。
- 修复后通过（绿）：两 spec 全场景矩阵通过（`pnpm test:e2e:vscode:real` 3 passed）。

## 修复方案

- 方案：让 VSCode real 套件的辅助函数**布局自适配**（不依赖窗口宽度，桌面/移动两分支共用同一份用例）：
  - `isMobileLayout(frame)`：`matchMedia("(max-width: 1023px)")`（与 `breakpoints.ts` 同值，注释交叉引用）。
  - `setRadixHex`：移动布局先点工具栏「More toolbar actions」展开「更多」面板 → 点选 HEX → **再收起面板**（浮层会遮挡表格右侧 Read/Write 按钮）；桌面布局保持原路径。
  - `openBottomPanel` / `closeBottomPanel` / `openCommLog`：移动布局下底部面板位于**带遮罩的抽屉**内 —— 展开（Header「Open panel」）→ 切 Comm Log 页签 → 清空日志 → **收起抽屉**（遮罩会拦截表格点击）→ 操作表格生成目标帧 → 重新展开并切页签断言 → 收起。
  - 桌面布局下上述 helper 退化为 no-op / 等价原行为（关闭走抽屉自带关闭按钮，不可用时回退 `Esc`）。
- 影响文件：`tests/e2e-vscode/real/real-rtu.spec.ts`、`tests/e2e-vscode/real/real-tcp.spec.ts`（**仅测试**，产品代码零改动）
- 兼容处理：不改 1023px 断点与移动布局设计（窄窗口走移动分支是 ADR-050 Phase 3 的既定行为），不改协议层 / 调度器 / 能力矩阵 / HostMessage / 持久化；桌面布局路径行为不变。

## 影响范围与回归

- 受影响模块：VSCode 端真实端口 e2e（UI 级驱动 webview 共享 UI）。
- 回归测试：
  - `pnpm --filter @mamep2026/e2e-vscode typecheck`（`tsc --noEmit` ×2）与 `lint` 通过；
  - 定向 `pnpm test:e2e:vscode:real` → **3 passed**；
  - 随后 `pnpm test:all` 全量 11 步全绿：三端 real（web 14 / electron 27 / vscode 3）、单测 28 tasks、acceptance 5、e2e-web 141、e2e-electron 30、e2e-vscode（mock）、serial-virtual 109、lint 0、typecheck 32/32。
- 执行时机：由用户要求本次执行（docs/AGENTS.md §27）。
- 迭代记录：中途一次失败（「写后回读 Verify=ON」步骤表格点击被抽屉遮罩拦截 `ant-drawer-mask intercepts pointer events`）已在同一修复内收敛 —— 通信日志断言结束后收起抽屉。

## 遗留 / 待确认（不在本次范围）

- 窄窗口 VSCode 面板走「移动布局」（抽屉侧栏 / 抽屉底部面板 / 工具栏溢出）是 ADR-050 Phase 3 的既定行为；若希望 VSCode 保持「窄桌面布局」，需新需求确认后再评估（本次不改产品行为）。
