# 刷新后外壳界面状态首帧闪烁（工作区派生 UI 全面）

> 日期：2026-09-17　状态：已修复（已全量回归）
> 关联：[2026-09-16-刷新后主题语言首屏闪烁.md](2026-09-16-刷新后主题语言首屏闪烁.md)（同源问题的主题/语言部分）、
> [2026-09-16-插件主题色首帧默认蓝.md](2026-09-16-插件主题色首帧默认蓝.md)（同源问题的插件主题色部分）、ADR-049（崩溃后的状态恢复）

## 现象

刷新页面（或四端重开窗口）时，除主题 / 语言 / 主题色外的**全部工作区派生界面状态**都会先按默认值渲染、
再切换到持久化值：

- 侧栏折叠态、侧栏宽度；
- 底部面板折叠态、高度、活动页签；
- 已打开的 Tab 集合与活动 Tab；
- 表与行数据（首帧是默认的 `Sheet 1` 空表，随后整表替换）；
- 底部面板 Notes 内容等。

## 根因分析

**首屏渲染发生在「事实源加载完成」之前**：store 初始状态是 `createEmptyWorkspace()`
（`packages/domain/src/workspace-model.ts`，**含一张默认 `Sheet 1`** + 默认 `panelLayout`），而启动骨架
`hostStatus === "assembling"` 此前**只覆盖宿主装配** —— `apps/web/src/host-assembly.ts` 在接线完成后
立即 `setHostStatus("ready")`，工作区随后才由宿主仓储**异步**加载（浏览器 IndexedDB / Electron 主进程
文件 + IPC / VSCode 内嵌 IndexedDB）。

因此主题 / 语言 / 主题色只是这条路径上最容易被注意到的三个字段（已由启动缓存修复）；`panelLayout`（5 项）、
`sheets`/`activeSheetId`/`open`、`notes`、以及插件贡献（侧栏插件分组 / 底部面板 `Plugins` 页签）全部走
同一条异步路径，**逐个抄进 `localStorage` 既不可穷尽（行数据太大），也不是"一样的机制"**。

## 复现测试（强制）

- 测试文件：`tests/e2e-web/tests/boot-ui-state-first-paint.spec.ts`（新增 3 例）。
  记录器在「`#root` 首次渲染出外壳」（`.ant-layout-sider` 首次出现）那一刻抓取**外壳快照**
  （侧栏折叠/宽度、侧栏表项数、Tab 数、活动 Tab 名、表格行数、底部面板折叠/高度/活动页签），
  与刷新前**稳定态**快照做深比较。
- **先写复现测试并确认失败（红）**：3 例全部失败，首现快照即默认工作区状态，例如
  `tabCount 3 → 1`、`activeTabLabel "Sheet 3" → "Sheet 1"`、`sidebarWidth 220 → 160`、
  `bottomHeight 280 → 179`、`bottomCollapsed true → false`、`activeBottomTabLabel "Comm Log" → "Messages"`。

## 修复方案（机制「要么不画，要么画对」）

**把启动骨架的窗口从「宿主装配」扩展到「宿主装配 + 工作区加载 + 插件就绪」**：

1. `apps/web/src/host-assembly.ts` 新增**就绪门**：`host.loadWorkspace()` 与 `host.startPlugins()` 各自
   落定（成功 / 失败 / 异常都算）→ 先写完 sinks（`setWorkspace` → `setWorkspaceRecovery` → `setLoaded`
   →（mock）`connect` / （非 mock）打开连接弹窗）→ **最后** `setHostStatus("ready")`。
   不变式：**`ready` ⟹ 工作区已就位、插件已注册**。
2. **5s 超时兜底**：`gateWithTimeout()` 与就绪门竞速；超时即置 `ready` 并追加 warning 消息
   （新增 i18n `messages.startupTimeout` 双语），应用退回"可操作但可能跳变一次"的旧行为，
   不至于骨架常驻。超时值经 `HostAssemblyDeps.shellReadyTimeoutMs` 注入（默认 5000，便于单测）。
3. 取消（StrictMode 双挂载 / 卸载）后不再写 UI（`signal.aborted` 守卫）。
4. **失效指向兜底**（同域边界修复）：
   - `packages/ui/src/app-store.ts` `fixActiveSheetId` 增强：活动表必须是**存在且已打开**的表，
     否则回退首个打开的表（`setWorkspace` 加载 / 导入 / 重置时生效）；同时清空会话态
     `state.activeSheetId`，让工作区值成为唯一权威。
   - `packages/ui/src/components/BottomPanel.tsx`：`activeBottomTab` 不在当前可用页签集合时
     （典型：插件卸载后残留 `plugins`）回退 `messages` 并把纠正写回持久化，避免空内容区。

- **影响文件**：`apps/web/src/host-assembly.ts`（+ 测试）、`packages/ui/src/app-store.ts`（+ 测试）、
  `packages/ui/src/components/BottomPanel.tsx`（+ 测试）、`packages/ui/src/i18n/index.ts`（新消息键）、
  `packages/ui/src/components/AppStartupPlaceholder.tsx` / `MamepApp.tsx`（骨架作用域注释）、
  `tests/e2e-web/tests/boot-ui-state-first-paint.spec.ts`（复现测试）。
- **兼容处理**：无工作区 schema 变更、无 HostMessage v1 变更、无能力矩阵 / CSP / 协议层 / 调度器改动。
  骨架窗口变长是**有意**的行为变化（用户已确认接受）：外壳首现推迟一次仓储读 + 插件存储读（上限 5s），
  连接设置弹窗与 mock 自动连接随之在同一批更新中完成（不再「外壳先出现、弹窗后弹」）。

### 与已落地的启动偏好缓存（M1）的关系

M1（`apps/web/src/boot-preferences.ts`）负责**骨架自身**的主题 / 语言 / 主题色种子（必须在首帧前同步生效）；

## 修复过程中发现（既有、与本次无关）：antd Splitter 首帧布局沉降

逐帧实测（`addInitScript` + `requestAnimationFrame` 采样，逐帧数据）：

| 帧 | 底部面板高度（持久化 280） | 底部面板高度（持久化默认 200） |
| --- | --- | --- |
| 外壳出现的第 1 帧 | **239** | **179** |
| 第 2 帧起 | 280 | 200 |

即 antd `Splitter` 的首帧会先落在一个沉降中间值、次帧才采用受控 `size`（**与持久化值是否为非默认无关**，
默认值同样如此）。它发生在任何刷新之后，且不是「持久化状态未恢复」——两者已分离处理：

- 本次复现测试对 `bottomHeight` 用容差断言（±80），其余字段严格深比较（见测试内注释）；
- 该沉降作为**独立缺陷**留待决策（可选方向：让垂直 `Splitter` 在首帧即拿到确定的容器高度、
  或在挂载前预置尺寸）。**未在本轮修复**。
