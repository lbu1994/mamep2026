# 插件主题色首帧默认蓝（AC 色值晚于首帧到达）

> 日期：2026-09-16　状态：已修复（回归通过）
> 关联：ADR-038（插件安装/持久化）/ ADR-047（主题色固定预设）/ ADR-054（插件手动安装 + 同进程执行）/
> `docs/bugs/2026-09-16-刷新后主题语言首屏闪烁.md`（同批启动时序问题的前一项）

## 现象

用户选择**插件提供的主题色**（如 example-theme 的 Indigo）后刷新页面（或四端重开窗口）：
首屏先按 **Ant Design 默认蓝**渲染（主按钮 / 表头选中态 / 表格选行 / 启动骨架的 `Spin`），
等插件从存储恢复后才变成插件色。默认蓝用户不可见。

## 根因分析

`themePrimary`（预设 ID `example-theme:indigo`）在首帧**已经**被启动缓存正确恢复，但**色值来自插件贡献，而插件注册表是异步填充的**：

1. `main.tsx` hydrate → `store.themePrimary = "example-theme:indigo"`（首帧即正确）。
2. `packages/ui/src/MamepApp.tsx` 首帧解析装配链：`usePluginContributions(host, "theme")` →
   **空数组**（插件尚未注册）→ `findThemeColorOption(...) === null` →
   `effectiveThemeConfig = baseThemeConfig` = **默认蓝**。
3. 与此同时 `apps/web/src/host-assembly.ts` 的 `wireHost` 里是 `void host.startPlugins()`
   （**fire-and-forget**）：读插件存储（浏览器 IndexedDB / Electron 主进程 IPC / VSCode `globalState`）
   → 逐个 `pluginRegistry.register(...)`（触发 `activate`，同进程 entry 还要 blob `import()`）
   → 贡献点写入 → `usePluginContributions` 因注册表版本变化重渲染 → 此刻才 merge 成插件色。
4. `--mamep-brand-primary` / `--mamep-focus-ring` 由 effect 从 `effectiveThemeConfig.token.colorPrimary`
   派生 → 同样要等第 3 步。

即 2→3 之间（**插件存储读取 + 全部插件 activate 的耗时**）界面一直是默认蓝。

**关键缺陷**：系统里没有「插件注册表已就绪」的信号 —— `startPlugins()` 是 fire-and-forget，UI 无法区分
「插件还没加载完」与「插件已禁用/卸载（解析不到 → 应当回退默认蓝）」。这也是不能简单「一直用缓存色」的原因
（否则卸载插件后品牌色会永远停在插件色）。

## 复现测试（强制）

- 测试文件：`tests/e2e-web/tests/plugin-theme-color-first-paint.spec.ts`（新增）。
  手动安装 `plugins/example-theme` → Settings 选 Indigo → 等自动保存 → `addInitScript` 记录器在
  「`#root` 首次出现子节点」（= 首帧提交）读取 `.ant-app` 上的 `--ant-color-primary`。
- **先写复现测试并确认失败（红）**：`pnpm --filter @mamep2026/e2e-web test plugin-theme-color-first-paint`
  → `Expected substring: "#4f46e5"  Received string: "#1677ff"`（记录器自检 `appAtFirstRender: true` 通过，
  说明是干净的复现而非测试自身问题）。
- 修复后同一命令转绿。

## 修复方案

1. **启动缓存记住「上次解析出的主色种子」**：`apps/web/src/boot-preferences.ts` 载荷增可选
   `themePrimarySeed`（`themePrimary` 预设 ID 对应的 `colorPrimary`；旧缓存缺省 `null`，`version` 保持 1，
   不失效既有缓存）。hydrate 写入 store `themeColorSeed`，写回时从 store 读取。
2. **补「插件就绪」信号（fail-open）**：`apps/web/src/host-assembly.ts` 在 `host.startPlugins()`
   **落定后**（成功或失败都算）经既有 `HostAssemblySinks` 置 `store.pluginsReady = true`；
   无插件存储的宿主立即置位。失败也置位 = 以注册表为准，避免陈旧种子长期生效。
3. **装配链过渡**：`packages/ui/src/plugin/theme-contributions.ts` 新增纯函数
   `resolveThemeColorSeed(resolvedSeed, { themePrimary, pluginsReady, cachedSeed })` ——
   已解析 → 用它；选了预设但插件未就绪 → 用缓存种子；未选预设 / 插件已就绪但解析不到（禁用·卸载）→
   `null`（默认蓝）。`MamepApp` 用它取种子，并经新增的 `themeConfigForColorSeed(seed)` 合并进主题。
4. **回写**：`MamepApp` 仅在 `pluginsReady` 后把解析结果（或 `null`）写进 store `themeColorSeed`
   （未就绪期间**不写**，保留缓存种子）；值未变化则不写（守卫，避免 set → 重渲染 → effect 循环）。
   缓存订阅把它持久化，供下次刷新首帧直接使用。

- **影响文件**：`packages/ui/src/plugin/theme-contributions.ts`、`packages/ui/src/app-store.ts`
  （新增 `pluginsReady` / `themeColorSeed` 两字段与动作）、`packages/ui/src/MamepApp.tsx`、
  `apps/web/src/host-assembly.ts`、`apps/web/src/store-sinks.ts`、`apps/web/src/boot-preferences.ts`；
  测试 `apps/web/src/{boot-preferences,host-assembly}.test.ts`、`packages/ui/src/plugin/theme-contributions.test.ts`。
- **兼容处理**：无工作区 schema 变更、无 HostMessage v1 变更、无能力矩阵 / CSP / 协议层 / 调度器改动；
  旧缓存（无 `themePrimarySeed`）按 `null` 解析，行为与修复前一致。

### 被否决的备选

把启动骨架延长到插件就绪（`setHostStatus("ready")` 移到 `startPlugins()` 之后）：改动更小，但会推迟外壳首现
（插件存储异常时骨架可能长时间停留），且骨架里的 `Spin` 仍是默认蓝，未真正解决。

## 影响范围与回归

- 受影响模块：四端渲染器共用入口的主题装配链（`MamepApp`）与装配编排（`host-assembly`）。
- **已知残留（用户确认接受）**：
  1. **本设备首次**遇到插件主题色（无缓存种子，例如从别的机器拷入工作区 JSON）时仍有一帧默认蓝——
     此时确实没有色值来源。导入工作区不受影响（插件已就绪，导入后会立刻把种子写进缓存）。
  2. 宿主装配失败（`hostStatus === "failed"`）时 `pluginsReady` 永不置位 → 沿用缓存种子（退化态、纯视觉，
     且更接近上次状态）。
- 回归测试（执行时机**由用户决定**，docs/AGENTS.md §27）：`apps/web` / `ui` 单测、`pnpm typecheck`、
  `pnpm lint`、e2e-web 定向（新 spec + `theme-color-presets` + `boot-preferences`）。
