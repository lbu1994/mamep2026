# 侧边栏折叠态分组图标未水平居中（并伴随横向溢出）

> 日期：2026-09-16　状态：已修复（浏览器实测通过；e2e 执行时机由用户决定）
> 关联 ADR：docs/adr/ADR-041-侧边栏协议分组.md（侧边栏分组）、ADR-050-Android端接入与Capacitor方案.md（Phase 3 移动布局，本次不涉及）

## 现象

侧边栏**折叠（收起）**到 36px 窄条后，代表各分组的图标不在窄条中线上（视觉偏左），观感不佳；同时窄条底部存在一条横向滚动条（窄条内容溢出）。

复现步骤：任意平台桌面布局 → 点侧边栏顶部「折叠」按钮 → 观察窄条内 4 个分组图标相对折叠按钮明显偏左；`.sheet-sidebar__groups` 出现横向滚动条。

（移动布局 < 1024px 走抽屉、无折叠态；Android 无折叠态，均不受影响。）

## 根因分析

实测（1600×900，`?mockTransport=1`，dev server）：

| 量                       | 实测值                                         |
| ------------------------ | ---------------------------------------------- |
| 侧栏盒子 / 内容区        | 36px / 35px（`.sheet-sidebar` 有 1px 右边框）  |
| 顶部折叠按钮中心         | 距侧栏左边 **17.5px**（= 内容区中线，已居中）  |
| 分组图标中心             | 距侧栏左边 **13.5px** → 偏左 4px               |
| `.sheet-sidebar__groups` | `scrollWidth 44` > `clientWidth 35` → 横向溢出 |

三条独立成因（`apps/web/src/index.css` + antd v6 css-var 机制）：

1. **折叠态标签仍在参与布局**：折叠态下 antd 只把分组头 `.sheet-sidebar__group-head` 置 `opacity: 0`，节点仍在 flex 流中；本文件又强制其 `flex: 1 1 auto !important`（为了让分组头可收缩、长标题省略号），于是标题盒内「图标 + 占满剩余的隐形标签」，`justify-content: center` 形同虚设，图标被挤到左边。
2. **antd v6 用 css 变量给了 4px 缩进**：`.ant-menu-inline .ant-menu-submenu-title { width: var(--ant-menu-item-width); margin-inline: var(--ant-menu-item-margin-inline) }`，而折叠态下这两个变量为 `calc(100% - 4px)` / `2px` → 子菜单标题盒比窄条窄 4px，图标即便在盒内居中也不在窄条中线上（盒中线 15.5 vs 窄条 17.5）。
3. **4px 水平 margin 叠加固定宽度**：`.sheet-sidebar__list { margin: 2px 4px }` 与折叠态 `width: 36px` 叠加 → 实占 44px 塞进 35px，产生横向滚动条（与第 1、2 条同源：都源于折叠态按「展开态的内边距假设」渲染）。

> 附注：折叠态菜单根类名为 `ant-menu-root ant-menu-vertical ant-menu-light ant-menu-inline-collapsed`，**不含** `ant-menu-inline`，因此展开态规则（如 `width: auto`、隐藏箭头）不会误伤折叠态——本次修复同样用折叠态选择器精确限定。

## 复现测试（强制）

- 本缺陷为**视觉几何**问题，jsdom 无布局引擎、也不加载 antd 真实 CSS，**无可行单测**。
- 守护方式：e2e 几何断言（`tests/e2e-web/tests/sidebar-collapsed.spec.ts` 新增用例）——
  ① 每个分组图标中心与折叠按钮中心（= 内容区中线）偏差 ≤ 1px；
  ② `.sheet-sidebar__groups` 无横向溢出（`scrollWidth ≤ clientWidth`）；
  ③ 既有「悬停弹出子菜单 → 切表」流程不回归 + 无 console 错误。
- 修复前实测：图标中心 13.5（偏差 4px）、`scrollWidth 44 > clientWidth 35`；修复后：17.5（偏差 0）、`35 ≤ 35`，弹出子菜单仍正常。

## 修复方案

- 方案（用户确认「一并修溢出」）：折叠态两处 CSS 覆盖，落在 `apps/web/src/index.css` 单一文件：
  1. `.sheet-sidebar__menu.ant-menu-root.ant-menu-inline-collapsed` 改为 `width: 100%` + `margin-inline: 0`，并覆盖 `--ant-menu-item-width: 100%` / `--ant-menu-item-margin-inline: 0`（antd 公开的 css-var 接口）；
  2. 折叠态隐藏 `.sheet-sidebar__group-head`（`display: none !important`）：该内容折叠态本就不可见（opacity 0）且无交互，悬停弹出子菜单由标题行本身触发，不受影响。
- **实现踩坑（必记）**：第 2 条**必须 `!important`**。antd 隐藏折叠态标签用的是
  `:where(...).ant-menu-inline-collapsed > .ant-menu-submenu > .ant-menu-submenu-title .anticon + span { display: inline-block; opacity: 0 }`，
  其中 `+ span` 为元素选择器 → 特异性 **(0,4,1)**，高于本规则 (0,4,0)，不加 `!important` 时计算值仍为 `block`
  （首次实现实测：图标中心仍 7.5px）。本仓对 antd Menu 的覆盖本就沿用 `!important` 做法（见 `submenu-title` 的 `padding-inline`、`group-head` 的 `flex`）。
- 影响文件：`apps/web/src/index.css`（产品代码唯一改动）、`packages/ui/src/help/help-content.ts`（补充「折叠态无新建入口」说明）、`tests/e2e-web/tests/sidebar-collapsed.spec.ts`（断言）。
- 兼容处理：
  - 展开态视觉零变化（选择器限定 `.ant-menu-inline-collapsed`）；
  - 窄条宽度不写死数值（`width: 100%`），避免 1px 边框/滚动条造成的再次偏移；
  - 无工作区 schema / HostMessage v1 / 能力矩阵 / 协议层 / 调度器改动；四端共用同一 `index.css`，实际影响面 = 浏览器 / Electron / VSCode 桌面折叠态。
  - 已知副作用（用户确认可接受）：标题盒变宽后，悬停弹出的子菜单贴窄条左缘（较修复前左移约 6px）。
- 顺带清理（用户确认）：`help-content.ts`「连接 → Modbus RTU」中文正文中残留的 **Rx Delay（毫秒）** 条目（该字段 2026-09-06 已全局删除）。
