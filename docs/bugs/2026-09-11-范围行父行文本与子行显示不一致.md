# 范围行父行 Data 文本与子行显示不一致

> 日期：2026-09-11　状态：修复中
> 关联 ADR：docs/adr/ADR-030-多寄存器连续读写与范围行.md、docs/adr/ADR-031-范围行子行可编辑化.md、
> docs/adr/ADR-053-Type切换即时刷新显示格式.md（决策 5 遗留项）、docs/adr/ADR-052-寄存器位明细展开.md

## 现象

范围行（`registerCount > 1`）**已读取过**时，手工编辑父行 Data 并提交后：

1. 父行显示新输入的组合文本；
2. 展开的子行（每寄存器一行）仍显示**上次读取的旧值**；
3. 位明细行（ADR-052）同样显示旧位值；
4. 此时再点击某一位切换，父行**刚输入的组合文本被旧读值重新覆盖**（用户输入丢失）；
5. 保存并重启后不一致依旧（`registerValues` 与 `cellText` 均随工作区持久化）。

单寄存器 `binary` 行（可展开位明细）存在同源问题（第 3、4 点）。

复现步骤：范围行（如 `1000-1001`，Type HEX）读回 `1234 ABCD` → 父行 Data 改为 `FFFF 0000` 提交 →
展开子行 → 子行仍显示 `1234` / `ABCD`。

## 根因分析

数据模型约定（ADR-030/031）：`RegisterRow.registerValues[i]` 是**当前原始值单一事实源**，
`cellText` 是它的显示文本；**派生展示只读 `registerValues`**：

- `packages/ui/src/tree-rows.ts`：子行 `dataText = formatRawValue(registerValues[i], childDataType)`
  （未读到 → `null` → 显示「—」）；
- `packages/register-table/src/bit-register.ts`：位明细由 `registerValues[registerIndex]` 现算
  （`readRegisterBit`），位切换基准（`registerValueBase`）也**优先 `registerValues`**。

`cellText` 的写入方中，**只有两处不同步 `registerValues`**：

| 写入方                                                                            | 同步 `registerValues`                                                |
| --------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 读取 / 轮询 / 写后回读（`applyReadValue(s)ToRow`）                                | ✅                                                                   |
| 子行 Data 提交（`commitChildCellText`）                                           | ✅                                                                   |
| 位切换（`setRegisterBit`）                                                        | ✅                                                                   |
| **父行 Data 提交（`packages/register-table/src/cell-text.ts` `commitCellText`）** | ❌ 只改 `cellText`                                                   |
| 粘贴新建行（`packages/register-table/src/row-clipboard.ts` `pasteClipboardRows`） | ❌ `registerValues = null`（ADR-051 决策「粘贴即清零」，本次范围外） |

不变式「`cellText` ⟺ `registerValues`」被破坏后，派生展示与位切换基准都停在旧值，即上述全部症状。

> 写路径不受影响（`table-service.writeRow` 按 `row.cellText` 解析）；读 / 轮询 / 写后回读会重建
> `registerValues` 使不一致**自愈**，因此该缺陷只在「手工编辑父行文本后、下一次读取前」可见。

## 复现测试（强制）

- `packages/register-table/src/cell-text.test.ts`（新增 `commitCellText 同步 registerValues` 用例组，4 例）：
  范围行提交后 `registerValues` 必须为解析结果、单寄存器 binary 行同样、未读取时按输入派生、失败路径不动旧值。
- `packages/register-table/src/bit-register.test.ts`（新增 1 例）：父行手工编辑后位切换以**编辑后**的值为基准
  （`FFFF 0000` 清 bit0 → `FFFE 0000`，修复前为 `FFFF 0000`，切换未生效）。
- `packages/ui/src/app-store.test.ts`（新增 1 例）：store `commitCellText` 后 `registerValues` 同步，
  且 `buildTreeRows` 派生的子行显示与父行文本一致（修复前仍为旧读值）。
- 红→绿：修复前 5 例失败（`[4660, 43981]` vs `[65535, 0]`、`171` vs `65535`、`undefined` vs `42`、
  `FFFF 0000` vs `FFFE 0000`、子行旧值），修复后全绿。

## 修复方案

- 方案（用户确认 **A**）：**父行编辑同步 `registerValues`**，保持「`registerValues` 单一事实源」
  （选项 B「子行渲染改由父行文本派生」会与 ADR-031/052 的派生链冲突，且不解决位切换覆盖用户输入）。
- 落点：`packages/register-table/src/cell-text.ts` 单一文件
  - 内部把「解析 → 规范文本」合并为一次解析（`canonicalize`：范围行 `parseCompositeText`、
    单寄存器 `resolver.parse`），同时产出 `{ text, values }`；
  - `canonicalCellText(row, text, resolver)` 对外契约与行为不变（粘贴路径继续使用）；
  - `commitCellText` 成功时同步写回 `registerValues`（逐个经 `RawRegisterValue.create` 校验）；
  - 失败路径（`DATA_EMPTY` / 解析错误）完全不变，不触碰 `registerValues`。
- 覆盖范围（用户确认）：范围行 + 单寄存器行（含 `binary` 位明细同源问题、`registerValues = null` 时按输入派生）。
- 兼容处理：
  - 无工作区 schema 变更（`registerValues` 本已持久化）、无 HostMessage v1 变更、无能力矩阵/协议/调度改动；
  - `registerValues` 语义由「最近设备读值」明确为「当前原始值（含手工编辑）」；读 / 轮询 / 写后回读仍会覆盖它；
  - 边界：编辑后 `registerValues` 非 `null`，位明细不再显示「—」而按编辑值显示 0/1（与「父子一致」目标一致）。

## 遗留（本次范围外）

- **粘贴新建行**：`pasteClipboardRows` 仍维持 `registerValues = null`（ADR-051 决策），
  粘贴出的范围行父行有文本而子行/位明细显示「—」；如需一致另行确认（会修订 ADR-051 语义）。
