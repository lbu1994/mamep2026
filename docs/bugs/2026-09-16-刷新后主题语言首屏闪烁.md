# 刷新网页后主题 / 语言首屏闪烁（FOUC）

> 日期：2026-09-16　状态：已修复（回归通过）
> 关联：ADR-047（主题色固定预设）/ ADR-048（默认主题色运行时跟随 antd）/ TODO「阶段二 `[bug] 暗黑模式 / 语言 FOUC`」

## 现象

用户选择**暗色主题**或**中文界面**后刷新网页（`F5` / reload / 四端重开窗口），首屏会先按
「明亮模式 + 英文（en-US）」渲染，随后才切换到已保存的暗色 / 中文 —— 即主题与语言都命中
首屏闪烁（FOUC）。

复现步骤：打开应用 → Settings → General → 切 `Dark` + 语言切 `中文` → 刷新页面 → 可观察到
先亮后暗、先英文后中文的跳变。

## 根因分析

**首屏渲染发生在「持久化偏好被读取」之前**（根因非症状）：偏好的唯一事实源是工作区
（`workspace.preferences.theme / themePrimary / language`），而工作区由宿主仓储**异步**加载
（浏览器 IndexedDB / Electron 主进程文件 + IPC / VSCode 内嵌 IndexedDB / Android IndexedDB），
故启动序列必然是「先渲染默认 → 后读取偏好 → 再切换」：

| 步骤 | 位置 | 界面表现 |
| --- | --- | --- |
| ① | `apps/web/src/main.tsx`：`initI18n()` 固定 `lng: "en-US"`；store 默认 `theme: "light"`（`packages/ui/src/app-store.ts` `create` 初始状态）→ `createRoot().render()` | 首帧 = 明亮 + 英文 |
| ② | `packages/ui/src/MamepApp.tsx` 的主题 effect：`document.documentElement.dataset.mamepTheme = theme` | 浅色令牌（`index.css` `:root`）在**首次绘制之后**才被显式锁定 |
| ③ | `apps/web/src/host-assembly.ts`：动态 `import()` 平台宿主 → 构造 → `hostStatus: "ready"` | 骨架屏 → 真实外壳，仍是明亮 + 英文 |
| ④ | `apps/web/src/host-assembly.ts` `host.loadWorkspace().then(...)` → `setWorkspace()` → `applyLanguage(...)` + 回填 `theme` / `themePrimary`（`app-store.ts`） | **此时才**切到暗色 / 中文 |

①→④ 之间是真实耗时（宿主装配 + 仓储读取），且 React `useEffect` 在首次绘制之后才执行 ——
所以「明亮 + 默认语言」**一定**被画出来。

关键约束：四端仓储都是异步的，**没有任何可同步读取的偏好来源**；`index.html` 也不含任何主题 /
语言处理。

## 修复方案

- **方案（首屏偏好缓存 + render 前 hydrate）**：工作区仍是唯一事实源，另加一份**可同步读取**的
  启动提示缓存（`localStorage`，键 `mamep:preferences`，带 `version`）：
  1. **写**：`apps/web/src/boot-preferences.ts` 的 `installPreferencesCache()` 订阅 store 的偏好
     三元组（`theme` / `themePrimary` / `workspace.preferences.language`），变化即写回
     （`setTheme` / `setThemePrimary` / `setLanguage` / `setWorkspace`（加载 / 导入 / 重置）全覆盖）。
  2. **读**：`apps/web/src/main.tsx` 在 `createRoot().render()` **之前**调用
     `hydrateBootPreferences()` → 解析缓存（无则用默认值）→ 写 store（`theme` / `themePrimary`）
     → `initI18n(language)` → 设 `<html data-mamep-theme>` 与 `<html lang>`。
  3. **容错**：storage 缺失 / 抛错（隐私模式、被禁）/ JSON 坏 / 版本不符 / 字段非法 → 一律退回默认值，
     不抛错、不影响任何流程（best-effort，与 ADR-049 flush 同一态度）。
- **影响文件**：
  - `apps/web/src/boot-preferences.ts`（新增：缓存读写 + hydrate + 订阅）
  - `apps/web/src/boot-preferences.test.ts`（新增单测）
  - `apps/web/src/main.tsx`（render 前 hydrate + 注册缓存订阅）
  - `packages/ui/src/i18n/index.ts`（`initI18n(language?: AppLanguage)`，默认 `en-US` 不变）
  - `packages/ui/src/MamepApp.tsx`（新增 `<html lang>` 同步 effect，与既有 `data-mamep-theme` 同模式）
  - `tests/e2e-web/tests/boot-preferences.spec.ts`（复现测试）
- **兼容处理**：无工作区 schema 变更、无 HostMessage v1 变更、无能力矩阵 / CSP / 协议层 / 调度器改动；
  `initI18n` 形参可选，既有调用与测试不受影响。
  `<html lang>` 由 `en` 变为实际语言（`en-US` / `zh-CN`），属无障碍改进（屏幕阅读器按此发音）。

### 实施中发现的第二个坑（必须同时写 `workspace.preferences.language`）

只初始化 i18n + 写 `<html lang>` 是不够的：`MamepApp` 的 `<html lang>` effect 读的是
**`workspace.preferences.language`**，而首帧渲染时工作区尚未加载（值仍是默认 `en-US`）——
effect 会把刚写好的 `zh-CN` 顶回 `en-US`，等 `setWorkspace` 后才恢复。实测标记序列：
`en → zh-CN → en-US → zh-CN`。
修复：`hydrateBootPreferences` 的默认实现（`applyBootPreferencesToStore`）把偏好三元组同时写入
store 顶层与 `workspace.preferences`（写入的是**加载前**的空工作区，随后被 `setWorkspace` 整体替换，
值一致故无可见影响；加载失败时反而与界面语言保持一致）。

## 影响范围与回归

- 受影响模块：四端渲染器共用入口（浏览器 / Electron / VSCode / Android）；主题装配链
  （`MamepApp`：`themeConfig ?? buildTheme(theme === "dark")`）与语言初始化。
- **已知残留（本轮不做，用户确认）**：
  1. **模块脚本执行前的一帧**：`index.html` 的默认白底先于 module 脚本被绘制。覆盖它需在 `<head>`
     加内联脚本，并给两处生产 CSP（`apps/web/src/csp.ts`、`apps/vscode-extension/src/webview/prod-csp.ts`）
     加 `'sha256-…'` 哈希；改动面大、收益仅在网络慢时的几十 ms 窗口，故本轮不做。
  2. **~~插件主题色（`themePrimary`）~~**：缓存的是预设 ID，色值来自插件（需等插件恢复后才解析得到），
     故品牌色仍可能有一帧「默认蓝」——**已于同日后续修复解决**（缓存主色种子 + 插件就绪信号，
     见 [2026-09-16-插件主题色首帧默认蓝.md](2026-09-16-插件主题色首帧默认蓝.md)）。
- 回归测试（执行时机**由用户决定**，docs/AGENTS.md §27）：`apps/web` / `ui` 单测、`pnpm typecheck`、
  `pnpm lint`、e2e-web 定向（`boot-preferences` + `theme-color-presets` + `settings-drawer` +
  `sidebar-rename-dark-theme`）。
