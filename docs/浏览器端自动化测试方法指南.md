# 浏览器端自动化测试方法指南

> 用途：在 VS Code 的 Copilot 编码代理（或任何集成浏览器的 Agent）中，对 Web 工程执行"打开页面 → 交互 → 断言"的自动化测试，与开发同屏进行。
> 本文以 Mamep2026 原型开发中的实际操作总结，可直接复制到其他工程，让该工程里的 AI 代理照此执行。

---

## 一、用到的工具（在 Copilot/Agent 里）

| 工具                                               | 作用                                                                                                       | 关键参数                              |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| `run_in_terminal`                                  | 启动/运行命令。开发服务器用 `mode: async` 后台常驻                                                         | command, mode:'async'                 |
| `open_browser_page`                                | 在 VS Code 内置浏览器打开 URL，返回 `pageId`                                                               | url                                   |
| `read_page`                                        | 返回页面的**无障碍快照**（DOM 树 + 文本 + ref），验证结构/状态首选                                         | pageId                                |
| `screenshot_page`                                  | 截图（视觉确认，但对模型不一定可见，优先用 read_page）                                                     | pageId                                |
| `click_element` / `type_in_page` / `hover_element` | 模拟点击/输入/悬停，可传 `ref`（来自快照）或 CSS `selector`                                                | pageId, ref/selector, element         |
| `navigate_page`                                    | 跳转 / 刷新 / 前进后退（`type:'reload'` 刷新）                                                             | pageId, type                          |
| `run_playwright_code`                              | **核心**。执行 Playwright JS 代码块：改视口、用代码点击、读取单元格、抓 console 错误、操作 localStorage 等 | pageId, code（纯 JS，不能用 TS 语法） |
| `handle_dialog`                                    | 处理浏览器弹窗（alert/confirm/prompt）                                                                     | pageId                                |

所有浏览器工具都依赖同一个 `pageId`，先 `open_browser_page` 拿到它再复用。

## 二、标准工作流

### 1) 启动开发服务器（后台常驻）

```
npm run dev
```

用 `run_in_terminal` 且 `mode: async`，拿到一个终端 ID。服务器一直在后台跑，期间所有交互都打到它的 URL（如 http://localhost:5173/）。

### 2) 打开浏览器

```
open_browser_page  url=http://localhost:5173/
```

返回 `pageId`，后续所有浏览器操作都用它。

### 3) 读取页面快照（最重要的验证手段）

```
read_page pageId=...
```

返回的是无障碍快照（元素层级 + 文本 + ref 编号）。用它来：

- 确认布局/组件是否渲染（列、行、按钮、标签页、弹窗标题……）；
- 拿到元素 `ref`（如 `e10`）用于点击；
- 验证状态变化（连接状态、单元格数值、Status 标签、日志消息……）。

> 注意：快照很大时会写入临时文件，结果里会给出文件路径，用 `read_file` 去读那个路径。

### 4) 交互

- 简单点击：`click_element`，传快照里的 `ref`，或 CSS `selector`（如 `button:has-text("Read All")`）。
- 输入：`type_in_page`（传 ref/selector，或先聚焦再打字）。
- 复杂/批量操作：直接用 `run_playwright_code`（见下文代码模式），一次脚本完成"点一下 + 等待 + 读结果"。

### 5) 断言（回到第 3 步）

交互后再次 `read_page`，或用一个 Playwright 脚本把关键值读出来返回 JSON，检查是否符合预期。

### 6) 控制台错误检查（收尾必做）

用 `run_playwright_code` 挂 console 监听器，加载 + 交互一轮，确认无 error。

### 7) 清理

测试完可 `kill_terminal` 杀掉后台 dev server（或留着方便用户预览）。

## 三、Playwright 代码模式（`run_playwright_code` 直接可抄）

> 约束：代码必须是**纯 JS**（不能写 `el as HTMLElement` 这类 TS 语法）；`return` 一个可 JSON 序列化的值；注意异步操作要 `await`。

### 设置真实桌面视口（必做）

默认浏览器视口可能很小，会把桌面布局挤塌、触发窄窗口分支，导致误判。先设成 1600×900：

```js
await page.setViewportSize({ width: 1600, height: 900 });
```

### 用 evaluate 点击（绕过"元素不稳定"超时）

页面持续更新（轮询、动画）时，Playwright 的 `.click()` 会因元素"不稳定"而超时。用 DOM 原生 click 直接触发：

```js
await page
  .getByRole("button", { name: "api Connect", exact: true })
  .evaluate((el) => el.click());
```

### 读取表格某行/单元格

```js
const row = page.locator(".ant-table-tbody tr[data-row-key]").first();
const cells = await row.locator("td").allInnerTexts();
// cells = ['', '1', '', 'Run Command', '0001', ..., 'Read Success']
```

### 精确选择器（避免误匹配）

按钮文字可能被其他元素包含，用 role + exact：

```js
page.getByRole("button", { name: "api Connect", exact: true });
```

多选一时用 filter：

```js
page.locator(".ant-select").filter({ hasText: "Normal Device" }).first();
```

### 等待 + 采样状态

```js
await page.waitForTimeout(1200);
const chip = (await page.locator(".conn-chip").innerText()).trim();
```

### 操作 localStorage + 刷新（测持久化 / 损坏兜底）

```js
await page.evaluate(() => localStorage.setItem("my-key", "{bad json"));
await page.reload();
await page.waitForTimeout(600);
```

### 抓控制台错误

```js
const errors = [];
page.on("console", (m) => {
  if (m.type() === "error") errors.push(m.text());
});
page.on("pageerror", (e) => errors.push("PAGEERROR: " + String(e)));
await page.reload();
await page.waitForTimeout(800);
// ...做一轮交互...
return JSON.stringify({ errors });
```

### DOM 结构 / 几何调试

元素找不到或疑似遮挡时，用 evaluate 看类名、display、坐标：

```js
const b = await page.evaluate(() => {
  const el = document.querySelector(".sidebar");
  return {
    cls: el.className,
    display: getComputedStyle(el).display,
    box: el.getBoundingClientRect().toJSON(),
  };
});
```

## 四、踩坑与技巧（重要）

1. **ref 会变，选择器更稳**：`read_page` 里的 `e10` 这种 ref 在每次重渲染后会变。临时点一次可以，多次/断言请用 CSS/role/文本选择器。
2. **持续轮询让 `.click()` 超时**：轮询每几百毫秒改状态 → React 不停重渲染 → Playwright 判定"元素不稳定"。一律用 `evaluate(el => el.click())` 触发。
3. **先设视口再看**：不设视口，内置浏览器可能只有几百像素高，导致 `flex:1` 区域被压到 0，出现"表格固定列盖住底部面板"之类的假问题。
4. **antd v6 Modal 结构变了**：没有 `.ant-modal-content`，改用 `.ant-modal-container` / `.ant-modal-body` 定位弹窗内元素。
5. **antd v6 Tabs 结构变了（页面有两个 Tabs 时极易误匹配）**：活动面板 DOM 类是 `.ant-tabs-content-active`（**不是** v5 的 `.ant-tabs-tabpane`，v6 无 tabpane 类）。Mamep2026 主表格页签类名 `.register-table-tabs`，断言表格列头/单元格时选择器必须限定 `.register-table-tabs .ant-tabs-content-active ...`，否则会误匹配 BottomPanel 的页签。`+` 新建按钮 `.ant-tabs-nav-add` 在 DOM 出现两次，可见的在 `.ant-tabs-nav-list` 内，用 `.ant-tabs-nav-list .ant-tabs-nav-add` 定位；页签关闭按钮 `.ant-tabs-tab-remove` 是 `div[role=tab]` 的兄弟节点，定位用 `.ant-tabs-tab` 容器 hasText + 后代 remove，不能从 `getByRole('tab')` 下找。
6. **antd v6 `List` 已弃用、用 `Listy`**：`List` 会在 dev console 报弃用警告，污染「无 console 错误」断言。虚拟列表用 `Listy`（`items`+`itemRender`，渲染类 `.ant-listy-item`），PluginManager 已用它。
7. **截图不一定看得见**：`screenshot_page` 返回的图片对本模型不一定可见。**以 `read_page` 快照为主**，截图仅作辅助。
8. **HMR 会让服务单例脱钩**：改了服务模块后，页面里连接状态可能和内部 `connected` 标志不一致。遇到诡异状态先 `navigate_page type:'reload'` 整页刷新。
9. **deferredResultId**：`run_playwright_code` 如果没跑完会返回 `deferredResultId`，用同样的 pageId 不带 code 再调用一次拿结果。
10. **弹窗（antd Modal）里选 Select**：先对目标 Select 的容器 `dispatchEvent(new MouseEvent('mousedown', {bubbles:true}))` 打开下拉，再点 `.ant-select-dropdown:visible [title="选项文字"]`。别用 `:has-text` 匹配 label，容易匹配到别的下拉。
11. **日志面板内容**：`allInnerTexts()` 返回的是当前渲染的行；要看最新日志取数组**末尾**。

## 五、可选的自检模板（按用户要求执行）

> 说明：测试/自检的执行时机由用户决定，不要求每轮开发后都跑；用户要求自检或验证时才执行。

用一段 Playwright 脚本串起来：

```js
// 1) 设视口
await page.setViewportSize({ width: 1600, height: 900 });
// 2) 刷新 + 抓错误
const errors = [];
page.on("pageerror", (e) => errors.push(String(e)));
await page.reload();
await page.waitForTimeout(600);
// 3) 冒烟：连一连、读一读、点开弹窗
await page
  .getByRole("button", { name: "api Connect", exact: true })
  .evaluate((el) => el.click());
await page.waitForTimeout(1200);
// 4) 断言关键状态（自定义）
const chip = (await page.locator(".conn-chip").innerText()).trim();
// 5) 返回结果 + 错误
return JSON.stringify({ chip, errors });
```

断言项参考：核心布局在（顶栏/侧边栏/表格/底栏）、关键列顺序、状态流转、弹窗可开合、刷新后状态不恢复运行、窄视口下仍可操作、无控制台错误、无未释放定时器。

## 六、Mamep2026 专用：Mock 传输 E2E 要点

浏览器自动化无法走真实 Web Serial 授权流程，Mamep2026 按 TECH_DESIGN §26.7 提供 dev 环境内置模拟 Modbus RTU 传输：

1. **启用**：dev server 下访问 `http://localhost:5173/?mockTransport=1`；生产构建不包含该能力。
2. **预置/断言寄存器值**：页面暴露 dev-only 钩子 `window.__mamepMock`：
   ```js
   await page.evaluate(() => window.__mamepMock.setRegister(0x0001, 0x1234));
   const reg = await page.evaluate(() =>
     window.__mamepMock.getRegister(0x0001),
   );
   ```

2.1 **失败场景（按地址区间区分成功/失败）**：Mock 传输按「地址区间 → 读写行为」规则响应（规则与默认表预填同源，见 `packages/platform-web/src/mock-scenarios.ts`）。默认区间：

- `0x0000–0x000F` 正常区：读/写均成功；
- `0x0100–0x010F` 只读区：读成功、写返回异常 `0x02`；
- `0x0200–0x020F` 只写区：写成功、读返回异常 `0x02`；
- `0x0300–0x030F` 不存在区：读/写均返回异常 `0x02`；
- `0x0400–0x040F` 非法数据值区：写入值须 ≤ `0x7FFF`，超出返回异常 `0x03`；
- `0x0500–0x050F` 不支持功能区：读/写均返回异常 `0x01`；
- `0x0600–0x060F` 无响应区：读/写均不回帧（触发请求超时/重试路径）。
  未配置地址回退为正常行为。**Mock 模式新建默认表会自动预填上述分类寄存器**（前 20 行，Name 如 `Normal_01`/`ReadOnly_01`/`NotExist_01`/`BadValue_01`/`NoResponse_01`，Comment 为中文行为说明），仅当默认表仍为「未编辑的 50 空行」时预填，已编辑/已删除行的工作区不会被覆盖；可经 `window.__mamepMock` 预置值后按 Name 定位做读/写断言。

3. **启动行为分两种模式**：
   - **Mock 模式**（`?mockTransport=1`）：启动**不弹** Connection Settings，直接用默认 RTU 配置自动连接模拟设备；E2E 的就绪信号是 header 出现 `DISCONNECT`（`await expect(page.locator(".ant-layout-header")).toContainText("DISCONNECT", { timeout: 15000 })`），并断言 `.ant-modal-container:visible` 数量为 0。
   - **非 Mock 模式**（无查询参数）：启动自动弹出 Connection Settings Modal；E2E 需先断言 `.ant-modal-container` 存在、配置参数默认值（Timeout=50ms、Address Adjust=OFF；Slave Address 已迁移为每表独立设置，2026-08-19，见表格上方工具栏选择器，默认 1；Rx Delay 已移除 2026-09-06），再关闭或连接。antd v6 Modal 结构见第四节第 4 条。
4. **连接按钮是单按钮**：离线态文案 `CONNECT`、在线态 `DISCONNECT`，用 `getByRole('button', { name: /CONNECT|DISCONNECT/ })` 断言切换。
5. **通信日志断言**：日志行仅含 时间/方向/字节 三要素，直接对日志面板 `allInnerTexts()` 检查是否出现大写十六进制字节串（如 `01 03 00 00 00 01 84 0A`），不检查功能码解析字段。
6. **WP 轮询**：间隔默认 50ms，测试中用 `waitForTimeout` 采样 Data 变化时注意 HMR 与轮询重渲染，点击一律用 `evaluate(el => el.click())`。
7. 其余通用工作流（设视口、read_page 快照断言、抓 console 错误、localStorage/IndexedDB 恢复验证）按本指南第二~五节执行。

## 七、一句话总结

**方法 = 后台起 dev server + 内置浏览器打开页面 + `read_page` 无障碍快照断言 + `run_playwright_code` 做"设视口/代码点击/读单元格/抓错误/localStorage"四类操作**；关键技巧是"用 evaluate 点击绕过稳定性超时、优先快照而非截图、选择器优先于 ref"。
