# Mamep2026 AI 开发工作流（固化）

> 权威规范与优先级以根 `AGENTS.md` 与 [docs/AGENTS.md](../../../docs/AGENTS.md) 为准；本技能把「开发工作流」固化为可触发、可复用的标准步骤，冲突时以 `AGENTS.md` 为准。

## 何时使用

- 任务会修改产品实现、应用/共享包代码、测试、构建配置、运行时会话/协议/数据行为或交付产物。
- 用户提出新功能、Bug 修复或会改变产品行为的实现变更。
- 不适用于只读分析、信息盘点、解释问答、普通文档整理，以及 AI 提示词/技能/工具链配置。

## 先决

- 开工前先读 `docs/AGENTS.md`（指令优先级、§27 测试约定、§32 禁止行为、§35 未确认事项先提问）。
- 遵守指令优先级；未确认事项先提问，不得静默取舍。

## 0. 判断任务类型

执行开发工作流前先判断：

- 会改变产品代码、测试、构建/运行配置、协议/数据行为或交付产物 → 开发任务，继续六步流程。
- 只读分析、信息盘点、解释问答、普通文档整理、AI 提示词/技能/工具链配置 → 非开发任务，直接执行，不套用六步流程。
- 混合任务 → 只对开发部分使用六步流程，其余部分直接处理并说明边界。
- 判断不明确 → 以“是否改变产品行为或交付物”为准；仍不明确且影响执行方式时询问用户。

## 六步工作流

每步**结束暂停，等用户确认再进入下一步**；用户可让 AI 合并或跳过某步。

### 1. 需求澄清

输出《需求澄清清单》：边界条件、异常场景、性能/安全、对现有模块影响、未确认项（列出问题）。等待确认。

### 2. 计划（Plan）

输出实施计划，格式：

```markdown
## Plan：<标题>

### 影响文件

- `路径`：改动原因

### 变更点

1. ...

### 测试策略

- 新增/修改测试：覆盖 ...
- 回归：重点检查 ...

### 风险与回滚

- 风险：...
- 回滚：...
```

**必须等用户确认「计划通过」后才写代码。**

### 3. 文档记录

- 轻量需求记录：`docs/features/YYYY-MM-DD-描述.md`（新功能）或 `docs/bugs/YYYY-MM-DD-描述.md`（缺陷），套用 `docs/templates/feature-request.md` / `docs/templates/bug-report.md`。
- 架构/产品级决策：按项目惯例补 `docs/adr/ADR-XXX-...md`（参考既有 ADR 风格），并把进度写进 `docs/PROJECT_STATUS.md`。

### 4. 代码变更

- 单次变更聚焦单一职责；先读相关测试与类型定义，了解既有模式。
- 公共 API 变更同步更新类型与 schema；跨端/协议按既有分层。
- 红线：不新增内置插件（2026-09-02 ADR-045），厂商私有规则进 `plugins/`；UI 不直接访问串口/TCP/FS；不得用 `any`/断言蒙混。

### 5. 测试（轻量 TDD，兼顾速度）

项目约定：**测试执行时机由用户决定**（根 `AGENTS.md`「开发工作流」第 5 步 /
docs/AGENTS.md §27，2026-08-19）。先列测试策略征求用户；用户同意后才跑；**不得谎报**。

- **核心算法/协议/调度**：先写失败测试 → 实现 → 全绿（项目已有 TDD 传统）。
- **Bug 修复**：先写复现测试（红）→ 修复（绿）→ 防回归。
- **UI/胶水**：实现 + 测试同轮，或依赖既有 e2e 覆盖。
- **不强制最小红绿循环**：用户不要 TDD 时按此分级，优先速度。

### 6. 回归验证

- `pnpm --filter <受影响包> test`（单测）/ `pnpm typecheck` / `pnpm lint`。
- 涉及界面/传输：提醒用户 `pnpm dev` 冒烟或相关 e2e（`test:e2e:web`/`electron`/`vscode`），**先征得同意**。
- 汇总：通过数 / 失败项；失败项给建议。

## 工具入口

- Codex：显式调用 `$plan-feature`、`$fix-bug`、`$write-tests`、`$regression-check`，定义在 `.agents/skills/`。
- Copilot prompt 存档：位于 `docs/prompts/`，仅在复制回 `.github/prompts/` 后才会被 Copilot 自动发现。
- 模板在 `docs/templates/`。
