## 0. 任务与已确认决策

**任务**：根据仓库分层架构设计，优先使用框架（Ant Design v6）已有功能与 API，统筹三端（浏览器 / Electron / VSCode 插件），设计插件功能并产出设计文档。

**用户已确认 5 项决策**：

| # | 决策点 | 方向 |
|---|---|---|
| ① | 插件代码执行边界 | **开放可执行插件**（含第三方代码隔离机制设计，属 §35 待确认项，需 ADR） |
| ② | Address Adjust 归属 | **由插件提供**（核心删除 Connection Settings 选项，插件贡献 `addressTransform` 扩展点） |
| ③ | 主题色修改形态 | **插件贡献 + 用户设置** |
| ④ | 浏览器端安川协议表 | **支持**（安川协议编解码为纯 TS，作为 web 插件运行） |
| ⑤ | P3 功能范围 | **聚焦安川 / 表类型强相关项** |

**补充要求（需求⑥）**：插件接口须具备扩展性，将来能为插件扩展新的能力（→ 贡献点注册表机制，见 §3.2）。

## 1. 概述

### 1.1 目标

把插件体系从「清单注册骨架」升级为「**可执行 + 可扩展贡献点**」架构，落地：

1. 安川公开私有协议（安川 MEMOBUS 及其公开扩展）；
2. 新的「寄存器表」类型（可使用安川公开私有协议）；
3. 旧（核心）寄存器表中的 ROM Enter / RAM Enter 功能；
4. 默认主题色修改；
5. 旧（核心）寄存器表中的表级 Address Adjust（删除原本位于 Connection Settings 的选项）；
6. 精选 P3 阶段功能（线圈表 / 离散输入表 / 输入寄存器表 / 自定义功能码 / Memory Access / 设备描述文件 / 寄存器手册插件 / 数据解析扩展）；
7. 插件接口具备面向未来的可扩展性。

### 1.2 非目标

- 不做插件市场 / 联网下载 / 签名校验（仅预留扩展位，ADR-038 边界）；
- 不实现全部 P3 功能（自动化测试序列、脚本化调试、波形分析等不在本文档范围）；
- ROM Enter / RAM Enter 的地址与写入规则**不进入核心**（PRD §2.4.2.7 / §5.2 / AGENTS §10.1）；
- 浏览器端**不**支持 Modbus TCP（产品红线，PRD §8.6）。

### 1.3 关键红线（设计约束）

1. 插件**不得直接修改核心源代码**，只能通过稳定贡献点扩展（TECH_DESIGN §23.1 / AGENTS §24.1）；
2. 插件必须声明平台支持（web / node）与权限；**浏览器不得加载 Host 插件**（TECH_DESIGN §23.2 / AGENTS §24.2）；
3. 单个插件失败不得导致核心应用无法启动（错误隔离，AGENTS §24.1 / TECH_DESIGN §23.7）；
4. 插件不得直接取得串口 / Socket 句柄；插件请求必须进入统一通信队列（`RequestScheduler`，AGENTS §12.1 / TECH_DESIGN §11.1）；
5. 插件通信必须记录 `pluginId` 与完整日志（AGENTS §24.1 / TECH_DESIGN §23.6）；
6. 插件配置使用独立命名空间；插件 API 必须版本化（apiVersion）；
7. **Enter ROM / Enter RAM 等厂商专用操作只能存在于专用插件中**（AGENTS §24.4），必须提供必要提示，并经统一权限、调度与日志机制执行；
8. 安川公开协议可以作为示例插件，但**不得与核心 Modbus 模块耦合**（AGENTS §5.3）；
9. Address Adjust 已确认为核心功能（Connection Settings，ADR-013）；迁移到表级并由插件提供属**产品决策变更**，需新 ADR，本文档不自行拍板（§35）；
10. 设计须优先复用 antd v6（6.6）既有能力：Tabs（editable-card）、Table（树形、rowSelection、虚拟滚动）、Select / Segmented / Switch / InputNumber / Modal / Dropdown / message / ColorPicker / ConfigProvider 主题令牌等；注意 antd v6 差异（`List` 已弃用、用 `Listy`；Modal 结构 `.ant-modal-container` 等）。

### 2.2 协议层与通信层现状

- `protocol-modbus` 为纯函数包（`rtu-frame.ts` / `tcp-frame.ts` / `crc16.ts`），**无协议接口抽象**；`CommunicationSession.SessionProtocol = "rtu" | "tcp"` 封闭联合；
- `CommunicationSession` 内部 `buildReadAttempt/buildWriteAttempt/startExchange` 硬编码 Modbus 编解码与分帧（`RtuFrameParser` 私有类 / `TcpFrameParser`）；**协议不可注入**；
- `RequestScheduler` 已预留 `RequestPriority."plugin-background"` 与 `log-event.ts` 的 `RequestSource."plugin"`（**均未接线**）；
- `CommunicationLogEvent` 无 `pluginId` 字段（TECH_DESIGN §8.3 要求插件请求记录 plugin ID，当前不满足）；
- HostMessage v1：31 个 request kind + 7 个 event kind（2026-08-31 核实，原文 33/8 有误已修正），Zod discriminatedUnion + kind 白名单 + 两端 ipc 穷尽守卫（`default: const _exhaustive: never`）——**新增 kind 缺一端即 typecheck 报错**；
- 能力矩阵 `PlatformCapabilities`（`packages/domain/src/capabilities.ts`）固定字段，5 处 `Object.freeze` 声明点（browser / electron / vscode / nodeHost / nodeTcpHost）必须同步。

### 2.3 主题体系现状

- 默认主题色：`packages/ui-theme/src/base.ts` `buildTheme(dark)` → `colorPrimary: dark ? "#1668dc" : "#1460d6"`（浅色 #1460d6 / 暗色 #1668dc），配套 `colorLink` 等；
- `mergeThemeConfig(base, overrides)` 现成（token 浅合并 + components 逐组件合并，override 优先）；
- 单一装配点：`packages/ui/src/MamepApp.tsx` L362 `<ConfigProvider theme={themeConfig ?? buildTheme(theme === "dark")}>`；`store.themeConfig` 运行时派生**不持久化**；
- 浅 / 深主题持久化于 `workspace.preferences.theme`（schema v4）；
- `apps/web/src/index.css` 存在第二份硬编码品牌色 `--mamep-brand-primary`（12+ 处直接消费），**只改 colorPrimary 不会同步**；
- VSCode：`mapVscodeTheme` **品牌蓝 / 状态语义色保留、中性色跟随** VSCode（ADR-027 决策 1），自定义主色在 VSCode 端可存活；但 `colorPrimaryBg/Border` 等派生 token 被 VSCode 覆盖；
- `scripts/check-contrast.mjs` 静态硬编码调色板，未接入 npm script；运行时对比度工具 `packages/ui-theme/src/contrast.ts`（`ensureContrast` 等）现成。

### 2.4 寄存器表与 Address Adjust 现状

- `RegisterSheet.type` 封闭字面量 `"holding-register"`（`workspace-model.ts:129/311`、`schema.ts:72` z.literal、`undo-redo.ts:169`），**零判别使用**；PRD §6.5.1 明示未来多表类型用独立表类型；
- `workspaceSchemaVersion = 4`；迁移范本 **v1→v2（全局→每表下放）** 可直接复刻；
- Address Adjust 全链路：`ConnectionSettingsModal.tsx:512` Select → `connection-settings-model.ts` → `RtuConnectionProfile.addressAdjust`（domain，默认 off）→ `session-connect` payload → `RtuSessionHost` → `SessionHostCore.getAddressAdjustMode`（注入）→ `register-table/address.ts` `computeSentAddress`（ON 时发送 = 用户 − 1，0 下溢报错）→ `session.readRegister(sent,{userAddress})` → 日志双地址（`userAddress`/`sentAddress`）；
- 轮询（Renderer `App.tsx:138/226`）：`buildPollingTargets(sheets, profile.addressAdjust)` / `applyPollResult(...)` 读**全局 profile**，作用于所有 sheet；
- 每表独立配置现有 5 项：`registerRadix` / `slaveAddress` / `columnWidths` / `columnOrder` / `writeVerify`（store setter 均快照入撤销栈）；工具栏模式：`Tooltip + 控件 + aria-label + i18n`；
- 原版参考：Enter(ROM) = 写 0 到 0x0900（EEPROM+RAM 持久）、Enter(RAM) = 写 0 到 0x0910（仅 RAM），执行后触发批量轮询刷新，禁止对该类寄存器读（**待安川公开文档核实**）。

## 3. 总体设计：可扩展插件架构（核心）

### 3.1 Manifest v2（可执行化）

```ts
// 相对现状（仅 panels）的扩展
PluginManifestV2 {
  id: string; name: string; version: string;
  apiVersion: string;              // 新增：插件 API 版本（compatibility 判定依据）
  author?: string; description: string; license?: string;
  entry?: { web?: string; node?: string };   // 新增：可执行入口（模块路径）
  requiredCapabilities: string[];  // 新增：平台能力要求（如 ["modbus-rtu"]）
  platform: { web: boolean; node: boolean };
  permissions: PermissionId[];     // 类型化权限枚举（见 §6）
  contributes: Record<string, unknown>;  // 贡献点 map：key = 贡献点 ID，value = 该点 payload
}
```

- `contributes` 从固定 `panels` 改为 **`Record<ContributionPointId, unknown>`**，由贡献点注册表按 ID 校验与消费（见 §3.2）；
- 破坏性变更提升 `apiVersion`；`compatibility.ts` 实现「可加载 / 可加载但警告 / 禁止加载」三级判定，错误码 `PLUGIN_VERSION_INCOMPATIBLE`；
- `PluginStoreData` schemaVersion 1→2 迁移已装插件（manifest v2 字段）。

### 3.2 贡献点注册表（可扩展性核心 —— 需求⑥）

**机制**：核心模块通过 `registerContributionPoint<TSchema>(id, { schema: ZodSchema, consumer })` 注册「贡献点」；插件向贡献点提交贡献。**新能力 = 核心注册新贡献点并扩展 `contributes` 类型，不破坏存量插件** —— 这是面向未来的扩展性底座。

```ts
interface ContributionPoint<TSchema> {
  id: string;
  schema: z.ZodType<TSchema>;
  consumer: (contributions: Contribution<TSchema>[]) => void; // 装配/渲染消费方
}
interface Contribution<TSchema> { pluginId: string; payload: TSchema; }
```

**内置贡献点（v1）**：

| 贡献点 ID | payload 要点 | 消费方 |
|---|---|---|
| `panels` | `{id, titleKey, component}` | 补渲染（侧边栏/底部面板注册表） |
| `toolbarAction` | `{id, titleKey, icon, scope:"table-toolbar", targetTableType?, requiresConfirm}` | RegisterTable 工具栏注入 |
| `tableType` | `{id, protocolId, titleKey, columns?, rowActions?, createDefaultRow?}` | 新建表 + 表渲染注册表 |
| `protocolExtension` | `{protocolId, codecFactory}` | CommunicationSession codec 注册表 |
| `addressTransform` | `{id, protocol, apply, validate, defaultConfig?}` | register-table 地址提交链 |
| `theme` | `{colors?: Array<{id, titleKey, colorPrimary:{light,dark}, colorLink?}>}` | Settings 主题色选择器（可选预设，ADR-047：不再自动应用） |
| `settings` | `{id, titleKey, schema, component}` | Settings 弹窗分区渲染 |
| `dataType` | `{id, parse, format, registerCountRules}` | 数据类型注册表 |
| `command` | `{id, titleKey, handler}` | 命令分发（快捷键/按钮） |
| `documentation` | `{id, titleKey, markdown}` | Help/文档面板 |

未登记贡献点 → `PLUGIN_CONTRIBUTION_UNKNOWN`，错误隔离，不影响其他贡献点加载。

### 3.3 插件运行时与生命周期

- **UI-safe 插件**：渲染进程加载（浏览器 / Electron Renderer / VSCode Webview 同构），能力受限（数据显示 / 工具面板 / 文档 / 地址显示 / 纯计算 / 受控命令按钮）；
- **Host 插件**：Electron 主进程 / VSCode Extension Host（Node）加载；适合厂商私有协议、特殊通信封装、本地文件处理、受控设备操作；**浏览器不加载**；
- 生命周期：`load → validate(manifest + compatibility + permissions) → instantiate → activate(ctx) → [deactivate] → unload`；
- 错误隔离：每个插件独立错误边界，捕获同步/异步异常 → 记录 `pluginId` → 禁用故障贡献点 → 保持核心可用 → 展示可理解的加载失败原因；错误码 `PLUGIN_LOAD_FAILED` / `PLUGIN_HOOK_FAILED`；
- **执行隔离机制（§35 待确认，设计建议）**：
  - UI-safe → **Web Worker**（postMessage 边界，无 DOM / 无 `navigator.serial` / 无本地存储）；
  - Host → **Node `worker_threads` 或 `vm` + 能力白名单**；
  - 两者均只暴露 `PluginCommunicationApi`，不暴露 Transport / 文件系统 / 网络句柄；
  - 该机制属 §35「插件第三方代码隔离机制」待确认项，**需新增 ADR**。

### 3.4 PluginCommunicationApi（接通统一调度器）

```ts
interface PluginCommunicationApi {
  read(req: { protocolId, address, quantity, meta }, opts?): Promise<Result<...>>;
  write(req: { protocolId, address, values, meta }, opts?): Promise<Result<...>>;
  batchRead(rows, opts?): Promise<Result<...>>;
  traceStart/stop(...): ...;
  // 不暴露 Transport / 不暴露 socket 句柄 / 不允许插件自行并发写串口
}
```

流程：校验权限（`communication`）→ 校验平台 → 构造 `source:"plugin"` + `pluginId` + 默认 `RequestPriority:"plugin-background"` → `RequestScheduler.enqueue` → 记录日志（`CommunicationLogEvent` 增 `pluginId` 字段）→ 应用超时/取消。

- `plugin-runtime-load`（渲染 → 宿主：请求加载 Host 插件实例）

## 4. 分项设计

### 4.1 安川公开私有协议（`protocolExtension`）

**承载位置（2026-08-31 确认，决策 B）**：安川插件包 `plugins/yaskawa-memobus-67h-010dh-010eh/`——codec（67/010D、67/010E 等厂商专用功能码）随插件存放，**不进核心**、不进 `protocol-modbus`，也不进独立共享包；软件（core）仅提供 `ProtocolCodec` 接口 + codec 注册表 + 会话注入等**调用接口**（AGENTS §5.3 / §10.1、ADR-040 修订）。

**核心开放 `ProtocolCodec` 接口**（通信层改造点，需 ADR）：

```ts
interface ProtocolCodec {
  protocolId: string;                                  // "yaskawa-memobus-67h-010dh-010eh"
  encodeRead(req: { address, quantity }): Uint8Array;
  encodeWrite(req: { address, values[] }): Uint8Array;
  decodeResponse(frame, expected): Result<DecodedResponse>;
  parserFactory(expected): FrameParser;                // 分帧 / 半包粘包 / 重同步
  expectedLength(kind, quantity): { normal, exception };
}
```

**分层落位**：

1. `CommunicationSession.SessionOptions.protocol` 开放（`"rtu" | "tcp" | codecId`），`buildReadAttempt` / `buildWriteAttempt` / `startExchange` 委托 codec（核心通信包改造 → 新 ADR，涉及调度必测场景与 §43 不变量，须经 ADR 确认）；
2. `CommunicationLogEvent.protocol` 扩展 + `commLogEventPayloadSchema` 同步；`CommunicationLogEvent` 增 `pluginId` 字段；
3. 会话层：新增 `MemobusSessionHost`（仿 `TcpSessionHost` 模式）或 `SessionHostCore` 支持 codec 工厂注入；`getAddressAdjustMode` 复用既有注入抽象；
4. 承载：**web 插件（纯 TS codec，浏览器走 Web Serial）+ Host 插件（桌面）**，共享同一 codec 实现，三端一致；
5. **待核实项**（以安川公开文档为准，不得猜测）：MEMOBUS 帧差异、私有功能码、校验方式、Enter ROM/RAM 地址、禁止读取区。

### 4.2 新寄存器表类型（`tableType`）

**数据模型**：

- `RegisterSheet.type` 改判别联合 `"holding-register" | "<pluginId>:<tableTypeId>"`；
- `packages/workspace/src/schema.ts:72` `z.literal("holding-register")` → 开放字符串 + 格式校验；
- **v4→v5 迁移**：旧 sheet 补 `type:"holding-register"`（复刻 v3→v4 浅层遍历模式）；
- `packages/register-table/src/undo-redo.ts`：`SheetEditSnapshot` 增 `type`，`sheetFromSnapshot`（:169）携带 type；
- `packages/domain`：`createRegisterSheet(name, order, type?)` 工厂扩展；`workspaceSchemaVersion` 4→5。

**贡献点 payload**：

### 4.4 主题色（`theme` 贡献点 = 注册可选预设，ADR-047，逆转 ADR-042 任意取色）
