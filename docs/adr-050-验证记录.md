## 1. 生产构建 CSP 缺 `worker-src`（已完成，实测确认 + 修复）

### 背景

`apps/web/vite.config.ts` 的 `injectCspMeta()` 注入的生产 CSP 为
`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; connect-src 'self'`，
**无 `worker-src`**；而插件隔离运行时（ADR-044）用 `new Worker(URL.createObjectURL(blob))` 加载单文件 JS 插件
（`packages/platform-web/src/plugin-remote-runtime.ts`）。CSP 的 `worker-src` 缺失时回退 `child-src → script-src → default-src`，
`'self'` 不匹配 `blob:` → **打包产物下的可执行插件应被拦截**。dev 不注入 CSP（`apply: "build"`），故 e2e-web / e2e-vscode 均未暴露。

### 方法

临时脚本（用完即删，未入库）：用 http 把 `apps/web/dist` 起两个服务——一个原样、一个把响应 HTML 中的 `worker-src …;` 剥掉；
在系统 Edge（`channel: "msedge"`）加载真实文档，在真实文档 CSP 下尝试创建 Blob Worker 并收发消息。

### 结果

| 场景                                   | Blob Worker 结果 | 证据                                                                                                                                                                                                                                                 |
| -------------------------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 无 `worker-src`（修复前）              | `worker-error`   | `Creating a worker from 'blob:http://127.0.0.1:…' violates the following Content Security Policy directive: "script-src 'self'". Note that 'worker-src' was not explicitly set, so 'script-src' is used as a fallback. The action has been blocked.` |
| 有 `worker-src 'self' blob:`（修复后） | `ok:pong`        | 无 CSP 违规日志                                                                                                                                                                                                                                      |

结论：**修复前打包产物（浏览器 / Electron / VSCode，以及之后的 Android）下可执行插件确实不可用**；补 `worker-src` 后恢复正常。

### 修复落点

| 文件                                                       | 说明                                                                              |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `apps/web/src/csp.ts`（新）                                | `buildWebCsp()` 纯函数，CSP 单一事实源；`vite.config.ts` 引用                     |
| `apps/web/src/csp.test.ts`（新）                           | 断言含 `worker-src 'self' blob:`、保留基线指令、不放开 `script-src`               |
| `apps/web/vite.config.ts`                                  | `injectCspMeta()` 改用 `buildWebCsp()`                                            |
| `apps/vscode-extension/src/webview/prod-csp.ts`（新）      | `buildWebviewCsp(cspSource)`（VSCode 生产 Webview，资源源用 `webview.cspSource`） |
| `apps/vscode-extension/src/webview/prod-csp.test.ts`（新） | 同上断言（含 `cspSource`）                                                        |
| `apps/vscode-extension/src/extension.ts`                   | `getProdHtml` 改用 `buildWebviewCsp(webview.cspSource)`                           |

验证：`pnpm --filter @mamep2026/web test` 87/87（8 文件）、`pnpm --filter @mamep2026/vscode-extension test` 78/78（6 文件）、
`pnpm typecheck` 30/30、`pnpm lint` EXIT=0；重建产物后 `apps/web/dist/index.html` 的 CSP meta 已含 `worker-src 'self' blob:`。

**遗留待办**：仍缺「生产构建产物 + 插件执行」的 e2e（现仅单测守住 CSP 字符串）；Android 打包产物同样受益于本修复。

## 2. 桥延迟 spike（已完成，结论：桥不是瓶颈）

### 结论

**`TransportPort` 字节流接缝成立：Capacitor 桥的固定开销 p50 ≈ 1–2 ms / p99 ≈ 3.3 ms**，
相对默认 `requestTimeoutMs = 50` 只占 4–7%，**不需要**把帧解析下沉原生（退路保留但不动用）。

### 环境与工程

| 项   | 值                                                                                                                                                             |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 设备 | vivo V2303A，Android 16（API 36），**WebView 151.0.7922.199**                                                                                                  |
| 容器 | Capacitor 8.5.1（`@capacitor/core` / `cli` / `android`），minSdk 24 / compileSdk 36 / targetSdk 36                                                             |
| 构建 | Gradle 8.14.3 + AGP 8.13.0 + **JDK 21**；Kotlin 2.2.20（`kotlin-android` 插件为自研插件必需）                                                                  |
| 插件 | 自研 `SpikeTcpPlugin`（Kotlin，~180 行）：仅 connect / write / close / ping / report + `data` 事件；原生侧**整帧聚合**后单次 `notifyListeners`；无 Modbus 语义 |
| 页面 | 极简页面：`www/index.html` + `capacitor.js`（IIFE，就地增强原生注入的 `window.Capacitor`），`registerPlugin("SpikeTcp")`                                       |
| 对端 | 本机 Node TCP 回显服务（`adb reverse tcp:1502` → 127.0.0.1:1502）；8 字节 Modbus 风格帧；20 次预热 + 200 次采样                                                |

> **工具链坑（必记）**：Android Studio 自带的 JBR 为 **JDK 25**，而 Capacitor 8 模板固定 Gradle 8.14.3 ——
> Gradle 8.14 最高只支持 Java 24（Java 25 需 Gradle ≥ 9.1，且官方测试矩阵中 AGP 8.x 只配 Gradle 8.x），
> 直接构建报 `Unsupported class file major version 69`。**必须在 JDK ≤24 下构建**（本次用便携版 OpenJDK 21，
> 见文末路径；Android Studio 内需把 Settings → Build Tools → Gradle → Gradle JDK 指到 JDK 17/21）。

### 数据（单位 ms，200 次采样）

| 场景 / 指标                                 | p50     | p90     | p99     | max     |
| ------------------------------------------- | ------- | ------- | ------- | ------- |
| `pingInvoke`（纯桥调用往返，无 I/O）        | 1.1     | 1.2     | 1.5     | 1.7     |
| `writeInvoke`（JS→原生 write 返回）         | 1.1     | 1.2     | 1.8     | 2.2     |
| `nativeWrite`（原生 socket write 自身）     | 0.07    | 0.08    | 0.15    | 0.23    |
| `dataDelivery`（原生 → JS `onData` 投递）   | 0.9     | 1.2     | 1.9     | 2.1     |
| **`writeToDataTotal`（写完成 → 收到字节）** | **2.0** | **2.4** | **3.3** | **3.5** |

对端人为延迟 30 ms（模拟慢从站）时：`dataDelivery` p50 41.7 / p99 54.0，`writeToDataTotal` p50 47.2 / p99 61.2 ——
即总耗时由对端延迟主导；比 30 ms 多出的 ~11 ms 出现在 **adb reverse 隧道空闲唤醒**上（回显服务侧），
不是 Capacitor 桥（桥的三项指标在同一轮里仍为 p99 ≤ 2 ms）。

（第一次 delay=0 与 delay=30 的采样中，delay=30 那轮曾中途挂 CDP 客户端，数据偏大；
重跑均改为「先等测量跑完、再附着 CDP」，上表为无干扰数据。）

### 其他一并验证的事实

1. **手动注册插件可行**：插件源码不在 `node_modules` 时，须在 `MainActivity.onCreate` 中
   `registerPlugin(SpikeTcpPlugin.class)` 且**放在 `super.onCreate()` 之前**；`window.Capacitor.PluginHeaders`
   中确认插件已注册（与 Capapitor 官方文档一致）。
2. **页面处于安全上下文**：`server.androidScheme` 默认 `https` → 页面 URL 为 `https://localhost/`。
3. **`adb logcat` 在本机 vivo 设备上无任何输出**（OEM 限制）→ 原有「用 logcat 取数」的思路不可用；
   **Android 侧 e2e 与诊断必须走 CDP**（已实测可行）。
4. **Playwright `chromium.connectOverCDP` 能驱动 Android WebView**（实测：连上 `http://127.0.0.1:9222` 后
   拿到 `1 context / 1 page`，可 `locator().innerText()`、可截图）—— ADR-050 方案 9 的 e2e 路线成立。
   通道建立：`adb forward tcp:9222 localabstract:<从 /proc/net/unix 取到的 webview_devtools_remote_<pid>>`；
   **应用重启后 socket 名会变**，须重新解析并重建 forward。
5. **Capacitor debug 构建会把每次插件调用 marshal 到 console**（大对象），控制台噪声极大；
   Phase 1 的 e2e「无 console 错误」断言需注意：这些是 `log` 不是 `error`，但测量/断言时应避免中途附着 CDP
   （会引入可观开销），必要时用 `loggingBehavior` 降低日志。
6. 构建耗时：首次 `assembleDebug`（含 Gradle 分发与依赖下载）约 10 分钟，增量构建秒级。

| Gradle 实际解析                                                                                       | `pnpm build:android` 成功（`allprojects.repositories` 加 `maven { url 'https://jitpack.io' }` 后编辑 Kotlin 直接引用到库类型） |

库坐标固定在 `apps/android/android/variables.gradle`（`usbSerialForAndroidVersion = '3.11.0'`），许可为 **MIT**。

### 6.2 库真实 API（用 `javap` 核对 AAR，避免按旧版假设写代码）

早期版本与 3.11.0 不一致的三处（首次编译即暴露，已按实际签名修正）：

| 项   | 3.11.0 实际签名                                                                                                                                                          |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 流控 | `setFlowControl(UsbSerialPort.FlowControl)` 取**枚举** `NONE / RTS_CTS / DTR_DSR / XON_XOFF / XON_XOFF_INLINE`；`getSupportedFlowControl(): EnumSet<FlowControl>` 可预检 |
| 写   | `write(byte[], int timeout)` / `write(byte[], int, int, int)` 返回 **void**（阻塞至写完或超时）                                                                          |
| 常量 | `PARITY_NONE/ODD/EVEN`、`STOPBITS_1/2`、`DATABITS_*` 仍为 int 常量                                                                                                       |

读侧用 `SerialInputOutputManager(port, listener)`（自带读线程）+ `onNewData/onRunError`，其上层再叠 **10ms 空闲窗口聚合**（用户决策 Q6）。

### 6.3 实施中发现的真实问题（均已修复）

1. **vivo ROM 静默拒绝「流式安装」**（本机 V2303A / Android 16，Android 16 + `adb` 平台工具）：
   `adb install -r <apk>` 返回 `Failure [INSTALL_FAILED_ABORTED: User rejected permissions]`，
   而**手机端没有任何确认弹窗**（不是「等用户点确认」）。诊断：`adb devices` 为 `device`（已授权）、屏幕 `mWakefulness=Awake`、
   旧版本应用已在设备上。
   **修复**：改用 `adb install -r --no-streaming`（输出 `Performing Push Install … Success`）。
   `tests/e2e-android/helpers/adb.ts` 现为「先非流式 → 失败回退流式 → 仍失败才抛出带指引的错误」，并把该现象写入指引文案。
2. **e2e 辅助不认默认 SDK 路径**：`adbBinary()` 只查 `ANDROID_HOME/ANDROID_SDK_ROOT`，在没有这些环境变量的 shell 里
   报 `spawnSync adb ENOENT`。已改为与 `scripts/build-android.mjs` 同策略探测（含 `%LOCALAPPDATA%\Android\Sdk`）。
3. **能力位翻转使既有 Android e2e 断言过时**：`tcp-loop.spec.ts` 原断言「弹窗不含 `Modbus RTU`」（Phase 1 只有 TCP）。
   翻转后协议分组出现 → 改为断言「含 `Modbus TCP` 并显式切到 TCP」后继续。
4. **错误映射重构时误删 TCP 分支**（`connectFailed/openFailed`）：既有单测立即报 `TCP_CONNECTION_FAILED` 变
   `TCP_OPEN_FAILED`；已修回。教训：改共享映射必须回归既有断言。
5. **e2e 定位细节**：antd `Select` 非 search 态下 placeholder 渲染为 `span`（不在 `input` 上），
   故串口下拉按 Form.Item 标签 `filter({ hasText: "Port" })` 定位；RTU 表单实际文案为
   `Port / Speed / Data Length / Stop Bit / Parity Bit / Flow Control`（与 Electron/VSCode 同源）。

### 5.3 实施中踩的坑（供 Phase 2 复用）

1. **JDK 25 ⟂ Gradle 8.14.3**（`Unsupported class file major version 69`）：Android Studio 自带 JBR 可能是 Java 25；
   命令行已由 `build-android.mjs` 探测兜底，IDE 内需手动把 Gradle JDK 指到 17/21（见 `apps/android/README.md`）。
2. **设备安装被拒**（`INSTALL_FAILED_ABORTED: User rejected permissions`）：休眠/OEM 授权导致无法弹确认框 →
   辅助先 `KEYCODE_WAKEUP` + `wm dismiss-keyguard`（并建议 `svc power stayon true`），失败时抛出可操作指引。
3. **devtools socket 名带 `@` 前缀**：`/proc/net/unix` 里是 `@webview_devtools_remote_<pid>`，
   `adb forward localabstract:` 前必须剥掉 `@`；应用重启后 socket 名变化需重新解析。
4. **表格默认行地址为空**：不先填 `Register` 就直接点读，`RegisterTableService` 以 `addressEmptyError()` 短路，
   **不会有任何字节到达传输层**（易误判为「桥不通」）。e2e 必须先填地址再读；
   地址输入用 `pressSequentially` 而非 `fill()`（React 受控组件 onChange 可能被跳过）。
5. **窄屏（手机竖屏）按钮退化为图标态**：断言 Header 按钮须按无障碍名在 `.mamep-header` 内定位；
   另注意弹窗内还有第二个 Disconnect 按钮，locator 需限定作用域。
6. **Capacitor debug 构建日志量大**（每次插件调用 marshal 到 console，均为 `log` 不是 `error`）；
   「无 console 错误」断言不受影响，但测量类用例不应中途附着 CDP。
