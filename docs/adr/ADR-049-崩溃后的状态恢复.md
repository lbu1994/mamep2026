# ADR-049：崩溃后的状态恢复（关闭/崩溃时 flush + 恢复提示 + §19.1 仓储接口补齐）

- 日期：2026-09-04
- 状态：已确认
- 关联：PRD §8.3（P1）、PRD §6.7 / §14.6 / §15.2 / §16.5、TECH_DESIGN §19.1~19.7、ADR-036

## 背景

「崩溃后的状态恢复」为 PRD §8.3 P1 待办，依赖已落地的工作区持久化（浏览器 IndexedDB /
Electron `filesystem:"full"`，ADR-036；VSCode 走 webview IndexedDB）。§21.2「状态恢复依赖
工作区持久化」已满足。

现状盘点：启动已 `loadWorkspace()` 恢复；`AutoSaveCoordinator` 有 debounce + flush + 备份 +
损坏自愈；`load` 失败提示 `messages.loadFailed`；用户可经 Settings Reset Workspace；Schema
已覆盖 §16.5 多数字段。**缺口**：

1. **关闭/崩溃前 flush 缺失**（TECH_DESIGN §19.2 第 3 条「应用关闭前尝试 flush」）：浏览器/
   Electron/VSCode 渲染上下文均无 `pagehide`/`visibilitychange` flush，500ms debounce 窗口内的
   最新编辑在关闭/崩溃时丢失。
2. **仓储接口不完整**（TECH_DESIGN §19.1）：仅 `load/save/clear`，缺 `reset/export/import/
   createBackup/getRecoveryInfo`。
3. **恢复模式/提示缺失**（TECH_DESIGN §19.7 / PRD §14.6）：主文件损坏→备份恢复时静默，无
   「恢复来源和时间」提示，未保留损坏原文件、无法导出损坏文件、无明确恢复模式。
4. **崩溃 vs 正常关闭检测缺失**：无 dirty/异常退出标记。

## 方案

按「关闭/崩溃时 flush + 恢复提示 + §19.1 仓储接口补齐」落到三端，**不做**崩溃与正常关闭的
区分（无 dirty 标记），恢复横幅**不提供操作按钮**。

### 1. 仓储端口（packages/workspace）

新增 `WorkspaceRecoveryInfo`（`recovered` / `source:"none"|"backup"|"fresh"` /
`recoveredAt` / `backupTimestamp` / `errorCode`）。`WorkspaceRepositoryPort` 保留
`load/save/clear`，新增 `reset`（清空持久化数据，语义等同 `clear`）、`export`（读持久化存储→
序列化 JSON 字符串）、`import(serialized)`（parse+校验+落盘）、`createBackup`（主→备份轮转）、
`getRecoveryInfo`（最近一次 load 的恢复元数据）。

### 2. 恢复元数据

各仓储 `load()` 内记录：主有效→`source:"none"`；主损坏且备份有效→`source:"backup"`、
`backupTimestamp`（Electron 取备份文件 mtime，IndexedDB 为 null）、`recoveredAt=now`；
主+备份均不可用→`source:"fresh"`、`errorCode`。`load` 成功路径返回类型不变，恢复信息经
`getRecoveryInfo()` 旁路返回（不破坏 `Result<Workspace>` 契约）。

### 3. 关闭/崩溃时 flush

`AutoSaveCoordinator.flush()` 已存在，经 `AppHost.flush()` 暴露。`apps/web/src/App.tsx` 组合根
注册 `pagehide`（`void host.flush()`）与 `visibilitychange`（`document.hidden` 时
`void host.flush()`），清理时退订。浏览器/Electron/VSCode 渲染上下文统一复用，`pending` 被清空
故幂等。

### 4. 恢复提示（UI）

`RecoveryBanner`（antd `Alert banner`，复用 `BrowserCompatibilityBanner` 位置/样式），store 增
`workspaceRecovery`。`loadWorkspace()` 后 `host.getWorkspaceRecoveryInfo()` 写入 store：
`source:"backup"`→「已从备份恢复（含时间）」；`source:"fresh"`→「恢复失败已重置为默认」；
`source:"none"`→不显示。无按钮（重置仍走 Settings，导出仍属 ADR-033 交换格式）。

### 5. HostMessage v1 契约（packages/platform-api）

`workspaceLoadResponseSchema` 增 `recoveryInfo: WorkspaceRecoveryInfo | null`；新增 request kind
`workspace-create-backup`（payload `{}`）+ `MamepHostApi.workspaceCreateBackup`。两端 `ipc.ts`
按既有穷尽守卫补齐分支（Electron 主进程实现；VSCode 扩展宿主返回
`WORKSPACE_FILESYSTEM_UNSUPPORTED`），preload / vscode-bridge 同步。

## 决策点

1. **范围**：仅「关闭/崩溃时 flush + 恢复提示 + §19.1 接口补齐」；不实现完整 §19.7 恢复模式
   （保留损坏原文件 / 导出损坏文件 / 恢复模式入口 UI）。
2. **崩溃检测**：不做 dirty/异常退出标记；崩溃时 flush 不生效、autosave 兜底（最多丢 500ms），
   不区分崩溃/正常关闭显示。
3. **关闭时机**：采用 **`visibilitychange→hidden`（仅）**——关闭窗口/切后台时页面先进入
   `hidden`（仍存活），IndexedDB/IPC 写入能可靠完成；`pagehide`（页面卸载）会中断异步
   IndexedDB 写入（e2e 验证「立即重载」不落盘），且 reload 也触发 `pagehide`，会把「清工作区→
   reload」的测试隔离破坏（把已清空的工作区又写回，如 tcp-reconnect 用例）。`pending` 清空故
   幂等。**兜底**：崩溃无 graceful 时机，由 autosave（debounce 500ms）保证；故「关闭丢数据」e2e
   以「编辑后关闭/重载不丢数据（autosave 兜底 + flush best-effort）」断言。
4. **恢复提示形态**：antd `Alert banner`，纯信息、无按钮。
5. **仓储接口**：按 TECH_DESIGN §19.1 补齐 `reset/export/import/createBackup/getRecoveryInfo`；
   `export/import` 为接口完整性，不新增 UI 入口（避免与 ADR-033 交换格式重复）。
6. **能力矩阵**：不变（`filesystem` 维持 browser `limited` / electron `full` / vscode
   `unsupported`，如实声明）。
