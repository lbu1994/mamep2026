# ADR-054：删除「随包插件」机制与插件同进程执行（用户显式授权）

- 日期：2026-09-12
- 状态：已确认（用户决策 2026-09-12）
- 关联：ADR-038（插件安装入口）/ ADR-039（插件功能设计）/ ADR-040（协议扩展）/ ADR-041（安川 Phase C）/ ADR-042（Address Adjust）/ ADR-043（Phase E：基础表 / 自定义功能码 / dataType）/ ADR-044（Phase F：可执行插件与隔离）/ **ADR-045（内置插件外部化与一次性安装 —— 本 ADR 取代其「随包一次性安装」部分）**

## 1. 背景与动机

- ADR-045 把 4 个内置插件移出为 `plugins/` 包，并引入「随包插件首启一次性安装」（`seeded` 标记 + `restoreBundledPlugin` + `attachRuntime` + Plugin Manager「Restore bundled」）。
- 该机制的副作用：
  1. **插件列表里出现用户没有主动安装过的插件**，「已安装/可卸载/可恢复」的语义与「用户自己安装的插件」混同；
  2. 同步能力（codec / dataType / addressTransform）只能由**随包编译**的插件提供（用户安装入口只给隔离运行时），形成「两套信任等级 + 一套隐藏路径」；
  3. `attachRuntime` 只为「随包清单」服务，是装配层的特殊分支。
- 用户决策：**删除随包插件机制，所有插件一律手动安装**；为保持同步能力可被安装的插件提供，**放宽 ADR-044 的执行边界：安装时由用户显式授权「同进程执行」**（默认仍为隔离线程）。

## 2. 用户决策（2026-09-12，两轮确认）

1. **删除随包机制**：移除 `seeded` / `isSeeded` / `markSeeded` / `restoreBundledPlugin` / `restoreAllBundledPlugins` / `bundledPlugins` / Plugin Manager「Restore bundled」按钮 / `attachRuntime`。
2. **插件一律手动安装**：`release/plugins/<pluginId>/` 下的 `manifest.json`（纯清单）或 `<pluginId>.mjs`（可执行 entry）由用户在 Settings → Plugins 安装。
3. **同步能力改由「同进程执行」提供**：安装可执行插件时，用户在安全确认框中选择执行模式——**Isolated worker（默认/推荐）** 或 **Same process（贡献同步能力时必需）**；同进程执行 = 插件代码获得与应用同等权限（渲染端 DOM/IndexedDB；桌面宿主为完整 Node 环境），文案明确提示风险。
4. **宿主侧插件执行面**：Electron 主进程 / VSCode Extension Host 也装配插件执行面（`hostPlugins` 翻转为 true）——**已由 [ADR-055](ADR-055-宿主侧插件执行面.md)（2026-09-12）实施**（`HostPluginRuntime` + 两端装配 + 能力翻转）。
5. **能力矩阵动态化**：`protocolExtensions` / `tableTypes` 由「平台基础值 + **已启用**插件贡献」派生（`host.capabilities` 读取即派生），基础常量只保留核心能力（基础表 codec）。
6. **迁移：清空插件存储**：`PluginStoreData` schemaVersion **3 → 4**，v1/v2/v3 数据迁移时**清空全部已安装插件**（连同用户此前安装的插件），其余数据（工作区、偏好）不变；用户需重新安装插件。
7. **插件 API 版本 1.0 → 2.0**：`PluginContext` 新增同步贡献面 `ctx.registries`（契约破坏性变更，1.x 插件被禁止加载）。
8. **删除 example-panel**（panels 示例插件，其主题色早已剥离到 `example-theme`）：示例插件改由 `example-theme`（纯清单）与 `custom-function-code`（可执行 + 同进程）承担。
9. **文档**：新增本 ADR；ADR-045 标注被取代；e2e 用例改写但**本次不执行**（用户决定，见 §7）。

## 3. 分层落位

### plugin-api

- `plugin-store.ts`：`PLUGIN_STORE_SCHEMA_VERSION = 4`；删 `seeded`；`StoredPlugin` 增 `executionMode?: "isolated" | "same-process"`；`migratePluginStoreData` 对 v1/v2/v3 一律返回空 store（`plugins: []`）；新增导出类型 `PluginExecutionMode`。
- `plugin-persistence.ts`：`init()`（load + hydrate）→ **`start()`（只订阅事件并持久化）**；hydrate 由装配方承担（需先异步加载执行面才能带 runtime 注册）。
- `lifecycle.ts`：
  - `PluginContext` 增 `registries: PluginSyncRegistries`（`codec` / `dataType` / `addressTransform` 注册面）；
  - 新增 `PluginLocalEntry`（同进程 entry 模块形态：`manifest` + `activate` + 可选 `deactivate` / `handleToolbarAction`）与 `runtimeFromLocalEntry()`（entry → `PluginRuntime` 胶水）；
  - 新增 `PluginProtocolCodec` 等**结构镜像**类型（避免 plugin-api 依赖 communication；漂移由插件调用点与组合根赋值校验在 `pnpm typecheck` 暴露）；
  - `PLUGIN_API_VERSION = "2.0"`。
- `registry.ts`：删 `attachRuntime` / `attachRemoteRuntime`（执行面在 `register()` 时随插件一同给出）；`register()` 增 `executionMode`（缺省按 runtime 推断）；`snapshot()` / `hydrate()` 携带 `executionMode`；新增 `getExecutionMode()`；新增 `PluginRegistryOptions.syncRegistries` 与 `createUnavailableSyncRegistries()` 兜底。

### platform-web

- 新增 `plugin-local-runtime.ts` → `loadWebPluginEntry(entrySource)`：Blob URL + `import()` 在**同进程**加载 entry，结构化收窄为 `PluginLocalEntry`（缺 `manifest`/`activate` → `PLUGIN_LOAD_FAILED`）。

### 应用装配层（apps/web）

- `AppHost.ts`：
  - 删 `BundledPluginEntry` / `bundledPlugins` / 两个 restore 方法 / `createPluginRemoteRuntime` / `restoreRemotePluginRuntimes`；
  - `startPlugins()`：`pluginStore.load()` → 逐个 `registerStoredPlugin()`（按 `executionMode` 加载执行面，entry 的 manifest 为权威清单；纯清单插件直接注册）→ `pluginPersistence.start()`；加载失败仅记录错误（错误隔离，不注册）；
  - 新增 `previewPluginEntry()` / `installPluginEntry()`（安装两步：预览取 manifest → 用户确认后按所选模式装配并注册）；
  - `capabilities` 改为 **getter**：`deriveCapabilities(基础能力, pluginRegistry)`（导出供三端门面复用）；
  - 新增 `sync-registries.ts`：`createPluginSyncRegistries({ codecRegistry, dataTypeResolver, addressTransformRegistry })`（**唯一适配点**，`CodecRegistry.register` 返回 void → 包成 `Result`）。
- `App.tsx`：删除 4 条 bundled entry 与插件包静态 import，改为「核心装配（基础表 codec）+ 同步注册面注入」。
- `ElectronAppHost` / `VscodeAppHost` / `AndroidAppHost`：去 `bundledPlugins`，增 `syncRegistries` 透传；`capabilities` 改为派生 getter；插件方法改为 `startPlugins` + `previewPluginEntry` + `installPluginEntry`。

### domain / platform-api / platform-android

- 基础能力常量只保留**核心**协议扩展与表类型（`modbus-basic-tables:*` / 四个表类型）；安川、自定义功能码等插件能力不再写死。

### ui

- `AppHost` 接口：`startPlugins` 语义更新，删两个 restore 与 `createPluginRemoteRuntime`，增 `previewPluginEntry` / `installPluginEntry`（类型 `PluginExecutionMode`）。
- `PluginManagerSection`：删「Restore bundled」按钮；`.mjs` 安装流程改为「预览（隔离）→ 确认框（清单 + **执行模式 Radio** + 风险提示）→ 按所选模式安装」；i18n 删 `plugins.restoreBundled*` / `executableEntryNotice`，增 `plugins.executionMode*`（隔离/同进程 + 风险提示），`errors.pluginLoadFailed` 措辞中立化（不再限定隔离线程）。
- 能力矩阵的响应式：沿用既有 `usePluginContributions`（`useSyncExternalStore` 订阅注册表版本），不再新增 store 字段。

### plugins/

- `address-adjust` / `custom-function-code` / `yaskawa-memobus-67h-010dh-010eh`：改为**单文件 entry** 形态（`export const manifest` + `export function activate(ctx)`，yaskawa 另导出 `handleToolbarAction`），同步能力经 `ctx.registries` 注册；删除 `createXxxRuntime` / `registerXxxPlugin` 工厂。
- **删除 `plugins/example-panel`**（含 `apps/web` 依赖、i18n 键、e2e 用例、文档示例）。
- 主题色插件（`example-theme` 等）保持纯清单手动安装；`apiVersion` 统一升 2.0。
- 新增 **`pnpm build:plugins`**（`scripts/build-plugins.mjs`，esbuild）：可执行插件 → `release/plugins/<pluginId>/<pluginId>.mjs` + 从产物中提取的 `manifest.json`（加载产物校验：manifest.id 与 activate 存在）；纯清单插件 → 拷贝 `manifest.json`。根 `devDependencies` 增 `esbuild`。

## 4. 安全边界（重要）

- **默认隔离**：不选择执行模式时插件在 Web Worker / worker_threads 中执行（ADR-044 边界不变，唯一通道为 `PluginCommunicationApi`）。
- **同进程执行 = 用户显式授权的高权限路径**：插件代码与应用同进程、同权限（渲染端可访问 DOM / IndexedDB / 网络；若宿主侧执行面落地则为完整 Node 环境）。因此：
  - 执行模式选择放在 §6.10.4 安全确认框内，并附风险文案；
  - `same-process` 会被持久化（`executionMode`），重启后仍以该模式加载；
  - **不引入签名/权限提升机制**：选同进程即等同于信任该插件（与「本地文件安装」同一信任等级）。
- **用户安装的插件不再局限于隔离运行时**——这是对 ADR-044 的**有意放宽**，取代 ADR-045 中「只有随包受信插件可同进程」的信任模型（信任来源改为「用户安装时的显式授权」）。

## 5. 插件存储迁移（破坏性）

| 来源版本                         | 处理                                                                                                        |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| v1 / v2 / v3（历史，含随包机制） | **清空 `plugins`**，`schemaVersion` 升 4（`plugins: []`）；`plugins` 非数组 → `PLUGIN_STORE_SCHEMA_INVALID` |
| v4（当前）                       | 严格校验（manifest 走 `pluginManifestSchema`；`entrySource` / `executionMode` 可选）                        |

- 影响：用户此前安装的插件（含随包自动安装的 4 个）在升级后全部消失，需重新手动安装；工作区数据与偏好不受影响。
- 主题色预设（`preferences.themePrimary` 引用插件颜色 id）在插件未重装时自然回退默认蓝（既有逻辑，无需迁移）。

## 8. 取代关系

- 取代 ADR-045 的：随包插件一次性安装（`seeded` / `markSeeded`）、「Restore bundled」入口、`attachRuntime` 恢复路径、`AppHostOptions.bundledPlugins`、「installed 同进程 runtime 仅限随包受信插件」的信任模型。
- **保留** ADR-045 的有效结论：插件一律放在 `plugins/` 目录、**禁止新增内置插件**（docs/AGENTS.md §32 ㉞）、安川 ROM/RAM 命令写移入插件（`handleToolbarAction`）。
