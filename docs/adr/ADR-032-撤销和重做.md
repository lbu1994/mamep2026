# ADR-032：撤销和重做（工作区编辑命令栈）

- 状态：已确认（**已实施完成**，2026-08-28）
- 日期：2026-08-28
- 决策来源：PRD §8.3 P1「撤销和重做」+ TECH_DESIGN §24.4「撤销和重做」；README 分阶段
  ToDoList 遗留项（行编辑基础已在 MVP，ADR-015；撤销/重做未实现）

## 背景

- 寄存器表的行编辑（新增/插入/删除/移动/复制/剪切/粘贴/多行选择/键盘快捷键/右键菜单）已在
  浏览器 MVP 完整实现（ADR-015）；PRD §8.3 P1 的「撤销和重做」维持未实现，是 V1.0 待办。
- TECH_DESIGN §24.4 是撤销范围的权威定义：撤销栈只处理**工作区编辑操作**（新增行、删除行、
  修改名称、修改地址、修改 Type、修改轮询设置、粘贴、移动行、标签页操作）；**不撤销**设备
  读取结果、Data 单元格文本修改、已经发送的写入、连接和断开、通信日志、设备产生的外部状态；
  写入设备后不能通过普通 UI 撤销恢复设备值。
- packages/register-table 已在 §6.8 预留「撤销与重做命令（P1 未来项，当前未实现）」的位置。

## 实现方案调研结论

- 候选库 zundo（zustand 时间旅行中间件，Context7 官方文档）：对**整个 store 状态**做快照，
  undo 会回滚 commLog / traceWindows / connectionState 等全部状态，直接违反 §24.4「不撤销
  设备读取结果、连接和断开、通信日志」；且轮询/读取持续 set workspace，需大量 pause/resume
  交互，复杂度反而更高。
- **结论：手写命令栈**（TECH_DESIGN §2 亦列「撤销和重做」为需自行实现的能力），精确匹配
  §24.4 语义（只撤销工作区编辑、保留当前读值），并落到 register-table 层预留位置。

## 决策（3 项，用户确认）

1. **撤销范围**：行级编辑 + 每表配置 + 表结构性操作——
   - 行级：新增/插入/删除（含多选批量）/移动（单行、批量、拖拽排序）/复制行/剪切/粘贴/
     改名/改地址（含范围行 registerCount/registers）/改 Type（含 Scale）/WP 轮询开关/
     范围行子行元数据（name/comment/dataType）。
   - 每表配置：Register 地址进制（radix）、Slave Address、写后回读（writeVerify）。
   - 表结构性：新增表、删除表、重命名表、复制表、移动表顺序。
   - 列宽/列序布局（columnWidths/columnOrder）不入栈（非编辑类布局微调）。
2. **标签页显示切换不纳入**：表的打开/关闭（closeSheet/openSheet/closeOtherSheets/
   closeSheetsToRight）是非破坏性视图状态（类似连接/断开的环境状态），不产生撤销步骤；
   仅结构性操作（增/删/改表名/复制/移动表）入栈。
3. **批量操作 = 单个撤销步骤**：一次批量删除/移动/剪切/粘贴整体作为一步撤销，符合直觉。

## 实现要点

- **数据模型（packages/register-table/src/undo-redo.ts，纯函数、可单测）**：
  - `RowEditFields`：行编辑字段（name/comment/addressDraft/addressValue/registerCount/
    dataType/pollingEnabled/registers）；`extractRowEditFields`/`applyRowEditFields` 提取与
    应用——应用时保留运行时字段（cellText/registerValues/order/traceEnabled 等），
    registerCount 变化且值长度不匹配时清空 registerValues（与 commitAddress 一致，ADR-030）。
  - `SheetEditSnapshot`：表编辑结构快照（表配置字段 + 每行 edit 字段 + full 完整行）。
    full 仅在被增删的行/表重建时需要（撤销删除恢复完整行含当时读值，「撤销删除」语义）。
  - `applySheetSnapshot`：恢复结构时快照中存在的行恢复编辑字段、保留当前读值；被删除的行
    用 full 重建；快照中没有的行移除；`sheetFromSnapshot` 重建整表（含布局默认值）。
  - `UndoEntry`：`{kind:"sheet", sheetId, before, after, removeFallback?}` 或
    `{kind:"sheets-reorder", before, after}`（表顺序重排）。
  - 栈状态机：`UndoRedoState`（undoStack/redoStack）、`pushEntry`（新编辑清空重做栈、
    容量上限 100 丢弃最旧）、`popUndo`/`popRedo`/`pushUndo`/`pushRedo`、`clearHistory`。
- **store 集成（packages/ui/src/app-store.ts）**：
  - 新增 `undoStack`/`redoStack`（纯会话状态，不持久化）与 `undo()`/`redo()`（应用
    before/after 快照、sheets-reorder 按 sheetId 顺序重排、修复 activeSheetId 指向）；
    `setWorkspace` 加载/重置时清空历史。
  - 每个入栈操作在编辑前后捕获快照（新增 `setRowName`/`setRowComment`/`setPollingEnabled`
    供 Name/WP/Comment 单元格使用；`commitRowAddress`/`setRowDataType`/`setChildMeta`
    成功才入栈；行级/表级结构操作为块体捕获前后）。
  - 删除唯一表时 UI 重建默认空表：`removeFallback` 标记，撤销删除后只保留被恢复的表。
  - Data 编辑（`commitCellText`/`commitChildCellText`）、读值覆盖（updateRow 的运行时路径）、
    traceEnabled、列布局、表的打开/关闭、连接相关一律不入栈（§24.4 / 决策 2）。
- **UI（packages/ui/src/components/RegisterTable.tsx）**：
  - 工具栏新增 antd `Button`+`Tooltip` 撤销/重做按钮（`UndoOutlined`/`RedoOutlined`，
    `canUndo`/`canRedo` 由栈长度派生驱动禁用态，aria-label + i18n 双语）。
  - `handleGlobalKeyDown` 扩展 Ctrl+Z 撤销、Ctrl+Shift+Z / Ctrl+Y 重做（焦点在文本输入
    控件时不拦截，与既有快捷键约定一致；与浏览器原生文本撤销区分）。
  - i18n：`table.undo`/`table.redo`/`table.undoHint`/`table.redoHint`（en-US + zh-CN）。

- e2e：`tests/e2e-web/tests/undo-redo.spec.ts` 6 用例（按钮初始禁用与闭环、快捷键

## 后续

- 撤销/重做为纯内存会话状态（不随工作区持久化），刷新/重启后清空（与 selectedRowIds 等
  会话态一致）。
- 表内大行数（500+）下每次编辑保存整表编辑字段快照（含 full 引用，行对象不可变更新故引用
  安全）；容量 100 步可防无限增长。若后续内存压力明显，可改为受影响行差分快照。
