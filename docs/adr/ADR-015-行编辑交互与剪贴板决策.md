# ADR-015：行编辑交互与剪贴板决策

- 状态：已确认
- 日期：2026-08-15
- 决策来源：用户指令 + 用户对范围澄清的确认

## 背景

PRD §6.5.14「行编辑」要求支持：新增、插入、删除、向上/向下移动、复制、剪切、粘贴、多行选择、键盘快捷操作、右键上下文菜单，且删除含数据行须支持撤销或提供适当防误操作机制。

浏览器 MVP 此前已实现：新增（末尾追加）、删除、上移/下移、行级复制（duplicate）。未实现：插入（中间位置）、剪切、粘贴、多行选择、行级键盘快捷键、行级右键菜单。其中多行选择 / 剪切 / 粘贴 / 撤销重做在 PRD §8.3 P1（V1.0 正式版）才列为目标。

用户要求：优先使用框架（Ant Design）提供的已有功能实现多选与右键菜单。

## 决策

1. **范围**：本轮完整实现 插入行、剪切、粘贴（系统 + 应用内剪贴板）、多行选择、行级键盘快捷键、行级右键上下文菜单。PRD §8.3 P1 的「表格多行选择」提前到浏览器 MVP 实现；撤销/重做不引入（维持 P1）。
2. **插入行**：在当前选中行**下方**插入一个**空行**，不继承名称 / 地址 / 类型 / 备注等字段；行号自动重排（复用 `addRowAfter` / `renumberRows` / `createEmptyRow`）。右键菜单「插入下方」与快捷键 Ctrl+I 均提供；右键菜单另提供「插入上方」。
3. **删除防误操作**：删除（含多选）采用**直接删除，不弹确认弹窗、不引入撤销/重做**。用户明确：删除弹窗影响调试体验，不视为缺口，尽量不弹窗。本决策覆盖 PRD §6.5.14「应支持撤销或提供适当防误操作机制」。
4. **剪贴板**：同时实现**系统剪贴板**与**应用内剪贴板**。
   - 系统剪贴板为 CSV 文本：表头 `Name,Register,Data,Type,Comment`；Register 列用**十进制数值**（空行留空），避免跨表 HEX/DEC 进制歧义；RFC4180 风格转义。
   - 应用内剪贴板跨标签页生效，作为系统剪贴板的兜底。
   - 粘贴：在目标行（最后选中行或右键目标行）之后插入；无目标则追加表尾；行数超过剩余空间时**自动补行，不静默截断**；地址按目标表进制重新格式化；非法数据**不静默丢弃**（行级 issue 汇总提示，Data 文本原样保留，写入时走既有 `parseCellText` 校验路径）。
5. **多行选择**：采用 Ant Design Table `rowSelection` **原生能力**——选择复选框列、表头全选、Shift 范围选择、Ctrl 多选（antd v6 `useMultipleSelect`）。领域层只持有 `selectedRowIds: RowId[]`（会话态，不随工作区持久化，不依赖 AntD 内部结构，满足 AGENTS §25.4）。普通点击行空白处单选该行；多选/范围选择经复选框交互。
6. **行级右键上下文菜单**：用 Ant Design `Dropdown trigger={['contextMenu']}` 包裹表格，`onRow.onContextMenu` 记录目标行。菜单项：插入上方 / 插入下方 / 上移 / 下移 / 复制 / 剪切 / 粘贴 / 删除（删除无确认）。动作全部经 `app-store` 统一路径，不重复实现业务逻辑。
7. **键盘快捷键**（仅在焦点**不在文本输入控件** `input[type=text]` / `input:not([type])` / `textarea` / `select` / `.ant-select` 时生效，避免与单元格编辑/addressDraft 冲突）：
   - Alt+↑ / Alt+↓：上移 / 下移选中行（块）；
   - Delete：删除选中行（含多选）；
   - Ctrl+C / Ctrl+X / Ctrl+V：复制 / 剪切 / 粘贴；
   - Ctrl+I：在最后选中行下方插入（无选中则追加表尾）。
8. **系统剪贴板端口**：经 `AppHost` 增加 `copyTextToClipboard(text)` / `readTextFromClipboard()`；浏览器端用 `navigator.clipboard` 实现，无权限/非安全上下文返回结构化错误；复制/剪切写系统剪贴板失败**不影响**应用内剪贴板。
9. **分层**：行操作与剪贴板模型（`row-operations.ts` / `row-clipboard.ts`）位于 `packages/register-table`（TDD）；UI 仅经 `app-store` 调用，不重复业务逻辑。

## 备选方案

- 多选自建点击选择模型（Ctrl/Shift+Click 行体 + 自绘高亮）：被否决，用户要求优先使用 Ant Design 已有功能，改用 `rowSelection` 原生能力。
- 右键菜单用自定义固定定位 Menu + 遮罩：最初实现；因需自行处理定位/关闭且用户要求优先框架功能，改用 `Dropdown trigger={['contextMenu']}`。
- 删除引入撤销/重做基础设施：被否决（P1 保留），用户明确不弹窗、不引入撤销。
- 仅应用内剪贴板（系统剪贴板留接口）：被否决，用户要求系统 + 应用内两者都实现。

## 理由

- 优先复用框架成熟能力，减少自研交互的定位/状态管理复杂度与回归面；
- 保持调试流程流畅（减少打断式弹窗），符合 AGENTS §25.1「调试中的修改优先内联完成」；
- 剪贴板地址用十进制数值 + 目标表进制重格式化，消除跨表 HEX/DEC 粘贴歧义。

## 正面影响

- 多选 / Shift 范围选择 / 表头全选由 antd 维护，行为一致且稳定；
- 删除不弹窗、快捷键直达，符合调试工具的高频操作习惯；
- 系统 + 应用内剪贴板双实现，离线/权限受限场景仍可复制粘贴。

## 负面影响

- 多选引入 antd 选择复选框列（位于 No 列之前），PRD §25.4 固定列序实际为「[选择列] No / TM / ...」；
- 删除含数据行无确认、无撤销，误删后不可恢复（以不弹窗换取流畅性，用户已确认）；
- 系统剪贴板 Register 用十进制数值，粘贴后地址 draft 文本会按目标表进制归一化，原始 draft 格式不保留；
- Electron / VSCode 端的系统剪贴板实现尚未落地（仅浏览器端，编译不破坏）。

## 复审条件

- 用户反馈删除需要防误操作（确认弹窗或撤销）时，重新评估第 3 条决策；
- 多选交互与其它表格技术方案（如虚拟滚动）冲突或影响 1000 行性能时复审；
- Electron / VSCode 端需要系统剪贴板时补齐对应 `AppHost` 实现。
