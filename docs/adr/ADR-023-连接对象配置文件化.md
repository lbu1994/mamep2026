# ADR-023：连接对象配置文件化（真实设备连接参数集中管理）

- 状态：已确认
- 日期：2026-08-24
- 决策来源：用户指令（将 MOCK/虚拟连接切换为真实设备连接，并支持配置文件化连接对象）

## 背景

- 三端（浏览器 / Electron / VSCode）的真实连接路径已就绪：浏览器 `WebSerialTransport`
  （`navigator.serial`）、Electron RTU=Renderer Web Serial + TCP=主进程 `NodeTcpPlatformHost`、
  VSCode=`NodePlatformHost`（serialport/net）+ `RtuSessionHost`/`TcpSessionHost`。
- MOCK/FAKE（`?mockTransport=1`、`MAMEP_FAKE_SERIAL=1`、`MAMEP_FAKE_TCP=1`）均为显式 dev-only
  可选手段，默认路径已走真实设备——但真实连接参数散落硬编码于 `scripts/`（COM4/COM5、
  9600/8N1、127.0.0.1:1502 等），且应用侧无任何「从文件加载连接对象」能力。
- 需要：连接对象（连接参数）通过配置文件集中管理，供 UI 与测试/验证脚本消费，消除硬编码；
  并明确 MOCK/FAKE 保留边界（显式可选 dev 手段，默认走真实设备）。

## 已确认决策（用户 2026-08-24）

1. **格式与位置**：JSON + 项目根 `config/` 目录（`config/connections.json` 仓库内提交默认/示例）。
2. **与 connectionProfiles 的关系**：配置文件作为**默认值来源 + 导入预填**——UI 载入后预填连接
   表单，关闭时照常合并进 `connectionProfiles[0]` 持久化（不破坏现有持久化边界与格式）。
3. **浏览器端**：**三端都支持**——浏览器无文件系统（`filesystem: limited`），通过「导入 JSON 文件」
   （`<input type=file>` + FileReader）与 `?connectionConfig=<base64>` URL 参数载入；
   桌面端（Electron/VSCode）读文件系统。
4. **消费方**：应用 UI（连接设置「从配置载入」）+ 测试/验证脚本（`scripts/` 探针等从同一配置
   读取主站连接参数）。
5. **生效时机**：**重连 / 重启时重新读取**（打开连接设置弹窗时加载），无热更新。
6. **真实验收路径**：com0com 虚拟串口 COM4↔COM5 + `modbus-slave`（COM5）+ 本地 TCP 从站
   （127.0.0.1:1502），走**真实** serialport/net 协议栈完成 FC03 读 / FC10 写闭环；真机项
   （COM10+ 真机、macOS/Linux、打包原生模块加载）列入后续清单。

## 决策

1. **共享包 `packages/connection-config`**（新包，只依赖 `@mamep2026/domain` + zod，无平台依赖）：
   - `ConnectionConfigFile`：`{ schemaVersion:1, activeConnectionId: string|null, connections: ConnectionConfigObject[] }`；
   - 连接对象 Zod schema（判别联合 `protocol`）：RTU（`name/port/baudRate/dataBits/stopBits/parity/
     flowControl/slaveAddress/requestTimeoutMs/retryCount/interRequestDelayMs/addressAdjust`，缺省字段
     回填 `defaultConfig`）；TCP（`name/host/port/unitId/connectTimeoutMs/requestTimeoutMs/retryCount/
     autoReconnect/interRequestDelayMs`）；
   - 纯函数：`parseConnectionConfig`（→ `Result<ConnectionConfigFile>`，结构化 `MamepError`）、
     `createDefaultConnectionConfig`、`resolveConnection`/`resolveDefaultConnection`、
     `connectionToProfile`（→ 领域 profile，RTU 的 `port` 写入 `recentPortHint` 仅作提示）、
     `connectionConfigLoadError`。
   - **串口名 `port` 扩展边界**（对 ADR-017「串口选择是运行时状态、不持久化」的扩展）：`port`
     仅存在于**外部配置文件**的连接对象，`connectionProfiles` 持久化格式不变（仍不含串口名）。
   - **`slaveAddress` 语义**：连接对象的**默认从站地址**（可选字段，默认 1）；UI 载入时同步到
     当前表从站地址（走 `host.setSlaveAddress`），不改变「从站地址按表独立」模型（2026-08-19）。
2. **能力矩阵**：`PlatformCapabilities` 新增 `connectionConfig: "file" | "import" | "unsupported"`：
   - browser=`"import"`、electron/vscode=`"file"`、nodeHost/nodeTcpHost=`"file"`；联动全部断言
     （`apps/electron` ipc/preload/smoke、`apps/vscode-extension` ipc/webview bridge、e2e）。
3. **HostMessage v1 契约（platform-api）**：新增 request kind **`connection-config-load`**（payload 空，
   Zod 校验 + 白名单注册）；响应 `{ config: ConnectionConfigFile | null, sourcePath: string | null }`
   （未找到配置文件返回 `config:null`，可选能力非错误；读取/解析失败经 error 通道返回结构化错误）；
   `MamepHostApi`/`VscodeHostApi` 均暴露 `loadConnectionConfig()`。
4. **桌面端文件加载**：
   - Electron 主进程 `config-loader.ts`：候选路径 `MAMEP_CONNECTION_CONFIG` env > exe 目录
     （打包）/仓库根（dev）`config/connections.json` > 用户数据目录 `config/connections.json`；
   - VSCode Extension Host `config-loader.ts`：设置项 `mamep2026.connectionConfigPath` > 工作区根
     `config/connections.json` > 用户主目录 `config/connections.json`；
   - 均为纯函数（注入候选路径，可单测），经 `ipc.ts` 分发、preload/vscode-bridge 白名单桥暴露。
5. **UI（packages/ui）**：`ConnectionSettingsModal` 增加「Load from Config File」分组（能力矩阵
   `connectionConfig` 门控）：连接对象 Select（`activeConnectionId` 默认选中）→ `loadConnectionToSettings`
   预填表单（RTU 自动按 `port` 匹配 enumerated 端口并 `selectPort`、同步 `slaveAddress`；TCP 直接
   预填 host/port/unitId）；浏览器端增加「Import JSON…」按钮（`<input type=file>`）+ `?connectionConfig=`
   base64 URL 载入；关闭时照常 `extractPersistedSettings` 合并持久化。i18n en-US/zh-CN 补齐。
6. **Host 层（apps/web）**：`AppHost` 接口新增 `loadConnectionConfig()` / `importConnectionConfigText()`
   （浏览器实现：URL 参数 + 导入持有；桌面端桥接宿主）。`BrowserAppHost` 构造时解析
   `?connectionConfig=`；`ElectronAppHost`/`VscodeAppHost` 委托 `bridge.loadConnectionConfig()`。
7. **脚本消费**：新增 `scripts/lib/connection-config.mjs`（读 `config/connections.json` +
   `findConnection(id)`）；`scripts/prototype/electron-serial-probe.mjs` 主站连接参数（COM4/9600/8N1）
   改为从 `config/connections.json` 的 `rtu-com4-master` 读取。从站侧（`modbus-slave`）维持自身配置
   （从站语义，独立工具）；`dev-with-slave`/`serial-virtual-test` 的 COM5 仅注释/日志文本，不承载参数。
8. **MOCK/FAKE 保留边界（明确）**：`?mockTransport=1`（`import.meta.env.DEV` 门控，生产构建不含）、
   `MAMEP_FAKE_SERIAL=1`/`MAMEP_FAKE_TCP=1`（`extensionMode !== Production` 门控）保持为显式、可选的
   dev-only 手段；**默认路径（不带开关）即真实设备**，配置文件描述真实连接参数，与 MOCK 正交。
9. **文档同步**：本 ADR + `config/README.md`（字段说明/加载方式/生效时机/消费方/MOCK 边界）+
   TECH_DESIGN（能力矩阵表 + 连接配置文件章节）+ 根 AGENTS.md 进度段 + docs/AGENTS.md 实现状态。

## 备选方案

- **YAML 格式**：可读性更好但需新增 yaml 依赖与校验映射，三端统一性差，未选。
- **配置文件替代 connectionProfiles 持久化**：与 ADR-017 持久化边界（串口选择运行时状态）冲突大，
  且丢失自动保存/恢复体验，未选。
- **仅桌面端支持**：浏览器 Web Serial 已支持真实 COM 口，三端一致降低切换成本，故浏览器经
  导入/URL 也支持，未选。
- **热更新（文件监听）**：增加监听复杂度且浏览器端不可行；重连/重启重读已满足调试场景，未选。
