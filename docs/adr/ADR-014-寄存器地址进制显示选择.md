# ADR-014：Register 地址列进制（HEX/DEC）按表独立选择

- 状态：已确认
- 日期：2026-08-14
- 决策来源：用户指令（优先级最高）
- **修订（2026-09-13）**：决策 3 的**列头文案**由 `Register[DEC]` / `Register[HEX]` 泛化为 `Address[DEC]` / `Address[HEX]`（i18n 键 `table.addressDec` / `table.addressHex`；工具栏标签 `Address:`、aria-label `Address format`），原因是线圈 / 离散输入 / 输入寄存器等非保持寄存器表类型下「Register」不再准确。进制选择机制、按表独立、默认 DEC、解析/显示规则与提交链路均不变。详见 [docs/features/2026-09-13-列头Address化与侧边栏分组命名.md](../features/2026-09-13-列头Address化与侧边栏分组命名.md)。

## 背景

Register 地址列此前固定为十六进制显示与输入（ADR-013 #9 列规格 "Register[HEX]"；docs/AGENTS.md §16.6 "UI 显示为四位大写十六进制"）。不同用户习惯不同：有的习惯十六进制，有的习惯十进制。用户要求提供 HEX / DEC 选择，默认十进制，且选择仅作用于当前表格。

## 决策

1. **按表独立设置**：`RegisterSheet` 新增 `registerRadix: "dec" | "hex"` 字段，默认 `"dec"`（来自集中 `defaultConfig.registerTable.addressRadix`）。设置随工作区自动保存持久化，表与表之间互不影响；复制表（duplicateSheet）继承源表进制。
2. **默认十进制**：新建表、老数据缺省字段均默认 DEC。schema 用 `z.enum(["dec","hex"]).default("dec")` 向后兼容，`schemaVersion` 保持 1，免迁移。
3. **切换控件**：放在表格上方工具栏（`.table-toolbar`）的 `Segmented`（DEC | HEX）；列头文案动态显示 `Address[DEC]` / `Address[HEX]`（i18n 键 `table.addressDec` / `table.addressHex`；**2026-09-13 修订**：原为 `Register[DEC]` / `Register[HEX]`）。
4. **解析与显示规则**（`parseRegisterAddressDraft(text, radix)` / `formatRegisterAddress(value, radix)`）：
   - DEC：仅接受十进制数字，值域 0~65535，超范围报错（新错误码 `ADDRESS_OUT_OF_RANGE`）；提交保留去空格后的原文本（不补零）。
   - HEX：仅接受 1~4 位十六进制字符，**不接受 0x 前缀**（相对旧行为变更）；提交后自动补全为 4 位大写（如 `1f` → `001F`）。
   - 切换模式不重排已提交的 `addressDraft`（仅影响列头与后续输入解析）。
5. **提交链路**：`commitAddress(row, draft, radix)` 接收所属表的进制；store `commitRowAddress` 按 rowId 定位所属表取其 radix。

## 备选方案

- 全局单一进制设置（工作区级）：被否决，用户要求按表独立。
- 切换控件放表头单元格内：被否决，表头列宽有限，改为表格上方工具栏（用户已确认）。
- HEX 继续接受 0x 前缀：被否决，用户要求 HEX 仅 1~4 位十六进制。
- 切换模式时自动重排已提交地址文本：被否决，用户要求保持原始输入文本。

## 影响

- ADR-013 #9 中静态 "Register[HEX]" 列规格被本决策覆盖（列头随模式动态）。
- docs/AGENTS.md §16.6 已同步更新。
