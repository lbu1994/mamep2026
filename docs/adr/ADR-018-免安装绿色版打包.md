# ADR-018：Electron 免安装绿色版打包（win-unpacked 文件夹分发）

- 状态：已确认
- 日期：2026-08-22
- 决策来源：用户指令（MVP 阶段只需要"桌面能跑起来分发给同事"，产出一个一体化文件夹，不要求安装包）

## 背景

三端（浏览器 / Electron / VSCode）MVP 已具备 Electron 生产构建链路（ADR-016：`pnpm build:electron` 产出根 `dist-electron/main.js` + `preload.js` 与 `apps/web/dist-electron/` 渲染器产物；`pnpm start:electron` 直接运行）。但此前没有任何"分发给同事"的打包产物：electron-builder（26.15.3，根 devDependencies）无配置文件、无打包脚本。

用户目标（2026-08-22）：不需要安装包，只要求把运行所需文件放进一个文件夹，同事拷贝后双击即可运行（Windows x64，Electron 默认图标即可）。

调研发现 electron-builder 26.15.3 的两个问题：

1. **`@electron/get` 依赖声明 bug**：`app-builder-lib@26.15.3` 声明依赖 `@electron/get: ^3.0.0`，但其 `resolveCacheMode`（`out/util/electronGet.ts`）使用了 `@electron/get` **5.x 才导出**的 `ElectronDownloadCacheMode` → 打包时抛 `Cannot read properties of undefined (reading 'ReadWrite')`。本机 `@electron/get@5.1.0` 已存在（ESM-only、`engines: node >=22.12`，Node 24 的 `require(esm)` 可加载；`downloadArtifact`/`download`/`ElectronDownloadCacheMode` API 与 3.x 兼容）。
2. **workspace 根 production deps 被打进 app**：26 的 node 模块收集器会从 pnpm monorepo 根 `node_modules` 收集根 `package.json` 的 production dependencies（antd/react/serialport/zod 等 13 项）并复制进 app，导致体积 430MB+，且 serialport 原生模块可能触发 rebuild。主进程/渲染器产物均为 Vite 自包含（zod 等已 bundle），运行时**不需要**任何外部 npm 依赖。

## 决策

1. **产物形态**：用 electron-builder `--dir`（`win.target: ["dir"]`）产出 `release/win-unpacked/` 整个文件夹（含 `Mamep2026.exe` + dll + `resources/app/`），同事拷贝整个文件夹、双击 exe 即用；不产 NSIS 安装包、无需安装、无需 Node/pnpm 环境。
2. **staging 应用根**：新增 `scripts/package-electron.mjs`，把 `pnpm build:electron` 的自包含产物组装成 `release/staging-app/`——拷贝 `dist-electron/`（主进程 + preload）与 `apps/web/dist-electron/`（渲染器，保持 `main.ts` 依赖的 `__dirname` 相对结构），写一个**无 production dependencies** 的 `package.json`（`main: dist-electron/main.js`、`type: module`）；`electron-builder.yml` 的 `directories.app` 指向它。
3. **排除 node_modules**：`electron-builder.yml` 的 `files` 显式加 `!node_modules/**` / `!**/node_modules/**`（26 的收集器会应用 files 的排除模式）→ 最终 `resources/app/` 内只有 `dist-electron/`、`apps/web/dist-electron/`、`package.json`，无 node_modules。
4. **依赖覆盖**：`pnpm-workspace.yaml` 顶层加 `overrides: { "@electron/get": "5.1.0" }` 修复问题 1。**注意：pnpm 11 已不再读取 `package.json` 的 `pnpm` 字段**（会 WARN 忽略），overrides 必须放 `pnpm-workspace.yaml`。
5. **打包参数**：`asar: false`（`resources/app/` 以目录存放，结构透明便于排障，避免 asar+ESM 边缘情况）；`win.signAndEditExecutable: false`（跳过 rcedit/winCodeSign 下载，本机网络受限；exe 名仍正确为 `Mamep2026.exe`，图标/版本资源用 Electron 默认）。
6. **命令**：根 `package.json` 新增 `"dist:portable": "pnpm build:electron && node scripts/package-electron.mjs && electron-builder"`。

## 备选方案

- **直接在仓库根打包**（electron-builder 默认读根 package.json 的 `main` 与 dependencies）：被否决——根 `dependencies` 的 13 个 production deps 会被无条件打进 app，体积暴涨且 serialport 触发 rebuild；需大改根依赖结构（迁移到 devDependencies），影响面大。
- **升级 electron-builder 到 27**（master 分支已含 `declaredDependencies.length === 0` 跳过收集的逻辑与 `ignoredProductionDependencies`）：被否决——27 仍为 alpha、breaking 大、需网络下载，MVP 阶段成本过高；保留 26.15.3 + overrides 最小干预。
- **NSIS 安装包**（`win.target: ["nsis"]`）：MVP 不需要，留作后续升级路径。

## 理由

- 主进程（`dist-electron/main.js`）与渲染器（`apps/web/dist-electron/`）均为 Vite 自包含产物，运行时不需要任何外部 npm 依赖 → 完全符合"无 production deps 应用根 + files 排除 node_modules"的分发模型；
- staging 应用根把打包逻辑与仓库依赖结构解耦，不动根 `package.json` 的 dependencies（避免影响 monorepo 安装/测试/脚本）；
- `--dir` + `signAndEditExecutable: false` + 本机已有 Electron 43.4.0 二进制 → 全程零额外下载（本机网络受限，`raw.githubusercontent.com` 不可达）。

## 正面影响

- 一条命令 `pnpm dist:portable` 产出拷贝即用文件夹（实测 348.9MB，主要为 Electron 运行时与 Chromium）；
- `release/` 已加入 `.gitignore`，产物不进版本库；
- Playwright 可启动打包 exe 冒烟（`_electron.launch({ executablePath })` 断言 title/React 挂载/无 console 错误），打包产物可客观验证。

## 负面影响

- exe 图标/版本资源为 Electron 默认（`signAndEditExecutable: false`），暂未自定义名称图标；
- `asar: false` 使应用文件明文存放（内部工具分发场景可接受）；
- 当前仅 x64；32 位/ARM 或 macOS/Linux 分发需另行配置。

## 后续复审条件

- 需要自定义图标/签名时：提供 `.ico`，开启 `win.signAndEditExecutable`（或 `win.signExecutable`），并配 `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/` 下载 winCodeSign；
- 需要正式安装包时：`win.target` 改为 `nsis`，补图标/签名；
- 升级 electron-builder 时：确认 `@electron/get` 依赖声明已修复后移除 `pnpm-workspace.yaml` 的 overrides；
- 需要 32 位/ARM 或 macOS/Linux 分发时：分别配置 `arch` 与平台 target。
