# ADR-035：TCP 自动重连（有限次数 + 指数退避，Application 层协调器）

- 状态：已确认
- 日期：2026-08-30
- 决策来源：用户任务（PRD §8.3 P1「自动重连」；README 阶段二「TCP profile 字段已就绪、UI 灰显
  占位（部分完成）」推进到完成）；4 项用户决策：有限次数 + 指数退避、参数为内部默认值
  （defaultConfig）、UI = 状态点 + 最终失败提示、重连成功自动恢复轮询/追踪）

## 背景

- **PRD §8.3 P1**：自动重连。
- **PRD 343 行**：不自动反复连接，除非用户显式启用了重试或自动重连能力。
- **docs/AGENTS.md §11.4/§11.5**：连接状态机含 `reconnect-waiting`/`reconnecting`；用户主动断开后
  不得被自动重连逻辑再次连接；资源释放顺序含「停止自动重连」。
- **docs/TECH_DESIGN.md §9.4**：是否自动重连不由 Adapter 决定，而由 Application 层的连接策略决定；
  §10.1 状态机合法转换 `interrupted → reconnect-waiting → reconnecting → connected/failed`；
  §19.2 重连计时器不得持久化；恢复后保持离线、不自动连接。
- **ADR-022**：`autoReconnect` 为 P1 能力（UI 灰显禁用），profile 字段默认 false；
  `connectTimeoutMs`/`autoReconnect` 不入 TCP 表单。
- **既有资产**：`TcpConnectionProfile.autoReconnect` 字段（domain/workspace/platform-api 已就绪）；
  `ConnectionStateMachine` 已含重连状态；`ConnectionSettingsModal` 灰显 Switch + i18n 占位文案；
  `NodeTcpPlatformHost.openTcpTransport` 可反复重开传输；`SessionHostCore.connect` 成功后自动
  重建轮询/追踪协调器并恢复目标（重连成功自动恢复的基础）。

## 决策

1. **范围 = 仅 TCP（Electron 主进程 / VSCode Extension Host）**：浏览器端不实现 Modbus TCP
   （产品红线，PRD §8.6），RTU 不做自动重连。`TcpSessionHost` 装配协调器，`RtuSessionHost` 不涉及。
2. **重连策略 = 有限次数 + 指数退避**：默认最多 5 次尝试，间隔 1s→2s→4s→8s→15s（封顶）。
   策略参数为**内部默认值**，只进 `packages/domain/src/config.ts` 的 `defaultConfig.tcp`
   （`reconnectMaxAttempts: 5` / `reconnectBaseIntervalMs: 1000` / `reconnectMaxIntervalMs: 15000`），
   **不入 profile、不入表单、不持久化**——无工作区 schema 变更、无迁移、能力矩阵不变。
3. **分层落点（重连决策在 Application 层，TECH_DESIGN §9.4）**：新增 `ReconnectCoordinator`
   （`packages/application/src/reconnect-coordinator.ts`），由 `TcpSessionHost` 装配：
   - **armed**：TCP 会话连接成功且 `profile.autoReconnect === true`；
   - **disarm**：用户 `disconnect()` / 新 `connect()` / `dispose()`（generation 计数使挂起的
     等待与尝试失效——幂等、异常安全）；
   - **触发**：会话状态到 `interrupted` 且 armed → 重连循环：emit `reconnect-waiting` →
     指数退避等待（注入 `Clock` 计时，禁散落 `setTimeout`）→ emit `reconnecting` →
     注入 `openTransport` 重新打开传输 → 内部重连（重建 `CommunicationSession`，`Transaction ID`
     连接时重置，旧 pendingExchange 在 `SessionHostCore.connect` 断连旧会话时取消，避免旧请求
     污染新连接，TECH_DESIGN 1388）→ 成功回 `connected`（`SessionHostCore.connect` 自动恢复
     轮询/追踪）→ 失败按退避继续，达到上限转 `failed` + `app-message`（`messages.reconnectFailed`）。
   - 重连状态（`reconnect-waiting`/`reconnecting`/`failed`）经 `events.onStateChange` 通道推送 UI
     （宿主转发 `connection-state` 事件），`getState()` 供宿主 `getConnectionState()` 协调——
     不任意写状态字符串、不改会话内部状态机。
4. **传输重开工厂注入**：`TcpSessionHostOptions` 新增可选 `openTransport(profile)`（由平台宿主
   注入，包装 `NodeTcpPlatformHost.openTcpTransport` / `NodePlatformHost.openTcpTransport`）；
   缺省时 `TcpSessionHost` 不启用自动重连（`autoReconnect` 忽略）——Electron/VSCode 传参，
   既有构造（测试）不传即关闭。
5. **UI**：
   - `ConnectionSettingsModal` 的 autoReconnect `Switch` 从灰显改为受控启用（React Hook Form +
     Zod），接入 `settingsSchema`/`tcpPersistedSettingsSchema`/`toProfile`/`profileToValues`；
   - 提示：**状态点 + 最终失败提示**。状态点复用既有 Badge/connection-state 映射（
     `reconnect-waiting`/`reconnecting` 已存在）；中间尝试不打扰；最终失败经既有 `app-message`
     通道（BottomPanel）展示 `messages.reconnectFailed`（新 i18n 键，双语）；
   - i18n：`connection.autoReconnectHint` 文案更新（描述断线自动重连），新增 `messages.reconnectFailed`。
6. **无新增生产 HostMessage kind**：重连状态经既有 `connection-state` 事件推送、失败提示经既有
   `app-message`；能力矩阵不变；工作区 schema 不变。**唯一新增**为 dev/e2e 探针 kind
   `debug:fake-tcp-drop`（`HOST_REQUEST_KINDS` 白名单 + Zod + 穷尽守卫，仅 isDev 生效，
   对齐 `debug:get-state` 先例）：VSCode 端断开 `DevFakeTcpServer` 当前客户端（`MAMEP_FAKE_TCP=1`
   假设备），供 `tests/e2e-vscode` 真实 RPC 路径验证自动重连；Electron 主进程该探针恒返回
   `{dropped:false}`（假 TCP 设备在 Playwright 测试进程内，不驻留主进程）。

## 边界（明确不做）

- 浏览器端不实现 TCP/自动重连（红线）；RTU 不做自动重连。
- 重连参数不提供 UI 配置、不持久化（内部默认值，后续如需可配置再演进）。
- 不新增生产 HostMessage kind、能力矩阵不变、工作区 schema 不变、无迁移。
- 重连最终失败后的自动「停止重连」：等待用户手动重连，不再自动重试。

## 已知限制与后续复审条件

- 真机验证项（待后续）：真实设备断线（如设备重启/网线拔出）场景的端到端行为。
- `messages.deviceDisconnected` 文案偏「串口设备」（既有行为，RTU 语境），重连场景暂不改写。
