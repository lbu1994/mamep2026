# ADR-051：Binary 每 8 位分组显示 + 单元格提交/粘贴后规范化

- 状态：已确认并实施
- 日期：2026-09-11
- 决策来源：用户任务（ToDoList「寄存器表中二进制数据表示时每 8 位加一个空格分组」），经两轮澄清共确认
  9 + 6 项决策；本 ADR 记录「二进制分组显示」与随之扩大的「提交/粘贴后规范化」两项行为决策。

## 背景

- 现状 `Binary` 类型显示为**连续 16 位无分隔**字符串（`0000000000000101`），范围行（ADR-030）为各寄存器
  16 位**直接拼接**（32 位 = 32 个字符连排），人工核对位序困难。
- 现状 `parseBinary` **明确拒绝中间空格**（`^[01]+$`），而范围行的 `parseCompositeBinary` 已忽略任意空白——
  两者行为不对称，用户粘贴带空格的位串（Excel/文档复制）会在单寄存器行报 `DATA_BINARY_INVALID`。
- 现状 Data 单元格提交**保留用户原文**（`commitCellText` 头注释「成功提交保留用户原文，不规范化」），
  即「用户输入的文本」与「设备读回后的文本」可能是两种形式（小写 HEX、前导零、无空格二进制…），
  同一值在不同时间显示不同，易被误判为「值变了」。
- 现状地址列只在 HEX 进制补零（ADR-014），DEC 保留原文（含前导零）；粘贴路径 `pasteClipboardRows`
  直接采用剪贴板文本，不校验也不规范化。

## 决策（用户确认）

### 1. 二进制显示分组

- 单寄存器（16 位）：每 8 位一组、组间单空格 → `00000000 11111111`（2 组）。
- 范围行：宽度 = `registerCount × 16`，同样每 8 位一组 → 32 位 4 组、48 位 6 组、64 位 8 组；组间统一
  **单空格**（不额外强调寄存器边界；HTML 会折叠连续空格，双空格不可靠）。
- 分隔符形态固定：**不引入**寄存器间双空格/竖线等其它分隔。
- 列宽、换行、列固定等 UI 布局**不改**（64 位分组后 71 字符沿用既有 `nowrap` + 省略号）。

### 2. 二进制解析对称容忍

- 单寄存器与范围行**统一忽略任意空白**（空格/制表/换行）后校验字符集与位数。
- 位数上限仍按去空白后的位数判定（16 / `count×16`），超长仍 `DATA_BINARY_TOO_LONG`，**不静默截断**。
- 仍**不接受** `0b` 前缀（保持原决策）。
- 由此 `"10 1"` 由「非法」变为「合法（= 101）」，属**有意放宽**。

### 3. 提交后规范化（Data 列，**所有类型**）

提交（`commitCellText`）成功后，写回该类型的**规范显示形式**，即与设备读回后显示完全同源
（复用 `formatRawValue` / `formatRawValues` / `resolver.format`）：

| 类型 | 规范化形式 | 示例 |
| --- | --- | --- |
| hex（单） | 4 位大写、无 `0x` | ` ab ` / `0xAB` → `00AB` |
| unsigned | 十进制去 `+`、去前导零 | `0005` → `5` |
| signed | 十进制（16 位补码解释） | `+5` → `5` |
| 各 scale 类型 | 按类型固定小数位（不四舍五入，超精度仍报错） | `12` → `12.0` |
| binary（单） | 16 位、每 8 位一组 | `101` → `00000000 00000101` |
| binary（范围行） | `count×16` 位、每 8 位一组 | 2 寄存器 `1` → `00000000 00000000 00000000 00000001`（左侧补零） |
| hex（范围行） | 每寄存器 4 位大写、单空格 | `1234abcd` → `1234 ABCD` |
| unsigned/signed/scale（范围行） | 组合十进制（BigInt） | `65538` → `65538` |
| bool | `0` / `1` | 无可见变化 |
| string（单/范围行） | ASCII，补齐到 `2×count` 字符（可含尾随空格） | 单 `A` → `A `；2 寄存器 `AB` → `AB  ` |
| 插件 dataType | `resolver.format`（插件自定义；未注册格式化器沿用 hex 回退） | `12.5` → `12.5` |

- 校验失败路径**不变**：保留用户输入、红框 + Tooltip（docs/AGENTS.md §23）。
- 规范化**不做任何舍入/截断**：超范围/超小数位仍返回结构化错误。
- 范围行子行（ADR-031）本就以 `formatRawValue` 派生显示、父行文本以 `formatRawValues` 重算，天然规范化，
  无需额外改动。

### 4. 地址列提交后规范化（ADR-014 语义修订）

| 形态 | 规范化后 | 示例 |
| --- | --- | --- |
| HEX 单地址 | 4 位大写补零（原行为） | `ab` → `00AB` |
| DEC 单地址 | 十进制、**去前导零**（原「保留原文」→ 变更） | `0031` → `31` |
| HEX 范围 | `0400-0401`（两端各自补零） | `400-401` → `0400-0401` |
| DEC 范围 | `1000-1002`（两端各去前导零） | `01000-01002` → `1000-1002` |
| 空输入 | `""`（原保留原样空白） | `"   "` → `""` |

不变：值域 0~65535、HEX 仍拒绝 `0x` 前缀、范围 end<start 仍报错、校验失败保留输入。

### 5. 粘贴路径规范化

- `pasteClipboardRows` 对每行按其**自身 dataType + registerCount** 走同一规范化；
  成功写回规范文本，**失败保留原文、不新增 issue 类型**（维持 ADR-015「非法数据不静默丢弃」；
  错误在写入/编辑时按既有校验提示）。
- `registerValues` 维持粘贴即清零的既有语义（运行时状态不随剪贴板传递）。
- 粘贴地址字段统一改用 `formatRegisterAddressRange`（与提交路径同源）。
- 应用内剪贴板与系统剪贴板 CSV 两条来源共用同一路径；UI 侧注入 `dataTypeResolver`，
  插件类型同样可规范化。

### 6. 明确不做

- **工作区导入不规范化**（保持导入保真：`导出 → 导入 → 导出` 一致；旧文件的无空格二进制会在下次
  编辑/读取时才变为分组形式）。
- 提交后规范化**不改变**设备请求内容（写入仍按同一解析值组帧），不改变持久化 schema（
  仍存规范化后的 `cellText`，无需迁移；旧数据按既有时机自然规范化）。
- 不新增内置插件、不改能力矩阵、不改 HostMessage v1、不改列布局。

## 设计落位

- `packages/data-conversion/src/data-types.ts`：新增导出 `groupBinaryBits(bits)`；
  `formatRawValue("binary")` 使用分组；`parseBinary` 去空白后校验。
- `packages/data-conversion/src/multi-register.ts`：`formatRawValues("binary")` 复用 `groupBinaryBits`。
- `packages/register-table/src/cell-text.ts`：新增导出 `canonicalCellText(row, text, resolver?)`；
  `commitCellText` 成功写回规范文本。
- `packages/register-table/src/address.ts`：`commitAddress` 成功分支统一
  `formatRegisterAddressRange(value, count, radix)`；空输入规范为 `""`。
- `packages/register-table/src/row-clipboard.ts`：`pasteClipboardRows` 增可选 `resolver`，逐行规范化。
- `packages/ui/src/app-store.ts`：提交/粘贴调用点传 `dataTypeResolver`；`applyCellCommit` 的
  `after` 改用**规范化后文本**，避免「输入等价形式」被误判为值变化（`00AB` 手输 `00ab` 不置编辑完成态）。

## 影响与验证

- 单测：`data-conversion`（分组格式 + 容错解析 + 往返）、`register-table`（`canonicalCellText` 表驱动、
  地址 DEC 去零、粘贴规范化）、`ui`（store 提交规范化 / dirty 语义 / 子行二进制显示）。
- e2e-web：新增 `binary-grouping.spec.ts`（读回分组显示、带/不带空格提交、范围行父行 4 组 + 子行 2 组、
  无 console 错误）；`row-editing.spec.ts` 增「提交规范化」与「粘贴规范化」用例。
- 已知影响：提交/粘贴后单元格文本会按类型改写（小写 HEX 变大写、前导零被去、二进制加空格），
  属**有意的行为变更**；用户既有工作区数据不迁移。
