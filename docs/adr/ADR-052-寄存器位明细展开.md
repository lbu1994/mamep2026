# ADR-052：寄存器位明细展开（Binary 行 → 一行一 bit）

- 状态：已确认并实施
- 日期：2026-09-11
- 决策来源：用户任务（ToDoList「单个寄存器 Type 为二进制（Binary）时，可展开以『一行一个 bit』形式显示位明细」），
  经三轮澄清共确认 8 + 4 + 3 项决策；关联 ADR-030（范围行展开子行）、ADR-031（子行可编辑化）、
  ADR-032（撤销/重做边界）、ADR-051（二进制分组显示）。

## 背景

- MVP 起寄存器表以「一行一寄存器」呈现，Binary 类型的位意义只能靠人工对照二进制字符串逐位解析；
  嵌入式调试场景中「某一位是否置起」是高频诉求（如报警位、状态位）。
- 范围行（ADR-030/031）已建立「父行 → 派生虚拟子行」的成熟模式：`buildTreeRows()` 生成 antd Table
  树形 `children`；虚拟子行不落 store、不持久化、各列按 `isVirtualChildRow(row)` 分支渲染。
- 现状 `RegisterRow` 只有行级与「每寄存器」级元数据（`comment` / `registers[i].comment`），
  **没有位级元数据**；位级内容（位注释）无处存放。

## 决策（用户确认）

### 1. 展开范围（三层语义）

- **单寄存器行**（`registerCount === 1`）且 `dataType === "binary"` → 展开 16 行位明细。
- **范围行**（`registerCount > 1`）：父行**不**直接展开位；其**寄存器子行**（该寄存器自身 `dataType` 为
  binary）各自可再展开 16 行位明细（树形两层嵌套：父行 → 寄存器子行 → 位子行）。
- 非 `binary` 类型行不生成位子行；插件自定义 `dataType`（非内置 `binary`）不参与。

### 2. 位注释数据模型（工作区 schema v8 → v9）

- `RegisterRow` 新增 `bitComments: (string[] | null)[] | null`：
  - 外层 index = **寄存器序号**（单寄存器行长度 1；范围行长度 = `registerCount`）；
  - 内层长度固定 16，**下标 = bit 号**（0..15），显示时 bit15 在上（MSB first）；
  - 某寄存器 16 条全空 → 该元素存 `null`；整体全空 → `bitComments = null`（保持工作区精简、迁移零转换）。
- 不复用 `registers`（`RegisterSubRowMeta`）：该字段语义为「长度 = `registerCount` 的范围行子行元数据」，
  单寄存器行为 `null`，塞入 16 项位元数据会破坏既有长度不变量（`ensureRegisters`/迁移/校验均依赖）。

### 3. 位序与列呈现

- 位序 **bit15 → bit0**（高位在上）。

| 列                                                      | 位子行                                                                                                         |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| No                                                      | 空（留给树形缩进/展开图标）                                                                                    |
| TM / WP / Read / Write / Scale / 拖拽 / 多选 / 右键菜单 | 不可用（`null` 或禁用）                                                                                        |
| Name                                                    | **位名称（可编辑，语义同 Comment 列）**                                                                        |
| Register                                                | **寄存器地址 + Bit 序号（如 `2000 Bit 15`，按本表 HEX/DEC 进制格式化）；位掩码（如 `0x8000`）作为 hover 提示** |
| Data                                                    | `0` / `1` 文本（可编辑输入）+ 右侧独立「切换」控件；无当前值 `—`                                               |
| Comment                                                 | 位注释（可编辑，落 `bitComments[reg][bit]`）                                                                   |

### 4. 位值可编辑（写回当前值，不写设备）

- 位行 0/1 **可点击切换**，也可**文本输入** 0/1；两者都只更新该寄存器的**当前值**
  （`registerValues[i]` + 父行 `cellText`），**不触发任何设备写入**；是否写设备仍由用户按 Write 决定。
- 未读取（`registerValues === null`）时显示 `—`，切换/输入以「父行 `cellText` 派生，失败全 0」为基准
  （与 `commitChildCellText` 同语义），**不禁用**。
- 只读表（`discrete-input` / `input-register`）位明细**可展开查看**，但位值切换与位注释编辑**禁用**
  （与 `WriteCell` 既有只读守卫一致）。
- 位值切换**不入撤销栈**、不做「未写入」脏标记（与 ADR-032「Data 编辑/设备读值不入栈」一致）。

### 5. 位注释可编辑且入撤销栈

- 位注释视为**编辑字段**（同 `Name` / `Comment` / 范围行子行元数据），编辑后
  `snapshotSheet` + `pushSheetEntry` → Ctrl+Z / Ctrl+Y 可回退（ADR-032）。
- 落点：`RowEditFields` 增 `bitComments`（撤销/重做只回退编辑字段，读值不被回退）。

### 6. 展开入口与状态

- 复用 antd 表格树形「+」（与范围行一致，`children` 数据驱动），**默认收起**；
  **展开状态仅会话内、不持久化**（antd 内部展开态；类型切走时位子行消失，切回重新生成）。

### 7. Data 单元格交互（点击切换 vs 点击编辑共存）

- 文本区单击 → 进入编辑态（`EditableCellValue` 既有交互，可输入 `0`/`1`；非法输入保留草稿 + 错误提示）；
- 右侧独立切换控件（antd `Switch`，复用 `EditableCellValue` 的 `trailing` 插槽）→ 点击即切换；
  其 `onClick` 必须 `stopPropagation`，禁止同时触发外层「进入编辑」（已列为单测/e2e 断言项）。

### 8. 性能取舍

- 位子行仅在展开时生成（惰性 `children`），不落 store、不进剪贴板/导出/选择集/拖拽计数。
- 虚拟滚动降级条件由「存在范围行」扩为「**存在范围行或 binary 行**」
  （antd tree 数据与 `virtual` 不兼容，沿用 ADR-030 风险 1 回退先例；阈值 `> 500` 行）。

## 需求追加（2026-09-11，实施中追加，同一功能）

1. **位 Name 列可编辑**（用户要求「Name 列和 Comment 列一样，可以自行编辑」）：
   - 新增 `RegisterRow.bitNames`（结构、归一化、撤销、裁剪、payload 映射与 `bitComments` **完全对称**）；
   - UI 位 Name 单元格改用 `EditableCellValue`（`setBitName`，只读表禁用）；
   - 工作区 schema **v9→v10**（各 row 补 `bitNames=null`，**v9 的 bitComments 原值保留**；采用新增对称字段而非改写 v9 的 bitComments，以免动已通过全量 e2e 的数据形状与既有数据）。
2. **Register 列改显示「寄存器地址 + Bit 序号」**（用户要求「例如：2000 Bit 15」）：
   - 位行 Register 列 = `formatRegisterAddress(address, radix) + " " + t("table.bitLabel", {bit})`
     （`address` = 父行起始地址 + `registerIndex`，随表 HEX/DEC 进制）；
   - 位掩码（`0x8000`）不再占列，改为 Register 单元格 hover `title` 提示。

## 边界与异常（实现约定）

- Type 由 `binary` 切走 → 位子行即时消失；切回重新生成。
- 位子行 `rowId` 派生规则：单寄存器行 `"<rowId>:b<bit>"`；范围行子行 `"<rowId>:c<reg>:b<bit>"`。
- **位值/位注释编辑一律经「真实父行 rowId + `registerIndex`」路由**（`VirtualBitInfo.parentRowId`）：
  范围行寄存器子行 id（`<rowId>:c<i>`）是**派生的虚拟 id、不在 store 中**，早期版本误将其当作 store 行 id
  导致范围行位切换静默失效（单寄存器行两者相同、单测掩盖），2026-09-11 由 e2e `bit-detail.spec.ts` 捕获后修复
  （`registerRowId` 仅保留用于派生位行 key）。
- 位子行不参与 `rowSelection`、行拖拽（`SortableContext.items` 只含父行）、右键行菜单。
- 范围长度变化：`bitComments` 按寄存器序号保留/截断/补齐（与 `resizeRegisters` 同处调用）；
  缩小到单寄存器行时保留第 1 个寄存器的位注释（单寄存器行外层长度 1），位注释不因收窄而清空。

## 风险与回滚

- 风险：两层树 + 位行数量放大（32 位范围行最多 32 位行）、tree + virtual 不兼容（已按第 8 条降级）、
  「点击切换」与「点击进入编辑」手势冲突（`stopPropagation` + 测试断言）、
  v9 迁移影响面（纯增字段 + 缺省 `null`，旧版本 zod strip 忽略，**降级安全**）。
- 回滚：功能级 = `buildTreeRows` 不再为 binary 行生成 `children`（一处开关，字段与迁移保留无害）；
  完整回滚 = revert 批次提交（无需数据回退脚本）。
