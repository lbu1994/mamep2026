# ADR-030：多寄存器连续读写与范围行（Register 范围输入 + Type「进制 + scale」双列 + 范围行展开子行）

- 状态：已确认（**设计阶段，实施未开始**）
- 日期：2026-08-27
- 决策来源：用户任务（目标嵌入式产品的 Modbus 实现中，某些寄存器**不允许单读/单写**（会返回
  错误码），必须**连续读取/写入**才能正确访问，该特性已影响当前使用；必须多寄存器连续读写的
  典型场景=组成 32 位整数 / 64 位整数 / 字符串；产品提案=Register 列范围输入（如 `1000-1001`）、
  Type 拆「进制 + scale」两列、范围行展开；阶段 0 经用户确认 10 项产品决策；本 ADR 仅记录设计
  与范围，实施按 README 分阶段 ToDoList 顺序逐个进行）

## 背景

- 当前寄存器表仅支持**单寄存器**读取/写入（读=FC03 quantity 恒 1、写=FC0x10 单寄存器），但
  Modbus 功能码 03 / 0x10 本身支持一次请求读写多个连续寄存器。
- 目标嵌入式产品的 Modbus 实现中，某些寄存器**不允许单读/单写**（会返回错误码），必须连续
  读取/写入才能正确访问，该特性已影响当前使用。
- 必须多寄存器连续读写的典型场景：组成 32 位整数、组成 64 位整数、组成字符串。
- 现状（调研事实，2026-08-27）：
  - 协议读路径（RTU/TCP）已支持 quantity>1：`ReadHoldingRegistersRequest.quantity`、响应
    `values: number[]`、帧长按 quantity 计算；
  - 协议写路径仅有单寄存器：`WriteSingleRegisterRequest` / `encodeWriteSingleRegisterRequest`
    （硬编码 quantity=1 / byteCount=2）；
  - 通信层 `readRegister` / `writeRegister` 硬编码 quantity=1（`buildReadAttempt` /
    `buildWriteAttempt`）；`RtuFrameParser` / `TcpFrameParser` / `executeExchange` 已通用；
  - 批量读（BatchReadCoordinator）/ 轮询（PollingCoordinator）/ 追踪（TraceCoordinator）逐行
    单请求，无连续合并；
  - 写后回读（WriteVerifyCoordinator，ADR-029）单值 compare；`WriteOutcome` verify 字段为单 number；
  - 数据转换层纯 16 位（DataType 12 种），无 32/64 位、无字符串、无字节序处理（PRD §6.5.13
    明确列为未来项）；
  - 全部 mock/fake/从站（ScriptedModbusRtuDevice、MockTransport、modbus-core.mjs + RTU/TCP 从站、
    DevFakeSerial/DevFakeTcpServer、e2e inline responder）均假设 quantity=1；
  - 表格零 expandable/树形先例：行拖拽为自研 dnd-kit 单行实现，虚拟滚动依赖固定行高 29px，
    `tr[data-row-key]` 被 e2e 广泛使用。

## 决策（阶段 0，用户确认 10 项）

1. **类型表达模型**：组合宽度由「范围长度 + 进制 + scale」推导（2=32 位、4=64 位）；进制列
   新增「字符串」类型；**不引入**显式 INT32 / INT64 / FLOAT 复合类型枚举。
2. **展开展示**：范围行经 antd Table 树形数据（`children`）展开，每子行显示一个寄存器
   （地址 + 原始值，只读）。
3. **Type 拆列作用于所有行**：Type 列拆为「进制（HEX / Unsigned / Signed / Binary / String）+
   scale（1 / 0.1 / 0.01 / 0.001 / 0.0001）」两列；scale 仅对有符号/无符号十进制有意义。
4. **编辑与写入粒度**：父行与子行**互相动态绑定**（单一事实源=各寄存器原始值，父单元格=组合值）；
   **本期仅父行的写按钮可用**（点击后一次 FC0x10 写全部子寄存器），子行写按钮禁用；
   子行写功能留**后续阶段**（行为同普通单寄存器单行写）。
5. **64 位整数**：用 **BigInt** 完整支持（仅数据转换/显示层；持久化仍存各寄存器原始值，
   无 JSON 序列化问题）。
6. **落地范围**：三端（浏览器 / Electron / VSCode）全落地，共享分层实现。
7. **合法寄存器数**（跨字段校验，不满足在**进制列报错**并禁止该行读写）：整体默认 1；
   十进制（Signed/Unsigned）仅 1 / 2 / 4；二进制仅 1 / 2 / 3 / 4。
8. **十六进制**：允许任意数量。
9. **字符串**：ASCII 编码，每寄存器 2 字符。
10. **字符串长度**：任意（1~单行范围上限）。

## 设计（阶段 1，要点）

### 数据模型（domain / register-table / workspace）

- `RegisterRow` 新增 `registerCount: number`（默认 1，范围长度）；`addressValue` 保持=起始地址，
  范围=[start, start+count-1]。
- 新增 `registerValues: RawRegisterValue[] | null`（长度=count，**单一事实源**），替换
  `lastKnownRawValue`；`cellText` 仍为组合值显示文本（派生/编辑入口）。
- `dataType` 扩展 1 个枚举值 `"string"`（共 13 值）；进制/scale 由 dataType 推导
  （如 `signed-0.1` ⇔ (Signed, 0.1)）。
- schema **v2→v3 迁移**：`lastKnownRawValue` → `registerValues`、补 `registerCount=1`；
  迁移沿用 ADR-029 建立的 v1→v2 模式（`migrations.ts` + 迁移测试 + 断链检测）。
- 行操作（增删/移动/复制/重编号/剪贴板）在行级不变；**展开子行是派生的虚拟行，不持久化**。

### 地址范围（data-conversion / register-table）

- `parseRegisterAddressDraft` 支持 `start` 与 `start-end`（按表进制：HEX `0400-0401` /
  DEC `1000-1001`），输出 {start, count}；end≤65535。
- 跨字段校验「范围长度 × 类型合法集」（决策 7/8/10）→ 错误挂在**进制列**
  （`cellValidationErrors["${rowId}:type"]`），该行 Read/Write 禁用。

### 协议层（protocol-modbus）

- 读 FC03：已支持 quantity>1，无需改动；补充**上限守卫**（RTU 读≤125、写≤123；TCP 同 PDU 上限）。
- 写 FC0x10：新增多值请求类型（`values: number[]`）+ 编码器（fc 0x10、quantity=N、
  byteCount=2N、大端值）+ 写多响应解码（回执 address + quantity）+ `ExpectedResponse` 新 kind。

### 通信/会话层（communication / application / register-table）

- `CommunicationSession` 新增 `readRegisters(sentAddress, quantity, meta)`（返回 `number[]`）与
  `writeRegisters(sentAddress, values[], meta)`；`readRegister` / `writeRegister` 保留为
  quantity=1 包装（向后兼容）。
- `BatchReadRow` / `PollingTarget` / Trace 入口加 `quantity`；BatchReadCoordinator /
  PollingCoordinator / TraceCoordinator 透传；轮询/批量结果携带 `values[]`。
- `WriteVerifyCoordinator` 支持多值：FC0x10 写 N → 延迟 → FC03 读 N → **逐项 compare**；
  `WriteOutcome` verify 字段扩展为数组（`readValues` / `expectedValues`）。
- **单请求原子性**：FC03 / FC0x10 一次请求要么全部成功要么整体异常（协议级无「部分成功」）；
  错误/异常码沿用现有错误模型。
- Trace 对范围行采样**组合数值**（数值型）；字符串行 TM 复选框禁用。

### 数据转换层（data-conversion）

- 新增组合解释：`formatRawValues(values, dataType)` / `parseCompositeText(text, dataType, count)`。
- 32 位 = [hi, lo] 大端合并；64 位 = BigInt（`hi32<<32n | lo32`）；二进制 1/2/3/4 拼接位串；
  hex 任意数量 = 空格分隔 4 位大写组（解析兼容连续串）；字符串 = ASCII 每寄存器 2 字符。
- scale 作用于**组合十进制值**（沿用 §16.3 十进制定点运算，防浮点误差）。
- 字节序默认**大端**（高字在前，Modbus 惯例）；「字节序和字序配置」保持 P2 未来项（PRD §8.4）。

### HostMessage v1 契约（platform-api）

- **不加新 kind**：`registerRowPayloadSchema` 增 `registerCount` + `"string"`；
  `batchReadRowPayloadSchema` 增 `quantity`；`poll-result` 结果支持 `values[]`；
  `writeOutcomePayloadSchema` verify 字段数组化。
- 三端接线：AppHost.readRow / writeRow 已收**整行对象**天然透传；两端 ipc / preload /
  vscode-bridge 仅随 payload schema 更新，无新 kind / 穷尽守卫改动点。
- **能力矩阵不变**（多寄存器读写属协议层共享能力，三端同源，不新增能力字段）。

### UI（packages/ui RegisterTable）

- Type 列拆两列：进制 Select（i18n）+ scale Select（仅 signed/unsigned 可用），映射回 dataType。
- Register 列支持范围输入（`EditableCellValue` 模式扩展），提交后 `registerCount>1` 的行出现
  展开箭头。
- 展开：树形数据（children），子行=每寄存器一行（地址 + 原始值只读展示）；子行**不进
  SortableContext（不可拖拽）**、**不进 rowSelection（不可多选）**、读写按钮禁用（本期）。
- **整组拖拽**：父行拖拽即整组移动（子行为嵌套数据自动跟随）；`handleDragEnd` /
  `moveRowToIndex` 行级不变。
- 剪贴板：`RowClipboardData` 增 `registerCount`；CSV Register 编码 `start-end`（十进制）；
  解码支持范围；剪切/粘贴整组。
- 快捷键 / 右键菜单 / 多选对范围行按「整行」语义（子行不参与）。

### 测试基建（mock/fake/从站）

- 全部支持 quantity>1：ScriptedModbusRtuDevice、MockTransport + mock-scenarios、
  modbus-core.mjs + RTU/TCP 从站、DevFakeSerial / DevFakeTcpServer、e2e inline fake
  （FC03 返回多值、FC0x10 写多值并回显 quantity）。
- 新增「**must-multi**」区（如 0x0800）：单读/单写→异常码，多读/多写→正常——模拟真实设备
  行为，供 e2e 断言。

## 备选方案

- **显式复合类型（INT32 / INT64 / FLOAT / STRING 独立枚举）**：与「范围+进制+scale 推导」相比
  数据模型更复杂、与范围输入耦合更强、宽度语义两套并存；用户选推导模型（决策 1）。
- **动态子列展示**（同一行内展开成多列）：列数动态变化，布局/虚拟滚动复杂度高；用户选
  antd 树形数据子行（决策 2）。
- **Type 拆列仅作用于范围行**：单寄存器行维持单列 12 项下拉，两套 Type 交互并存；用户选
  所有行统一双列（决策 3）。
- **逐子寄存器编辑/写入**：与「必须连续写」产品约束冲突（单个子写会触发设备错误码）；
  用户选父行组合编辑 + 本期仅父行写（决策 4）。
- **64 位限制在安全整数范围**：超出 2^53 精度丢失；用户选 BigInt 完整支持（决策 5）。
- **仅浏览器先落地**：用户选三端全落地（决策 6）。

## 选择理由

- 范围+进制+scale 推导：与用户提案一致、数据模型最小、宽度由范围长度自然决定，且天然满足
  「范围长度 × 类型合法集」校验。
- antd 树形数据：优先使用框架既有 API（Table `children` / expandable）；子行为标准行（可保持
  29px 固定行高假设）；整组拖拽天然成立（父行移动子行跟随）。
- 单请求原子性：Modbus 协议语义即全有或全无，错误模型无需引入「部分成功」概念。
- 本期仅父行写：直接满足「必须连续写」的产品约束；子行写留后续阶段（需求已明确，行为同
  普通单行写）。
- 不加新 HostMessage kind：行对象已跨边界透传，仅扩展 payload 字段，三端接线成本最低。
- 能力矩阵不变：多寄存器属协议层共享能力，三端同源，无需新增平台能力字段。
