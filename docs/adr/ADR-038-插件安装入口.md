# ADR-038：插件安装入口（本地 manifest 注册，三端开放）

- 状态：已确认
- 日期：2026-08-30
- 决策来源：用户任务（PRD §8.3 P1「插件安装入口」；5 项用户决策：入口在插件管理弹窗内、仅单个
  manifest JSON 文件、仅清单注册不执行任何脚本、三端开放 + 能力矩阵新增 `pluginInstall` 字段、
  仅「用户自担风险确认」无签名/信任列表）

## 背景

- **PRD §8.3 P1**：插件安装入口。
- **PRD §6.10.2 MVP 插件要求**：识别已安装插件、启用/禁用、显示名称版本作者说明、展示加载失败
  原因、单个插件失败不得阻止应用启动、声明平台能力、不支持的平台插件不得被错误启用。
- **PRD §6.10.4 插件安全提示**：安装和启用第三方插件时必须明确提示——插件来源、版本、所需权限、
  可能访问的设备或文件能力、未受信任插件的风险。
- **PRD §15.3 安全性第 3 条**：插件安装和启用需要明确提示。
- **PRD §20.6 插件 MVP 边界（2026-08-23 已确认）**：MVP 仅预留架构、不对用户开放插件安装能力；
  本地安装、安川示例插件、插件开发文档均延后到 V1.0 评估。本任务即该 P1 项（本地安装入口）。
- **docs/AGENTS.md §24 插件开发规则**：插件不得直接修改核心源代码；通过稳定贡献点扩展；必须声明
  平台支持和权限；插件失败不得导致核心应用无法启动；浏览器不得加载 Host 插件；MVP 插件来源 =
  随应用构建的内置插件 + 开发模式下的受信任本地插件；**不得默认开放从互联网下载并执行任意第三方
  代码**。
- **既有资产**：`packages/plugin-api` 的 `PluginRegistry`（manifest Zod 校验 + 平台过滤 + 错误
  隔离 + 启停 + 事件订阅，纯内存）；`packages/ui` 的 `PluginManagerModal`（antd v6 展示已装插件
  与加载错误）；HostMessage v1 已有 `open-text-file`（桌面端打开对话框读文本）与
  `workspace-load/save/clear`（主进程文件仓储薄桥）先例；浏览器 IndexedDB KV
  （`createIdbKeyValueStore`）可复用于插件存储。

## 决策

1. **入口位置 = 插件管理弹窗内**：`PluginManagerModal` 新增「安装插件」按钮（footer/extra），
   不新增顶栏/设置入口，管理与安装集中一处（用户决策）。
2. **插件来源形态 = 仅单个本地 manifest JSON 文件**：用户选择本地 manifest JSON → 经
   `pluginManifestSchema` 校验 → 注册；不支持 zip/多文件（含脚本），架构为未来 zip 预留
   扩展位（用户决策）。
3. **安装 = 仅清单注册，不执行任何脚本**：UI-safe 纯 manifest 注册，零代码执行；浏览器端不加载
   Host 插件（§24.2），不从互联网下载执行任意第三方代码（§24.3）。安装前按 §6.10.4 弹窗明确
   提示来源、版本、所需权限、平台能力、未受信任风险，用户确认后才注册（用户决策）。
4. **平台范围 = 三端都开放 + 能力矩阵新增 `pluginInstall` 字段**：`PluginInstallCapability =
"file" | "upload" | "unsupported"`（形状对齐 `WorkspaceImportCapability`）——
   - 浏览器 `browserCapabilities.pluginInstall = "upload"`（客户端文件选择）；
   - Electron / VSCode `electronCapabilities`/`vscodeCapabilities` 的 `pluginInstall = "file"`
     （复用 `open-text-file` 对话框读取）。
   - 能力矩阵如实声明，UI 按能力门控（用户决策）。
5. **信任模型 = 仅「用户自担风险确认」**：无签名、无来源信任列表；安全确认弹窗即 §6.10.4
   要求的全部内容（用户决策）。
6. **持久化 = app 级独立存储，不并入工作区**：已安装插件（manifest + 启用状态）为应用级资产，
   非工作区数据——浏览器 IndexedDB KV（`createIdbKeyValueStore` 的独立 key）、Electron
   userData `plugins.json`（原子保存 + 单份 .bak，复用 `WorkspaceFileRepository` 模式）、VSCode
   `context.globalState`；工作区导入导出不带插件，无 workspace Schema 迁移。
7. **内置插件与用户安装插件分离（`source` 标记）**：`PluginRegistry.register(input, { source:
"builtin" | "installed" })`，默认 `builtin`；持久化只落 `installed` 源插件（内置示例插件
   `registerExamplePlugin` 每次启动注册、不持久化，避免重启重复注册报
   `PLUGIN_ALREADY_REGISTERED`）。
8. **跨边界 = HostMessage v1 新增 `plugin-store-load` / `plugin-store-save` 两个 request kind**
   （Zod 校验 + kind 白名单 + preload/vscode-bridge 桥 + 两端 ipc 穷尽分支）：
   - `plugin-store-load`（无 payload）→ `{ plugins: Array<{ manifest, enabled }> }`；
   - `plugin-store-save`（payload = `{ plugins: [...] }`）→ void。
   - Electron 主进程 `PluginFileStore`、VSCode Extension Host globalState 存储、浏览器直接
     IndexedDB；错误经 `sessionResult` 原样往返（category/userMessageKey，ADR-028 不回归）。

## 影响与边界

- **不影响**：协议层 / 调度器 / 工作区 Schema / 会话逻辑零改动；不新增事件 kind。
- **范围外（明确排除）**：插件市场/联网下载、zip 多文件、任何第三方脚本执行、签名/来源信任
  列表、per-plugin 配置 UI（仅 manifest 注册 + 启用状态）。安川示例插件、插件开发文档为独立
  P1 待办，不在本 ADR 范围。
- **测试**：plugin-api（注册 source/snapshot/hydrate/持久化协调器）、domain（能力矩阵）、
  platform-api（新 kind 白名单/校验/往返）、Electron/VSCode/浏览器三端（存储实现 + ipc 分支 +
  桥 + 宿主装配）、ui（安装流程/安全确认/错误/i18n）、e2e-web（安装/坏文件/安全确认/取消/
  重启持久化/无 console 错误）。

## 后续复审条件

- 插件第三方代码隔离机制（docs/AGENTS.md §35 待确认项）落地前，安装入口维持「仅清单注册」。
- 如需 zip 包 / Host 级代码加载，须另立 ADR 并先确认安全模型。
