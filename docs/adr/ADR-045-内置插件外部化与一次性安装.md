# ADR-045：内置插件外部化（随应用分发·一次性安装）与「禁止新增内置插件」规范

- 日期：2026-09-02
- 状态：**部分被取代（2026-09-12，ADR-054）**——「随包插件一次性安装」（`seeded` / `markSeeded` / `attachRuntime` / `restoreBundledPlugin` / `bundledPlugins` / Plugin Manager「Restore bundled」）已删除，
  插件一律由用户手动安装，同步能力改由安装时「同进程执行」授权提供（见 [ADR-054](ADR-054-删除随包插件机制与插件同进程执行.md)）。
  本文保留为历史决策记录；仍有效部分：插件一律置于 `plugins/` 目录、**禁止新增内置插件**、安川命令写移入插件。
- 关联：ADR-038（安装入口）/ ADR-039（插件功能设计）/ ADR-041（安川 Phase C）/ ADR-042（Phase D 主题色 + Address Adjust）/ ADR-043（Phase E）/ ADR-044（Phase F 可执行插件正式化）/ ADR-054（取代随包机制）

## 1. 背景与动机

- README 待办「内置插件移出为独立插件（example-panel / yaskawa / custom-function-code / builtin-address-adjust）」自 ADR-044 起挂在 Phase F 已知限制之后。
- 现状：4 个内置插件以 `source:"builtin"` 注册（`apps/web/src/App.tsx` 内联 example-panel / builtin-address-adjust；`plugins/` 下 yaskawa / custom-function-code 虽已独立成包但仍是 builtin 来源），且存在核心残留：
  - `packages/register-table/src/address.ts` 内建 `BUILTIN_ADDRESS_ADJUST_TRANSFORM` / `resolveBuiltinAddressTransform` / `computeSentAddress`；
  - `packages/ui/src/plugin-toolbar-actions.ts` 硬编码安川 ROM/RAM 命令写（0900H/0910H，Phase C 决策③④）。
- 目标：把所有内置插件功能移出到 `plugins/` 目录作为外部插件；从今往后**严禁新增内置插件**（除非用户明确强调）；更新文档与受影响的测试。

## 2. 用户决策（2026-09-02）

1. **来源模型：全部改为 `source:"installed"` + 放宽 runtime 限制**。`PluginRegistry.register` 不再按来源拒绝同进程 `runtime`——随应用分发的受信插件保持同进程同步运行时（可贡献 codec/dataType/transform 等同步纯函数）；用户安装入口（PluginManagerModal）不提供 runtime → 第三方代码仍仅经 `remoteRuntime` 隔离线程（ADR-044 安全边界不变）。
2. **一次性安装（无「预装」概念）**：插件（同步/异步一起）都是 install 一次。随包插件在**首次启动时自动安装**（register + 持久化 manifest/启用状态 + `seeded:true`），此后与用户安装插件完全等同——可禁用、可卸载（卸载=从存储删除，重启不再出现）、可恢复（Plugin Manager「Restore bundled」）。重启后经 hydrate 恢复注册，装配方按代码清单**重建同进程 runtime**（`attachRuntime`，恢复同步能力）。
3. **保留现名**：插件 id `builtin-address-adjust` / transformId `builtin.address-adjust` 不变 → 工作区数据/持久化/测试零迁移（文档注明 builtin 仅为历史命名）。
4. **安川命令写一并移入插件**：扩展 `PluginRuntime.handleToolbarAction()`；`toolbarAction` 贡献点 schema 增 `confirmKey`；`packages/ui` 硬编码的 `COMMAND_REGISTER`/`hasBuiltinCommandWrite`/`buildCommandWriteRow` 删除，执行改为 `PluginRegistry.invokeToolbarAction(pluginId, actionId)` 经插件通信面（PluginCommunicationApi，走统一调度器）写 0900H/0910H。

## 3. 迁移映射

| 插件 | 之前 | 之后 |

## 4. 分层落位

- **plugin-api**：
  - `PluginRegistryOptions.communicationApiFactory`（按 pluginId 动态通信面，同进程 runtime 的 ctx.communication 经统一调度器）；
  - `register()` 允许 `installed` + 同进程 `runtime`（注释说明受信随包路径；`remoteRuntime` 仍仅 installed）；
  - `attachRuntime(pluginId, runtime)`（重启后重建同进程 runtime，仿 attachRemoteRuntime）；
  - `canHandleToolbarAction` / `invokeToolbarAction` + 错误码 `PLUGIN_ACTION_NOT_HANDLED`；
  - `PluginRuntime.handleToolbarAction(actionId, ctx)`；`TOOLBAR_ACTION_ITEM_SCHEMA` 增 `confirmKey`;
  - `PluginStoreData` **schemaVersion 2→3**：新增 `seeded: boolean`（随包插件一次性安装标记；manifest 随代码包，仍入库为普通 installed 条目）；`migratePluginStoreData` v2→v3 补 `seeded:false`（升级后首次启动自动安装随包插件）。
- **plugins/ 包**：`createXxxRuntime(deps)` 工厂（App 装配层在首次安装与重启恢复复用）导出 + `registerXxxPlugin(registry, deps)`（source installed）；example-panel 无 runtime。
- **应用装配层**：
  - `AppHost`（packages/ui host.ts）新增 `startPlugins()` / `restoreBundledPlugin()` / `restoreAllBundledPlugins()`；
  - `BrowserAppHost.startPlugins()`：无存储端口→内存注册；首次（`isSeeded()===false`）→注册全部随包插件 + `markSeeded()` + flush；重启→hydrate 后按清单 `attachRuntime`；随后 `restoreRemotePluginRuntimes()`（用户安装的可执行插件）；
  - `AppHostOptions.bundledPlugins`（`BundledPluginEntry { pluginId, manifest, createRuntime }`）+ `resolveAddressTransform`；
  - `ElectronAppHost` / `VscodeAppHost` 薄门面透传 + 委托；
  - `apps/web/src/App.tsx`：删除内联注册；创建 `transformRegistry` / `dataTypeResolver` 经闭包注入 bundled entry；`buildPollingTargets` / `applyPollResult` 传 `resolveAddressTransform`（经随包插件注册表解析，核心不再内置）。
- **核心残留清理**：
  - `packages/register-table/src/address.ts`：删除 `BUILTIN_ADDRESS_ADJUST_TRANSFORM` / `resolveBuiltinAddressTransform` / `computeSentAddress`；`resolveSheetAddressTransform` 默认 resolver 改为 `() => null`；
  - `packages/application/session-host-core.ts`：默认 `resolveAddressTransform` 改为 `() => null`（宿主注入）；
  - `packages/ui/plugin-toolbar-actions.ts`：删除厂商地址硬编码，改为代理 `registry.invokeToolbarAction`；
  - `packages/ui/RegisterTable.tsx`：动作可用性 = `canHandleToolbarAction`；确认文案 = 贡献点 `confirmKey`；
  - `packages/ui/PluginManagerModal.tsx`：footer 增「Restore bundled」；随包插件（installed）显示 Installed 标签 + 卸载按钮（与用户安装一致）。
- **桌面端**：
  - `apps/vscode-extension` / `apps/electron`：会话宿主注入 `resolveAddressTransform`（host 端直接引用随包 `@mamep2026/address-adjust` 导出的 resolver——app 层依赖插件包，合法方向）；VSCode Extension Host codec 装配（`MemobusCodec` import）保持不变（app 装配依赖，宿主同步能力）。
  - package.json 依赖：`apps/web` + example-panel/address-adjust；`apps/vscode-extension` / `apps/electron` + address-adjust。

## 5. 能力矩阵 / 协议

- 能力矩阵 `protocolExtensions` / `tableTypes` 数值不变（随包插件仍开箱即用）；`executablePlugins` / `hostPlugins` 不变（第三方隔离执行语义不变）。
- HostMessage v1 协议零改动：不新增/修改 kind；`plugin-store-load/save` payload schema（platform-api session-payloads）随 `PluginStoreData` v3 同步 `seeded` 字段（结构对齐，非行为变更）。

## 6. 验证

- 单测：plugin-api（registry 同进程 runtime/attachRuntime/invokeToolbarAction、plugin-store v3 迁移、plugin-persistence seeded）、plugins 四包（示例面板/地址调整/安川 handler/custom）、register-table（注入式 resolver）、application（host 注入 resolve）、ui（工具栏动作代理、PluginManager 恢复按钮、i18n）、两端 ipc/preload/bridge（payload v3）。
- e2e-web：plugin-install（随包插件显示卸载按钮、坏文件断言按目标名）、plugin-exec、address-adjust、theme-color 等回归。
- 未执行：本次按用户要求不做测试（手动）。

## 7. 已知限制

- 随包插件 manifest 在首次安装时入库：后续插件包升级版本不会自动刷新 store 中的 manifest（重启以 store 为准；「恢复」时用代码清单 manifest 重新写入）。如需随包插件升级策略，另立 ADR。
- `PluginRuntime.handleToolbarAction` 仅同进程 runtime 支持（installed 预装/受信路径）；用户安装的第三方插件仍只走 `remoteRuntime`（当前通信面不含动作执行，另行归档）。
