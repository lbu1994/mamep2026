# ADR-033：工作区导入和导出（版本化 JSON 公开交换格式 + `open-text-file` kind）

- 状态：已确认
- 日期：2026-08-29
- 决策来源：用户任务（PRD §8.3 P1「工作区导入和导出」§20.7 待确认项按已确认设计执行；
  3 项用户决策：入口放 Settings 弹窗、交换格式直接导出不裁剪、连接态导入提示先断开）

## 背景

- **PRD §8.3 P1**：工作区导入和导出。
- **PRD §20.7** 待确认项：是否需要导出配置文件 / 是否支持 CSV / 是否支持完整工作区文件 /
  是否允许跨三端导入 / 是否保存连接信息 / 是否排除设备敏感信息 / 文件格式是否长期维护。
- **TECH_DESIGN §46 导入导出扩展预留**：区分「内部持久化格式」与「公开工作区交换格式」；
  公开交换格式应避免包含本机绝对路径、临时连接 ID、串口授权对象、未声明的插件内部状态、
  运行时错误、Timer 与任务状态；CSV 导入导出不应直接成为领域数据源（属 P2，不在本次范围）。
- **TECH_DESIGN §6**：版本化 JSON 更适合跨端导入导出和人工诊断。
- **既有资产**：`packages/workspace` 已有 `workspaceSchema` + `serializeWorkspace` /
  `parseWorkspace`（Zod 校验 + v1→v4 迁移 + 断链检测）；日志导出（2026-08-28）已建成
  `save-text-file` kind + `logExport` 能力位 + 三端落盘实现；`connection-config-load` kind
  - `connectionConfig` 能力位（桌面端读文件 / 浏览器导入）。

## 决策

1. **交换格式 = 版本化 JSON，直接复用 workspaceSchema**：导出 = `serializeWorkspace(workspace)`
   （含 schemaVersion 4），导入 = 读文本 → `JSON.parse` → `parseWorkspace`（复用 Zod 校验 +
   v1→v4 迁移 + 断链检测）。不另写序列化。公开交换格式与内部持久化格式同构；workspaceSchema
   本就排除运行时状态（连接句柄/Timer/任务），不包含本机绝对路径与串口授权对象，满足 §46
   排除清单；`recentPortHint`（RTU 端口名提示）仅作提示字段保留，用户确认不裁剪。
2. **入口 = Settings 弹窗**（与「Reset Workspace」同级）：antd Button + Tooltip + 图标
   （`DownloadOutlined` / `UploadOutlined`），i18n 双语。导入流程：读取 → 解析 → 预览
   Modal（工作区名 / 表数 / 行数 / 连接数 / schemaVersion 摘要 + 覆盖风险提示，含「建议先
   断开连接」）→ 确认 → `setWorkspace` 替换（清空撤销栈，语义对齐 ADR-032）→ 自动保存
   （App 层 workspace 变更订阅触发）。解析失败 message + 底部消息报错，当前工作区不被破坏。
3. **新 HostMessage v1 kind `open-text-file`**（桌面端导入读文件）：request payload 可选
   `{ suggestedName? }`（默认文件名/目录提示），response `{ content: string | null }`
   （null = 用户取消，非错误，对齐 `save-text-file` 的 `saved:false` 语义）。Zod 校验 +
   `HOST_REQUEST_KINDS` 白名单 + preload / vscode-bridge 桥 + 三端 ipc 分发。
   - Electron 主进程：`dialog.showOpenDialog`（JSON 过滤）+ `fs.readFile`（utf-8）；
   - VSCode Extension Host：`window.showOpenDialog` + `workspace.fs.readFile`（utf-8 解码）；
   - 浏览器：不走本 kind——UI 用隐藏 `<input type="file">`（客户端读取，浏览器原生能力），
     `BrowserAppHost.openTextFile` 按能力矩阵返回能力错误。
4. **导出复用 `save-text-file`**（不新增 kind）：`suggestedName = workspaceExportFileName(name)`
   （`mamep-workspace-<name>-<YYYYMMDD-HHmmss>.json`，`packages/workspace/src/exchange.ts` 纯函数
   做文件名安全清洗），`mimeType: "application/json"`；浏览器 Blob 下载 / 桌面端保存对话框。
5. **能力矩阵**：新增 `workspaceImport`（`"file"|"upload"|"unsupported"`）与 `workspaceExport`
   （`"save-dialog"|"download"|"unsupported"`），命名风格对齐 `logExport`/`connectionConfig`。
   Electron/VSCode = `file`/`save-dialog`；浏览器 = `upload`/`download`；node 宿主 = unsupported。
6. **分层**：序列化/解析/迁移/文件名纯函数在 `packages/workspace`（UI 直接调用纯函数）；
   平台文件读写经 `AppHost` 端口（`saveTextFile`/`openTextFile`）+ HostMessage；UI 不直接
   访问文件系统（浏览器端 Upload 属于浏览器原生能力，允许）。

## 实现要点

- `packages/workspace/src/exchange.ts`：`workspaceExportFileName` / `sanitizeWorkspaceNameForFile`
  （纯函数 + 单测）；roundtrip 单测（serialize → parse 字段不丢）。
- `packages/platform-api/src/host-message.ts`：`open-text-file` kind 白名单 + Zod +
  `openTextFileResponseSchema`；`vscode-bridge.ts` 桥。
- 三端接线：Electron `main.ts`/`ipc.ts`/`preload.ts`、VSCode `extension.ts`/`ipc.ts`/bridge、
  浏览器 `AppHost.ts`；渲染端 `electron-app-host.ts`/`vscode-app-host.ts` 委托 + 单测。
- `packages/ui`：`host.ts` 端口、`app-store.ts`（`workspaceImportDraft` + `applyWorkspaceImport`
  清栈语义）、`WorkspaceFileActions`（按钮 + 处理器 + 隐藏输入，渲染于 Settings 弹窗内，
  可用 `App.useApp()` message）、`WorkspaceImportModal`（预览/确认）；i18n 双语键。
- e2e：`tests/e2e-web/tests/workspace-import-export.spec.ts`（5 用例：导出下载内容/roundtrip/
  预览取消/坏文件/无 console 错误）；`tests/e2e-electron/tests/workspace-import-export.spec.ts`
  （RPC 闭环：save-text-file 落盘 + open-text-file 读取 + 取消语义 + roundtrip + 无 console
  错误，主进程对话框经 `electronApp.evaluate` 桩替换）；`tests/e2e-vscode` run.test.ts
  `runWorkspaceFileLoop`（完整闭环：open 读回 + save 落盘 + 取消语义，经 `MAMEP_FAKE_DIALOG=1`
  门控扩展宿主假文件对话框 `apps/vscode-extension/src/dev-fake-dialog.ts`，与 MAMEP_FAKE_SERIAL/
  TCP 同模式——测试宿主与扩展宿主跨进程无法桩替换 vscode.window 对话框，故由扩展宿主在 isDev
  门控下把 save/open 对话框替换为固定路径读写，run-e2e.mjs 注入环境变量暴露路径）。

## 后续事项

- 寄存器表 CSV 导入导出为 P2（PRD §8.4，§46 要求解析→校验→导入预览），不在本次范围；
- 连接态导入为「提示先断开」策略（不静默断开、不拒绝导入），预览确认文案已含提示；
- 跨三端 roundtrip 已由各端导出文件互导验证（浏览器导出 → Electron/VSCode 导入同构）；
- **系统对话框自动化边界（2026-08-29 落实方案 A）**：真实系统对话框（Electron/VSCode 的
  save/open 原生框、macOS/Linux 行为、打包后）仍属人工验收项；自动化覆盖到「端口边界」为止——
  浏览器（file input + Blob 下载）、Electron（主进程 `electronApp.evaluate` 桩）、VSCode
  （`MAMEP_FAKE_DIALOG=1` 门控假对话框）三端均可确定性自动化导入导出闭环。
