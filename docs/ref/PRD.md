# Mamep2026 产品需求文档（PRD）

- 文档版本：V1.0
- 产品名称：Mamep2026
- 产品类型：跨平台 Modbus 开发调试工具
- 目标平台：浏览器、Electron 桌面客户端、VSCode 插件、Android 客户端
- 开发模式：核心通信与协议在用户要求测试时采用测试驱动开发 / 验收测试驱动；测试执行时机由用户决定
- 文档状态：初始规划
- 需求来源：M@MEp2006 使用体验研究及现有 Modbus 工具痛点分析

# 1. 文档定位

本文档用于定义 Mamep2026 的产品目标、用户范围、功能需求、版本优先级、交互原则、技术选型约束、产品边界和验收方向。

---

# 2. 产品概述

## 2.1 产品简介

Mamep2026 是一款面向设备开发人员和嵌入式开发人员的轻量化、现代化、可扩展 Modbus 开发调试工具。

产品借鉴 M@MEp2006 高效的单表格寄存器调试方式，在保留“不连续寄存器集中管理、单行独立读写、批量读取、周期轮询”等核心体验的同时，重新设计现代化用户界面，并支持以下四种部署形态：

1. 浏览器在线工具；
2. Electron 桌面客户端；
3. VSCode 插件；
4. Android 客户端。

Mamep2026 同时支持 Modbus RTU 和 Modbus TCP，并根据不同运行环境的能力边界进行差异化适配：

| 客户端          | Modbus RTU | Modbus TCP |
| --------------- | ---------: | ---------: |
| 浏览器端        |       支持 |     不支持 |
| Electron 客户端 |       支持 |       支持 |
| VSCode 插件端   |       支持 |       支持 |
| Android 客户端  |       支持 |       支持 |

产品主要面向开发人员自用和研发调试场景，不作为工业生产控制系统、功能安全系统或无人值守设备监控系统使用。

## 2.2 产品愿景

打造一款比传统 Modbus 工具更容易使用、比 M@MEp2006 更现代、比单一桌面工具更灵活，并且适合 AI 驯化、生成和持续迭代的跨平台调试工具。

## 2.3 核心价值

1. 使用一张表管理任意不连续寄存器，不需要为每个地址创建独立窗口；
2. 各端保持一致的核心操作逻辑，降低环境切换时的学习成本；
3. 修复 M@MEp2006 无法正常使用 COM10 以上串口的问题；
4. 同时覆盖在线快速调试、桌面深度调试和 VSCode 内嵌调试场景；
5. 通过插件机制隔离通用开源能力和设备厂商私有能力；
6. 采用现代化界面，移除老式 Windows 顶层菜单和过时控件；
7. 采用主流、成熟、AI 熟悉度高的技术体系，降低 Vibe Coding 的生成和纠错成本；
8. 通过测试驱动和验收测试驱动方式保障核心通信功能质量。

## 2.4 产品目标

1. 提供单表格、不连续寄存器集中调试能力；
2. 三端实现一致的 Modbus RTU 核心调试能力；
3. Electron 和 VSCode 端支持 Modbus TCP；
4. 正确识别和使用 COM10 及以上串口；
5. 支持保持寄存器的读取与写入；
6. 支持单行读取、单行写入、全表读取和周期轮询；
7. 支持配置、标签页和寄存器表内容的会话恢复；
8. 提供通信日志、运行消息和当前通信参数查看能力；
9. 提供插件化扩展边界，避免把私有协议写入核心产品；
10. 保持三端的数据模型、操作概念和主要界面结构一致。

# 3. 目标用户

## 3.1 核心用户

### 3.1.1 嵌入式软件开发人员

主要任务：

- 调试设备的 Modbus RTU 或 Modbus TCP 通信；
- 验证寄存器地址、数据格式和读写行为；
- 同时观察多个不连续寄存器；
- 检查原始请求、响应和异常报文；
- 在固件开发过程中快速修改设备参数。

核心诉求：

- 操作直接；
- 不需要频繁切换窗口；
- 原始报文透明；
- 支持串口和网络两种连接；
- 能在 VSCode 中完成基本调试。

### 3.1.2 设备应用开发人员

主要任务：

- 配置设备参数；
- 验证设备协议实现；
- 根据寄存器清单进行批量调试；
- 保存不同设备或场景的寄存器表。

核心诉求：

- 表格配置易于保存和恢复；
- 支持多个标签页；
- 支持备注和多种数值显示格式；
- 能快速复制已有寄存器配置。

### 3.1.3 通信协议开发和测试人员

主要任务：

- 验证不同串口配置；
- 检查通信异常、超时、重试和校验行为；
- 比较读写前后的设备数据；
- 定位 Modbus 异常码和报文格式问题。

核心诉求：

- 完整日志；
- 清晰的错误分类；
- 可配置超时、重试和写后回读；
- 能查看实际下发和接收的原始数据。

## 3.2 次要用户

1. 现场调试工程师；
2. 测试工程师；
3. 自动化设备方案开发人员；
4. 需要临时在线调试串口设备的开发者；
5. 需要通过插件支持厂商私有扩展的设备开发团队。

## 3.3 不作为主要目标的用户

1. 没有通信协议基础的普通消费者；
2. 需要工业生产级权限和审计能力的运维人员；
3. 需要长期无人值守监控的工厂操作人员；
4. 需要完整组态和可视化大屏的 SCADA 用户；
5. 需要功能安全、防误写联锁和认证体系的安全关键系统用户。

# 4. 典型使用场景

## 4.1 浏览器快速调试

用户通过浏览器打开 Mamep2026，授权访问本地串口，配置波特率等参数后连接 Modbus RTU 设备，在寄存器表中读取、写入和周期监控设备数据。

适用场景：

- 临时调试；
- 无法安装桌面软件；
- 展示或培训；
- 快速验证串口设备。

限制：

- 不支持 Modbus TCP；
- 串口能力受浏览器和操作系统支持情况限制；
- 用户必须主动授权串口访问。

## 4.2 Electron 桌面深度调试

用户安装桌面客户端，通过串口连接 Modbus RTU 设备，或通过 IP 地址和端口连接 Modbus TCP 设备，使用完整寄存器调试、日志、会话恢复和插件能力。

适用场景：

- 日常设备开发；
- 多串口环境；
- 完整日志分析；
- 私有协议插件扩展；
- 长时间调试。

## 4.3 VSCode 内嵌调试

用户在开发固件或上位机程序时，通过 VSCode 侧边栏、编辑区或面板打开 Mamep2026，无需离开开发环境即可读取和修改设备寄存器。

适用场景：

- 固件编码和设备调试同步进行；
- 在项目工作区中保存调试表；
- 开发、测试和问题定位一体化。

## 4.4 不连续寄存器集中监控

用户在同一个表格中配置多个不连续地址，例如 0001、0100、0900 和 F100，分别定义名称和数据显示类型，然后通过单行读取、全表读取或周期轮询查看数据。

系统不要求寄存器地址连续，也不要求用户为不同地址创建多个窗口。

## 4.5 多设备或多场景配置

用户为不同设备、功能模块或调试阶段创建多个寄存器表标签页。关闭并重新打开应用后，系统恢复标签页、寄存器内容和通信参数。

# 6. 核心功能需求

## 6.1 应用工作区

### 6.1.1 总体布局

应用主界面由以下区域组成：

1. 顶部应用栏；
2. 左侧工作区侧边栏；
3. 中央多标签页区域；
4. 标签页内寄存器操作栏；
5. 核心寄存器表格；
6. 底部消息与通信日志面板；
7. 当前连接状态展示区域。

### 6.1.2 顶部应用栏

应提供以下入口：

- 新建寄存器表；
- Connection Settings（打开连接配置，使用 Modal，每次应用启动自动弹出）；
- 连接/断开切换按钮（单个按钮：离线时显示 CONNECT，在线时显示 DISCONNECT）；
- 当前连接状态（文字 + 语义色，不只用颜色表达）；
- 当前协议类型；
- Settings（全局设置，包含 Plugins 插件管理页签）；
- 帮助或关于信息。

连接配置和全局设置的入口放置在顶部应用栏；插件管理位于 Settings → Plugins，侧边栏仅用于寄存器表（标签页）列表。

不得沿用 File、Edit、View、Communication、Option、Window、Tools 等老式顶层菜单结构。

常用操作应直接出现在工具栏、上下文菜单或对应功能区域中。

---

## 6.2 连接管理

### 6.2.1 连接类型

用户创建连接时，应先选择：

1. Modbus RTU；
2. Modbus TCP。

浏览器端只显示或只允许选择 Modbus RTU。不得提供一个可以点击但必然失败的 Modbus TCP 入口。

### 6.2.2 连接状态

至少包含以下状态：

- 未连接；
- 正在连接；
- 已连接；
- 正在断开；
- 连接失败；
- 连接中断；
- 正在重连或等待重试。

界面必须明确展示当前状态，不能只依靠按钮颜色表达。

### 6.2.3 连接互斥

同一工作区当前只维持一个活动连接。

所有打开的寄存器表共享当前活动连接及当前从站地址。

多连接并行能力不属于当前产品范围。

### 6.2.4 连接失败行为

连接失败时：

1. 保持未连接状态；
2. 保留用户已经填写的配置；
3. 展示可理解的失败原因；
4. 提供重新连接入口；
5. 不清空寄存器表；
6. 不自动反复连接，除非用户明确启用了重试或自动重连能力。

连接失败后不得强制关闭配置界面，使用户能够直接修改参数并重试。

## 6.3 Modbus RTU 配置

### 6.3.1 串口号

要求：

1. 发现当前可用串口；
2. 支持 COM1 至 COM9；
3. 支持 COM10 及以上串口；
4. 支持非 Windows 平台的串口命名方式；
5. 在平台允许时提供串口列表刷新；不能直接枚举串口的平台应通过重新打开设备选择界面发现新设备；
6. 只允许用户主动选择并授权的串口连接；
7. 串口不存在、已占用或权限不足时给出明确且可区分的提示；
8. 串口号不要求在重启后自动恢复连接；
9. 不应因为保存的串口已不存在而阻塞应用启动。

浏览器端：

- 用户发起串口选择时，打开系统设备选择界面并展示当时可用的设备，用户选择后完成本次授权；
- 不提供独立的自定义串口列表或刷新按钮，重新打开设备选择界面即可刷新；
- 未获用户授权的设备不展示或不可连接；
- 历史串口仅用于提示，不自动连接；
- 保存的串口不存在时，应用仍可正常启动。

Electron 端：

- 主进程枚举系统串口并把端口列表转发给渲染进程；
- 用户在应用下拉框中选择端口，可主动刷新或取消；
- 不默认选择第一个端口。

### 6.3.2 波特率

至少支持：

- 1200；
- 2400；
- 4800；
- 9600；
- 19200；
- 38400；
- 57600；
- 115200。

波特率使用固定选项，避免非法输入。

默认值：9600。

### 6.3.3 数据位

支持：

- 7 位；
- 8 位。

默认值：8 位。

### 6.3.4 停止位

支持：

- 1 位；
- 2 位。

默认值：1 位。

如果某个客户端运行环境支持 1.5 位停止位，可在能力检测后提供；不得为了界面一致性，在底层不支持时显示不可用选项。

### 6.3.5 校验位

支持：

- None；
- Even；
- Odd。

默认值：None。

### 6.3.6 流控

目标选项：

- OFF；
- XON/XOFF；
- RTS/CTS。

各端仅展示或启用实际支持的模式。不支持的模式应隐藏或明确标记不可用，不得静默降级。

默认值：OFF。

### 6.3.7 从站地址

要求：

1. 使用数字选择或数字输入控件；
2. 默认值为 1；
3. 允许范围为 0 至 255；
4. 从站地址 0 属于广播地址语义；不实现广播写入，配置为 0 时设备按标准不会应答，请求按超时或失败处理；
5. 对不适用于当前操作的地址给出明确提示；
6. 所有寄存器表默认共享当前从站地址；
7. 从站地址修改后，对后续请求立即生效；
8. 已经在队列中执行的请求不应被中途修改。

不提供每行独立从站地址。

### 6.3.8 请求间隔

相邻请求之间无附加间隔，WP 轮询间隔为 0（读完一个立即读下一个）。

### 6.3.9 超时

要求：

1. 用户可配置单次请求响应超时时间；
2. 必须显示时间单位；
3. 应提供合理默认值；
4. 超时后进入重试或失败处理；
5. 超时不能导致整个应用无响应。

### 6.3.10 重试次数

要求：

1. 支持 0 至 10 次；
2. 默认值为 1；
3. 重试结束后仍失败，应返回最终失败状态；
4. 每次重试应在日志中可识别。

### 6.3.11 RTU 校验方式

核心产品仅提供标准 Modbus RTU 所需的 CRC-16。

BCC、CHECK-SUM 等非标准或私有校验方式不进入核心产品，应通过插件扩展。

## 6.4 Modbus TCP 配置

适用端：

- Electron；
- VSCode。

配置项：

1. 主机名或 IP 地址；
2. TCP 端口；
3. 从站地址或 Unit ID；
4. 连接超时；
5. 请求超时；
6. 重试次数；
7. 自动重连开关；

浏览器端不支持 Modbus TCP，不显示对应连接表单。

## 6.5 寄存器表

### 6.5.1 表格定位

核心提供“保持寄存器表”。

该表只支持：

- 读取保持寄存器：功能码 03；
- 写入多个保持寄存器：功能码 0x10，即十进制 16。

即使单次只写一个 16 位寄存器，仍使用功能码 0x10。

其他功能码不得混入该表格；线圈、离散输入和输入寄存器使用各自的独立表类型。

### 6.5.2 表格列

数据列固定顺序如下：

1. 行号（No）；
2. TM（轨迹追踪，复选框，勾选后弹出 Memory Trace 追踪窗口）；
3. 名称（Name）；
4. 寄存器地址（Address[HEX]）；
5. WP（周期轮询开关，每行独立）；
6. 读取（READ 按钮，按钮内必须包含完整的 “READ” 文字，可同时配图标但不得只有图标）；
7. 数据（Data）；
8. 写入（WRITE 按钮，按钮内必须包含完整的 “WRITE” 文字，可同时配图标但不得只有图标）；
9. 数据类型（Type，分为「进制」和「scale」两列，见 §6.5.13）；
10. 备注（Comment）。

表格最前提供多行选择列，其后按上述顺序排列数据列。

不设独立的状态或错误提示列（Status 列）。地址与输入错误在对应单元格内提示，读写结果与错误通过底部消息面板和通信日志展示。

TM 和 WP 必须使用现代且含义明确的开关、按钮和提示；WP 列使用标准开关控件。

### 6.5.3 行号

要求：

- 自动生成；
- 从 1 开始；
- 仅表示表格顺序；
- 不等于寄存器地址；
- 行增删和移动后自动更新。

### 6.5.4 TM 列（轨迹追踪）

**控件类型：** 复选框

**作用说明：**

- 轨迹追踪使能标记；勾选该复选框后，会独立弹出专属数据追踪小窗口，对当前行配置的寄存器数值进行持续增量刷新更新，自动保留完整历史变化数据，实现寄存器数据动态轨迹监视效果。
- 未勾选时无弹窗追踪效果，仅支持常规手动单次读取操作。

**TM 追踪弹窗完整界面与功能详情：**

- 弹窗标题固定为 `M@MEp2006 Advance [Memory Trace]`
- 顶部自动回显当前监控参数信息，包含：
  - **Name** 输入框：同步所选行 Name 列内容
  - **Address** 输入框：同步所选行 Address 列 4 位十六进制地址
  - **Type** 下拉框：同步所选行 Type 数据格式
- 内置 **Play**、**Stop**、**Save** 三大功能按钮，分别用于启动追踪、暂停追踪、导出保存追踪数据
- 右侧配备 **Buffer Size** 下拉缓冲区配置，可选档位：`Continue`、`100`、`500`、`1000`、`1500`、`2000`、`3000`，用于限制或持续采集历史数据条数；`Continue` 并非真正无限，内部使用环形缓冲区硬上限（10000 条）防止内存无限增长
- 同时配有 **Speed** 速度调节刻度，上为 Quick（快速）、下为 Slow（慢速），可自定义数据刷新频次
- 窗口主体为数据列表表格，表头为 No.、Data：
  - **No.** 代表读取次序编号
  - **Data** 为对应采样数值
  - 增量滚动刷新并留存完整时序记录
- 弹窗底部设有 **Average** 平均值显示输入框，点击 Stop 停止追踪后，自动计算并展示本次已采集所有数据的平均值

### 6.5.5 名称

要求：

- 用户可自由填写；
- 允许为空；
- 用于说明寄存器含义；
- 支持复制和粘贴；
- 随标签页内容一起保存和恢复。

不提供名称历史，避免历史数据无限增长和跨项目污染。

### 6.5.6 寄存器地址

要求：

1. 按十六进制输入和显示；
2. 默认显示为 4 位大写十六进制；
3. 不足 4 位时自动补零；
4. 接受用户输入小写字符，并自动转换为大写；
5. 自动去除首尾空格；
6. 非法字符应在当前单元格中明确提示；
7. 地址为空时不发送请求；
8. 超出有效范围时不发送请求；
9. 地址校验失败时，不应无提示地清空用户输入；
10. 全表读取时跳过无效地址，并汇总提示；
11. 每行地址相互独立，允许任意不连续地址。

范围行：

- Address 列支持范围输入（如 `1000-1001`，按当前进制格式化），表示该行覆盖多个连续寄存器；
- 范围行一次功能码 03 读 / 0x10 写全部连续寄存器（不跨行合并）；
- 范围长度受类型合法集约束（§6.5.13），不满足在类型列报错并禁止读写。

Address Adjust 由核心产品提供，位于 Connection Settings 中（ON 时发送地址 = 用户地址 − 1，默认 OFF）。通信日志必须同时记录用户输入地址与实际发送地址。

### 6.5.7 WP 列（周期轮询）

要求：

1. 每行通过 WP 开关独立开启或关闭周期轮询；
2. 轮询开启后，按恒定间隔 0 重复读取（读完一个立即读下一个）；
3. 不提供独立的全局轮询间隔配置，也不提供全部行持续轮询（ALL Polling）功能；全表读取为一次性批量操作；
4. 每个寄存器使用独立的功能码 03 请求；
5. 不自动合并连续地址；
6. 同一连接上的请求应有序执行，避免串口请求并发冲突；
7. 用户断开连接时立即停止或取消后续轮询；
8. 行被删除或地址变更时，旧轮询任务必须停止；
9. 周期轮询期间，数据单元格默认作为只读结果展示；
10. 编辑或准备写入时不暂停该行轮询：Data 单元格采用单一当前值模型（读取结果与待写值共用同一输入区域，无独立写入输入态、草稿或提交事务），读取成功结果无条件强制覆盖单元格内容，包括用户正在输入时；
11. 应明确展示当前行是否正在轮询。

### 6.5.8 单行读取

读取按钮显示完整文字 “READ”（可配图标）。点击读取按钮后：

1. 校验连接状态；
2. 校验当前行地址是否有效；
3. 校验寄存器地址；
4. 使用功能码 03 读取一个 16 位保持寄存器；
5. 成功后更新 Data；
6. 失败后保留错误状态；
7. 记录请求和响应日志；
8. 不影响其他行是否开启周期轮询。

> 范围行：读取一次覆盖全部连续寄存器，按组合类型格式化后更新 Data。

### 6.5.9 全表读取（Read All，一次性）

全表读取是一次性批量操作，不提供全表持续轮询。全表读取应：

1. 遍历当前标签页的所有行；
2. 只处理地址合法的行；
3. 跳过空行和地址非法行；
4. 每行独立发送功能码 03 请求；
5. 不自动合并连续地址；
6. 按可预测顺序执行；
7. 支持用户取消尚未执行的任务；
8. 展示总行数、成功数、失败数和跳过数；
9. 单行失败不应中断整个批次；
10. 将每次请求记录到通信日志。

### 6.5.10 数据列

Data 列采用可编辑单元格交互，点击单元格空白区域即可进入编辑状态。职责如下：

1. 展示读取结果，格式随该行 Type；
2. 作为普通输入框，允许用户直接输入要写入的值；
3. 点击 Write 时对输入执行 Type 格式与 16 位范围校验；
4. 读取成功返回新内容时，无条件强制覆盖单元格已有内容，包括用户正在输入时；
5. 读取失败时，单元格内容保持不变，不做提示；
6. 通信日志照常记录每次读取失败。

### 6.5.11 单行写入

写入按钮显示完整文字 “WRITE”（可配图标）。点击写入按钮后：

1. 校验连接状态；
2. 校验当前行地址是否有效；
3. 校验寄存器地址；
4. 校验输入值；
5. 将输入值转换为 16 位原始值（范围行转换为多个原始值）；
6. 使用功能码 0x10 写入一个或多个连续保持寄存器（范围行一次写全部）；
7. 根据 Read Verify 配置决定是否回读（范围行逐项比较）；
8. 展示写入或回读结果；
9. 记录完整通信日志。

写入失败时：

- 不清空单元格内容；
- 显示失败原因；
- 允许用户修改后重试。

### 6.5.12 写后回读

支持以下产品行为：

- OFF：写入成功后不回读；
- ON：写入成功后立即回读；
- ON 100 ms：等待 100 ms 后回读；
- ON 200 ms：等待 200 ms 后回读；
- ON 500 ms：等待 500 ms 后回读。

新表默认使用 OFF；工作区中已明确保存的回读设置保持不变。

回读使用功能码 03。

结果必须区分：

1. 写入失败；
2. 写入成功且回读成功，值一致；
3. 写入成功且回读成功，值不一致；
4. 写入成功但回读失败。

回读失败不能被错误地展示为写入失败。

### 6.5.13 数据类型

当前支持以下 16 位显示类型：

- HEX；
- Unsigned Dec.；
- Unsigned 0.1；
- Unsigned 0.01；
- Unsigned 0.001；
- Unsigned 0.0001；
- Signed Dec.；
- Signed 0.1；
- Signed 0.01；
- Signed 0.001；
- Signed 0.0001；
- Binary。

通用规则：

1. Type 只改变 Data 的解释、输入和显示方式；
2. 不改变底层寄存器原始 16 位数据；
3. 切换 Type 后应基于同一原始值重新显示；
4. 有符号类型使用 16 位有符号数解释；
5. 无符号类型使用 16 位无符号数解释；
6. Binary 显示为固定 16 位，每 8 位一组空格分组（如 `00000000 11111111`）；
7. HEX 显示为固定 4 位大写十六进制；
8. 缩放类型应明确小数位；
9. 写入时必须验证转换后的原始值是否处于 16 位范围；
10. 无法精确表示的输入，应提示用户，不得静默产生不可预测结果；
11. 提交成功或粘贴后按 Type 写回规范显示形式（去前导零 / 补零大写 / 二进制分组 / 固定小数位等）。

Endian Type 对单个 16 位寄存器不产生可感知差异，不作为核心表格配置项。多寄存器组合值使用固定大端字节序；字节序和字序可配置能力不属于当前产品范围。

#### 多寄存器组合类型

为支持嵌入式设备「某些寄存器必须连续读写」的约束，类型体系扩展如下：

- **Type 列拆为两列**：第一列进制（HEX / Unsigned / Signed / Binary / String），第二列 scale（1 / 0.1 / 0.01 / 0.001 / 0.0001，仅对 Unsigned / Signed 有意义；其余进制无 scale）；
- **Address 列支持范围输入**（如 `1000-1001`），范围行一次 FC03 读 / FC0x10 写全部连续寄存器；
- **组合宽度由范围长度决定**：32 位 = 2 个寄存器、64 位 = 4 个寄存器；二进制 = 1/2/3/4 个寄存器；HEX 与 String 任意数量；单寄存器行为默认（宽度 1）；
- **字符串**：ASCII 编码，每寄存器 2 字符，长度任意（1~范围上限）；
- **64 位整数**：完整支持（超出 2^53 不丢精度）；
- **合法寄存器数约束**：Unsigned/Signed 仅 1/2/4；Binary 仅 1/2/3/4；HEX 与 String 任意；不满足时在类型列报错并禁止该行读写；
- **scale 作用于组合值**：如 32 位有符号 × 0.1；
- **字节序默认大端**（高字在前，Modbus 惯例）；「字节序和字序配置」仍为 §8.4 P2。

### 6.5.14 行编辑

支持：

- 新增行；
- 插入行；
- 删除行；
- 向上移动；
- 向下移动；
- 复制；
- 剪切；
- 粘贴；
- 多行选择；
- 键盘快捷操作；
- 右键上下文菜单。

删除包含数据的行时采用直接删除，不弹确认弹窗，不提供撤销/重做；多选删除同样不弹窗。

行编辑应遵循以下行为：

- **插入行**：在当前选中行**下方**插入一个**空行**，不继承名称 / 地址 / 类型等字段；行号自动重排。
- **删除**：采用直接删除，不弹确认弹窗，不引入撤销/重做。
- **剪贴板**：同时实现系统剪贴板与应用内剪贴板。系统剪贴板为 CSV 文本（表头 `Name,Address,Data,Type,Comment`，Address 列用十进制数值）；应用内剪贴板跨标签页生效；系统剪贴板不可用时回退应用内剪贴板。
- **键盘快捷键**：Alt+↑/↓ 上移/下移、Delete 删除、Ctrl+C / Ctrl+X / Ctrl+V 复制/剪切/粘贴、Ctrl+I 插入；焦点位于文本输入控件（单元格编辑等）时不拦截。
- **右键上下文菜单**：插入上方 / 插入下方 / 上移 / 下移 / 复制 / 剪切 / 粘贴 / 删除。
- **多行选择**：提供选择复选框，支持表头全选、范围选择和多项选择；选中状态仅用于当前会话，不随工作区持久化。

### 6.5.15 表格容量

产品应支持用户持续新增行。

当前性能目标：

- 普通表格包含 1000 行时仍能正常编辑；
- 开启轮询的行数应受到通信带宽和轮询周期约束；
- 系统不承诺所有行都能在极短周期内完成刷新；
- 当配置的轮询量超过通信链路能力时，应提示实际刷新频率可能下降。

## 6.6 多标签页管理

### 6.6.1 标签页功能

支持：

- 新建；
- 重命名；
- 复制；
- 关闭；
- 关闭其他标签页；
- 关闭右侧标签页；
- 调整顺序；
- 恢复上次打开的标签页。

### 6.6.2 默认标签页

首次启动时创建一个默认寄存器表。

默认表可以编辑和删除。删除某个核心表类型的最后一张表时，系统在原位置补建同类型空表并激活；关闭的表也计入同类型数量。删除、补建和活动表切换作为一个可撤销步骤；撤销恢复完整原表并移除补建表，重做复用同一补建结果。插件类型不自动套用按类型保留规则；删除后整个工作区无表时仍补建保持寄存器空表。

首次启动及恢复工作区时，在启动完成前补齐缺少的四种核心表类型，保留已有表和有效活动表。
重置成功后也补齐四种核心表类型，并清空撤销、重做历史；重置失败不改变当前工作区。
补齐不进入撤销历史，不触发设备通信，也不得增加额外异步等待或逐表更新界面的启动开销。

### 6.6.3 保存状态

自动保存不展示保存状态，静默执行。

只有手动保存（例如文件保存）才展示保存状态：

- 已保存；
- 正在保存；
- 保存失败。

如果提供文件导入导出功能，则应区分自动保存与外部文件修改状态。

### 6.6.4 项目或工作区

以一个本地工作区管理多个标签页。多工作区、团队共享配置和设备模板不属于当前产品范围。

## 6.7 状态恢复和持久化

## 6.7.1 必须恢复的数据

应用重新打开后，应恢复：

1. 上次打开的标签页；
2. 标签页顺序；
3. 标签页名称；
4. 每个标签页的寄存器行；
5. 名称；
6. 地址；
7. TM（轨迹追踪）；
8. 数据类型；
9. Comment（备注）内容；
10. 轮询配置状态（WP 开关）；
11. 面板展开或折叠状态；
12. 通信参数（含超时、重试、Address Adjust 等 Connection Settings 配置）；
13. 超时和重试配置；
14. 写后回读配置；
15. 主题和界面偏好。

## 6.7.2 串口号恢复规则

除串口号外，其他串口设置在重新打开时应恢复为关闭前状态。

串口号不作为必须恢复项，原因包括：

- 浏览器端需要重新授权；
- 串口设备路径可能变化；
- 保存的设备可能已不存在；
- 自动选择旧串口可能导致误连接。

即使客户端保存了最近使用的串口，也只能作为提示，不得自动建立连接。

## 6.7.3 连接恢复规则

应用启动时默认保持离线。

不得在未获得用户明确配置的情况下自动连接设备。

不提供启动后自动连接；应用启动时始终保持离线并等待用户主动连接。

## 6.7.4 数据保存时机

用户进行以下操作后应自动保存：

- 修改标签页；
- 修改寄存器行；
- 调整设置；
- 调整布局；
- 关闭标签页；
- 关闭应用。

异常退出后，应尽可能恢复最近一次已成功保存的状态。

TCP 示例信息：

- Unit ID；

# 9. 关键用户流程

## 9.1 打开应用与 RTU 连接

1. 用户打开应用（每次启动都会自动弹出 Connection Settings 连接配置 Modal）；
2. 系统自动打开 Connection Settings Modal（浏览器端仅提供 Modbus RTU 配置）；
3. 选择或授权串口；
4. 配置波特率、数据位、停止位、校验位、从站地址（0~255）、Address Adjust 等参数；
5. 点击 CONNECT（连接/断开为同一个切换按钮）；
6. 系统显示连接状态；
7. 用户输入寄存器地址；
8. 点击 READ（单行读取）；
9. 系统发送功能码 03；
10. Data 显示结果；
11. 日志展示请求和响应原始字节。

## 9.2 写入寄存器

1. 用户选择目标行；
2. 输入合法地址；
3. 选择数据类型；
4. 在 Data 单元格中直接输入要写入的值；
5. 点击写入；
6. 系统执行格式和范围校验；
7. 使用功能码 0x10 写入；
8. 若启用 Read Verify，则执行回读；
9. 展示写入和回读结果；
10. 通信日志记录完整过程。

## 9.3 周期监控

1. 用户配置多个不连续地址；
2. 为目标行开启 WP 轮询；
3. 无需设置轮询间隔；
4. 系统按恒定间隔 0 依次读取各行（读完一个立即读下一个）；
5. Data 持续更新；
6. 用户关闭某行 WP 轮询；
7. 系统停止该行后续任务；
8. 其他行继续运行。

## 9.4 重新打开应用

1. 用户关闭应用；
2. 系统保存工作区；
3. 用户再次打开；
4. 系统保持离线；
5. 恢复标签页、寄存器表和界面状态；
6. 恢复除串口号外的通信配置；
7. 用户重新选择串口并连接。

# 10. 界面设计要求

## 10.1 设计原则

1. 现代、简洁、专业；
2. 保留 M@MEp2006 高效的操作逻辑，不复刻其视觉样式；
3. 高频操作直接可见；
4. 低频操作放入设置、上下文菜单或插件区域；
5. 避免多层菜单；
6. 使用明确文字配合图标，不依赖难以理解的图标；
7. 状态和错误必须可见；
8. 三端视觉一致，但遵循各平台交互规范；
9. 高信息密度与可读性并重；
10. 优先支持键盘和鼠标高效操作；
11. 连接建立、进入调试阶段后，尽量减少打断式弹窗与让用户选择的操作，保证调试流程流畅；调试中的修改操作优先内联完成（反面教材：Modbus Poll 修改参数经常需要右键选择、弹窗修改）。

## 10.2 视觉风格

建议方向：

- 现代开发工具风格；
- 中性灰作为基础背景；
- 单一品牌强调色；
- 在线、警告和错误使用语义色；
- 浅色和深色主题；
- 扁平化控件；
- 适度圆角；
- 清晰的边界和层级；
- 不使用老式立体凸起按钮；
- 不复制浅绿、白色交替行的原始样式。

表格可使用轻微的斑马纹或悬停高亮，但必须保证深色主题下的对比度。

## 10.3 主界面建议结构

### 顶部

- 产品名称；
- 当前连接摘要；
- 连接和断开按钮；
- 新建表；
- 设置；
- 插件；
- 帮助。

### 左侧

- 寄存器表列表；
- 新建表入口；
- 连接入口；
- 插件入口。

### 中央

- 多标签页；
- 当前标签页工具栏；
- 寄存器表格。

### 底部

- 消息；
- 通信日志；
- 通信属性；
- 备注。

## 10.4 寄存器工具栏

建议包含：

- 全表读取（Read All，一次性批量读取）；
- 新增行；
- 删除选中行；
- 当前从站地址；
- 当前任务状态。

不提供开始/停止全部轮询按钮（不支持 ALL Polling），也不提供全局轮询间隔配置；WP 轮询按恒定间隔 0 执行。

Enter ROM 和 Enter RAM 不出现在核心工具栏中。插件启用后，可以通过插件贡献的按钮出现。

## 10.5 连接配置形式

连接配置使用 Modal，每次应用启动自动弹出。

连接配置应：

- 按 RTU 和 TCP 分组；
- 只展示当前协议相关配置；
- 支持在失败后直接修改；
- 显示字段说明和有效范围；
- 将主要连接按钮置于明显位置；
- 提供刷新串口列表（浏览器端由授权 picker 承担：每次打开 picker 即实时刷新设备列表，无独立刷新按钮）；
- 清楚显示浏览器授权状态。

不需要显示：

- 品牌 Logo；
- 授权用户；
- Access Counter；
- 版权装饰；
- 与连接无关的信息。

## 10.6 响应式要求

窗口宽度不足时：

1. 侧边栏可折叠；
2. 底部面板可折叠；
3. 表格允许横向滚动；
4. 关键列优先显示；
5. 操作按钮可以收纳，但不得隐藏连接状态；
6. 不应强行压缩导致地址和数据不可读。

# 11. 技术栈建议

本节只给出产品级技术选型建议和约束，不定义具体工程配置、依赖版本、模块组织和实现代码。

## 11.1 选型原则

所有技术选型应满足：

1. AI 模型训练覆盖充分；
2. 社区活跃；
3. 文档公开且完整；
4. 长期维护风险较低；
5. 跨平台生态成熟；
6. TypeScript 支持良好；
7. 自动化测试生态成熟；
8. 浏览器、Electron 和 VSCode 可复用；
9. 避免小众 DSL 和封闭框架；
10. 避免为追求技术新颖而增加复杂度。

## 11.2 推荐技术体系

### 核心语言

- TypeScript。

理由：

- 三端均可使用；
- AI 熟悉度高；
- 静态类型有利于通信和数据转换逻辑；
- 前端、Electron 和 VSCode 生态统一；
- 便于共享核心业务模型。

### 前端框架

- React。

理由：

- 社区成熟；
- 资料丰富；
- AI 生成准确率较高；
- 适用于浏览器、Electron 和 VSCode Webview；
- 表格、状态管理和测试工具丰富。

### 构建工具

- Vite。

### 桌面客户端

- Electron。

理由：

- 与 Web 技术栈一致；
- 串口和 TCP 能力成熟；
- AI 和社区资料丰富；
- 可最大化复用 React 界面和 TypeScript 核心逻辑。

### VSCode 插件

- VSCode Extension API；
- Webview 用于复杂寄存器表界面；
- TypeScript 作为插件端语言。

### 状态管理

优先选择主流、轻量、可测试的 React 状态管理方案。

具体选型由技术设计文档决定，但应避免：

- 过度复杂的全局状态体系；
- 大量隐式副作用；
- 状态和通信逻辑直接耦合；
- 三端分别维护三套独立状态模型。

### 表格组件

优先选择：

- 主流；
- 支持虚拟滚动；
- 支持单元格编辑；
- 支持键盘操作；
- 支持多行选择；
- 可在 Electron、浏览器和 VSCode Webview 复用；
- 许可证符合开源要求的表格方案。

表格组件选型必须通过虚拟滚动、受控输入、键盘操作和跨 Webview 验证。

### 串口能力

- 浏览器端使用 Web Serial 能力；
- Electron Renderer 与浏览器一致使用 Web Serial 能力；
- VSCode 使用 Node.js 生态中成熟的串口方案。

### TCP 能力

- Electron 和 VSCode 使用 Node.js TCP 能力；
- 浏览器端不实现直接 Modbus TCP。

### 测试

推荐形成以下测试层级：

- 纯函数单元测试；
- 协议行为测试；
- 状态和任务调度测试；
- 组件测试；
- 三端适配测试；
- 端到端验收测试；
- 虚拟 Modbus 设备集成测试。

具体测试框架和配置属于技术设计文档或 AGENTS.md。

## 11.3 不建议采用的技术

1. 停止维护的前端框架；
2. 小众桌面 UI 框架；
3. 仅适用于 Windows 的旧式控件框架；
4. 缺乏 TypeScript 类型定义的关键依赖；
5. 无可靠测试能力的串口库；
6. 强依赖闭源服务的核心实现；
7. 大量自定义元编程或特殊语法；
8. 为三端分别使用完全不同的前端框架；
9. 在核心通信逻辑中直接绑定具体 UI 框架；
10. AI 训练数据覆盖明显不足的冷门工具链。

# 12. 代码风格和架构模式要求

本节只定义产品对代码质量和架构的约束，不提供具体目录、接口、类、函数和编码规则。

## 12.1 总体架构要求

产品应采用以下方向：

1. 核心业务逻辑与界面分离；
2. Modbus 协议逻辑与串口、TCP 传输分离；
3. 平台能力通过适配层接入；
4. 浏览器、Electron 和 VSCode 共享核心模型；
5. 插件功能与核心功能隔离；
6. 持久化逻辑与业务状态分离；
7. 通信任务可被测试替代和模拟；
8. 错误必须结构化，不依赖字符串判断；
9. 避免全局可变状态；
10. 避免 UI 组件直接操作串口或 TCP。

推荐采用分层架构和 Ports and Adapters 思想，但具体分层方案由技术设计文档确定。

## 12.2 模块边界

产品概念上应至少区分：

- 协议核心；
- 传输能力；
- 通信会话；
- 寄存器表；
- 数据类型转换；
- 轮询和任务队列；
- 工作区和持久化；
- 日志；
- 插件；
- 平台适配；
- 用户界面。

## 12.3 代码质量要求

1. TypeScript 开启严格类型检查；
2. 核心数据不得滥用宽泛类型；
3. 通信协议数据应有明确模型；
4. 输入必须在进入核心逻辑前校验；
5. 通信错误必须可分类；
6. 公共逻辑必须可独立测试；
7. 三端不得复制粘贴核心协议代码；
8. 复杂逻辑应有测试表达预期行为；
9. 不允许通过吞掉异常维持表面运行；
10. 不允许把厂商私有规则硬编码到核心模块。

## 12.4 Vibe Coding 约束

1. 每个功能先定义验收条件；
2. 核心通信逻辑在用户要求测试时优先测试先行；
3. 一次变更聚焦一个明确目标；
4. AI 生成代码必须经过类型检查，测试执行时机由用户决定（详细规则见 AGENTS.md）；
5. 不接受仅凭界面看起来正常即判定功能完成；
6. 协议行为必须通过可重复测试验证；
7. 依赖库使用公开稳定 API；
8. 避免生成难以理解的大型单文件；
9. 避免没有测试保护的大范围重构；
10. 详细 AI 操作规则应写入 AGENTS.md，而不是写入本文档。

# 13. 限制条件

## 13.1 产品定位限制

1. 面向开发调试，不面向生产控制；
2. 不提供工业级安全联锁；
3. 不保证设备写入操作无风险；
4. 用户应自行确认寄存器地址和允许写入范围；
5. 工具不理解未知设备寄存器的业务含义；
6. 工具无法自动判断某个合法 Modbus 写入是否会导致设备故障。

## 13.2 协议限制

当前协议边界：

- 保持寄存器使用功能码 03 读取、0x10 写入；
- 保持寄存器支持单寄存器与连续范围多寄存器组合；
- 线圈、离散输入和输入寄存器使用各自的核心表类型与已确认 codec；
- 不跨行合并请求；
- 不支持广播写入；
- 厂商私有功能码和协议通过插件贡献点提供；
- 浏览器不支持直接 Modbus TCP。

## 13.3 浏览器限制

1. 不支持 Modbus TCP；
2. 串口支持依赖浏览器和操作系统；
3. 必须由用户主动授权设备；
4. 页面刷新或关闭可能使连接中断；
5. 浏览器可能限制后台页面的任务执行频率；
6. 不承诺页面处于后台时仍保持精确轮询周期；
7. 无法访问浏览器没有授权的本地设备。

## 13.4 VSCode 限制

1. 界面运行在 VSCode 规范约束下；
2. 插件关闭、重载或 VSCode 重启会断开连接；
3. 工作区信任状态可能限制插件能力；
4. 不应阻塞 VSCode 扩展宿主；
5. 长时间任务必须允许取消；
6. UI 必须兼容 VSCode 主题。

## 13.5 Electron 限制

1. 桌面客户端体积通常高于原生轻量工具；
2. 串口权限可能受到操作系统安全策略影响；
3. macOS、Linux 和 Windows 的串口命名及权限模型不同；
4. 插件和本地能力必须考虑桌面安全边界；
5. 应避免界面层直接获得不必要的系统权限。

# 14. 边界场景

## 14.1 串口场景

必须处理：

- 系统没有串口；
- COM10 及以上；
- 串口在列表刷新后出现（浏览器端：重新打开授权 picker 即看到新插入设备）；
- 串口在连接前消失；
- 串口被其他程序占用；
- 连接后设备被拔出；
- 串口权限不足；
- 浏览器拒绝授权；
- 浏览器撤销授权；
- 配置的参数不被当前环境支持；
- 设备持续返回无效 CRC；
- 收到不完整报文；
- 响应长度异常；
- 响应从站地址不匹配；
- 响应功能码不匹配。

## 14.2 TCP 场景

必须处理：

- 主机名为空；
- IP 地址格式错误；
- 端口非法；
- DNS 解析失败；
- 连接超时；
- 对端拒绝连接；
- 连接后立即断开；
- 请求过程中断线；
- 响应事务不匹配；
- 响应 Unit ID 不匹配；
- 自动重连过程中用户主动断开。

## 14.3 表格场景

必须处理：

- 空地址；
- 地址包含非法字符；
- 地址超过 4 位；
- 地址越界；
- 重复地址；
- 大量空白行；
- 删除正在轮询的行；
- 修改正在轮询的地址；
- 复制包括无效数据的多行；
- 粘贴数据超过当前表格长度；
- 切换标签页时仍有任务运行；
- 关闭存在轮询任务的标签页；
- 全表读取过程中断开连接；
- 批量读取过程中用户取消；
- 同一地址存在于多行；
- 同一地址以不同 Type 显示。

重复地址允许存在，每行按独立配置处理。

## 14.4 数据输入场景

必须处理：

- HEX 中输入非法字符；
- Binary 中输入非 0 和 1（每 8 位一组的空格分隔符除外）；
- 无符号类型输入负数；
- 有符号类型超出 16 位范围；
- 小数位超过类型精度；
- 输入空值；
- 输入前后有空格；
- 粘贴本地化数字格式；
- 输入极大数值；
- 类型切换后原值无法按新类型表示。

## 14.5 并发和任务场景

必须处理：

- 用户连续快速点击读取；
- 用户连续快速点击写入；
- 轮询过程中执行手动读取；
- 轮询过程中执行写入；
- 全表读取与周期轮询同时触发；
- 切换连接时仍有请求排队；
- 请求超时后迟到响应到达；
- 重试期间用户断开；
- 插件请求与核心请求同时发送。

同一通信连接必须保证请求不会以不可控方式并发发送。

具体任务优先级和调度策略由技术设计文档定义。

## 14.6 状态恢复场景

必须处理：

- 保存内容损坏；
- 保存失败；
- 磁盘空间不足；
- 浏览器存储不可用；
- 上次版本数据结构与当前版本不一致；
- 应用异常退出；
- 标签页部分保存成功；
- 恢复时插件不存在；
- 恢复时保存的串口不存在。

发生恢复错误时，应尽可能保留可恢复数据，并允许用户重置工作区。

# 16. 产品验收标准

## 16.1 核心调试闭环

满足以下条件，可认为产品具备基础可用性：

1. 用户可以创建或恢复寄存器表；
2. 用户可以建立支持的 RTU 或 TCP 连接；
3. 用户可以在同一表格中配置多个不连续地址；
4. 用户可以使用功能码 03 读取单个保持寄存器；
5. 用户可以使用功能码 0x10 写入单个保持寄存器；
6. 用户可以执行全表读取；
7. 用户可以开启和停止单行周期轮询；
8. 用户可以查看格式化数值和原始通信日志；
9. 关闭并重新打开应用后可以恢复工作区内容；
10. 连接、读取或写入失败不会导致应用崩溃或用户配置丢失。

## 16.2 Modbus RTU 验收

1. 三端均可完成 RTU 连接、读取、写入和日志查看；
2. 当前环境没有串口时，界面给出明确提示；
3. 串口被占用时，连接失败原因可理解；
4. 设备拔出后，连接状态及时更新；
5. 超时和重试行为符合用户配置；
6. 错误 CRC、响应地址不匹配和功能码不匹配能够被识别；
7. 浏览器拒绝授权后，应用保持可操作；
8. 不受支持的串口参数不会被静默接受；
9. 断开连接后不再发送新的请求。

## 16.3 Modbus TCP 验收

1. Electron 和 VSCode 可以使用主机、端口和 Unit ID 建立连接；
2. 浏览器端不显示可用的 Modbus TCP 调试入口；
3. 主机或端口非法时不发送连接请求；
4. 连接超时和对端拒绝连接时显示不同的错误信息；
5. 连接中断后停止或取消待执行请求；
6. 用户主动断开后不应被自动重连逻辑再次连接；
7. 请求和响应可在通信日志中正确关联；
8. 事务不匹配和异常响应能够被识别。

## 16.4 寄存器表验收

1. 支持任意不连续地址；
2. 地址输入不足 4 位时自动补零；
3. 地址显示为大写十六进制；
4. 非法地址不会发送请求；
5. 非法输入不会被无提示清空；
6. 重复地址允许存在；
7. 每行的数据类型可独立设置；
8. Type 切换不改变原始 16 位数据；
9. 全表读取跳过空行和地址非法行；
10. 单行失败不终止全表读取；
11. 删除正在轮询的行后，不再产生该行请求；
12. 读取失败时 Data 单元格内容保持不变，不做提示；
13. 写入失败时保留单元格内容；
14. 行编辑和多标签页操作不会破坏其他行的数据；
15. 普通 1000 行表格可以正常编辑和滚动；
16. Address 列支持范围输入（如 `1000-1001`），按当前进制格式化；
17. 范围行一次请求读写全部连续寄存器（FC03/FC0x10 多寄存器，不跨行合并）；
18. 类型列支持组合类型（32/64 位整数、ASCII 字符串等），scale 作用于组合值；
19. 范围长度与类型合法集不匹配时在类型列报错并禁止该行读写；
20. 范围行可展开为每寄存器一子行（只读）；子行不可拖拽、不可多选；父行拖拽整组移动。

## 16.5 状态恢复验收

重新打开应用后，应正确恢复：

- 标签页数量；
- 标签页名称和顺序；
- 寄存器行；
- 名称和地址（含范围行起始地址与覆盖范围 registerCount）；
- 数据类型（含组合类型/字符串）；
- TM 追踪状态；
- 轮询配置；
- 通信参数；
- 超时和重试；
- 写后回读配置；
- 备注；
- 面板状态；
- 主题和用户偏好。

同时满足：

1. 应用启动时默认离线；
2. 不自动连接上次使用的设备；
3. 串口号不作为必须恢复项；
4. 保存数据损坏时不导致应用无法启动；
5. 用户可以重置损坏的工作区；
6. 恢复失败时提供明确提示。

## 16.6 三端一致性验收

以下项目在三端应使用相同的产品规则：

- 地址格式；
- 数据类型；
- 读取和写入规则；
- 全表读取跳过规则；
- 周期轮询行为；
- 超时和重试含义；
- 错误分类；
- 日志核心字段；
- 工作区核心数据；
- 插件平台能力提示。

允许存在的差异：

- 窗口布局；
- 快捷键；
- 系统权限申请方式；
- 串口选择方式；
- 主题来源；
- TCP 能力；
- 插件可使用的平台权限。

# 22. 发布与版本策略

## 22.1 发布要求

产品发布必须完成 P0 功能、四端目标范围内的验收测试、工作区恢复、插件边界和生产产物验证。

## 22.2 发布阻断条件

存在以下情况之一时，不得发布：

1. 核心读取或写入存在已知数据转换错误；
2. 断开连接后仍持续发送请求；
3. 写入目标地址与用户输入地址不一致；
4. Type 转换可能产生无提示的数据截断；
5. 工作区恢复会稳定导致用户配置丢失；
6. 单个通信错误会导致应用崩溃；
7. 浏览器端错误宣称支持直接 Modbus TCP；
8. 插件加载失败会阻止应用启动；
9. 三端对相同寄存器数据产生不一致解释；
10. P0 验收用例未全部通过；
11. 存在未解决的阻断级或严重级缺陷。
