# Modbus 协议设计

## 1. packages/protocol-modbus

包含：

- Modbus RTU ADU 编解码；
- Modbus TCP ADU 编解码；
- PDU 编解码；
- 功能码 03 请求和响应；
- 功能码 0x10 请求和响应；
- CRC-16；
- Modbus TCP MBAP Header；
- 异常响应解析；
- 响应一致性校验；
- 报文长度校验；
- 事务 ID 校验；
- Unit ID 和 Slave Address 校验。


## 2. Modbus 协议设计

### 2.1 实现范围

MVP 协议核心只实现：

1. Modbus RTU；
2. Modbus TCP；
3. 功能码 03；
4. 功能码 0x10；
5. 单个或多个连续 16 位保持寄存器读取（FC03，quantity 可 >1，范围行，ADR-030）；
6. 单个或多个连续 16 位保持寄存器写入（FC0x10，多值写，ADR-030）；
7. Modbus 异常响应；
8. RTU CRC-16；
9. TCP MBAP Header；
10. 请求和响应一致性校验。

不得在核心协议包中加入：

- BCC；
- CHECK-SUM；
- 厂商私有功能码；
- Enter RAM；
- Enter ROM；
- 厂商寄存器语义；
- 私有报文封装。

Address Adjust（ON 时发送地址 = 用户地址 − 1，默认 OFF）由 register-table 应用层实现，协议包只接收最终已验证的实际发送地址。

### 2.2 协议层次

协议处理分为：

1. 领域请求；
2. PDU；
3. ADU；
4. Transport 字节流；
5. 响应帧；
6. 领域结果。

读取请求转换流程：

    ReadHoldingRegisterCommand
    -> Function 03 PDU
    -> RTU ADU 或 TCP ADU
    -> Transport
    -> RTU ADU 或 TCP ADU
    -> Function 03 Response PDU
    -> RawRegisterValue

写入请求转换流程：

    WriteHoldingRegisterCommand
    -> Function 0x10 PDU
    -> RTU ADU 或 TCP ADU
    -> Transport
    -> RTU ADU 或 TCP ADU
    -> Function 0x10 Response PDU
    -> WriteAcknowledgement

### 2.3 请求模型

每个通信请求至少包含：

- requestId；
- connectionId；
- protocol；
- source；
- operation；
- target；
- timeoutMs；
- retryCount；
- createdAt；
- cancellationToken；
- metadata。

source 用于区分：

- manual-read；
- manual-write；
- batch-read；
- polling；
- write-verify；
- plugin。

operation 用于区分：

- read-holding-register；
- write-holding-register。

target 至少包含：

- slaveAddress 或 unitId；
- registerAddress；
- registerCount。

MVP 的 registerCount 固定为 1，但协议层不应依赖 UI 假设。

### 2.4 响应校验

RTU 响应必须校验：

1. 最小帧长度；
2. CRC；
3. Slave Address；
4. 功能码；
5. 异常功能码；
6. 字节数；
7. 数据长度；
8. 写入响应中的起始地址；
9. 写入响应中的数量；
10. 是否存在多余或缺失字节。

TCP 响应必须校验：

1. Transaction ID；
2. Protocol ID；
3. Length；
4. Unit ID；
5. 功能码；
6. 异常功能码；
7. 字节数；
8. 数据长度；
9. 写入地址；
10. 写入数量。

### 2.5 RTU 帧读取

串口字节流可能分多次到达，不能假设一次 data 事件包含完整响应。

RTU Transport Adapter 应提供字节缓冲，通信会话根据当前请求推导预期响应长度。

需要处理：

1. 响应被拆分为多个数据片段；
2. 一次收到完整响应；
3. 收到多余字节；
4. 收到上一个请求的迟到响应；
5. 收到噪声或非法前缀；
6. CRC 错误；
7. 超时前只收到部分帧；
8. 设备断开。

对于当前 MVP 的功能码 03 和 0x10，可以根据响应头确定完整帧长度：

- 功能码 03：根据 byte count 推导；
- 功能码 0x10：响应长度固定；
- 异常响应：长度固定。

不得仅依赖固定延迟判断帧结束。

### 2.6 TCP 帧读取

TCP 是字节流协议，必须处理：

1. 半包；
2. 粘包；
3. 多个响应连续到达；
4. 连接中断；
5. MBAP Length 非法；
6. Transaction ID 不匹配；
7. 超时后的迟到响应。

TCP Adapter 应维护接收缓冲，根据 MBAP Header 中的 Length 分帧。

### 2.7 Transaction ID

Modbus TCP Transaction ID 由 CommunicationSession 维护。

要求：

1. 在 16 位范围内递增并回绕；
2. 单连接内唯一关联当前未完成请求；
3. 响应必须与当前请求 Transaction ID 匹配；
4. 超时后的迟到响应不得被后续请求误接收；
5. 连接重建后重置或重新初始化；
6. Transaction ID 不进入持久化工作区。
