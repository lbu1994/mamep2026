# 领域模型

## 1. packages/domain

包含：

- 标识符；
- 通用 Result 类型；
- 结构化错误；
- 工作区聚合根；
- 标签页实体；
- 寄存器行实体；
- 核心表类型与插件表类型身份；
- 内置与插件数据类型身份；
- 连接配置值对象；
- 平台能力类型；
- 插件贡献类型。

不得包含平台实现。


## 2. 工作区数据模型

### 2.1 Workspace

工作区为主要持久化聚合根。

建议字段：

    Workspace
      schemaVersion
      workspaceId
      name
      createdAt
      updatedAt
      activeSheetId
      sheets
      connectionProfiles
      activeConnectionProfileId
      pollingSettings
      panelLayout
      preferences
      notes
      migrationHistory

### 2.2 RegisterSheet

    RegisterSheet
      sheetId
      name
      type
      order
      registerRadix      // "dec" 默认或 "hex"，每表独立（ADR-014）
      slaveAddress       // RTU Slave Address / TCP MBAP Unit ID，每表独立
      addressTransform   // { transformId, enabled } | null，每表独立
      writeVerify        // OFF / immediate / delayed，每表独立
      rows
      createdAt
      updatedAt
      uiState

核心表类型为：

- `holding-register`：FC03 读、FC0x10 写；
- `coil`：FC01 读、FC0F 写，值只有 0/1；
- `discrete-input`：FC02 只读；
- `input-register`：FC04 只读。

插件表类型使用 `<pluginId>:<tableTypeId>` 命名空间。表类型决定可用操作、
显示列和协议 codec；读写状态、轮询、Trace、写后回读与调度不因表类型复制。
只读语义属于表类型元数据，不增加可被错配的独立模型开关。

`addressTransform` 是表级地址变换配置。未配置时使用用户地址；启用时由受控
`addressTransform` 注册表解析最终发送地址。用户地址、变换 ID 和最终发送地址
必须同时进入请求上下文与通信日志。

### 2.3 RegisterRow

    RegisterRow
      rowId
      order
      name
      comment
      addressDraft        // 支持 "start" 或 "start-end"（范围行）
      addressValue        // 起始地址；registerCount>1 时范围=[start, start+count-1]
      registerCount       // 范围长度，默认 1
      dataType            // 进制/类型（hex/unsigned/signed 各 scale/binary/string）
      pollingEnabled
      traceEnabled
      cellText            // 组合值显示文本（范围行为组合解释）
      registerValues      // 各寄存器原始值数组，单一事实源
      registers           // 展开子行元数据数组；长度=registerCount，单寄存器行为 null
      bitComments         // (string[] | null)[] | null；外层按寄存器，内层按 bit 0..15
      bitNames            // 结构同 bitComments；位级名称
      createdAt
      updatedAt

`dataType` 的描述范围是“内置类型 + 已注册插件类型”。内置类型固定由
`data-conversion` 解释；插件类型与插件 ID 一样是开放字符串，必须经
`DataTypeResolver` 解析。插件数据类型当前只允许用于单寄存器行。未知类型
在解析/编辑时必须报错，不得被当作可编辑 HEX 或猜测其范围；读取格式化可在
formatter 缺失时做防御性显示回退，但不改变类型身份。

`registers` 中每一项由 `name`、`comment` 和该子寄存器的 `dataType` 组成。展开子行不是独立
寄存器实体，而是 `registers[i]` 元数据与 `registerValues[i]` 原始值的联合呈现；行身份、
地址、轮询、读写和拖拽始终归属父行 `rowId`。

父行 `dataType` 决定组合值文本的解析/格式化和设备请求的组帧方式；子行 `dataType` 只解释
该子行对应的单个 16 位寄存器。两者共享同一份 `registerValues`，子行编辑后必须重新生成
父行 `cellText`。设备读取、轮询和写后回读只更新 `registerValues`，不得覆盖子行名称、备注
或 Type。

范围长度变化时，`registers` 按索引保留、截断或补齐，新增项默认继承父行 Type；不能把旧范围
的原始值继续解释成新范围的设备值。数组缺失或长度不匹配必须在 Schema/迁移/提交边界显式
规范化，不得由展示层静默拼接。

`bitNames` / `bitComments` 是位明细的持久元数据，不是可随时重建的 UI 缓存：

- 外层下标对应寄存器序号；单寄存器行长度为 1，范围行长度等于
  `registerCount`；
- 内层下标对应 bit 0..15，每个寄存器内层长度为 16；
- 某寄存器所有位都为空时该外层元素为 `null`；整体为空时字段为 `null`；
- 范围长度变化时按寄存器序号保留、截断或补齐，不能与寄存器范围错位；
- 位值本身不是新事实源，仍由 `registerValues` 导出和写回。

是否持久化寄存器原始值应采用明确策略。

建议：

- 持久化最近成功值仅用于恢复显示（单行=`registerValues[0]`，范围行=整组）；
- 恢复后仅作为普通单元格文本展示，不视为当前设备实时值；
- 不持久化正在进行的请求状态；
- 不持久化运行时错误对象；
- 不自动恢复正在运行的轮询任务。

PRD 要求恢复轮询配置状态，但应用启动保持离线。因此恢复的是 pollingEnabled 配置，不是自动启动实际请求。

### 2.4 ConnectionProfile

RTU 配置：

    RtuConnectionProfile
      id
      name
      protocol
      baudRate
      dataBits
      stopBits
      parity
      flowControl
      slaveAddress       // 0~255，默认 1；0 不触发广播写入
      requestTimeoutMs
      retryCount
      recentPortHint

> **持久化边界（2026-08-17 确认）**：工作区持久化「除串口/端口选择外」的全部连接配置——
> 端口参数（baudRate、dataBits、stopBits、parity、flowControl）与 requestTimeoutMs、
> retryCount 均随工作区保存。串口/端口选择本身是
> 运行时会话状态（浏览器侧每次打开 Connection Settings 处于待选状态），不进入持久化；
> recentPortHint 仅作端口提示（docs/AGENTS.md §19.3），不用于自动连接。旧数据格式兼容，
> schemaVersion 不变。

TCP 配置：

    TcpConnectionProfile
      id
      name
      protocol
      host
      port
      unitId             // 0~255，默认 0（2026-08-23 确认：MBAP Unit Identifier 为 RTU Slave ID 的 TCP 版本，纯 TCP 忽略寻址、网关场景寻址；与 RTU Slave Address 默认 1 不同）
      connectTimeoutMs
      requestTimeoutMs
      retryCount
      autoReconnect

> **TCP 持久化边界**：TCP 配置随工作区
> 持久化（host/port/unitId/requestTimeoutMs/retryCount；
> connectTimeoutMs/autoReconnect 默认值随 profile 保存）。恢复后保持离线、不自动连接；
> Unit ID 与 RTU 每表从站地址同构——工具栏
> 按协议切换「Slave Address / Unit ID」，每表独立值经 `session-set-unit-id`（远程端）对
> 后续请求生效；连接建立时按活动表值覆盖 profile.unitId 初始值。

串口路径不作为必须恢复项。

recentPortHint 只能用于显示最近使用信息，不得触发自动连接。

### 2.5 测试连接对象

仓库根 `config/connections.json` 只保存真实端口 E2E、探针和验证脚本使用的连接对象。
它是测试输入，不是工作区模型、应用启动配置或用户可见的“载入连接配置”功能。

应用连接对象由工作区 `connectionProfiles` 持久化；跨端共享通过工作区导入导出完成。
测试文件可以包含串口名，因为测试编排需要打开固定主站口；该串口名不得被复制进
`connectionProfiles`，也不得触发应用自动连接。

### 2.6 ReadVerifySettings

    ReadVerifySettings
      mode
      delayMs

mode：

- off；
- immediate；
- delayed。

当 mode 为 delayed 时，delayMs 只能为允许的配置值。

`ReadVerifySettings` 挂载在每张 `RegisterSheet`，不是工作区全局设置。新表默认
`{ mode: "immediate", delayMs: null }`。旧工作区的全局 `readVerifySettings` 必须在迁移中
复制到各表后删除；缺失新字段时由 Schema 默认值提供策略。

范围行使用同一设置完成“一次多值写入 → 可选延迟 → 读取相同数量 → 逐项比较”，
结果使用数组，不把多寄存器结果拆成彼此独立的写事务。

### 2.7 PollingSettings

    PollingSettings
      enabledBehavior
      maxPendingPollingTasks

MVP 不设独立的全局轮询间隔配置，也不提供每行间隔。轮询读完一个目标后立即重新入队；上一个轮询仍在等待或执行时跳过本轮，不形成积压。实际刷新周期由通信耗时和调度决定。

MVP 中 maxPendingPollingTasks 由系统内部控制，不提供给普通用户配置。

### 2.8 PanelLayout

包含：

- 侧边栏展开状态；
- 侧边栏宽度；
- 底部面板展开状态；
- 底部面板高度；
- 当前底部标签页；
- 可选表格列宽；
- 可选表格列显示状态。

布局数据损坏时使用默认布局，不影响核心工作区恢复。

### 2.9 Preferences

工作区偏好至少包含界面语言和主题预设：

    Preferences
      language
      themePrimary       // string | null

`themePrimary = null` 表示跟随 Ant Design 默认主题色；非空值是已安装插件
注册的完整预设 ID `<pluginId>:<colorId>`。预设不存在、插件被禁用或卸载时
回退默认色。

已安装插件、启用状态、执行模式和 `entrySource` 属于应用级资产，不属于
工作区模型，也不得随工作区导入导出。

## 3. 错误模型

### 3.1 结构化错误

所有应用可识别错误使用 MamepError。

建议字段：

    MamepError
      code
      category
      severity
      retryable
      userMessageKey
      technicalMessage
      cause
      context

category：

- validation；
- capability；
- permission；
- connection；
- transport；
- timeout；
- protocol；
- modbus-exception；
- cancellation；
- persistence；
- plugin；
- internal。

UI 不通过字符串匹配判断错误类型。

### 3.3 用户信息与技术信息分离

用户界面显示：

- 简短原因；
- 可执行建议；
- 相关字段；
- 是否可以重试。

诊断日志保存：

- 底层错误；
- 堆栈；
- 平台错误码；
- 请求上下文。

不得直接把未知异常堆栈作为主要用户提示。
