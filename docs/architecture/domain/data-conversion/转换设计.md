# 数据类型转换设计

## 1. packages/data-conversion

包含：

- 16 位 HEX；
- 16 位 Binary；
- Unsigned；
- Signed；
- 十进制定点缩放；
- Boolean 0/1；
- IEEE 754 float32 / float64；
- 输入解析；
- 输出格式化；
- 精度和范围校验；
- 原始值与展示值转换；
- 地址格式化。

该包必须保持为纯函数包。


## 2. 数据类型转换设计

### 2.1 原始值

内部统一使用 0 至 65535 的 16 位无符号整数表示寄存器原始值。

创建 RawRegisterValue 时必须验证：

- 是整数；
- 大于等于 0；
- 小于等于 65535。

通信层只处理 RawRegisterValue，不处理格式化字符串。

### 2.2 有符号转换

Signed 16 位解释规则：

- 原始值小于 0x8000 时，值不变；
- 原始值大于等于 0x8000 时，解释为 rawValue - 65536。

允许范围：

-32768 至 32767。

### 2.3 缩放类型

缩放类型使用十进制定点数，不使用二进制浮点直接判断输入精度。

缩放因子：

- 0.1：10；
- 0.01：100；
- 0.001：1000；
- 0.0001：10000。

写入转换：

    rawNumeric = decimalInput × scaleFactor

要求：

1. 输入小数位不得超过类型允许精度；
2. 转换结果必须为整数；
3. Signed 和 Unsigned 分别校验范围；
4. 不进行无提示四舍五入；
5. 不进行无提示截断；
6. 不接受科学计数法；
7. 本地化逗号和小数点必须先由 UI 规范化，不得直接进入协议转换。

可以采用成熟十进制运算库，或通过字符串解析实现确定性的十进制转换。不得依赖浮点误差容忍来判断是否合法。

### 2.4 HEX

显示规则：

- 固定 4 位；
- 大写；
- 不包含 0x 前缀。

输入规则：

- 可接受可选的 0x 前缀；
- 可接受大小写；
- 去除首尾空格；
- 最多 4 位有效十六进制字符；
- 超出范围时返回结构化错误；
- 不无提示截断。

### 2.5 Binary

显示规则：

- 固定 16 位（单寄存器）；范围行宽度 = `registerCount × 16`；
- 每 8 位一组、组间单空格：16 位 `00000000 11111111`；32 / 48 / 64 位分别为 4 / 6 / 8 组；
- 只包含 0 和 1。

输入规则：

- 忽略任意空白（首尾、中间的空格 / 制表 / 换行），与显示对称（可粘贴已分组文本）；
- 不接受 0b 前缀；
- 最多 16 位（单寄存器）/ `registerCount × 16` 位（范围行），按去空白后的位数校验；
- 超出范围时返回结构化错误；
- 不足位数可以在提交后补零显示（并按 8 位分组）。

### 2.6 Type 切换

Type 或 Scale 切换时，Data 列必须立即按新类型显示同一数值：

- 先按切换前的 Type 解析当前 `cellText`，再按新 Type 格式化并写回
  `cellText`；
- 例如读回 HEX `00AB`，切到 Unsigned 显示 `171`，切到 Binary 显示
  `00000000 10101011`；
- 绝不按新进制重新解释旧文本。`171` 从 Unsigned 切到 HEX 必须是 `00AB`，
  不能变成 `0171`；
- `registerValues`、设备报文和目标地址不变；
- 当前文本为空或按旧 Type 解析失败时保留原文，只更新 Type，不得写入 0；
- 刷新显示不属于新的编辑步骤，Type 切换与文本刷新在撤销栈中仍是一步；
- 撤销/重做恢复 Type 时应用同一规则，避免留下“类型 A + 文本 B”的错写风险；
- 不允许因为 Type 切换而写入设备；
- 不修改通信报文；
- 不修改地址。

### 2.7 多寄存器组合类型

范围行（Address 列 `start-end`，`registerCount>1`）按组合解释，一次请求读写全部连续寄存器：

- 32 位整数：2 个寄存器，大端合并 `values[0]<<16 | values[1]`（有符号按 32 位补码解释）；
- 64 位整数：4 个寄存器，BigInt 合并（`hi32<<32n | lo32`），输入/显示用 BigInt，超出 2^53 不丢精度；
- 二进制：1/2/3/4 个寄存器，位串按每 8 位一组显示（16/32/48/64 位 → 2/4/6/8 组）；
- 十六进制：任意数量，显示为空格分隔的 4 位大写组（如 `0400 0401`），解析兼容连续串；
- 字符串：任意数量，ASCII 编码，每寄存器 2 字符（高字节在前）。

scale 作用于组合十进制值（沿用 §16.3 十进制定点运算，防浮点误差）。

合法寄存器数校验（跨字段：范围长度 × 类型合法集，错误显示在进制列并禁止该行读写）：

- Unsigned/Signed：1 / 2 / 4；
- float32：严格 2；float64：严格 4；
- Binary：1 / 2 / 3 / 4；
- HEX 与 String：任意数量；
- 整体默认 1。

字节序固定为默认大端（高字在前，Modbus 惯例）；字节序和字序配置不属于当前版本范围。

#### 提交与粘贴后规范化

Data 单元格提交成功、或从剪贴板粘贴时，按该行 Type 写回**规范显示形式**（与读取后格式化同源：
`formatRawValue` / `formatRawValues` / 插件 `resolver.format`）：

- hex：4 位大写、无 `0x`；unsigned/signed：十进制去 `+` 与前导零；带 scale：按类型固定小数位；
- binary：每 8 位一组；hex 范围行：每寄存器 4 位大写、单空格；
- string：ASCII，补齐到 `2 × registerCount` 字符；bool：`0` / `1`；插件类型：由插件格式化器决定。

整数和定点类型的规范化不做任何舍入或截断（超范围 / 超小数位仍返回结构化错误）；浮点类型按下述规则自动舍入。解析失败时保留用户输入
（提交路径红框 + Tooltip、粘贴路径保留原文）。写入请求内容不受影响（仍按同一解析值组帧）。

工作区导入不做显示规范化，保持交换格式保真；旧文件中的无空格 Binary 或非规范
文本在下次提交、粘贴或设备读取时再自然变成规范形式。这使得
“导出 → 导入 → 导出”不会因单纯加载而改变用户数据。

#### IEEE 754 浮点类型

**Base behavior**：内置类型不包含浮点数；整数和定点类型拒绝超出范围或小数位限制的输入。

**Current behavior**：新增 `float32` 和 `float64`，分别使用 2 和 4 个连续原始 word。
高字在前，每个 word 的高字节在前；不提供字序或字节序配置，不应用 scale。

- 输入支持十进制和科学计数法。Enter、失焦等提交操作以及粘贴规范化按 IEEE 754
  最近值舍入，中点取偶数；自动覆盖输入，不弹出提示或确认。
- `float32` 直接从十进制输入计算单精度舍入，避免先转为双精度后在单精度中点附近发生二次舍入；
  `float64` 使用 JavaScript 的双精度转换。
- 显示使用转换后数值的可往返十进制文本，保留 `-0`。例如 `float32` 输入 `0.1`
  提交后显示 `0.10000000149011612`；`float64` 输入 `9007199254740993`
  提交后显示 `9007199254740992`。
- 拒绝 NaN、Infinity、溢出和非零输入舍入为零；允许有限非规格化数。
  错误保留原输入，不生成写请求。读取到非有限位模式时保留原 Data，记录转换失败。
- 提交后同时更新规范文本与原始 word；批读、轮询和写后回读使用相同的解释。
  写后回读逐 word 比较，通信日志保留原始报文字节，不比较十进制显示文本。
- 范围子行仍表示单个 16 位 word，不能选择浮点类型；继承浮点父行类型时使用 HEX。
  子行或位编辑若产生非有限浮点值，拒绝本次编辑并保留父行原值。
- Trace 通过可选 `rawValues` 传递原始 word，格式化和统计直接解码这些 word；
  不从可能丢失低位的组合 Number 重建浮点数。旧 Trace 消息仍可解析，缺少原始 word
  的浮点样本不进入显示或统计。
- 类型标识使用现有开放字符串字段，原始值仍为 16 位 word 数组，不改变工作区存储格式。

源码：[浮点转换](../../../../packages/data-conversion/src/floating-point.ts)、
[组合转换](../../../../packages/data-conversion/src/multi-register.ts)、
[单元格提交](../../../../packages/register-table/src/cell-text.ts)。

### 2.8 插件数据类型

数据类型标识是开放字符串，但只有以下来源可被解释：

- `data-conversion` 的内置类型；
- 已启用且激活成功的插件通过 `DataTypeRegistry` 注册的类型。

解析和格式化通过 `DataTypeResolver` 注入。插件处理器至少提供 parse、format 和
合法寄存器数量；插件类型当前只允许单寄存器，组合/范围行继续使用内置类型。
未注册类型的解析返回结构化错误，不得把文本静默当作 HEX；格式化设备原始值时
可保留“未注册 formatter 防御性回退 HEX”的边界，避免不得写入的读取路径因插件
缺失崩溃。该回退不使未知类型变成可编辑的已知类型。`isSigned`、缩放和进制能力
只看内置元数据，不能通过类型名称前缀猜测。

单元格解析、范围合法性、剪贴板 CSV 白名单、Type 下拉和读取值格式化必须使用
同一个 resolver。插件被禁用、卸载或激活失败后，其类型不得继续出现在 UI 或
参与解析。

## 3. 寄存器地址设计

### 3.1 内部表示

内部地址使用 0 至 65535 的整数。

地址显示进制由所属表的 `registerRadix` 决定，新建表和缺失字段的旧数据默认 DEC：

- DEC：十进制文本，不补前导零；
- HEX：1–4 位输入，提交后规范为 4 位大写，不带 `0x` 前缀。

例如：

- DEC 下用户输入 1，提交后显示 `1`；
- HEX 下用户输入 `1`，提交后显示 `0001`；
- 内部值为十进制 1。

范围行：Address 列支持 `start-end` 范围输入（按当前进制，
HEX 如 `0400-0401`、DEC 如 `1000-1001`），内部记录起始地址 + `registerCount`，范围 =
[start, start+count-1]；单地址输入等价于 count=1。

### 3.2 编辑状态和提交状态

地址字段分为：

- addressDraft；
- addressValue；
- addressValidation。

编辑中允许暂时存在不完整内容。

在以下时机提交：

- Enter；
- 单元格失焦；
- 用户执行读取或写入；
- 全表读取快照创建。

提交结果：

- 合法：更新 addressValue 并规范化显示（HEX 4 位大写补零 / DEC 去前导零；范围行两端各自规范化）；
- 空白：addressValue 为空（addressDraft 归一为 `""`）；
- 非法：保留 addressDraft 并显示错误；
- 超范围：保留 addressDraft 并显示错误。

不得在校验失败时清空用户输入。

### 3.3 表级地址变换

地址变换属于 `addressTransform` 插件贡献点，不在核心写死厂商规则。每张表保存可选 `AddressTransformConfig`；未配置时不调整地址。

插件 `builtin-address-adjust`（用户手动安装）提供
“发送地址 = 用户输入地址 − 1”的变换；表级配置默认关闭。变换必须返回结构化结果：

- 用户地址、变换 ID 和最终发送地址进入请求上下文与通信日志；
- 变换失败或地址下溢时保留用户输入、拒绝发送请求；
- 协议层只接收已验证的最终发送地址，不了解插件内部规则；
- 插件禁用、卸载或表配置失效后不得继续应用旧变换。
