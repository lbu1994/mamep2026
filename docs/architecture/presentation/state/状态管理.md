# 前端状态管理

## 1. 状态管理

采用 Zustand 管理 UI 和应用层状态。

状态分为四类：

1. 领域持久状态；
2. 运行时连接状态；
3. 通信任务状态；
4. 纯界面状态。

### 1.1 领域持久状态

包括：

- 工作区；
- 标签页；
- 寄存器行；
- 通信配置；
- 轮询配置（不含每行 WP 开关）；
- 备注；
- 主题和布局设置；
- 插件启用配置。

这些状态通过工作区仓储保存。

每行 TM/WP 选择只在当前打开期间保留。自动保存不改变内存中的选择，但保存的
`traceEnabled` 和 `pollingEnabled` 固定为 `false`；恢复工作区时也忽略旧勾选值。
重新打开应用或刷新网页后，所有行的 TM/WP 均关闭。

### 1.2 运行时连接状态

包括：

- 当前连接状态；
- 当前连接 ID；
- 当前活动协议；
- 串口授权状态；
- 最近连接错误；
- 当前连接能力。

运行时连接状态不直接写入工作区。工作区仅保存允许恢复的配置。

### 1.3 通信任务状态

包括：

- 队列长度；
- 当前任务；
- 批量读取进度；
- 轮询运行状态；
- 取消状态；
- 当前重试次数；
- 实际轮询周期统计。

通信任务状态由通信服务提供，UI Store 只保存显示所需的投影。

### 1.4 纯界面状态

包括：

- 当前活动标签页；
- 侧边栏展开状态；
- 底部面板高度；
- 当前表格选择；
- 对话框状态；
- 筛选条件；
- 日志自动滚动状态。

纯界面状态不得反向驱动协议层的隐含行为。

### 1.5 编辑历史状态

撤销栈与重做栈属于内存中的工作区编辑历史，不是领域持久状态：

- 只记录工作区编辑命令，不记录设备读取结果、已发送写入、连接状态、通信日志或临时界面变化；
- 批量操作作为一个历史步骤，新编辑发生后清空重做分支；
- 历史容量有硬上限，当前为 100 步；
- 加载、导入、重置工作区时清空全部历史；
- 刷新或重启后历史自然清空，不得进入工作区 Schema。

历史快照应保留当前设备读值等运行时字段；具体命令边界见
[寄存器表应用服务](../../application/register-table/表格服务.md#5-撤销与重做)。

## 2. 启动偏好、首帧与就绪门

### 2.1 异步事实源与渲染窗口

工作区在所有平台都由异步仓储恢复（浏览器/Android IndexedDB、Electron 主进程文件
与 IPC、VSCode Webview 与 Extension Host 存储），React `useEffect` 也只能在首次
绘制后执行。因此只保证“Store 默认值正确”不能消除首帧闪烁，还必须控制何时允许
哪一类界面出现。

启动界面分为两个互补窗口：

- 启动骨架自身可见且必须包含主题、语言和品牌色，所以这些值通过轻量启动缓存
  在 React 首次 render 前同步 hydration；
- 侧边栏布局、底部面板、标签页、表和行数据、备注以及插件贡献等全部由工作区或
  插件派生的外壳状态，在异步事实源落定前不进入可交互外壳。

不能把整个工作区复制到 `localStorage` 来消除外壳闪烁。行数据规模、持久化格式和
插件状态仍只由工作区与插件存储负责；启动缓存不是第二份工作区，也不得成为业务
事实源。

### 2.2 首次绘制前的偏好缓存

启动缓存是带版本的 best-effort 提示，只保存足以正确绘制骨架的最小界面偏好：

- `theme`；
- `language`；
- `themePrimary` 预设 ID；
- 该预设上次成功解析出的主色种子。

启动流程在 `createRoot().render()` 前完成：

1. 同步读取缓存，缺失、损坏、版本不符或字段非法时整体或逐字段回退默认值；
2. 写入 Store 的主题、语言和主题色种子；
3. 同时把语言写入加载前的 `workspace.preferences.language`，避免语言同步 effect
   先用默认工作区值覆盖刚恢复的 `<html lang>`；
4. 初始化 i18n，并同步设置 `<html data-mamep-theme>`、`<html lang>` 等文档根标记；
5. 注册偏好订阅，供正式 Store 值变化后更新缓存。

缓存读写失败（隐私模式、存储被禁用、配额错误等）不得抛到启动主链。工作区加载后
以正式字段覆盖缓存状态；缓存回退只影响首帧表现，不改变持久化事实。插件主题种子的
解析与失效规则见[样式与主题](../ui-theme/主题设计.md)。

### 2.3 分阶段就绪门

全局启动状态至少区分 `assembling`、`ready` 和 `failed`。`ready` 表示 Host 已装配
且工作区已完整读取、迁移、Schema 校验并应用，主外壳可以进入交互。寄存器表继续在
后续独立 commit 中挂载，并以其 `data-startup-hydrated` 作为完整可操作信号。插件恢复
不再阻塞 `ready`，由独立的 `pluginsReady` 终态表示：

    ready => Host 已装配且已完成的工作区结果已应用
    pluginsReady => 插件恢复成功、失败或异常落定

`ready` 前不显示默认空工作区，也不允许编辑或自动保存尚未完成恢复的数据。工作区
仍是侧栏、Tab、表和行的唯一事实源，因此工作区校验与首次应用属于关键阶段；插件恢复、
通信日志/轮询结果接线、轮询目标装配和底部日志面板属于首屏绘制后的非关键阶段。

内部装配顺序为：

1. 同步 hydrate 主题/语言启动缓存并渲染轻量启动骨架；
2. 并行预热工作区解析 Worker，并装配平台 Host 与必要适配器；
3. 等待工作区读取、迁移和 Schema 校验并应用完整结果；
4. 进入 `ready`，分阶段提交主外壳和寄存器表；
5. 首屏绘制后接通信日志、轮询结果和页面生命周期；
6. 恢复已安装插件；无论成功、失败或异常，最后发布 `pluginsReady`。

`setLoaded` 在发布加载完成状态时一次性补齐缺少的核心表类型，保留已有表和有效活动表，
不进入撤销历史。补齐只检查表级信息，不遍历已有行；类型齐全时复用原工作区对象。
补齐复用加载完成的自动保存，不增加逐表更新或异步等待。具体规则见
[启动时补齐核心表](../../application/workspace/工作区.md#223-启动时补齐核心表)。

工作区迁移与 Zod 校验在 Web Worker 中执行，主线程只重建领域值对象。Worker 不可用
时必须回退原同步解析路径，错误码、备份恢复和“主数据损坏不覆盖有效数据”语义不变。
主壳、寄存器表格主体和非关键面板应拆成独立 React commit，避免启动阶段出现单次
超过 200 ms 的 Long Task。

生产组合根先渲染不依赖完整 antd 组件树的启动骨架，并从同步偏好缓存注入已保存的
主题色；Host 与工作区 Worker 先获得启动优先权，完整 `MamepApp` 经公开子路径在
其后空闲预取，工作区就绪后再分阶段挂载。移动端的
表内 Type/Scale 与写后回读控件使用原生 combobox，避免为可视区每行创建完整 AntD
Select 树；桌面仍使用 AntD Select。上述优化只改变调度和等义控件实现，不改变值域、
禁用、变更回调或持久化语义。

插件未完成前可以查看和编辑不依赖插件的基础表数据，但连接入口必须读取最新
`pluginsReady` 状态并在未就绪时拒绝连接，避免使用尚未恢复的 codec、数据类型或地址
变换。恢复工作区仍保持离线，插件恢复也不得触发连接或写请求。

就绪门必须有有限超时（当前默认 5 秒，可由 Host 装配依赖覆盖用于测试）。超时后
显示可理解的双语警告并进入可操作状态，退回“可能发生一次状态跳变”的旧行为，而不
让骨架常驻。StrictMode 双挂载、组件卸载或新一轮装配取消旧流程时，必须先用
`AbortSignal` 守卫所有后续 Store 写入，避免已被取消的加载覆盖新状态。

### 2.4 失效指向兜底

工作区或插件变化后，持久化 UI 状态可能指向不存在的对象：

- `activeSheetId` 必须是同时存在且已经打开的表；否则回退首个打开表，再回退空态，
  并让工作区值成为活动表的唯一权威；
- `activeBottomTab` 必须属于当前可用页签集合；插件卸载导致页签消失时回退
  `messages`，并把纠正后的值写回持久化，不能留下空内容区；
- 失效引用修复发生在加载、导入、重置和插件贡献变化边界，不能在渲染期间静默制造
  第二份持久化选择。

启动行为验收应在 `#root` 首次提交或外壳首次出现时比较稳定态快照，并分别覆盖主题、
语言、主题色、布局、标签页、活动表和表数据。首次绘制断言与“加载后最终状态”断言
必须同时存在，后者不能替代首帧验证。
