# 前端状态管理

## 1. 状态管理

采用 Zustand 管理 UI 和应用层状态。

状态分为四类：

1. 领域持久状态；
2. 运行时连接状态；
3. 通信任务状态；
4. 纯界面状态。

### 1.1 领域持久状态

包括：

- 工作区；
- 标签页；
- 寄存器行；
- 通信配置；
- 轮询配置；
- 备注；
- 主题和布局设置；
- 插件启用配置。

这些状态通过工作区仓储保存。

### 1.2 运行时连接状态

包括：

- 当前连接状态；
- 当前连接 ID；
- 当前活动协议；
- 串口授权状态；
- 最近连接错误；
- 当前连接能力。

运行时连接状态不直接写入工作区。工作区仅保存允许恢复的配置。

### 1.3 通信任务状态

包括：

- 队列长度；
- 当前任务；
- 批量读取进度；
- 轮询运行状态；
- 取消状态；
- 当前重试次数；
- 实际轮询周期统计。

通信任务状态由通信服务提供，UI Store 只保存显示所需的投影。

### 1.4 纯界面状态

包括：

- 当前活动标签页；
- 侧边栏展开状态；
- 底部面板高度；
- 当前表格选择；
- 对话框状态；
- 筛选条件；
- 日志自动滚动状态。

纯界面状态不得反向驱动协议层的隐含行为。

### 1.5 编辑历史状态

撤销栈与重做栈属于内存中的工作区编辑历史，不是领域持久状态：

- 只记录工作区编辑命令，不记录设备读取结果、已发送写入、连接状态、通信日志或临时界面变化；
- 批量操作作为一个历史步骤，新编辑发生后清空重做分支；
- 历史容量有硬上限，当前为 100 步；
- 加载、导入、重置工作区时清空全部历史；
- 刷新或重启后历史自然清空，不得进入工作区 Schema。

历史快照应保留当前设备读值等运行时字段；具体命令边界见
[寄存器表应用服务](../../application/register-table/表格服务.md#5-撤销与重做)。

## 2. 启动偏好与首帧

主题、语言和插件主题色在持久化工作区异步恢复前需要启动缓存：

- 缓存仅用于首帧 hydration，工作区仍是持久化事实源；
- 缓存带版本，缺失、损坏或版本不匹配时回退默认值；
- 在 React 首次 render 前恢复界面偏好和 `<html lang>` / 主题标记；
- 工作区加载后用正式数据覆盖缓存状态；
- 插件主题色在插件恢复前可以使用上次解析颜色种子过渡，插件就绪后以当前注册表为准；
- 启动缓存属于 best-effort，不得阻断应用启动。
