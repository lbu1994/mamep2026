## 1. packages/ui

- 页面布局；
- 顶部应用栏；
- 侧边栏；
- 标签页；
- 寄存器表（含多行选择、行级右键菜单、行级键盘快捷键，见 [ADR-015](adr/ADR-015-行编辑交互与剪贴板决策.md)）；
- 连接配置；
- 日志面板；
- 插件页面；
- 设置页面；
- 通用组件；
- 可访问性工具；
- UI Store。

## 3. UI 组成与 ViewModel

共享 UI 至少包含：

1. AppShell；
2. TopBar；
3. Sidebar；
4. SheetTabs；
5. RegisterToolbar；
6. RegisterGrid；
7. BottomPanel；
8. ConnectionDialog；
9. PluginManager；
10. SettingsView；
11. StatusIndicator；
12. NotificationCenter。

UI 不直接消费复杂领域对象，而使用 ViewModel。例如
`RegisterRowViewModel` 可以包含：

- `rowId`；
- `displayIndex`；
- `name`；
- `addressText`；
- `addressError`；
- `pollingState`；
- `readButtonState`；
- `cellText`；
- `writeValidation`；
- `dataType`；
- `operationState`；
- `statusText`。

ViewModel 由 Selector 或 Presenter 生成，组件不重复业务判断，也不依赖 Ant
Design Table 的内部数据结构。

## 4. 表格编辑呈现

Data 单元格使用受控 Input，编辑直接更新 Store 行数据：

1. 输入变化即时写入单元格当前值；
2. 无编辑会话、草稿或提交事务；
3. 读取成功结果无条件覆盖单元格内容，包括用户正在输入时；
4. 单元格值存放在 Store 行数据中，不随虚拟化卸载丢失；
5. 读取失败不修改单元格内容；
6. 写入校验失败不清空单元格内容；
7. Type 切换不改写单元格文本。

设备读取、写入和回读的完整语义见
[全表读取与写后回读](../../application/communication/读写流程.md)。

## 5. 可访问性与可用性

可访问性要求：

- 所有图标按钮具有辅助文本；
- 表格使用适当的 ARIA 语义；
- 单元格错误与编辑器关联；
- 焦点状态清晰；
- 状态不只依赖颜色；
- 动态读取不抢夺焦点；
- 日志自动滚动可暂停；
- 频繁轮询使用非侵入式更新；
- 键盘可完成核心任务；
- 对话框具有焦点圈定和关闭后焦点恢复；
- 表格虚拟化不破坏屏幕阅读器的基础导航；
- 界面缩放后核心操作仍可使用。

可用性要求：

1. 首次使用者无需阅读完整帮助即可完成连接、填写地址和读取；
2. 高频操作直接位于主界面；
3. 输入项显示名称、单位、范围或示例；
4. 禁用操作说明原因；
5. 错误提示包含问题和可执行的解决方法；
6. 连接、读取、写入和轮询提供明确的进行中状态；
7. 长时间操作允许取消；
8. 操作失败后不得无提示清空用户输入；
9. 多端使用相同的名称、位置和行为语义；
10. 专业术语保持一致。

## 6. 国际化

界面文案使用集中式资源键，业务层不拼接用户文案。当前共享 UI 使用
React i18n 资源，支持中文和英文扩展。

要求：

- 错误使用 message key 和参数；
- 原始报文不翻译；
- Type 内部值不本地化；
- CSV 和工作区字段名不依赖界面语言；
- 时间可以通过平台 Locale 格式化；
- 数字协议转换使用固定规则，不使用本地显示格式作为协议输入；
- 通信术语在各语言中保持一致；
- 十六进制地址始终按协议规则处理。

## 7. 标签页菜单

标签页右键菜单采用现代编辑器通用交互：

- 重命名；
- 复制；
- 关闭；
- 关闭其他；
- 关闭右侧；
- 调整顺序。

批量关闭前必须提示将影响的标签页数量。关闭标签页属于非破坏性的视图状态，
不进入撤销/重做栈；删除标签页及其数据才属于结构编辑。
