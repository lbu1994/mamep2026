# 样式与主题

## 1. 样式和主题

UI 组件框架统一采用 Ant Design，主题通过 ConfigProvider 主题令牌管理：

- Ant Design ConfigProvider token 体系；
- defaultAlgorithm 与 darkAlgorithm 切换浅色和深色主题；
- 基于 antd token 扩展的语义令牌；
- 平台主题适配层；
- @ant-design/icons 图标。

基于 antd token 扩展的语义令牌至少包括：

- 品牌强调色；
- 在线、警告、错误和离线语义色；
- 表格行高；
- 单元格边距；
- 焦点轮廓；
- 轮询和操作状态色。

VSCode 端通过主题适配层将 VSCode Theme Color 映射到 antd token，保持三端主题一致。

自定义 CSS 不能只给控件父容器设置文字色并假定原生表单控件会继承。`input`、
`textarea`、`select` 等 UA 控件必须显式使用 antd 背景、文字和边框语义令牌；
同类编辑器（例如页签与侧边栏的 Rename 输入框）共享同一套令牌映射。不得依赖
浏览器默认白底黑字，也不得以 `color-scheme` 代替应用主题令牌。

## 2. 默认主题色与派生规则

默认品牌色不保存浅色/深色十六进制字面量，而是在运行时通过 Ant Design 公开 API
`theme.getDesignToken({ algorithm })` 获取：

- 浅色使用 `defaultAlgorithm`；
- 深色使用 `darkAlgorithm`；
- Ant Design 升级默认色后应用自动跟随；
- 自定义 CSS 品牌变量映射 antd CSS 变量，不维护第二份色值。

禁止把已经派生后的颜色重新作为 `token.colorPrimary` 种子传回带 algorithm 的
`ConfigProvider`，否则会发生二次派生，导致 CSS 变量与实际渲染颜色不一致。

插件主题色只提供单一明亮主色种子；暗色主色、hover 和 active 由 antd 算法派生。
插件被禁用或卸载后，当前预设失效并回退默认色。VSCode 适配保留品牌/状态色，中性色
继续跟随编辑器主题。

### 2.1 启动时解析插件主题色

主题预设 ID 可以在工作区异步加载前恢复，但插件贡献的颜色值必须等插件注册表就绪后
才能解析。为避免外壳和启动骨架先绘制 antd 默认蓝，启动缓存还需要保存该预设上次
成功解析出的主色种子，并在首次 React render 前完成 hydration。解析规则为：

- 插件已就绪且预设可解析时，以当前插件注册结果为唯一权威；
- 已选择预设但插件尚未就绪时，只使用与当前预设匹配的缓存种子过渡；
- 未选择预设，或插件已就绪但预设不可解析（禁用、卸载、贡献缺失）时，回退应用
  默认主题色，不得继续使用陈旧种子；
- Host 装配在插件启动流程落定后发布明确的“插件就绪”信号；成功、失败或异常落定
  都结束过渡态，插件失败不能让旧颜色永久生效；
- 就绪后仅在解析结果变化时回写缓存，防止 Store 更新、重渲染和缓存订阅形成循环；
- 插件首次在本设备解析且尚无种子时允许短暂回退默认色；这是缺少输入来源时的明确
  边界，不通过延长启动骨架掩盖；
- Host 在插件启动前就进入不可恢复的装配失败时，UI 不可操作，允许继续使用缓存种子
  作为退化视觉；这是宿主不可用的视觉兜底，不得用于正常插件禁用/卸载路径。

### 2.2 固定预设模型

主题色是受控预设，不是任意取色。内置预设只有一个“Ant Design 默认色”；插件可以
以纯数据方式注册一个或多个色板：

    colors: Array<{
      id: string;
      titleKey: string;
      colorPrimary: string;
    }>

`id` 在插件内唯一。插件注册色只增加 Settings 的可选项，不因插件启用而自动覆盖
全局主题。暗色主色、hover、active 和链接相关派生值由 antd 算法生成，插件不维护
浅/深两套字面量。

工作区保存 `preferences.themePrimary: string | null`：

- `null` 表示内置默认色；
- `<pluginId>:<colorId>` 表示插件预设；
- 旧版任意 HEX 或 `{ light, dark }` 值迁移为 `null`；
- 预设解析不到时回退默认色，不缓存插件已卸载后的颜色。

Settings 使用单个主题色 `Select`，第一项恒为默认色，后续项来自当前启用且已成功
注册的插件色板。选择默认色等价于重置，不另设重置按钮。插件色不做运行时 AA
守卫或警告；插件作者负责提供可用对比度的种子色。

主题装配链为“选中的预设或默认色 → 平台主题覆盖”。插件主题不得作为启用即生效
的最高优先覆盖层；插件色必须由用户明确选择。

## 3. VSCode 主题适配

### 3.1 颜色来源与边界

Extension Host 只负责提供浅色/深色模式语义和主题变化事件，不跨进程传递完整 Workbench
色板。VSCode Webview 会把当前主题解析后的颜色注入为 `--vscode-*` CSS 自定义属性，
渲染端应从这些 CSS 变量获取实际颜色。

HostMessage 仍只使用：

- request `get-color-theme`；
- event `color-theme-changed`。

完整颜色映射在 Webview 侧完成，不新增宿主消息 kind，也不把 DOM 或 CSS 能力引入
`ui-theme` 纯函数包。

### 3.2 packages/ui-theme

VSCode 适配层包含：

- `base.ts`：基础主题、字体栈和通用设计令牌；
- `theme-colors.ts`：受支持的 `--vscode-*` 变量清单、从注入源读取，以及缺失值回退；
- `contrast.ts`：颜色解析、相对亮度、对比度、混合与最低对比度修正；
- `map.ts`：把 VSCode 中性色、表面色、边框色和组件色映射为 antd token override；
- `merge.ts`：基础主题与平台 override 的 token/组件浅合并；
- `build.ts`：生成最终 `buildVscodeTheme(colors, dark)`。

`ui-theme` 只依赖 Ant Design 和纯函数能力。DOM 读取由 Host/Webview 装配层注入，
避免主题包依赖浏览器全局对象。`theme-colors` 提供独立子路径导出，供开发模式 HTML 中继
脚本共用变量清单，不引入 antd。

### 3.3 映射策略

映射遵循“中性色跟随宿主，品牌与状态语义保持产品一致”：

- 背景、表面、边框、输入态、选择态和文字灰阶跟随 VSCode；
- 品牌主色、链接色、成功、警告、错误、字体、间距和圆角来自产品基础主题；
- 文字 alpha 从前景色派生，并通过对比度修正保证正文和交互文本可读；
- 缺失或非法 CSS 变量回退基础主题，不产生透明、未定义或仅颜色可辨识的状态；
- 高对比度主题先映射浅/深基础模式，再以高对比度 CSS 变量覆盖中性色和边框。

映射结果只覆盖必要 token，不能把已经派生的 Ant Design 色值再次作为主色种子交给算法，
避免二次派生。

### 3.4 运行时装配

共享 UI Store 保存运行时派生的 `themeConfig`。`ConfigProvider` 使用：

1. `themeConfig` 非空时应用平台主题；
2. 否则使用基础主题算法。

`themeConfig` 属于运行时状态，不写入工作区。浏览器、Electron 和 Android 不设置该值，
继续使用基础主题；VSCode Host 在首次装配和主题变化事件中读取 CSS 变量、重建主题并更新
Store。

主题变化事件与 CSS 变量刷新不保证同一帧到达。实现应在事件后立即读取一次，并在下一帧
幂等重读一次；读取失败必须回退基础主题，不能保留上一工作区的残留色板。

### 3.5 开发模式 iframe

开发模式通过 Vite server 将共享 UI 放在 iframe 中，CSS 自定义属性不会跨 iframe 文档
继承。主 VSCode Webview frame 与 iframe 之间使用 dev-only 中继：

1. 主 frame 读取当前 `--vscode-*` 颜色；
2. 在加载、主题事件转发和响应 iframe 请求时发送主题颜色消息；
3. iframe 将收到的变量物化到自身文档根；
4. 共享 UI 之后按生产同一路径读取和构建主题。

中继消息使用独立 `source/type`，不能伪装成 HostMessage Envelope，也不能被转发回 Extension
Host。生产构建不得依赖中继脚本。

### 3.6 验收

自动化至少覆盖：

- VSCode CSS 变量读取、缺失值回退和明暗/高对比度映射；
- 正文、次级文本和占位文本的对比度阈值；
- 基础主题与 override 合并后的组件 token；
- Webview 首次装配、主题事件后重建和失败回退；
- 开发模式主 frame 到 iframe 的中继，以及生产 Webview 的直接读取；
- 切换 VSCode 浅色/深色主题后面板实时更新、关闭重开正确、无控制台错误。
