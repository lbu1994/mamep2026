# 待确认技术事项

## 1. 待确认技术事项

以下事项需要在原型验证或产品决策完成后确定，不应在实现中自行假设。

### 1.1 串口库最终选型

已选择 `serialport@13`，并通过 Fake、Windows com0com 虚拟串口、Electron 探针和 VSCode Extension Host 接线验证基本可行性。Node Serial Adapter 作为唯一封装边界，库类型不得进入核心契约。

仍需目标环境验证：

- macOS 与 Linux 的枚举和真实设备；
- Electron 打包后按 Electron ABI 重建的绑定加载；
- VSCode 发布包中的绑定与扩展宿主 ABI；
- 真实 USB 串口驱动的拔出、占用和权限错误；
- 1.5 位停止位；
- XON/XOFF 与 RTS/CTS 的实际能力矩阵；
- 长时间轮询、分片、重试和资源释放。

### 1.2 浏览器停止位和流控能力

需要根据 Web Serial API 和目标浏览器实测确认：

- 1.5 位停止位是否可配置；
- XON/XOFF 是否可用；
- RTS/CTS 是否可用；
- 不支持时是隐藏选项还是显示禁用状态；
- 浏览器端通信配置如何与另外两端保持语义一致。

平台不支持的参数不得被静默忽略。

### 1.3 从站地址与 Unit ID 范围

RTU Slave Address 已确认（ADR-013）：允许范围 0~255，默认 1；地址 0 允许配置（广播语义，按标准无应答）；MVP 不实现广播写入。

TCP Unit ID 已确认（2026-08-23）：允许范围 0~255，允许 255，默认 0。MBAP Header 的 Unit Identifier 是 RTU Slave ID 的 TCP 版本：纯 TCP 通信中常被忽略（默认 0），经网关访问 RTU 从站时才是必要寻址字段。UI 字段名按协议动态显示：RTU 显示 "Slave Address"，TCP 显示 "Unit ID"（工具栏按协议切换已落地，2026-08-25，ADR-026；Unit ID 会话内可经工具栏动态修改，每表独立）。

仍待确认：

- 插件是否可以提供厂商专用范围校验；
- 地址 0 下除读写外哪些操作可用（RTU 0 为广播语义、不实现广播写入；TCP 0 为忽略寻址，语义不同，需分别说明）。

### 1.4 轮询间隔（已确认，2026-09 更新）

2026-09-06 更新：Rx Delay 已从 RTU、TCP 配置、工作区 Schema 和请求调度器中移除
（ADR-013 的旧方案由后续产品决策取代）。当前 WP 轮询不设独立全局间隔，也不提供
每行间隔；读完一个目标后立即处理下一个目标。

仍待验证：

- 页面进入后台后的行为；
- 实际刷新速度受通信耗时影响时，如何向用户提示当前能力。

内部仍使用毫秒表达超时、通信耗时和实际周期统计。

### 1.5 Data 单元格交互

已确定采用 Ant Design 表格默认交互：

- 读取值和待写值共用同一个单元格输入区域，内容即当前值；
- 无独立编辑模式、草稿或提交事务；
- 编辑不暂停该行轮询；
- 读取成功结果强制覆盖单元格内容，包括编辑中；
- 读取失败不改动单元格内容、不提示；
- 未启用回读时，写入完成后单元格保持用户输入值；
- 写后回读结果按读取规则覆盖单元格；
- 写入校验失败时提示且不清空单元格内容；
- Type/Scale 切换立即按新类型刷新显示，但原始值不变，且不得按新进制重解释旧文本；
- Enter 无特殊提交行为（与 Ant Design 默认一致）。

### 1.6 工作区文件格式

2026-08-29 已确认并实现（ADR-033）：

- 通过 Settings 提供工作区导入和导出；
- 使用带 `schemaVersion` 的纯 JSON，不压缩；
- 公开交换格式复用工作区 Schema，并排除运行时句柄、Timer、临时 ID 和错误；
- 导入前解析、校验并显示覆盖预览；
- 三端可以相互导入同一格式；
- 通信日志不写入工作区文件。

仍待后续版本决定：

- 寄存器表 CSV 导入导出；
- 更长周期的格式兼容承诺；
- 是否需要流式或压缩格式保存超大数据集。

### 1.7 插件运行隔离

截至 2026-09-12（ADR-054、ADR-055）已确认：

- 所有插件由用户手动安装，不再随应用自动安装；
- 可执行插件默认在隔离 Worker/线程中运行；
- 同进程执行必须在安装确认框中由用户显式授权，并等同于高权限信任；
- Electron Main 和 VSCode Extension Host 已装配宿主侧插件执行面；
- 插件失败不得阻止核心应用启动。

仍需评估：

- 插件崩溃后的自动恢复策略；
- 插件超时和资源限制；
- 插件签名与来源验证；
- 正式插件市场与分发策略；
- 各平台隔离执行能力的长期一致性。

### 1.8 表格组件决策

已确定采用 Ant Design Table，并与 Ant Design 组件框架统一。

原型阶段重点验证：

- 受控输入与虚拟滚动的兼容性；
- 多单元格粘贴；
- 键盘导航；
- 屏幕阅读器支持；
- VSCode Webview 性能；
- 大量实时更新下的渲染表现；
- 列宽拖动和固定列。

替换表格组件不得影响领域层和工作区数据结构。

### 1.9 TM Trace 技术边界

Memory Trace 已纳入核心范围并实现：`traceEnabled` 持久化，数据列表采样走统一
调度器，Continue 缓冲硬上限 10000 条，窗口支持 Play/Stop/Save、Buffer Size、
Speed、No./Data 和 Average。完整设计见
[轨迹追踪](../../application/trace/轨迹追踪.md)。

仍待后续确认：

- Register Trace 实时曲线和长期历史；
- 曲线降采样和外部导出格式；
- Register Trace 由核心还是插件实现；
- 长时间 Trace 是否改为流式文件；
- 多个长期 Trace 的资源上限。

### 1.10 多标签页与连接关系

MVP 假设所有标签页共享一个活动连接，但每张表可以有自己的从站地址、Unit ID
和协议路由配置。

仍需确认：

- 标签页是否需要保存期望的连接配置；
- 切换标签页时是否提示配置差异；
- 后续是否允许不同标签页绑定不同设备；
- 插件是否可以请求独立连接；
- 同一连接被不同协议路由复用时如何展示繁忙和跳过提示。

### 1.11 模块脚本执行前的首帧底图

当前启动偏好缓存只能在模块脚本执行后、React 首次 render 前同步 hydrate。`index.html`
在模块脚本执行前仍可能按浏览器默认白色绘制一帧；要覆盖该窗口，需要在 `<head>` 内
放行一段受 CSP 哈希约束的极小内联脚本，并同时维护 Web 与 VSCode 生产 CSP。该改动
收益主要出现在慢网络或慢模块加载场景，是否需要以 CSP 复杂度换取零白帧仍待确认。
在决定前，首帧测试应以 React 首次提交为边界，不得声称已消除模块脚本之前的白底。

### 1.12 antd Splitter 首帧布局沉降

垂直 `Splitter` 在首次出现时可能先绘制一个中间高度，下一帧才采用受控的持久化
`size`；默认高度和自定义持久化高度都可能出现，因此它不是工作区恢复失败。是否让
容器在首帧前提供确定高度、在挂载前预置尺寸，或接受一次轻微视觉沉降，仍待产品与
交互决策。修复前，启动首帧几何验收可对底部面板高度使用明确容差，但侧栏布局、页签、
活动表和表数据等其他外壳字段仍应严格比较。

### 1.13 Electron 诊断 E2E 与正式套件重复

`tests/e2e-electron/tests/diag-loop.spec.ts` 是 `serial-rtu-loop.spec.ts` 的严格子集：
前者缺少范围行多寄存器读写用例，没有独有覆盖，却增加运行时间和高负载下的 flake 面。
临时诊断文件本应在用完即删、不得进入正式 suite；是否删除该已提交 spec 仍需确认。
删除后现有三例覆盖可由正式套件保留，不应为了减少文件数而丢失范围行覆盖。
