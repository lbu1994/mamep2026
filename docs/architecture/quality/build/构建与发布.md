# 构建与发布

## 1. 构建和发布设计

### 1.1 构建产物

Browser：

- 静态 HTML、CSS 和 JavaScript；
- 可部署到静态站点；
- 不包含 Node.js 依赖；
- 不包含 TCP 功能代码入口。

Electron：

- Windows 安装包（MVP 落地为免安装绿色版：`pnpm dist:portable` 产出 `release/win-unpacked/` 整个文件夹拷贝即用，ADR-018；后续升级 `win.target: nsis` 产正式安装包）；
- macOS 安装包（未落地）；
- Linux 安装包（未落地）；
- 对原生串口依赖执行目标平台构建（MVP 用 Web Serial，暂无原生依赖）；
- Renderer 与 Main 分离打包（ADR-016：`dist-electron/` + `apps/web/dist-electron/`）。

免安装绿色版采用 staging 应用根：

1. `pnpm build:electron` 分别生成自包含的 Main/Preload 和 Electron Renderer 产物；
2. 打包脚本把两份产物按运行时的相对目录复制到 `release/staging-app/`；
3. staging `package.json` 只声明入口和版本，不复制仓库 production dependencies；
4. electron-builder 的 `files` 显式排除 `node_modules`，避免把 antd、React、serialport 等构建期依赖整体带入；
5. 当前使用 `asar: false`，使 `resources/app/` 结构透明，便于排查资源路径问题；
6. 输出 `release/win-unpacked/`，接收方无需安装 Node、pnpm 或桌面运行时。

产物验证必须启动实际打包后的可执行文件，而不是只验证 `electron .` 开发路径。未来 Electron 改用 Node Serial 后，必须把所需原生绑定作为明确运行时资产加入 staging；不得因为当前产物无外部依赖就删除该分支的打包校验。

`release/` 属于生成目录，不进入版本库。图标和版本资源由构建脚本生成；若打包工具需要外部 sign/edit 二进制，应在 CI 预热或使用受控镜像，不能依赖开发机偶然缓存。

VSCode：

- VSIX；
- Extension Host Bundle；
- Webview 静态资源；
- 平台相关原生依赖按发布策略处理。

### 1.2 原生串口依赖

> VSCode 已使用 Node Serial Adapter；Electron 当前仍使用 Web Serial API，若后续替换为 Node 串口库，本节约束立即适用。

串口库可能包含原生模块，需要处理：

- Electron ABI；
- Node.js ABI；
- VSCode 内置 Node.js 版本；
- Windows、macOS 和 Linux 构建；
- x64 与 arm64；
- 发布包体积；
- 原生模块签名。

为降低风险：

1. Node Serial Adapter 与具体库隔离；
2. 建立启动时原生模块自检；
3. CI 在目标平台构建；
4. Electron 和 VSCode 不直接共享已编译的二进制产物；
5. 按目标 Host 分别打包；
6. 原生依赖升级按用户要求执行真实连接回归。

`serialport@13` 的绑定可能按当前 Node ABI 构建。Electron 和 VSCode 的 ABI 不同，执行任何 `@electron/rebuild` 或绑定切换后，原运行环境中的二进制可能不再可用，必须在各自工作目录或 CI job 中分别重建和验证，不能把一次重建结果跨 Host 复用。

### 1.3 CI 流程

持续集成阶段包括：

1. 依赖安装；
2. 格式检查；
3. ESLint；
4. TypeScript 类型检查；
5. 单元测试；
6. 协议测试；
7. 组件测试；
8. 包依赖边界检查；
9. Browser 构建；
10. Electron 构建；
11. VSCode 构建；
12. 端到端测试；
13. 安全和许可证检查；
14. 发布产物生成。

CI 应在 Windows、macOS 和 Linux 上执行必要的平台构建验证。

### 1.4 包依赖边界检查

使用静态依赖检查阻止：

- domain 引用 React；
- protocol-modbus 引用平台包；
- web 引用 Node.js Adapter；
- UI 引用 Electron；
- UI 引用 VSCode；
- Renderer 引用串口库；
- 插件直接引用核心内部未公开模块；
- 平台包形成循环依赖。

### 1.5 版本策略

建议：

- 应用采用语义化版本；
- 插件 API 拥有独立 apiVersion；
- 工作区拥有独立 schemaVersion；
- Host Message 拥有独立 protocolVersion；
- 三者不得共用同一个版本号表达不同兼容关系。

### 1.6 Android 产物

- Android 使用 Capacitor 工程和 `apps/web` 的 `--mode android` 静态产物；
- `pnpm build:android` 执行插件构建、Web 构建、Capacitor sync 和 APK 构建；
- `pnpm build:android:release` 构建 Release APK 与 AAB；底层脚本还支持仅构建 AAB；
- 构建需要 JDK 17/21；JDK 25 与当前 Gradle 8.14 不兼容；
- Android `versionName` 从仓库根 `package.json` 的版本生成；
  `versionCode = major × 10000 + minor × 100 + patch`，不得在 Gradle 模板中
  维护第二份独立版本号；
- Debug 产物用于真机自动化；
- Release 签名材料从本地 keystore 配置或受控环境变量读取；
- 签名材料不完整时只能产出 unsigned APK/AAB 并提示，不得静默复用 Debug key；
- keystore、私钥和口令不得进入仓库、日志或汇报；
- Android 产物与浏览器、Electron、VSCode 产物共用同一套共享 UI 和 CSP 基线。

发布签名的材料来源按序为：

1. `apps/android/android/app/keystore.properties`，该文件必须被忽略且不得入库；
2. `MAMEP_ANDROID_KEYSTORE_PATH`、`MAMEP_ANDROID_KEYSTORE_PASSWORD`、`MAMEP_ANDROID_KEY_ALIAS`、`MAMEP_ANDROID_KEY_PASSWORD` 环境变量。

只有路径、Store 口令、Key Alias 和 Key 口令全部存在时才启用 Release 签名。Windows 绝对路径必须原样保留，不得经过会把反斜杠解释为转义符的 Properties 解析。签名材料缺失时仍可构建 unsigned APK/AAB，但发布流程必须明确提示；脚本不得接收、打印或回显口令。构建成功判定必须检查本次产出的实际文件，不能接受上一次构建遗留的同名产物。

### 1.7 构建级性能约束

- 大型可选 UI 模块使用按需加载；
- 非当前平台的 Host 实现不得进入其他平台首屏执行路径；
- 构建应检查单 chunk 大小和平台专属依赖泄漏；
- 性能优化不得以复制平台业务逻辑为代价。

共享渲染器的分包基线如下：

- 不自定义 `output.codeSplitting.groups`，使用 rolldown 默认分包；默认算法按
  动态入口可达性切分，避免把同一 npm 包内的循环依赖拆到不同 chunk 后破坏类
  初始化顺序；
- 不通过提高 `chunkSizeWarningLimit` 掩盖超限；超过 500 kB 的告警必须通过真实
  拆分解决；
- 非首屏 Help、Settings、Trace Window、工作区导入等覆盖层按需加载；每个懒组件
  使用独立 `Suspense`，首次打开后保持挂载以保留关闭动画；
- `RegisterTable`、`BottomPanel`、快捷键层、启动横幅和启动即自动打开的
  `ConnectionSettingsModal` 属于首屏路径，不得仅为减小入口 chunk 而懒加载；
- 非当前平台的 Host 由运行时平台探测后动态 `import()`，浏览器共用宿主保持静态
  路径；平台桥必须在 Capacitor 探测之前判定，避免宿主内嵌 WebView 误判；
- 动态 import 使用与产物同目录的相对 URL，必须同时兼容 Browser 的 HTTP、
  Electron 的 `file://`、VSCode 的 `vscode-webview://` 和 Android 的
  `https://localhost`；
- 分包验收必须在生产产物上执行，不能以 dev server 的 e2e 代替。至少验证入口与
  懒 chunk 均存在、单 chunk 不超过阈值、`#root` 已挂载、无
  `Class extends value undefined` 等循环依赖症状，并运行 Electron、VSCode 和
  Android 的产物级冒烟或 e2e；
- Android WebView 的 Resource Timing 可能不提供有效的 body size，产物大小
  验证应通过 `fetch(url) → blob.size` 等实际字节读取完成，并断言字节数大于 0。
