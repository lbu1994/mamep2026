# 关键技术难点

## 30. 关键技术难点

### 30.1 三端串口实现差异

难点：

- 浏览器使用授权式 Web Serial；
- MVP 阶段 Electron 与浏览器一致使用 Web Serial（ADR-017），后续版本 Electron 与 VSCode 改用 Node.js 串口；
- 串口参数支持程度不同；
- 设备标识方式不同。

方案：

- 统一 SerialPortPort；
- 使用 Capability Matrix；
- 不把端口路径作为领域规则；
- 不要求浏览器恢复端口；
- 建立三端共享的串口契约测试。

### 30.2 Electron 与 VSCode 原生模块兼容

> 本节针对后续版本 Node 串口库替换阶段（ADR-017）；Electron MVP 使用 Web Serial，不涉及原生模块。

难点：

- ABI 不同；
- 打包环境不同；
- 平台二进制不同。

方案：

- 隔离 Node Serial Adapter；
- 分平台构建；
- 启动自检；
- CI 覆盖目标系统；
- 不把已编译模块跨 Host 复用。

### 30.3 RTU 字节流分帧

难点：

- 数据分片；
- 噪声；
- 部分响应；
- 迟到响应；
- 无事务 ID。

方案：

- 单连接单请求；
- 根据当前请求推导响应长度；
- 使用 CRC 和响应字段校验；
- 超时后清理当前解析状态；
- 记录并忽略迟到数据；
- 真实设备验证。

### 30.4 轮询和手动操作冲突

难点：

- 多来源共享连接；
- 轮询可能积压；
- 手动写入需要及时执行；
- 读取结果按设计直接覆盖输入。

方案：

- 统一 RequestScheduler；
- 公平优先级；
- 轮询去重；
- generation 防止旧结果污染。

### 30.5 虚拟化表格编辑

难点：

- 行离开视口后组件卸载；
- 焦点跳转；
- 多行粘贴；
- 可访问性。

方案：

- 单元格值存放在 Store 行数据中，Input 受控，虚拟化卸载不丢失；
- 使用稳定 rowId；
- 原型先行；
- 建立键盘和焦点自动化测试。

### 30.6 工作区跨版本恢复

难点：

- 后续字段增加；
- 插件字段未知；
- 异常退出；
- 三端存储后端不同。

方案：

- 统一领域 Schema；
- Repository Adapter 分离；
- 版本化迁移；
- 原子保存；
- 备份恢复；
- 持久化契约测试。

### 30.7 插件安全

难点：

- 私有协议需要扩展；
- 任意插件代码具有设备风险；
- 三端能力不同。

方案：

- 区分 UI-safe 和 Host 插件；
- MVP 优先内置和受信任插件（2026-08-23 确认：MVP 仅预留架构、不对用户开放，见 PRD §20.6）；
- 权限声明；
- 统一通信 API；
- 平台能力检查；
- 错误隔离；
- 后续再开放公共安装。

### 30.8 浏览器后台限速

难点：

- 后台标签页 Timer 可能被限制；
- 轮询周期不精确。

方案：

- 不承诺精确实时轮询；
- 使用单调时钟计算实际间隔；
- 不用累计 Timer 假设；
- 页面隐藏时展示状态；
- 可以选择暂停或降低轮询；
- 记录实际刷新周期。
