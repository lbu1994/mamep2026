# Web 真实设备性能验证

本流程补足 `pnpm test:perf:production` 的模拟基线。Lighthouse 慢速 4G/CPU 节流与
Playwright Event Timing 只能证明生产产物在受控实验室环境下可用，不能替代低端 Windows、
真实 Chrome/Edge 或移动浏览器。真实设备验收以本流程导出的本地 JSON 和汇总 Markdown
为证据。

## 1. 验收目标

- 桌面与移动端真实设备均达到项目 3 s 可交互目标；
- 代表性交互真实 INP ≤200 ms；
- 已恢复或导入 1000 行工作区后仍可滚动、编辑和打开 Settings；
- 每个结论都能追溯到硬件、浏览器、网络、数据规模、缓存状态、主题和缩放条件；
- 仍超预算或无法采集 INP 的场景必须保留在最终摘要中，不得从验收表删除。

可交互时间取生产标记 `mamep:startup:interactive`；该标记表示 Host 已装配、工作区已
完整恢复且主外壳可操作。INP 由浏览器 Event Timing 按 `interactionId` 聚合后取 P98，
不是单次点击耗时，也不是 Lighthouse 的实验室近似值。

## 2. 隐私边界

Settings → General → Local performance sampling 默认关闭。打开后只记录：

- 启动、LCP、TTFB、CLS、INP、长任务等性能时序；
- 应用版本、浏览器 User-Agent、语言、CPU 并发数、设备内存提示、视口和 DPR；
- 工作区活动表行数与总行数；
- 测试者声明的缓存状态、浏览器缩放和网络档位，主题与视口自动读取。

不记录用户名、账号、稳定设备 ID、寄存器表行内容、地址、备注、插件私有数据、串口/
TCP 报文或通信日志。数据只写入当前 origin 的 `localStorage`，只有点击
**Export local report** 时才生成文件；应用不提供上传端点，也不会自动发送该报告。

## 3. 前置条件

1. 使用待验收的同一生产构建和部署地址；记录根 `package.json` 版本与部署版本。
2. 设备电量充足，关闭省电模式、锁定刷新率策略和会改变前台性能的系统优化。
3. 桌面使用系统稳定版 Chrome 与 Edge；移动端至少覆盖一台真实低端 Android Chrome 和
   一台 iPhone Safari。浏览器版本必须记录。
4. 网络使用可重复条件，例如同一 Wi-Fi、局域网热点或受控 4G。不要在不记录网络差异的
   情况下混合样本。
5. 工作区使用确定性生成的 1000 行测试数据。不得导出真实客户寄存器表用于验收。
6. 每个场景开始前在 Settings 选择缓存状态与缩放比例，然后刷新页面。冷缓存优先使用
   全新隔离浏览器配置或彻底清除该站点缓存；不能只依赖开发工具“Disable cache”作为
   唯一冷缓存证据。

## 4. 场景矩阵

对每个“设备 × 浏览器”组合执行：

| 维度   | 必测条件                                                                |
| ------ | ----------------------------------------------------------------------- |
| 缓存   | 冷缓存、热缓存                                                          |
| 工作区 | 默认工作区、已恢复/导入 1000 行工作区                                   |
| 主题   | 浅色、深色                                                              |
| 缩放   | 100%、125%、150%（平台不支持精确浏览器缩放时记录实际等效视口/系统缩放） |
| 网络   | 与验收目标一致的 Wi-Fi、局域网或受控移动网络；移动端记录信号类型        |

每个场景至少执行一遍以下代表性交互，再对 Settings 开关、1000 行表格滚动和单元格编辑
重复 20 次，以确保 Event Timing 有足够的真实交互样本：

1. 打开/关闭 Settings；
2. 跳转到 1000 行表格末尾，再滚回顶部；
3. 编辑并提交普通 Data 单元格；
4. 打开工作区导入预览并取消；
5. 切换浅色/深色主题后刷新。

不得为了得到好看的数字只点一次按钮。页面隐藏、切换应用或电量策略发生明显变化时，
放弃当前会话并重新开始。

## 5. 采集与导出

1. 打开 Settings → General，启用 **Collect performance data**。
2. 设置 Cache state、Browser zoom 与 Network，关闭抽屉并刷新以采集该场景启动。
3. 恢复或导入 1000 行工作区，执行第 4 节交互。
4. 等待至少 1 秒，让本地会话落盘；切到后台再回前台也会触发一次 checkpoint。
5. 重新打开 Settings，点击 **Export local report**；文件名为
   `mamep-web-performance-<时间戳>.json`。
6. 将文件按
   `test-reports/field-performance/<设备>-<浏览器>-<缓存>-<主题>-<缩放>.json`
   归档。`test-reports/` 是本地验收输入，不得把真实设备报告写入产品运行时或自动上传。
7. 完成全部场景后，用 **Clear local data** 清理设备浏览器中的采样；导出的验收文件由
   测试负责人留存。

## 6. 汇总与判定

在仓库根运行：

```powershell
$reports = Get-ChildItem .\test-reports\field-performance\*.json |
  ForEach-Object { $_.FullName }
node scripts/summarize-field-performance.mjs @reports --out .\test-reports\field-performance\summary.md
```

只要任一场景的启动可交互时间或 INP 缺失、超过预算，脚本返回非零退出码，并在
“仍超预算或无法确认的场景”中逐项列出。发布验收必须附带：

- 完整场景表；
- 原始本地 JSON 报告；
- 汇总 Markdown；
- 未执行设备/浏览器及原因；
- 超预算场景和对应硬件、网络、数据规模条件。

## 7. 当前结果

截至 2026-11-21，自动化生产基线已存在；真实低端 Windows、Chrome/Edge 和移动设备实机
数据尚未在本仓库中生成。因此在完成上述矩阵并归档报告前，不得把 Lighthouse 移动模拟
结果当作用户设备达标证据。
