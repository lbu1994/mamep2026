# 性能与稳定性

## 1. 性能目标

性能目标用于指导实现和回归，不等同于脱离硬件、操作系统、串口参数和网络
环境的绝对承诺。

### 1.1 启动性能

- 常规设备上首次可交互时间目标不超过 3 秒；
- 恢复普通工作区时不应长时间白屏；
- 插件加载不得阻塞核心界面显示；
- 单个插件异常不得拖延整个应用启动；
- 应用启动后保持离线，不因恢复工作区产生设备请求。

### 1.2 表格性能

- 1000 行寄存器配置可正常滚动和编辑；
- 普通单元格编辑响应时间目标不超过 100 ms；
- 日志持续增长时表格仍保持可操作；
- 大量行采用虚拟化和细粒度订阅；
- 标签页切换不重复创建无必要的通信任务。

### 1.3 通信性能

- 软件额外处理延迟应远低于实际串口或网络通信时间；
- 请求调度不得阻塞 UI 线程；
- 轮询周期短于实际完成时间时不得无限积累任务；
- UI 应展示实际刷新能力受波特率、超时、重试和行数影响；
- 不承诺毫秒级实时控制性能。

### 1.4 稳定性目标

- 单次通信错误不得导致应用崩溃；
- 设备拔出后应用保持可操作；
- 插件崩溃不得破坏核心工作区；
- 日志和 Trace 缓冲必须有上限或归档策略；
- 状态保存失败必须提示且保留内存状态；
- 串口和 TCP 连接必须可以安全释放；
- 关闭标签页、页面、窗口或扩展时不得遗留不可控任务；
- 核心协议与转换逻辑必须具备自动化测试。

## 2. 表格与界面性能

实现措施：

- 行虚拟化；
- 细粒度 Store Selector；
- 稳定 `rowId`；
- 避免单行读取结果导致整个表格重渲染；
- 单元格文本局部更新；
- 日志与表格状态分离；
- 低频保存使用 debounce；
- 批量粘贴作为一个事务；
- 计算型格式化函数缓存或按需执行。

性能验收至少覆盖：

- 1000 行；
- 1000 行中多行周期更新；
- 大量日志；
- 多标签页切换；
- 深色主题；
- 浏览器缩放；
- VSCode Webview。

## 3. 日志与 Trace 性能

- 消息日志、通信日志和 Trace 分别使用有界缓冲；
- 日志列表虚拟化；
- 合并批量事件更新；
- 用户手动离开底部时暂停自动滚动；
- 原始字节延迟格式化；
- 导出在 Host 或 Worker 中执行；
- 不为每个字节创建独立 React 节点；
- Trace 缓冲上限 10000 条，不允许无限增长。

## 4. 通信性能

- Electron 的远程通信在生产路径中由主进程承载；
- VSCode 远程通信由 Extension Host 承载；
- Browser 中不得以同步长任务阻塞 UI；
- CRC、MBAP 和帧解析使用 `Uint8Array`；
- 通信热路径不进行大型 JSON 序列化；
- 日志事件可批量推送到 UI；
- 轮询复用有限数量的 Clock/Timer；
- 所有设备请求统一进入 RequestScheduler。

## 5. Worker 使用边界

当前不强制引入 Web Worker。以下任务达到性能瓶颈后可迁移到 Worker：

- 大型日志导出；
- 大型工作区导入校验；
- Trace 数据处理；
- 大量数据格式转换；
- 曲线降采样。

串口和 TCP 通信仍由对应 Host 能力负责，不因 Worker 引入新的平台业务分叉。

## 6. 性能回归要求

性能回归应记录运行环境、数据规模、平台和通信参数，至少验证：

1. 启动和恢复工作区；
2. 1000 行滚动、编辑、粘贴和键盘导航；
3. 大量行持续更新与轮询；
4. 日志和 Trace 达到上限后的内存占用；
5. 标签页切换；
6. VSCode Webview；
7. 断开、页面隐藏和恢复后的任务数量；
8. 性能优化不改变领域模型、公共契约和平台能力语义。

### 6.1 1000 行寄存器表自动化验收

浏览器性能专项位于
`tests/e2e-web/tests/register-table-1000-perf.spec.ts`，执行：

```powershell
pnpm --filter @mamep2026/e2e-web exec playwright test tests/register-table-1000-perf.spec.ts
```

用例固定构造 1000 行工作区，覆盖普通表的新增、编辑、选择、虚拟滚动、标签页
切换、IndexedDB 自动保存和重复滚动后的 GC 后堆/DOM 稳定性；同时覆盖包含范围行
或位明细的 tree 数据。antd v6 会先按展开状态扁平化 tree children，因此上述派生行
继续使用兼容的虚拟渲染，不再为整表关闭 virtual。

首次可交互、跳转末尾、Event Timing 单元格提交、标签页切换、自动保存、虚拟 DOM
行数和内存快照写入 Playwright 同名 JSON 附件。普通 Data 单元格以重复交互的 Event
Timing 中位数不超过 100 ms 为验收；首屏在开发服务器下记录实际值并以 5 s 捕获
灾难性退化，生产构建的 3 s 目标由独立生产基线执行。

### 6.2 Web 生产性能回归门禁

`pnpm test:perf:production` 固定使用本次生产构建、Vite preview、系统 Microsoft Edge
和 Lighthouse 13.6。测试不读取真实设备报文或用户工作区，1000 行数据由测试代码
确定性生成，报告不包含工作区内容。

Lighthouse 对桌面和移动模拟各串行运行 3 次，以中位数进入预算；移动配置使用
Lighthouse 标准慢速 4G 与 CPU 节流。Lighthouse 导航模式没有用户交互，因此不伪造
其 INP 字段；INP 实验室近似值由 Playwright 对 Settings、导入和普通单元格编辑的
Event Timing 计算，并明确标记为非字段数据。

当前回归预算为：

| 指标           |     桌面 | 移动模拟 |
| -------------- | -------: | -------: |
| FCP            |  ≤500 ms | ≤2000 ms |
| LCP            | ≤1800 ms | ≤7000 ms |
| TTI            | ≤1900 ms | ≤7500 ms |
| TBT            |  ≤100 ms |  ≤600 ms |
| CLS            |    ≤0.02 |    ≤0.15 |
| 请求数         |      ≤90 |      ≤90 |
| 传输体积       | ≤650 KiB | ≤650 KiB |
| 最大脚本 chunk |  ≤72 KiB |  ≤72 KiB |

移动预算用于捕获当前标准模拟基线约 15% 以上的退化，不代表低端真机达标。产品
3 s 可交互目标仍在报告中单独记录，真实设备与部署环境按后续验证任务确认。

Playwright 生产预算为：首屏可交互 ≤3 s、1000 行热恢复 ≤300 ms、恢复长任务
≤50 ms、导入首行渲染 ≤300 ms、跳底 ≤100 ms、滚动长任务 ≤50 ms、Settings 首次
打开与导入 Event Timing ≤200 ms、普通单元格编辑 Event Timing 中位数 ≤100 ms。
冷缓存首屏请求数 ≤90、传输体积 ≤650 KiB、最大脚本 chunk ≤72 KiB。Event Timing
或页面错误不得被跳过，Console error 会使用例失败。

预算定义在 `tests/e2e-web/production-perf/budgets.ts`。每次执行生成
`web-performance-baseline.json`；其中包含环境、Git 版本、6 个 Lighthouse 原始
样本、中位数、Playwright 样本和逐项预算结果。任何一项超预算都会以软断言失败，
但报告会先完整落盘，便于定位波动来源。
