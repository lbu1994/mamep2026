# 架构验收标准

## 1. 架构验收标准

技术架构达到可进入全面实现阶段，应满足：

1. Monorepo 能够独立构建浏览器、Electron、VSCode 和 Android 四个平台产物；
2. 核心包不依赖具体平台；
3. 功能码 03 和 0x10 的协议测试通过；
4. RTU CRC 和 TCP MBAP 测试通过；
5. 数据类型转换具备边界测试；
6. Fake Transport 能完成读、写、超时、重试和错误注入；
7. RequestScheduler 能保证单连接串行；
8. 轮询不会无限积压；
9. 断开后不再发送请求；
10. 迟到响应不会污染后续请求；
11. 工作区可以版本化保存和恢复；
12. 四个平台使用相同的工作区域模型；
13. Electron Renderer 与 Node.js 隔离；
14. VSCode Webview 通过受控 RPC 访问 Host；
15. 浏览器构建不包含 TCP 和 Node.js 依赖；
16. 插件请求不能绕过统一调度器；
17. 表格实现满足 1000 行基础性能目标；
18. 四个平台的共同验收场景可以复用同一测试描述。

## 2. 模块完成定义

一个技术模块被认为完成，需要满足：

1. 接口和职责明确；
2. 不违反模块依赖规则；
3. 外部输入经过校验；
4. 错误使用结构化模型；
5. 资源能够释放；
6. 关键分支具有自动化测试；
7. 平台差异通过 Adapter 表达；
8. 不把运行时状态错误地持久化；
9. 不绕过通信调度器；
10. PRD 验收行为可以追踪到实现模块和测试；
11. 类型检查通过；
12. 构建通过；
13. 没有未说明的跨端行为差异；
14. 没有把厂商私有规则写入通用核心；
15. 已记录必要的技术限制。

## 3. 发布质量阈值

正式发布前目标：

- P0 验收用例通过率 100%；
- P1 验收用例通过率不低于 95%；
- 已知阻断级缺陷为 0；
- 已知严重级数据丢失缺陷为 0；
- 导致设备连接无法释放的严重缺陷为 0；
- 核心工作区恢复测试通过率 100%；
- 1000 行表格基础操作无阻断性性能问题；
- 单次通信失败不会导致未保存的寄存器配置丢失。

具体性能基准必须结合硬件、操作系统、通信参数和测试环境记录，不声明脱离
环境的绝对结果。

存在以下任一情况时不得发布：

- 功能码 03、0x10 或其他已声明核心表类型存在已知转换错误；
- 写入地址与用户目标地址不一致；
- 数据可能被无提示截断或舍入；
- 断开后仍发送请求，或迟到响应污染后续请求、新连接；
- 核心通信错误导致应用崩溃，或连接无法可靠释放；
- 工作区恢复稳定丢失用户配置；
- 浏览器错误宣称支持直接 Modbus TCP；
- 插件失败阻止核心应用启动；
- 各平台对相同原始值解释不一致；
- Electron Renderer 获得不必要的 Node.js 权限；
- VSCode Webview 可以绕过 Host 能力边界；
- 平台能力矩阵与实际实现不一致；
- P0 验收用例未全部通过；
- 存在阻断级或严重级数据丢失缺陷；
- TypeScript、Lint、测试或构建检查未通过且无明确批准。

## 4. 可维护性验收

1. 相同产品行为由共享实现承担，不为三端复制独立业务逻辑；
2. 平台不支持能力时通过能力差异表达，不复制规则相近但行为不同的功能；
3. Modbus 核心与厂商私有功能保持边界；
4. 新增插件不要求修改核心寄存器表既有规则；
5. 工作区升级考虑向后兼容；
6. 数据无法迁移时提供备份、导出或重置路径；
7. 发布前对关键通信流程执行回归；
8. 已知限制在发布说明中公开。

## 5. 跨端回归检查

修改共享核心、共享 UI、平台契约或资源生命周期时，除对应专项测试外，还应检查：

- Browser：构建不含 Node.js 内置模块和 TCP 入口；Web Serial 缺失时有能力提示；
  刷新后保持离线；IndexedDB 数据可加载；响应式布局可用；
- Electron：Renderer 无直接 Node.js 权限；IPC 输入经过校验；Main 能释放连接；
  原生串口依赖仍可按目标 ABI 打包；文件保存仍为原子操作；
- VSCode：Webview RPC 向后兼容或已版本化；工作区信任限制有效；主题适配正常；
  Extension 停用时释放连接；Webview 不直接访问 Host 能力；VSIX 不遗漏原生依赖和静态资源；
- Android：原生桥只经 `platform-android` 封装；能力按运行时探测如实声明；
  WebView 后台生命周期和 CSP 仍满足平台边界；
- 共享行为：地址格式、数据类型解释、错误分类、日志核心字段、超时和重试语义、
  工作区 Schema 以及 RTU 请求和响应行为在各平台保持一致。

真实端口、真实设备和 Android 真机结果必须分别记录；缺少环境而跳过的检查不能写成通过。
