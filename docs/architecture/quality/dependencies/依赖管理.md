# 依赖库管理

## 39. 依赖库管理

### 39.1 依赖选择原则

关键依赖必须满足：

1. 社区主流；
2. 文档完整；
3. TypeScript 支持良好；
4. 许可证允许开源和分发；
5. 最近仍有维护；
6. 安全问题可追踪；
7. 支持目标 Node.js 和浏览器版本；
8. 不依赖不可控的云服务；
9. 不引入特殊 DSL；
10. 能够被自动化测试替代或封装。

### 39.2 依赖封装

以下关键依赖必须经过项目适配层：

- 串口库；
- IndexedDB 库；
- Electron IPC；
- VSCode API；
- 表格库；
- 国际化库；
- 插件加载器；
- 文件保存实现。

不得让第三方库对象成为领域模型或持久化格式。

### 39.3 版本策略

- 使用明确版本范围；
- 锁定文件进入仓库；
- 关键依赖升级单独评审；
- 串口、Electron、VSCode 和表格依赖升级按用户要求执行专项回归；
- 不自动接受关键依赖的主版本升级；
- 删除不再使用的依赖；
- 定期检查许可证和已知漏洞。

具体升级命令和代理执行步骤属于 AGENTS.md。
