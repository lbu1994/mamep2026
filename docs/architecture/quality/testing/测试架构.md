# 测试架构

## 1. 测试架构

### 1.1 测试层级

测试分为：

1. 领域单元测试；
2. 协议编解码测试；
3. 通信调度测试；
4. 持久化测试；
5. React 组件测试；
6. 平台适配集成测试；
7. 跨端契约测试；
8. 端到端测试；
9. 真实设备验收测试。

### 1.2 单元测试

重点测试：

- CRC-16；
- 功能码 03 编解码；
- 功能码 0x10 编解码；
- TCP MBAP；
- 地址校验；
- HEX 和 Binary；
- Signed 和 Unsigned；
- 十进制缩放；
- 精度错误；
- 工作区迁移；
- 错误映射；
- 插件 Manifest；
- 状态机转换。

纯函数测试不得依赖真实时间或真实设备。

### 1.3 协议测试向量

协议测试应使用固定请求和响应向量。

每组向量至少包含：

- 输入领域请求；
- 预期字节；
- 输入响应字节；
- 预期领域结果；
- 错误变体。

错误变体包括：

- CRC 错误；
- 响应地址错误；
- 功能码错误；
- 数据长度错误；
- 异常响应；
- TCP Transaction ID 错误；
- Unit ID 错误；
- 部分帧；
- 粘包。

### 1.4 通信调度测试

使用 Virtual Clock 和 Fake Transport 测试：

- 同一时刻只有一个请求；
- 手动操作优先于轮询；
- 轮询不积压；
- 请求超时；
- 重试次数；
- 取消；
- 断开；
- 迟到响应；
- 写后回读；
- 全表读取继续执行；
- 插件请求进入同一队列；
- 修改地址后旧结果被丢弃；
- 删除行后不再发送请求。

TCP 自动重连另需覆盖：断线后成功重连、退避上限、达到尝试上限后停止、用户主动断开取消
等待、等待期间发起新连接使旧尝试失效、关闭 `autoReconnect` 不重连，以及重连成功后恢复
轮询和 Trace。codec 路径至少覆盖非连续读写、异常映射、未知 `protocolId`、数量上限，并用
Fake Transport 验证其仍经过统一队列及取消/迟到响应规则。

不得使用真实等待时间编写调度单元测试。

### 1.5 持久化测试

覆盖：

- 正常保存和加载；
- Schema 版本迁移；
- 损坏 JSON；
- 缺失字段；
- 插件字段未知；
- 保存中断；
- 主文件损坏后从备份恢复；
- 保存失败后内存状态保留；
- 串口号恢复规则；
- 恢复后保持离线；
- 轮询配置恢复但不自动发送请求；
- 工作区导出 roundtrip、导入预览/取消、坏文件、版本迁移和覆盖失败；
- Electron 临时 `userData` 下的原子写入、单份备份、重启恢复和损坏自愈。

### 1.6 组件测试

覆盖：

- 地址提交和错误展示；
- Data 单元格直接编辑、读取结果强制覆盖、读取失败不改动内容；
- Type 切换；
- 轮询状态；
- 连接状态；
- 全表读取进度；
- 日志导出；
- 对话框焦点；
- 页签和侧边栏 Rename 输入框挂载即聚焦，焦点不会被外层可聚焦 tab button 抢回，
  Enter/失焦提交与 Escape 取消保持原语义；
- 侧边栏 Rename 编辑项暂停拖拽，退出编辑后恢复，其他表项仍可排序；
- 多行复制粘贴；
- 表级 DEC/HEX 地址切换、提交规范化和失败保留输入；
- 行插入/移动/删除、选择块、右键菜单和系统/应用内剪贴板 CSV；
- 键盘导航；
- 快捷键注册表完整性、两级分发守卫、帮助总览和 Modal 冲突抑制；
- 范围行子行五列编辑、原始值与元数据同步、范围调整和无数据覆盖；
- 撤销/重做批量步骤、重做分支清空、运行时读值保留及加载后历史清空；
- 自动保存静默（不对外展示保存状态）；
- 插件加载错误。

组件测试使用 Application Service Fake，不连接真实串口。

### 1.7 浏览器端到端测试

浏览器 E2E 使用 Playwright（系统 Edge，`channel: "msedge"`），通过 dev 内置模拟 Modbus RTU 传输 `?mockTransport=1`（生产构建不包含）完成主要 UI 验收；具体约定见 [浏览器端自动化测试](浏览器端自动化.md)。

可编辑单元格的 E2E 定位不得依赖 `Name`、`Data`、`Comment`、`Address` 等语言相关
可访问名称。使用稳定的 `data-register-cell` 列身份，再按行容器或 `data-row-key`
限定目标；可访问名称只用于专门的国际化、上下文区分和辅助技术断言。

自动化覆盖：

- 首次工作区；
- 新建标签页；
- 编辑地址；
- 读取；
- 写入；
- 轮询；
- 日志；
- 保存和恢复；
- 浏览器不支持时的能力提示；
- 浏览器端不出现 TCP 入口。

### 1.8 Electron 端到端测试

覆盖：

- 启动；
- Main 和 Renderer IPC；
- 串口列表；
- TCP 连接；
- 文件持久化；
- 窗口重启恢复；
- 断开释放；
- 插件加载失败隔离；
- Renderer 无直接 Node.js 权限。

Electron 端到端测试已验证：

- 启动和共享 UI 加载；
- Main/Renderer IPC、preload 白名单和 HostMessage 校验；
- RTU Web Serial 选择与 FC03/FC10 闭环；
- TCP 配置、连接与读写；
- 文件持久化、窗口重启恢复和损坏备份恢复；
- 远程批任务取消；
- 插件手动安装、宿主执行、重启恢复和卸载；
- 打包后的 `release/win-unpacked/` 可执行文件启动、共享 UI 加载、生产 CSP 和资源路径；
- Renderer 无直接 Node.js 权限；
- 断开释放、关窗退出和无 console 错误。

### 1.9 VSCode 集成测试

覆盖：

- 扩展激活；
- 命令注册；
- Webview 打开；
- Extension 与 Webview RPC；
- 工作区存储；
- TCP；
- RTU Adapter；
- 主题切换；
- 工作区信任限制；
- 扩展停用时释放连接；
- VSCode 重载后保持离线并恢复工作区。

VSCode 骨架测试还应验证生产 HTML 的资源经 `asWebviewUri()` 重写、bridge 注入、`localResourceRoots` 和 CSP 不含 dev server；Webview 启动后至少通过 `get-color-theme` / `get-capabilities` 完成类型化 RPC 往返。面板隐藏、重载和扩展停用后不得遗留消息或主题订阅。

Node Serial Adapter 的第一层测试必须使用注入式 Fake `SerialPortLike`，覆盖打开、关闭、读写、分片、拔出、占用、权限、参数错误、取消、重复连接和监听器清理。第二层才使用虚拟串口或真实设备验证 OS、绑定和字节流集成；不能用 Fake 测试结果声称原生模块打包成功。

### 1.10 宿主插件执行测试

宿主插件运行时应覆盖：

- 只加载已启用、带 `entrySource` 的同进程插件，跳过隔离插件、纯清单插件和已禁用插件；
- `manifest`、`activate` 导出缺失、语法错误和激活异常只隔离对应插件；
- 集合签名不变时同步幂等，插件或 entrySource 变化时全量重建；
- 禁用、卸载和入口源码变化后不得残留 dataType 或 addressTransform；
- 插件存储读取失败、保存失败和并发同步的错误边界；
- 宿主 dispose 注销插件并清空可重建注册表。

Electron 必须从生产构建安装同进程插件，验证落盘、重启恢复、卸载和退出释放；VSCode 必须通过真实 Webview RPC 安装插件，并验证宿主侧地址变换或 codec 实际生效以及卸载后不可解析。测试还应区分“宿主已加载”与“当前平台存在用户可见消费路径”。

插件契约测试还必须覆盖：Manifest/权限/API 版本校验，未知或无效贡献点逐项隔离，启用、
禁用和卸载后贡献不可见，插件通信附加 `source`/`pluginId` 并进入统一队列，以及平台未开放
运行时桥时返回能力错误。Electron/VSCode 的系统文件对话框属于宿主边界，可使用受控替身完成
确定性的导入导出闭环；真实原生对话框和打包平台行为仍作为发布前人工验收项。

### 1.11 虚拟 Modbus 设备

测试工具应提供 Scripted Modbus Device。

支持配置：

- 正常响应；
- 响应延迟；
- 不响应；
- CRC 错误；
- 异常码；
- 地址不匹配；
- 功能码不匹配；
- 响应长度错误；
- 分片响应；
- 多响应粘连；
- 连接中断；
- 写入后值一致；
- 写入后值不一致；
- 写入成功但回读失败。

虚拟设备必须能够记录收到的原始请求，以验证实际发送地址和功能码。

### 1.12 真实设备测试

自动化模拟不能完全替代真实设备验收。

发布前至少验证：

- Windows COM1 至 COM9；
- USB 转串口设备插拔；
- 串口占用；
- 实际 RTU 03；
- 实际 RTU 0x10；
- Electron TCP；
- VSCode TCP；
- 浏览器授权和断开；
- 不同波特率；
- 超时与重试；
- 长时间轮询资源释放。

真实设备测试结果应记录环境信息，但具体执行清单放入测试文档或发布流程，不写入 AGENTS.md 以外的代理执行细节。

### 1.13 真实端口端到端测试

真实端口测试使用 com0com、真实 TCP Socket 与独立 Modbus 从站验证三端 UI 闭环，并与
Mock/Fake 测试分开报告。拓扑、配置、启动编排、场景矩阵、平台差异和稳定性规则见
[真实端口端到端测试](真实端口端到端测试.md)。

该套件按环境门控：缺端口或从站时 SKIP，不得记为通过；用户要求全量回归时，必须以完整
可执行结果作为验收，不能以“套件已创建”或零散用例通过代替。

### 1.14 产品级测试覆盖

架构测试必须能够追踪以下产品流程：

1. RTU 和 TCP 连接成功与失败；
2. 功能码 03 单行读取；
3. 功能码 0x10 单行写入；
4. 写后回读；
5. 不连续地址全表读取；
6. 周期轮询启动和停止；
7. 超时、重试和取消；
8. 无效地址和无效数据；
9. 设备断开与资源释放；
10. 标签页、寄存器表和工作区恢复；
11. 多端一致性；
12. 插件加载失败隔离；
13. 大量表格行、日志和 Trace 数据。

测试数据至少覆盖正常响应、超时、异常响应、无效校验和连接中断。具体测试
框架、目录和命令由测试工程及 `AGENTS.md` 定义。

### 1.15 Android 真机测试

Android 自动化通过 CDP 驱动真实 WebView，覆盖：

- TCP 与 USB-RS485 连接；
- 设备权限、端口枚举和安装；
- FC03/FC10 闭环；
- 移动布局、返回键和后台恢复；
- 纯清单与可执行插件安装；
- 隔离与同进程执行模式；
- 插件卸载和能力回收；
- Release CSP、签名分支和产物加载。

测试连接使用 `adb forward` 暴露 WebView DevTools socket，再由 Playwright
`connectOverCDP` 驱动真实 UI 与原生桥；应用重启后 socket 名称可能变化，必须
重新解析并重建 forward。TCP 用例可通过 `adb reverse` 连接独立 Modbus TCP
从站，USB-RS485 用例需要真机和物理适配器，按半自动用例报告。部分 OEM 设备的
`adb logcat` 不可用，因此 UI 断言和诊断应走 CDP，不能把 logcat 当唯一证据。
Capacitor debug 调用会把桥消息输出到 console，桥延迟测量时不得在测量期间附加
会放大开销的无必要 CDP 探针。

插件执行探测至少覆盖可用、Worker 创建抛错、Worker entry 加载失败和超时四种结果，并断言每条路径都终止 Worker、取消计时器且不抛异常。Android 插件用例还应验证文件输入仅按 `.json`、`.mjs`、`.js` 扩展名过滤、Manifest 内容仍被校验，以及探测失败时 `executablePlugins` 保持 `false`。

系统文件选择器由原生 SAF 承担，CDP 自动化不能稳定驱动。自动化可向隐藏文件输入投递文件，覆盖应用读取、确认、持久化和执行路径，但必须把“用户操作系统选择器”的界面行为单独列为未自动化项，不能声称已完整验证原生选择器。

真机测试依赖 USB 调试、设备解锁和 Android SDK。缺少设备时不得静默视为通过；
Android e2e 使用独立命令，不并入无设备环境可运行的全量套件。

无线调试通过 `MAMEP_ANDROID_ADB_TARGET=<ip:port>` 先执行幂等 `adb connect`，
并设置 `ANDROID_SERIAL` 固定目标设备；同一设备可能同时出现连接地址和 mDNS
别名两个 transport，裸 `adb` 不得依赖默认选择。配对端口与连接端口不同，设备
发现优先使用 `adb mdns services` 获取准确地址。

Android Playwright 配置必须设置有限的动作与导航超时，使定位失败快速返回而不是
一直等待测试总超时；当前动作超时为 30 秒、导航超时为 60 秒。涉及前台焦点的
用例在操作前唤醒屏幕并关闭锁屏；CDP 附着会使页面 `visibilityState` 恒为
`visible`，不能用它判断应用是否退到后台，应以系统窗口焦点（例如
`dumpsys window` 的 `mCurrentFocus`）作为断言依据。ROM 可能不允许通过
`am start` 把已退到后台的任务重新置前，需要恢复前台时使用独立、可靠的系统
操作，或把不可恢复的前台用例安排在文件末尾并依靠 fixture 重建应用状态。

Android 生产 WebView 还必须验证共享代码分割结果：首屏加载入口和共享 chunk、
React 已挂载、启动连接设置出现、无循环依赖类初始化错误；Help、Settings、Trace
Window 等懒 chunk 在首次打开后才出现；能力不支持的覆盖层显示明确提示且不得加载
不可达的懒 chunk。由于 Android WebView 的 Resource Timing 可能把 body size 报告
为 0，chunk 体积应通过实际 `fetch(url) → blob.size` 读取并同时断言字节数大于 0。

### 1.16 测试结果日志

单独测试脚本和 `pnpm test:all` 的终端输出通过共享 `run-logged` 机制 tee 到
`test-reports/run-<时间戳>/`。每个测试步骤写独立 `.log`，并把步骤级
`name`、`command`、`exitCode`、`durationMs` 汇总到 `summary.json`；
`test:all` 另写包含总体状态、失败步骤和步骤列表的 `result.json`。该目录属于
生成产物并应被版本控制忽略。

日志记录保持步骤级轻量语义：

- 不解析单个 Playwright 用例或各单测包的通过数；
- JSON 只保存汇总和退出信息，完整原始输出保存在 `.log`；
- `test:all` 按固定顺序执行并 fail-fast，任一非零退出立即停止；
- 真实端口套件因环境缺失而 SKIP 时退出码为 0，但报告和最终说明必须保留
  “未验证”语义，不能把它描述为真实环境已通过；
- 日志写入是 best-effort，写入失败不得改变测试本身的退出码；
- `MAMEP_TEST_ALL_STEPS` 可限制全量编排执行的步骤，用于受控子集验证。

### 1.17 执行层级

1. 局部改动优先运行受影响包单测与类型检查；
2. 共享协议、调度、持久化和跨端契约变更运行相关专项测试；
3. 用户要求全量回归时运行统一全量命令；
4. 真实端口、真实设备和 Android 真机测试分别报告环境与跳过项；
5. JSON 报告和日志只证明实际执行，不得把 SKIP 写成通过。

### 1.18 用例归属与去重

每个测试用例只能有一个主要执行入口。`scripts/lib/test-plan-audit.test.mjs`
在 `pnpm test:scripts` 中检查以下约束：

- 验收测试不属于 `pnpm test`，只由 `test:acceptance` 执行；
- 四个 E2E 包不属于 `pnpm test`，只由各自 E2E 步骤执行；
- 普通 `platform-node` 测试排除需要 com0com 的虚拟串口文件；
- `test:serial:virtual` 使用独立配置，只收集虚拟串口专项用例；
- 同一 E2E 平台套件不得出现重复测试标题。

浏览器 mock E2E 只保留浏览器渲染、布局几何、文件下载/上传、IndexedDB、
Blob Worker、首帧和跨层装配等不能由 jsdom / FakeTransport 等价验证的纵向场景。
纯格式化、单元格校验、地址进制、撤销重做、从站地址和状态点等业务分支由
组件或状态单测负责，不再复制为独立 E2E。RTU 与 TCP 的相同协议断言仍可分别存在，
因为二者验证不同传输栈，不构成可互相替代的重复用例。
