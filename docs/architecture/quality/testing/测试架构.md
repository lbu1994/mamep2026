# 测试架构

## 1. 测试架构

### 1.1 测试层级

测试分为：

1. 领域单元测试；
2. 协议编解码测试；
3. 通信调度测试；
4. 持久化测试；
5. React 组件测试；
6. 平台适配集成测试；
7. 跨端契约测试；
8. 端到端测试；
9. 真实设备验收测试。

### 1.2 单元测试

重点测试：

- CRC-16；
- 功能码 03 编解码；
- 功能码 0x10 编解码；
- TCP MBAP；
- 地址校验；
- HEX 和 Binary；
- Signed 和 Unsigned；
- 十进制缩放；
- 精度错误；
- 工作区迁移；
- 错误映射；
- 插件 Manifest；
- 状态机转换。

纯函数测试不得依赖真实时间或真实设备。

### 1.3 协议测试向量

协议测试应使用固定请求和响应向量。

每组向量至少包含：

- 输入领域请求；
- 预期字节；
- 输入响应字节；
- 预期领域结果；
- 错误变体。

错误变体包括：

- CRC 错误；
- 响应地址错误；
- 功能码错误；
- 数据长度错误；
- 异常响应；
- TCP Transaction ID 错误；
- Unit ID 错误；
- 部分帧；
- 粘包。

### 1.4 通信调度测试

使用 Virtual Clock 和 Fake Transport 测试：

- 同一时刻只有一个请求；
- 手动操作优先于轮询；
- 轮询不积压；
- 请求超时；
- 重试次数；
- 取消；
- 断开；
- 迟到响应；
- 写后回读；
- 全表读取继续执行；
- 插件请求进入同一队列；
- 修改地址后旧结果被丢弃；
- 删除行后不再发送请求。

不得使用真实等待时间编写调度单元测试。

### 1.5 持久化测试

覆盖：

- 正常保存和加载；
- Schema 版本迁移；
- 损坏 JSON；
- 缺失字段；
- 插件字段未知；
- 保存中断；
- 主文件损坏后从备份恢复；
- 保存失败后内存状态保留；
- 串口号恢复规则；
- 恢复后保持离线；
- 轮询配置恢复但不自动发送请求。

### 1.6 组件测试

覆盖：

- 地址提交和错误展示；
- Data 单元格直接编辑、读取结果强制覆盖、读取失败不改动内容；
- Type 切换；
- 轮询状态；
- 连接状态；
- 全表读取进度；
- 日志导出；
- 对话框焦点；
- 多行复制粘贴；
- 表级 DEC/HEX 地址切换、提交规范化和失败保留输入；
- 行插入/移动/删除、选择块、右键菜单和系统/应用内剪贴板 CSV；
- 键盘导航；
- 自动保存静默（不对外展示保存状态）；
- 插件加载错误。

组件测试使用 Application Service Fake，不连接真实串口。

### 1.7 浏览器端到端测试

浏览器 E2E 使用 Playwright（系统 Edge，`channel: "msedge"`），通过 dev 内置模拟 Modbus RTU 传输 `?mockTransport=1`（生产构建不包含）完成主要 UI 验收；具体约定见 [浏览器端自动化测试](浏览器端自动化.md)。

自动化覆盖：

- 首次工作区；
- 新建标签页；
- 编辑地址；
- 读取；
- 写入；
- 轮询；
- 日志；
- 保存和恢复；
- 浏览器不支持时的能力提示；
- 浏览器端不出现 TCP 入口。

### 1.8 Electron 端到端测试

覆盖：

- 启动；
- Main 和 Renderer IPC；
- 串口列表；
- TCP 连接；
- 文件持久化；
- 窗口重启恢复；
- 断开释放；
- 插件加载失败隔离；
- Renderer 无直接 Node.js 权限。

Electron 端到端测试已验证：

- 启动和共享 UI 加载；
- Main/Renderer IPC、preload 白名单和 HostMessage 校验；
- RTU Web Serial 选择与 FC03/FC10 闭环；
- TCP 配置、连接与读写；
- 文件持久化、窗口重启恢复和损坏备份恢复；
- 远程批任务取消；
- 插件手动安装、宿主执行、重启恢复和卸载；
- 打包后的 `release/win-unpacked/` 可执行文件启动、共享 UI 加载、生产 CSP 和资源路径；
- Renderer 无直接 Node.js 权限；
- 断开释放、关窗退出和无 console 错误。

### 1.9 VSCode 集成测试

覆盖：

- 扩展激活；
- 命令注册；
- Webview 打开；
- Extension 与 Webview RPC；
- 工作区存储；
- TCP；
- RTU Adapter；
- 主题切换；
- 工作区信任限制；
- 扩展停用时释放连接；
- VSCode 重载后保持离线并恢复工作区。

VSCode 骨架测试还应验证生产 HTML 的资源经 `asWebviewUri()` 重写、bridge 注入、`localResourceRoots` 和 CSP 不含 dev server；Webview 启动后至少通过 `get-color-theme` / `get-capabilities` 完成类型化 RPC 往返。面板隐藏、重载和扩展停用后不得遗留消息或主题订阅。

Node Serial Adapter 的第一层测试必须使用注入式 Fake `SerialPortLike`，覆盖打开、关闭、读写、分片、拔出、占用、权限、参数错误、取消、重复连接和监听器清理。第二层才使用虚拟串口或真实设备验证 OS、绑定和字节流集成；不能用 Fake 测试结果声称原生模块打包成功。

### 1.10 宿主插件执行测试

宿主插件运行时应覆盖：

- 只加载已启用、带 `entrySource` 的同进程插件，跳过隔离插件、纯清单插件和已禁用插件；
- `manifest`、`activate` 导出缺失、语法错误和激活异常只隔离对应插件；
- 集合签名不变时同步幂等，插件或 entrySource 变化时全量重建；
- 禁用、卸载和入口源码变化后不得残留 dataType 或 addressTransform；
- 插件存储读取失败、保存失败和并发同步的错误边界；
- 宿主 dispose 注销插件并清空可重建注册表。

Electron 必须从生产构建安装同进程插件，验证落盘、重启恢复、卸载和退出释放；VSCode 必须通过真实 Webview RPC 安装插件，并验证宿主侧地址变换或 codec 实际生效以及卸载后不可解析。测试还应区分“宿主已加载”与“当前平台存在用户可见消费路径”。

### 1.11 虚拟 Modbus 设备

测试工具应提供 Scripted Modbus Device。

支持配置：

- 正常响应；
- 响应延迟；
- 不响应；
- CRC 错误；
- 异常码；
- 地址不匹配；
- 功能码不匹配；
- 响应长度错误；
- 分片响应；
- 多响应粘连；
- 连接中断；
- 写入后值一致；
- 写入后值不一致；
- 写入成功但回读失败。

虚拟设备必须能够记录收到的原始请求，以验证实际发送地址和功能码。

### 1.12 真实设备测试

自动化模拟不能完全替代真实设备验收。

发布前至少验证：

- Windows COM1 至 COM9；
- USB 转串口设备插拔；
- 串口占用；
- 实际 RTU 03；
- 实际 RTU 0x10；
- Electron TCP；
- VSCode TCP；
- 浏览器授权和断开；
- 不同波特率；
- 超时与重试；
- 长时间轮询资源释放。

真实设备测试结果应记录环境信息，但具体执行清单放入测试文档或发布流程，不写入 AGENTS.md 以外的代理执行细节。

### 1.13 真实端口 e2e（com0com + 真实从站，ADR-024）

2026-08-24 落地（ADR-024）：三端「真实端口」e2e 作为**默认真实路径**的自动化闭环，
与 MOCK/FAKE（`?mockTransport=1`、`MAMEP_FAKE_SERIAL/TCP=1`）正交（MOCK 保留为显式可选
dev 手段）。统一编排 `scripts/e2e-real.mjs <web|electron|vscode|all>`：预检（RTU 用
serialport `list()` 检查主站口 rtu-com4-master.port 与从站口 modbus-slave.config.json.port
均存在；TCP 探测 tcp-local-slave 端口可监听）→ 设 `MAMEP_REAL=1` → 拉起从站（RTU: COM5 /
TCP: 127.0.0.1:1502，均来自 `config/connections.json` / 从站自身配置，不硬编码）→ 跑对应端
命令 → 回收。缺环境 → SKIP 提示、退出码 0（不失败）。命令：`pnpm test:e2e:real`（all）、
`pnpm test:e2e:web:real` / `:electron:real` / `:vscode:real`。

- **从站**：`scripts/modbus-slave/lib/modbus-core.mjs`（RTU/TCP 单一事实源：7 区 DEFAULT_RULES、
  行为归一化、CRC、日志、响应投递）+ `modbus-rtu-slave.mjs`（COM5，重构复用 lib，`--self-test`
  保回归）+ `modbus-tcp-slave.mjs`（MBAP，默认 host/port/unitId 取 config tcp-local-slave）。
  扩展行为（真实从站配置，不在 DEFAULT_MOCK_RULES）：`delayedResponse`（0x0700 延迟 2500ms →
  超时/迟到丢弃；2026-08-25 从 1500ms 上调——1500ms 落在 1000ms×2 重试窗口内会被重试消费，
  RTU 无事务 ID 无法区分）与 `splitResponse`（0x0800 拆段 2B/5ms → 半包/粘包组帧）。
- **浏览器**（`tests/e2e-web/tests-real/real-serial.spec.ts`，系统 Edge 有头）：Connection
  Settings → 系统 Web Serial picker（用户手势，启动时选择 COM4 一次）→ 记录 localStorage
  （`mamep:real-serial-port`）→ `test.describe.serial` 共享 page/连接复用；跨运行打印上次选择。
- **Electron**（`tests/e2e-electron/tests-real/real-serial.spec.ts` / `real-tcp.spec.ts`，
  生产构建路径，全自动）：RTU 走串口下拉枚举（用户手势）→ 自动选 config 指定串口 COM4；
  TCP 走切 Modbus TCP → 按 config tcp-local-slave 填表。
- **VSCode**（`tests/e2e-vscode/real/real-rtu.spec.ts` / `real-tcp.spec.ts`，
  vscode-test-playwright 0.0.1-beta2，UI 级断言）：extensionDevelopmentPath 加载扩展 → 生产
  webview（未设 MAMEP_DEV_URL → getProdHtml）→ `workbox.frames()` 定位承载共享 UI 的 webview
  内容 frame（VSCode 1.134 为两层：容器 index.html + 内容 fake.html，2026-08-25 修复；该库
  经 pnpm patch 绕过已移除的 playwright._toImpl）→ RTU 串口下拉 serial-enumerate（RPC）选
  COM4；TCP 按 config 填表。
  fixture 每测试新建 VS Code 实例 → 每协议单测试 + `test.step()` 控制启动次数。
- **场景矩阵（三端一致，RTU/TCP）**：连接 Online → FC03 读（0x0000=0x04D2）/ FC10 写 + 读回
  → 写值门控 0x0400（0x8000 拒/0x1234 成）→ 异常区 0x0100/0x0200/0x0300→0x02、0x0500→0x01
  → no-response 0x0600 超时且后续正常 → 边界 0x0000/0xFFFF → 扩展 0x0800 分片 / 0x0700 延迟
  → 通信日志帧字节 → 断开/重连（浏览器仅断开一次，重连稳定性由桌面端覆盖）→ 无 console 错误。
- 能力矩阵如实声明（modbusRtu/serialPorts/modbusTcp；`connectionConfig` 能力位已于 2026-08-29 移除，ADR-034）；无新增 HostMessage
  kind；浏览器不追加 TCP；测试参数不硬编码（读 `config/connections.json`）。
- **2026-08-25 修正（ADR-028）**：ADR-024 落地后真实端口 e2e 实际从未真正跑通（「已落地」≠
  「已跑通」），首次全量回归暴露并修复多层问题（从站 LOG_LEVELS 未导入、real 套件 setRadixHex
  用错 .ant-select、fill+Enter React 受控组件竞态（UI 根治：EditableCellValue 用 draftRef 同步草稿）、通信日志虚拟列表断言、HostMessage 错误投影
  bug（两端 ipc errorEnvelope 硬编码 userMessageKey/category）、vscode-test-playwright _toImpl
  补丁、VSCode webview 两层 frame 定位、串口下拉误点连接对象下拉、electron-smoke 白名单等），
  三端真实端口 e2e 首次全绿（web 12 / electron 24 / vscode 3）。详见 ADR-028。

### 1.14 产品级测试覆盖

架构测试必须能够追踪以下产品流程：

1. RTU 和 TCP 连接成功与失败；
2. 功能码 03 单行读取；
3. 功能码 0x10 单行写入；
4. 写后回读；
5. 不连续地址全表读取；
6. 周期轮询启动和停止；
7. 超时、重试和取消；
8. 无效地址和无效数据；
9. 设备断开与资源释放；
10. 标签页、寄存器表和工作区恢复；
11. 多端一致性；
12. 插件加载失败隔离；
13. 大量表格行、日志和 Trace 数据。

测试数据至少覆盖正常响应、超时、异常响应、无效校验和连接中断。具体测试
框架、目录和命令由测试工程及 `AGENTS.md` 定义。

### 1.15 Android 真机测试

Android 自动化通过 CDP 驱动真实 WebView，覆盖：

- TCP 与 USB-RS485 连接；
- 设备权限、端口枚举和安装；
- FC03/FC10 闭环；
- 移动布局、返回键和后台恢复；
- 纯清单与可执行插件安装；
- 隔离与同进程执行模式；
- 插件卸载和能力回收；
- Release CSP、签名分支和产物加载。

插件执行探测至少覆盖可用、Worker 创建抛错、Worker entry 加载失败和超时四种结果，并断言每条路径都终止 Worker、取消计时器且不抛异常。Android 插件用例还应验证文件输入仅按 `.json`、`.mjs`、`.js` 扩展名过滤、Manifest 内容仍被校验，以及探测失败时 `executablePlugins` 保持 `false`。

系统文件选择器由原生 SAF 承担，CDP 自动化不能稳定驱动。自动化可向隐藏文件输入投递文件，覆盖应用读取、确认、持久化和执行路径，但必须把“用户操作系统选择器”的界面行为单独列为未自动化项，不能声称已完整验证原生选择器。

真机测试依赖 USB 调试、设备解锁和 Android SDK。缺少设备时不得静默视为通过；
Android e2e 使用独立命令，不并入无设备环境可运行的全量套件。

### 1.16 执行层级

1. 局部改动优先运行受影响包单测与类型检查；
2. 共享协议、调度、持久化和跨端契约变更运行相关专项测试；
3. 用户要求全量回归时运行统一全量命令；
4. 真实端口、真实设备和 Android 真机测试分别报告环境与跳过项；
5. JSON 报告和日志只证明实际执行，不得把 SKIP 写成通过。
