# 浏览器端自动化测试

## 1. 目标与边界

浏览器自动化用于验证共享 UI、用户交互、工作区恢复和 Mock Modbus 通信闭环。它不能替代真实 Web Serial 授权、真实串口设备或 Electron/VSCode 宿主验证。

测试使用开发服务器和系统 Edge；生产构建不得包含 Mock 传输入口。

## 2. 标准流程

1. 启动开发服务器并等待页面可交互；
2. 设置明确的桌面或移动端视口；
3. 使用页面快照或语义选择器确认结构；
4. 执行用户操作并等待可观察状态，不使用无依据的长固定等待；
5. 读取表格、状态、日志或持久化结果；
6. 收集 `console.error` 与 `pageerror`；
7. 必要时刷新验证恢复和损坏兜底；
8. 释放测试连接和后台进程。

## 3. 选择器原则

- 优先使用角色、可访问名称、标签和稳定业务属性；
- 无障碍快照中的临时 ref 只适合单次交互，不应作为跨刷新断言；
- 同名控件必须限定容器作用域；
- Ant Design v6 Modal 使用 `.ant-modal-container` / `.ant-modal-body`；
- Tabs 活动内容使用 `.ant-tabs-content-active`，存在多个 Tabs 时必须限定外层；
- Drawer 开合状态在 root，内容面板和触控目标不能混用；
- Select 展开后只在可见 dropdown 内选择，不能仅按 label 文本全局匹配；
- 持续轮询导致普通 click 因元素不稳定超时时，可以在测试代码中用 DOM 原生 click 触发，但不能绕过真实业务动作。

## 4. Mock 传输

dev 模式使用 `?mockTransport=1` 启用模拟 Modbus RTU 传输。Mock 模式启动后自动连接，并在默认表仍为未编辑空表时预填分类行。

默认读写场景：

| 地址区间 | 行为 |
| --- | --- |
| `0x0000–0x000F` | 读/写成功 |
| `0x0100–0x010F` | 读成功，写返回异常 0x02 |
| `0x0200–0x020F` | 写成功，读返回异常 0x02 |
| `0x0300–0x030F` | 读/写均返回异常 0x02 |
| `0x0400–0x040F` | 读成功；写入值大于 0x7FFF 返回异常 0x03 |
| `0x0500–0x050F` | 读/写均返回异常 0x01 |
| `0x0600–0x060F` | 读/写无响应，触发超时和重试 |
| `0x0800–0x080F` | 单寄存器读写异常，多寄存器连续读写成功 |
| `0x0900–0x090F` | 写回执成功但不实际生效，用于写后回读不一致 |

线圈、离散输入和输入寄存器使用独立的表类型规则。Mock 行为与默认预填数据必须来自同一场景定义，避免地址和说明漂移。

dev-only `window.__mamepMock` 可预置和读取寄存器、线圈、输入状态，用于构造可重复测试；生产构建不得暴露该钩子。

## 5. 控制台与视觉验证

- 每轮完整交互必须检查 `console.error` 和页面异常；
- React 警告、Ant Design 弃用 API、CSP 违规都视为测试失败；
- 截图用于视觉辅助，结构化快照和 DOM 几何值用于可重复断言；
- 响应式测试必须显式设置桌面和手机视口；
- 动画/过渡后的测量应等待过渡结束，避免读取中间值；
- VSCode 等多层 iframe 场景必须把定位器限定到内容 frame，不能只查顶层页面。

## 6. 持久化与恢复

- localStorage、IndexedDB 和工作区仓储测试必须区分启动缓存与持久化事实源；
- 损坏数据、版本不匹配和存储不可用应回退默认值；
- 恢复工作区后必须保持离线，不自动发送设备请求；
- 刷新首帧测试应在首次 DOM 提交时比较主题、语言、标签页、布局和工作区数据；
- 启动就绪必须保证工作区已加载、插件已完成注册；超时应显示可理解警告并保持可操作。

## 7. 测试数据与清理

- 测试参数从统一配置读取，不硬编码端口、主机和从站；
- 文件、日志、插件安装态和连接态在用例间显式清理；
- 共享设备或串口的用例必须串行执行；
- 缺少真实设备时，真实端口套件按环境门控 SKIP，并如实标记“未验证”；
- Mock、Fake、虚拟串口和真实设备结果必须分别报告。
