# 兼容性设计

## 1. 兼容性设计

### 1.1 Node.js 运行环境

Electron 和 VSCode 可能使用不同 Node.js 版本。

共享 Node 平台包应：

- 避免依赖单一 Host 特有的全局变量；
- 声明最低 Node.js 版本；
- 通过构建目标分别输出；
- 对原生模块分别打包；
- 不假设 Electron 与 VSCode ABI 相同；
- 在启动时检查必要能力。

### 1.2 浏览器环境

Web 应用构建时：

- 不打包 Node.js polyfill；
- 不模拟 TCP；
- 不引用文件系统；
- Web Serial 不存在时仍允许打开只读工作区界面；
- 能力检测早于连接操作；
- 不支持的功能不创建无效入口；
- 页面刷新后保持离线。

### 1.3 工作区向后兼容

兼容策略：

- 新版本必须能够读取受支持范围内的旧 Schema；
- 旧版本不保证读取新 Schema；
- 导入较新 Schema 时显示明确错误；
- 迁移前保留原始数据；
- 插件未知字段尽可能保留；
- 删除字段需经过迁移；
- 字段语义变化不得只复用旧字段名。

### 1.4 插件兼容

插件兼容性由以下条件共同决定：

- apiVersion；
- 应用版本；
- 平台；
- 必需能力；
- 权限；
- 插件自身数据 Schema。

任何一个条件不满足时，不应尝试带病加载。
