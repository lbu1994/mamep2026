# 配置设计

## 1. 配置设计

配置分为：

1. 产品内置默认配置；
2. 用户偏好；
3. 工作区配置；
4. 平台配置；
5. 插件配置；
6. 构建配置。

优先级建议：

    产品默认值
      < 平台默认值
      < 用户偏好
      < 工作区配置
      < 当前运行时临时设置

敏感配置不得写入普通工作区。

插件配置使用独立命名空间：

    plugins.<pluginId>.<settingKey>

插件不得读取其他插件配置，除非通过明确共享 API。

## 2. 测试连接对象配置

仓库根 `config/connections.json` 保存真实端口测试、探针和验证脚本使用的连接对象，字段包括
RTU 串口与通信参数、TCP 主机/端口/Unit ID 等。它用于消除脚本中的设备参数硬编码。

该文件不是应用配置源：

- 应用启动不读取或监听该文件；
- Connection Settings 不提供“从配置文件载入”入口；
- 文件中的串口名、主机或 Unit ID 不自动进入用户工作区；
- 用户连接对象由工作区 `connectionProfiles` 持久化，跨端交换通过工作区导入导出。

测试脚本与真实 E2E 可以只读该文件，并应通过统一查找函数按稳定 id 解析连接对象。字段说明
和默认示例随仓库一起维护；缺少环境仍是 SKIP，不能由测试悄悄回退到生产连接或 Fake 传输。
