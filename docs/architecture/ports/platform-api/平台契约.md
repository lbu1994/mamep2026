# 平台统一接口与消息契约

## 1. packages/platform-api

定义 UI 和 Application 层可访问的平台统一接口，包括：

- 串口；
- TCP；
- 持久化；
- 文件选择；
- 剪贴板；
- 通知；
- 插件；
- 平台信息；
- 能力矩阵；
- 生命周期。


## 2. 平台通信桥设计

### 2.1 统一 Host API

共享 UI 通过 MamepHostApi 与平台通信。

主要能力：

- getCapabilities；
- enumerateSerialPorts（Browser 以授权 picker 承担；Electron Web Serial 转发的端口列表和 VSCode Node Serial 系统枚举使用该能力语义）；
- requestSerialPort；
- connect；
- disconnect；
- executeCommand；
- loadWorkspace；
- saveWorkspace；
- listPlugins；
- enablePlugin；
- disablePlugin；
- subscribeEvents；
- exportData；
- importData。

Browser Host 可以在同一线程直接实现该接口。

Electron 和 VSCode 使用消息桥实现。

### 2.2 消息协议

所有跨边界消息使用版本化 Envelope：

    HostMessage
      protocolVersion
      messageId
      type
      kind
      payload

消息类型分为：

- request；
- response；
- event；
- error。

要求：

1. 每条请求有唯一 messageId；
2. 响应引用原 messageId；
3. payload 使用 Zod 校验；
4. 未知 kind 被拒绝；
5. 不允许任意方法名调用；
6. 支持取消长任务；
7. 支持连接、日志和进度事件；
8. 消息协议版本可演进；
9. 错误通过结构化对象传递；
10. Uint8Array 采用明确可序列化格式传输。

HostMessage v2 由 Electron 和 VSCode 共用。`type` 为 `request | response | event | error`，响应的 `messageId` 必须引用原请求。错误投影只传递可序列化字段，不把 `Error` 实例、函数、句柄或循环引用跨边界传递。

`poll-result` 事件必须包含 `sheetId`、实际请求地址、发送时路由、请求 generation
和连接 generation。接收端不得仅凭行键与地址接受结果；校验失败时应同时丢弃数据
更新和成功/失败状态点。

错误在宿主边界必须保持语义字段原样往返：

- `code`；
- `category`；
- `severity`；
- `retryable`；
- `userMessageKey`；
- `technicalMessage`；
- 可序列化且不敏感的 `context`/`cause` 投影。

Host IPC 可以用默认值兜底未知异常，但不得把已经分类的会话错误统一改写为通用
`errors.hostMessageRejected`。用户消息 key 和技术诊断信息必须分离；RTU 本地路径与
TCP/远程路径对同一设备错误应得到相同的用户可见语义。

Electron IPC 使用独立频道：

- invoke 通道：`mamep:invoke`；
- event 通道：`mamep:event`。

Preload 不暴露通用 `ipcRenderer.invoke` 或任意 channel 名称，只暴露版本化 `MamepHostApi` 的语义方法。Main 与 Preload 都必须把消息视为不可信输入，Main 的 Zod 和 kind 白名单是最终校验边界。`debug:get-state` 只允许开发或测试探针使用，打包应用必须返回明确的禁用错误。

远程会话 RPC 至少包括：

- 串口枚举；
- RTU 连接和 TCP 连接；
- 断开和状态查询；
- RTU Slave Address 与 TCP Unit ID 更新；
- 单行读取/写入；
- 全表读取及按 `batchId` 取消；
- 轮询目标和启停；
- Trace 启停；
- 表级地址变换同步。

连接事件继续复用 `connection-state`；通信日志、行结果、Trace 样本和应用消息使用既有事件
kind。新增会话能力通过追加 request kind、payload Schema、白名单和穷尽性分发演进，不允许
Webview/Renderer 提交任意方法名。

远程批读取由渲染端在创建 handle 时生成唯一 `batchId`，随
`session-batch-read { batchId, rows }` 传入；`session-batch-cancel { batchId }` 取消
宿主活动批任务。行结果通过既有事件流返回，批任务响应只携带汇总。未知或已完成
`batchId` 为安全 no-op。

文件交换使用以下稳定语义：

- `save-text-file` 接收文件名提示、MIME 类型和 UTF-8 文本，响应以 `saved` 区分保存与取消；
- `open-text-file` 接收可选文件名提示，响应为 `{ content: string | null }`，取消返回
  `null`，不是异常；
- 文件路径由宿主选择或确定，Renderer/Webview 不得传入任意可读写路径；
- 浏览器不调用这些桌面 kind，而是使用文件输入和浏览器下载能力；
- Electron 文件仓储使用 `workspace-load`、`workspace-save`、
  `workspace-clear`、`workspace-create-backup`；`workspace-save` 在落盘前再次
  校验序列化内容，`workspace-clear` 删除主文件与备份，
  `workspace-create-backup` 轮转一份最近有效备份；
- `workspace-load` 响应携带可选 `recoveryInfo`。VSCode 没有桌面文件仓储能力时，
  创建备份返回结构化 `WORKSPACE_FILESYSTEM_UNSUPPORTED`，不能伪装成功。

插件执行面预留 `plugin-runtime-load`、`plugin-runtime-unload`、`plugin-rpc`、
`plugin-contribution-query` 请求和 `plugin-event` 事件。宿主对每个 kind 做 Schema 与能力
校验；平台尚未开放实际运行时或贡献消费时返回结构化插件能力错误，不向插件透传任意 RPC
方法名、Transport、文件系统或 Node.js 句柄。

多寄存器范围行不增加 kind，而是扩展既有 payload：

- `registerRowPayloadSchema` 携带 `registerCount` 和子行元数据；
- 批量读取与轮询目标携带 `quantity`；
- 行结果和 Trace 样本支持 `values[]`；
- 写后回读 verify 字段使用 `readValues`/`expectedValues` 数组；
- 三端 AppHost 仍以整行对象作为业务输入，不在 UI 重新组装协议字段。

行 payload 还承载范围子行 `registers` 以及位级 `bitNames` / `bitComments`。
这些字段往返时必须保留寄存器序号和 bit 序号，不得只传显示后的位行文本。
服务端不支持某字段时返回显式版本/能力错误，不能静默截断持久化语义。


## 3. 数据契约示例

本节仅用于明确数据边界，不代表完整实现代码。

### 3.1 读取命令

    type ReadHoldingRegisterCommand = {
      requestId: string;
      connectionId: string;
      source: RequestSource;
      slaveAddressOrUnitId: number;
      registerAddress: number;
      registerCount: number;
      timeoutMs: number;
      retryCount: number;
      cancellationId: string;
    };

### 3.2 写入命令

    type WriteHoldingRegisterCommand = {
      requestId: string;
      connectionId: string;
      source: RequestSource;
      slaveAddressOrUnitId: number;
      registerAddress: number;
      rawValues: number[];
      timeoutMs: number;
      retryCount: number;
      verify: ReadVerifyPolicy;
      cancellationId: string;
    };

### 3.3 平台能力

    type PlatformCapabilities = {
      platform: "browser" | "electron" | "vscode" | "android";
      supportsRtu: boolean;
      supportsTcp: boolean;
      supportsSerialEnumeration: boolean;
      supportsFileSystem: boolean;
      supportsHostPlugins: boolean;
      supportsWorkspaceFiles: boolean;
      supportedSerialOptions: {
        dataBits: number[];
        stopBits: number[];
        parity: string[];
        flowControl: string[];
      };
    };

### 3.4 请求结果

    type RequestResult<T> =
      | {
          ok: true;
          value: T;
          timing: RequestTiming;
          attemptCount: number;
        }
      | {
          ok: false;
          error: MamepError;
          timing: RequestTiming;
          attemptCount: number;
        };

### 3.5 写后回读结果

    type WriteOperationResult =
      | {
          kind: "write-failed";
          error: MamepError;
        }
      | {
          kind: "write-succeeded-no-verify";
        }
      | {
          kind: "write-succeeded-verify-matched";
          readValues: number[];
        }
      | {
          kind: "write-succeeded-verify-mismatched";
          expectedValues: number[];
          readValues: number[];
        }
      | {
          kind: "write-succeeded-verify-failed";
          errorCode: string;
          userMessageKey: string;
        }
      | {
          kind: "cancelled-before-verify";
        };
