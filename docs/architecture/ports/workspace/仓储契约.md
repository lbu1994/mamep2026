# 工作区仓储端口

## 1. Repository 接口

WorkspaceRepositoryPort 至少提供：

- load；
- save；
- reset；
- export；
- import；
- createBackup；
- getRecoveryInfo；
- 支持恢复保护的仓储另提供 `recover` 和 `exportRecovery`。

UI 不直接调用 IndexedDB 或文件系统。

`getRecoveryInfo()` 返回只读元数据，至少区分：

    WorkspaceRecoveryInfo
      recovered
      source              // "none" | "backup" | "fresh"
      recoveredAt
      backupTimestamp     // 可为 null
      errorCode           // 可为 null
      pending             // 可选，等待确认期间为 true
      archiveId           // 可选，归档成功后提供
      preview             // 可选，仅有效备份具有摘要

`load()` 成功返回领域工作区；恢复详情通过旁路元数据返回，不能把恢复元数据混入
工作区 Schema。`source: "none"` 表示主数据有效，`"backup"` 表示从备份恢复，
`"fresh"` 表示使用默认工作区；`pending: true` 时只是临时视图，原文尚未替换。

所有实现必须遵守以下语义：

- `load` 返回经过当前 Schema 校验和迁移的工作区；首次启动无数据时返回空工作区；
- `save` 接收不可变、完整一致的工作区快照，平台实现负责串行持久化，失败不得删除内存数据；
- `clear/reset` 删除主数据及其备份；保留损坏原文归档，不得误删其他应用级资产；
- `export/import` 与工作区交换格式使用同一 Schema，导入失败不得覆盖现有数据；
- `createBackup` 轮转主数据到最近一份有效备份，`getRecoveryInfo` 暴露最近一次
  load 的恢复来源和时间；损坏主数据时先归档，再预览最近有效备份，等待用户确认；
- 所有失败返回结构化 `MamepError`，保留 `category` 和 `userMessageKey`，不得吞掉异常；
- 运行时连接、Timer、任务、日志、撤销历史和平台句柄不得进入仓储数据。

`export/import` 是仓储接口完整性的一部分，不自动增加与工作区交换格式重复的 UI
入口。备份和恢复失败不得先删除仅存的完整数据。

浏览器、Electron 和 VSCode 可以选择不同物理存储，但共享相同的领域对象、版本与恢复语义。
具体适配差异由其平台适配文档定义。

## 2. 确认恢复

`recover()` 返回已持久化的备份工作区；没有待恢复状态、归档失败、候选失效或写入失败
均返回结构化错误。确认前禁止保存、导入和备份轮转；显式重置仍要求原文已归档且未变化。
`exportRecovery()` 返回包含来源和原数据的归档文本，不对损坏数据执行工作区解析或迁移。
具体交互与平台边界见[工作区损坏恢复](../../application/workspace/工作区.md#23-损坏恢复)。
