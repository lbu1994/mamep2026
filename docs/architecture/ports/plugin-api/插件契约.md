# 插件契约与架构

## 1. packages/plugin-api

包含：

- 插件 Manifest Schema；
- 插件生命周期接口；
- 插件贡献点；
- 插件权限声明；
- 平台能力要求；
- 版本兼容规则；
- 插件 Host 接口；
- 插件错误边界。

## 2. 插件架构

### 2.1 设计原则

1. 插件不直接修改核心源代码；
2. 插件只通过稳定贡献点扩展；
3. 插件必须声明平台支持；
4. 插件必须声明权限；
5. 单个插件失败不能导致核心应用失败；
6. 插件不能绕过统一通信队列；
7. 插件不能直接取得底层串口句柄；
8. 插件通信请求必须生成日志；
9. 插件配置必须拥有独立命名空间；
10. 插件 API 采用版本化设计。

### 2.2 插件类型

定义两类插件：

#### UI-safe 插件

可在 Browser、Electron、VSCode 和 Android 运行，能力受限。

适合：

- 数据显示类型；
- 工具面板；
- 文档和寄存器手册；
- 地址显示；
- 纯计算工具；
- 受控命令按钮。

不得执行任意 Node.js 代码。

#### Host 插件

仅在 Electron 主进程或 VSCode Extension Host 中运行。

适合：

- 厂商私有协议；
- 特殊通信封装；
- 本地文件处理；
- 受控设备操作。

Host 插件需要更严格的安装、权限和兼容性控制。

Browser 和 Android 不加载 Node Host 插件。

### 2.3 当前插件装载范围

所有插件由用户手动安装，禁止新增随应用自动安装的内置插件。

当前装载规则：

1. 用户在 Settings → Plugins 中安装 `manifest.json` 或单文件可执行 entry；
2. 纯清单插件只声明贡献点，不执行代码；
3. 可执行插件默认在隔离 Worker/线程中运行；
4. 同进程执行必须在安装确认框中由用户显式授权，等价于授予插件与应用相同的信任权限；
5. 插件通过 Manifest 驱动启用、禁用、兼容性检查和能力声明；
6. 插件加载失败只影响自身，不阻止核心应用启动；
7. Electron Main 和 VSCode Extension Host 通过同一插件存储加载宿主侧执行面；
8. 插件贡献和通信能力由当前启用插件动态派生，不写死到平台基础能力；
9. 插件代码不得直接访问底层 Transport；
10. 不提供签名、在线市场和随应用自动安装路径。

插件 API 当前版本为 `2.0`。激活上下文向可执行插件提供受控的同步注册面
`ctx.registries`，用于 codec、dataType 和 addressTransform；插件不能直接修改
贡献注册表、UI Store 或通信会话。可安装产物为单文件 `.mjs` entry 或纯清单
`manifest.json`，构建产物统一进入 `release/plugins/<pluginId>/`。

平台基础能力只声明核心协议与核心表类型。`protocolExtensions` 和 `tableTypes`
的实际可选项由“核心基础值 + 已启用且激活成功的插件贡献”动态派生；插件禁用、
卸载或激活失败后，其表类型、协议和同步注册项不得继续作为新操作入口。

安装入口位于 Settings → Plugins。用户只能选择本地 manifest 或受支持的单文件可执行 entry，
不提供联网下载、自动安装或 zip 多文件执行。安装前确认框必须展示来源、版本、所需权限、
平台要求、执行方式和未受信任代码风险。`pluginInstall` 能力为 `"upload"`（浏览器/Android
客户端文件选择）、`"file"`（Electron/VSCode 系统对话框）或 `"unsupported"`；UI 必须按
能力矩阵门控，不能通过捕获“文件 API 不存在”推断支持。

已安装插件及其启用状态属于应用级资产，不进入工作区。浏览器、Electron、VSCode
和 Android 分别使用独立应用级存储；导入导出工作区不得携带这些记录。单个插件
校验、加载或激活失败只产生插件错误，不阻止核心应用启动，也不使其他插件失效。

插件存储 schema 为 v5，校验 manifest、`entrySource`、`executionMode` 和可选批准记录
`approval`。v4 迁移保留插件源码与清单，但禁用可执行插件，等待用户重新确认权限。
v1/v2/v3 沿用空插件列表迁移；未知版本拒绝读取。工作区数据和偏好不受影响。

### 2.4 Manifest

Manifest v2 使用 `apiVersion = 2.0`，包含版本、平台、能力、权限、入口和贡献点。
字段、类型化权限和版本兼容规则见本文 §3、§4。

### 2.5 贡献点

核心通过稳定贡献点扩展 UI、协议、数据类型、地址变换和文档能力。当前 10 个
贡献点及消费边界见本文 §3。插件按钮执行受控 command，不直接访问 UI 内部 Store。

核心表类型与插件表类型的边界：

- `holding-register`、`coil`、`discrete-input`、`input-register` 是核心内置
  Modbus 表类型；
- 插件通过 `tableType` 声明命名空间 ID `<pluginId>:<tableTypeId>`，并通过
  `protocolExtension` 提供对应 codec；
- 表类型可以声明额外列和行操作，但读写、调度、日志、权限和错误边界仍走共享
  用例；
- 不同类型的表之间禁止复制粘贴行块；
- 只读、可写、协议映射和默认类型由表类型元数据决定，不能散落在组件分支。

`tableType` 的声明式 payload 至少包含 `id`、`protocolId`、`titleKey`，并可声明
`columns`、`rowActions` 和 `createDefaultRow`。这些字段只描述表如何呈现和创建；
实际协议函数在激活时注册，不能序列化进 manifest。插件表默认复用核心列语义；
新增列或行动作必须仍通过公开 Store/命令边界执行。

插件 ID、协议 ID 和表类型 ID 一旦进入工作区或能力声明就是持久兼容标识，
不能在无迁移的情况下改名。现有安川示例使用插件 ID
`yaskawa-memobus-67h-010dh-010eh`、协议 ID 同名，表类型 ID 为
`yaskawa-memobus-67h-010dh-010eh:holding-register`；地址调整的
`builtin-address-adjust` / `builtin.address-adjust` 是持久兼容标识。

`dataType` 贡献包括声明式标题和激活时注册的同步 parse/format 处理器。插件类型
当前只允许单寄存器；范围行继续使用内置组合类型。解析失败返回结构化错误，
未注册类型不得被当作可编辑 HEX；读取路径缺少 formatter 时只允许防御性 HEX
显示，不能使其成为已注册类型。`documentation` 只承载可序列化的轻量 Markdown，
渲染器限定支持标题、段落、列表、行内代码、加粗和围栏代码块，不执行文档中的
脚本、外部资源或任意 HTML。

`panels` 是可序列化的声明式贡献，payload 至少包含稳定的 `id` 与 `titleKey`，
并可携带可选 `title` 语言映射。`title` 存在时必须包含非空 `en-US`，其他语言
可自行补充；插件标题解析顺序固定为“当前语言 → `en-US` → 应用 i18n 的
`titleKey` → `titleKey` 原文”。旧插件不含 `title` 时继续按应用 i18n 回退，
属于向后兼容扩展。

纯清单 `example-panel` 演示 `panels` 的最小链路：权限为 `ui-contribution`，
平台要求为 Web，安装后每个声明在底部 Plugins 页签生成一个面板；一个插件可声明
多个面板，DOM 身份使用 `${pluginId}-${panelId}`。当前只落地声明式面板入口，
交互式面板组件机制尚未开放；不得把示例占位内容解释为任意第三方 UI 可注入共享
页面 DOM。禁用或卸载插件后其面板贡献必须回收，没有面板贡献时不渲染 Plugins
页签。

### 2.6 通信能力

插件发起通信时必须通过 PluginCommunicationApi。

该 API：

- 校验插件权限；
- 校验当前平台；
- 创建 source 为 plugin 的请求；
- 进入统一 RequestScheduler；
- 默认使用 `plugin-background` 优先级，记录 `source:"plugin"` 与 `pluginId`；
- 应用超时和取消；
- 不暴露 Transport；
- 不允许插件自行并发写串口。

### 2.7 插件错误隔离

插件 Hook 执行时：

1. 设置独立错误边界；
2. 捕获同步和异步异常；
3. 记录 pluginId；
4. 禁用故障贡献点；
5. 保持核心工作区可用；
6. 向用户展示可理解的加载失败原因；
7. 不因单个插件失败阻止其他插件加载。

### 2.8 插件版本兼容

插件声明 apiVersion。

Host 根据兼容范围决定：

- 可加载；
- 可加载但警告；
- 禁止加载。

插件 API 的破坏性修改必须提升主版本，并通过适配层保留必要的过渡期。

### 2.9 故障、撤销与资源预算

**Base behavior**：通信授权已有 generation 撤销，Worker 消息等待已有 10 秒超时。
注册表停用仍依赖 Hook 返回；激活期间的停用、无等待者时的错误和运行中失联缺少统一
退出规则。消息数量、待处理请求和宿主创建的 Worker 数量没有共同预算。

**Current behavior**：[注册表](../../../../packages/plugin-api/src/registry.ts)先撤销旧
generation 的通信资格，取消尚未发送的请求，并移除贡献入口。随后等待 `deactivate`，
最多 1 秒；无论成功、拒绝还是超时，均调用 `dispose`。卸载后的收尾仍由注册表跟踪，
Host 释放会等待这些有界任务。已经发到设备的写操作无法撤回；旧结果不会交给新实例。

[共享 Worker 生命周期](../../../../packages/plugin-api/src/remote-runtime.ts)每个实例只拥有
一个 Worker generation。停用首先断开通信绑定并取消请求计时器和心跳；此后不再执行
通信消息或回传旧请求结果。加载或激活期间收到停用请求时直接终止 Worker，避免与尚未
完成的 Hook 并发运行。正常激活后允许有界停用，最后释放 Worker、监听器、端口和 Blob URL。
加载、激活、停用异常、消息反序列化失败、非法消息、运行中错误和失联均关闭该实例。
Node 适配器还把提前 `exit`（包括退出码 0）作为运行失败。

预算定义在 [runtime-limits.ts](../../../../packages/plugin-api/src/runtime-limits.ts)：

| 对象                                | 上限或期限                                | 达到上限后的行为                           |
| ----------------------------------- | ----------------------------------------- | ------------------------------------------ |
| 加载、激活                          | 各 10 秒                                  | 返回错误并终止 Worker                      |
| 停用、注册表释放等待                | 各 1 秒                                   | 记录错误并继续释放                         |
| 单文件源码                          | UTF-8 2 MiB                               | 创建 Blob、data URL 或 Worker 前拒绝       |
| 同一 JS 宿主内由运行时创建的 Worker | 16 个，包含预览与加载中实例               | 拒绝新实例，成功释放后归还名额             |
| 入站消息                            | 256 KiB 估算预算、8192 个节点、32 层深度  | 关闭发送该消息的实例                       |
| 单实例入站消息速率                  | 每个 1 秒窗口最多 128 条                  | 关闭实例                                   |
| 单实例待处理通信请求                | 32 个；请求 ID 不得在未完成时重复         | 关闭实例并撤销队列请求                     |
| 单次代理通信等待                    | 30 秒                                     | 关闭实例，不重试该操作                     |
| 心跳                                | 激活后每 5 秒发送；10 秒内必须答复当前 ID | 关闭失联实例                               |
| 自动重启                            | 0 次                                      | 用户手动重新启用时重新校验批准并加载新实例 |

消息预算在克隆后的宿主接收边界执行，用于限制解析、排队和结果关联。字符串按每个
UTF-16 code unit 2 字节、数字与布尔值按 8 字节估算；对象节点和深度另行计数。
该预算不等同于浏览器分配前的硬内存配额，16 个实例也不计插件自行创建的嵌套 Worker。
浏览器不提供本实现可用的单 Worker 堆内存硬上限；心跳不能衡量仍能响应消息的插件
的全部 CPU 使用量。嵌套 Worker 仍继承不透明来源与 CSP，随所属 Worker 退出回收。

故障实例保持可见，标记为 `failed` 并设置 `enabled=false`，持久化使用现有字段。
用户重新启用会核对 Manifest、源码、执行模式和批准记录，创建新 Worker；旧实例的
消息、错误、激活完成回调和设备结果均不得改变新实例。恢复过程不保存或重放读写队列，
`activate` 继续不具备写入命令上下文。

同进程插件的异步加载、激活和停用也有等待期限，Hook 拒绝会被记录。但计时器不能
抢占同线程死循环，也不能终止超时后仍执行的代码或撤回其系统权限；同进程授权仍等价于
信任插件。单独的 codec 撤销契约不由本节改变。

[Node Worker 适配器](../../../../packages/platform-node/src/plugin-remote-runtime.ts)未接入产品
装配。其线程引擎配置为老生代 64 MiB、新生代 16 MiB、栈 4 MiB；这些限制不包含
`ArrayBuffer` 等外部分配，也不阻止整个进程耗尽内存，见
[Node Worker resourceLimits](https://nodejs.org/api/worker_threads.html#new-workerfilename-options)。
后续启用前必须单独评估文件系统、网络和子进程权限，线程不能作为 Node 权限沙箱。

供应链决策保持不变：只由用户安装本地 Manifest 或单文件 entry，不提供签名验证、
在线市场、自动下载或自动安装。批准摘要绑定被确认的内容，不能证明发布者身份；
来源、版本、权限及执行模式仍由安装确认框展示，不增加远程信任来源。

## 3. Manifest 与贡献点

当前插件 API 版本为 `2.0`。Manifest 至少包含：

- `id`、`name`、`version`；
- `apiVersion`；
- `description`，可选 `author`、`license`；
- 可选 `entry.web` / `entry.node`；
- `requiredCapabilities`；
- `platform.web` / `platform.node`；
- 类型化 `permissions`；
- `contributes`。

`contributes` 使用开放键值表；核心注册贡献点 ID、Zod Schema 和消费方。未知贡献点或无效 payload 逐项返回结构化错误，不影响同一插件的其他有效贡献。

当前贡献点：

| 贡献点              | 主要用途                 |
| ------------------- | ------------------------ |
| `panels`            | 底部面板或声明式插件页面 |
| `toolbarAction`     | 表工具栏命令             |
| `tableType`         | 新表类型及其列、行操作   |
| `protocolExtension` | 注入协议 codec           |
| `addressTransform`  | 表级地址变换             |
| `theme`             | 可选主题色预设           |
| `settings`          | Settings 分区            |
| `dataType`          | 数据类型解析与格式化     |
| `command`           | 注册可执行命令           |
| `documentation`     | 帮助或寄存器手册         |

新增贡献点应扩展 Schema 和消费方，不修改存量插件的贡献契约。

贡献点注册表负责开放扩展：

- 核心启动时注册贡献点 `id` 与 Zod Schema；贡献点 ID 是开放字符串，不为未来能力锁死枚举；
- 插件 Manifest 的 `contributes` 按已注册点逐项校验。未知点返回
  `PLUGIN_CONTRIBUTION_UNKNOWN`，无效载荷返回 `PLUGIN_CONTRIBUTION_INVALID`，错误隔离到
  单个贡献，不影响同一插件的其他有效点；
- 消费方只聚合启用且激活成功的插件贡献；禁用、卸载或激活失败后不得继续展示或执行贡献；
- 新增能力应同时增加 Schema、消费方和测试，不能仅声明一个无人消费的贡献点；
- 插件只能提交声明式数据或调用受控上下文，不得直接修改贡献注册表、UI Store 或核心模块。

Manifest 与 API 兼容性检查在加载前完成：

- Manifest v2 至少声明 `apiVersion`、平台、必需能力、类型化权限、入口和贡献；
- `apiVersion` 按兼容范围产生“可加载”“可加载但警告”“禁止加载”三种结论并附带原因；
- 未知权限、未满足平台能力或不兼容主版本均拒绝，不出现部分加载后再运行时报错；
- 插件生命周期为注册、校验、激活、停用和卸载；同步与异步 Hook 异常分别映射为结构化插件
  错误，并记录 `pluginId`。

## 4. 权限、执行与持久化

类型化权限包括：

- `communication`；
- `device-write`；
- `workspace-read` / `workspace-write`；
- `file-read` / `file-write`；
- `network`；
- `ui-contribution`；
- `theme`。

未知权限拒绝安装。权限检查必须发生在真实能力调用前，不能只在 UI 隐藏入口。
声明权限不等于获得授权。读取必须具有已批准的 `communication`；写入同时需要
`communication`、`device-write` 和宿主创建的命令上下文。`activate` 不获得写入
上下文。安装批准绑定完整 Manifest、源码和执行模式；禁用、卸载和运行实例失效后，
旧 API 与尚未发送的请求失效。详细规则见[插件通信授权](插件通信授权.md)。

执行模式：

- `isolated`：默认；Web 运行时使用无同源权限的沙箱 iframe 内的 Worker。
  Node Worker Thread 只提供独立执行线程，不能视为操作系统权限沙箱；
- `same-process`：用户安装时显式授权，插件与应用同进程并拥有相同权限。

`executionMode` 随批准记录持久化，重启后先核对启用状态和批准内容，再按同一模式加载。提供同步 codec、
dataType 或 addressTransform 的插件必须由用户选择 `same-process`；隔离插件
只有异步执行面，不能假装提供同步函数。安装确认框必须同时展示来源、版本、
权限、平台要求、执行模式和风险。执行模式不是权限提升机制：选择同进程等同于
信任该本地插件，现有 OS 用户权限仍是最外层边界。

安装流程分为“预览 manifest”和“确认安装”。单文件 entry 先在校验后的隔离环境
中读取并验证 manifest，确认后才按所选模式装配和执行。取消安装必须释放已创建
的 Worker/线程。卸载只对用户安装的插件可用；deactivate 失败仍继续回收贡献，
但不能把失败伪装成成功。

执行面按代码形态分层：

| 层         | 内容                                   | 边界                                                     |
| ---------- | -------------------------------------- | -------------------------------------------------------- |
| 声明式     | manifest、表类型、主题、文档和动作声明 | 纯数据，主线程解析，不执行插件代码                       |
| 同步纯函数 | codec、dataType、addressTransform      | 受 `same-process` 权限约束；隔离线程无法提供同步调用     |
| 异步 entry | activate/deactivate、通信、工具命令    | 默认 Worker/线程隔离，只能经受控上下文和通信代理访问应用 |

隔离 entry 不获得 DOM、任意 Node 全局、通用文件系统或网络能力。插件通信必须经
代理返回主线程统一调度器，并携带真实 `pluginId`。加载或激活失败只禁用该插件
贡献；取消安装或卸载时，Worker、线程、监听器和计时器必须释放。

插件通信经 `PluginCommunicationApi` 进入统一调度器。该 API 校验权限、平台和路由，附加 `source:"plugin"`、`pluginId` 和日志，不向插件暴露 Transport、Socket 或串口句柄。

插件记录属于应用级资产，不写入工作区。插件存储 schema 为 v5；v4 的旧记录保留源码，
重新确认前不执行。授权存储不能被隔离插件直接读写，摘要本身不能代替存储隔离。

Electron 和 VSCode 的宿主执行面与渲染端使用同一份插件存储，不通过静态 import 引入插件包。宿主只加载同时满足以下条件的插件：

- 已启用；
- `executionMode === "same-process"`；
- 带有单文件可执行 `entrySource`；
- Manifest、API 版本、平台和权限校验通过。
- 批准记录与完整 Manifest、源码和执行模式匹配。

隔离执行插件、纯清单插件和已禁用插件不进入同步贡献注册表。宿主加载器位于不依赖 serialport 的 Node 平台子路径，以内存中的单文件源码动态 import，只向插件暴露 `manifest`、`activate`、可选 `deactivate` 和可选 `handleToolbarAction`，通过受控上下文提供 codec、dataType 与 addressTransform 注册能力。导出缺失、语法错误和加载异常必须转换为结构化插件错误，不得向宿主调用方抛出未处理异常。

宿主同步按已启用同进程插件的 `id` 与批准内容摘要比较集合；摘要包含完整 Manifest、
源码和执行模式。集合变化时先注销全部宿主插件，再使用新建的 dataType 与
addressTransform 注册表重新激活。签名不变时不重建；同步期间的新保存会触发再次读取
最新存储，所有等待者在后续同步完成后返回。

**Base behavior**：codec 注册表没有撤销接口，卸载后仍保存插件 codec；已创建的会话
也保留 codec 引用，隐藏 UI 入口无法阻止旧会话继续使用它。

**Current behavior**：[CodecRegistry](../../../../packages/communication/src/codec.ts)
以 `pluginId` 和每次激活独有的注册范围记录所有权。核心 codec 经 `register` 单独登记。
插件不能覆盖核心、内置 `rtu`/`tcp` 或其他激活代的 ID，冲突返回 `CODEC_ID_CONFLICT`；
同一范围可替换自己的 codec，但替换会使旧注册实例失效。
[PluginRegistry](../../../../packages/plugin-api/src/registry.ts) 在禁用、卸载、激活失败
和释放时先撤销范围，再执行插件收尾。旧上下文注册返回 `CODEC_SCOPE_REVOKED`；同名
重装或重新启用会获得新范围。插件上下文只暴露 `register/list`，不暴露宿主的创建、
撤销或核心注册接口。插件 Manifest、安装批准和 `ctx.registries.codec` 调用形式不变。

[HostPluginRuntime](../../../../packages/platform-node/src/host-plugin-runtime.ts) 重建时
使用同一撤销路径，codec 注册表引用保持稳定，核心条目不会随插件清除。共享客户端
[装配点](../../../../apps/web/src/sync-registries.ts) 也使用相同的注册范围契约。
旧会话的请求与结果失效规则见[ProtocolCodec 扩展](../../application/communication/会话与连接.md#4-protocolcodec-扩展)。

同步生命周期固定为：

1. 宿主启动时执行一次；
2. 渲染端插件存储保存成功后执行一次，保存失败不触发；
3. 宿主退出或扩展停用时注销宿主插件并清空可重建注册表。

宿主插件加载失败或 `activate` 抛错只影响该插件，不阻止宿主会话和其他插件启动。当前不提供宿主到渲染端的能力失败回传，因此 UI 可能仍显示已声明的协议；实际使用时会表现为连接失败。此边界应在该平台正式开放对应消费路径时重新评估。

协议扩展使用通信层的通用 `ProtocolCodec` 与 `CodecRegistry`。插件在受控激活上下文中注册
codec，核心只提供编解码接口、注册表、分帧/期望长度契约和会话注入，不包含厂商功能码、
CRC 变体或寄存器语义。每个 `protocolId` 必须唯一，会话遇到未知 ID 返回
`CODEC_NOT_FOUND`，不得回退为 Modbus。插件 codec 必须复用统一调度、超时、重试、取消、
日志和迟到响应隔离，并且不能取得 Transport 句柄。具体接口和会话注入边界见
[通信会话与连接](../../application/communication/会话与连接.md#4-protocolcodec-扩展)。

`toolbarAction` 只声明动作、作用域和确认文案；实际执行由插件 runtime 的
`handleToolbarAction` 完成。需要写的动作必须声明 `device-write` 权限，经
`PluginCommunicationApi` 进入统一调度器和日志，不能在 UI 中硬编码厂商地址。
动作完成后是否刷新轮询必须是显式产品行为；未声明时不得隐式触发整表刷新。

以安川 MEMOBUS 示例插件为例，ROM/RAM Enter 是插件工具栏动作，写入地址和确认
语义属于插件包；核心只负责确认、权限、调度、日志和错误投影。第三方功能码、
BCC/CHECK-SUM、专用寄存器规则和厂商手册均不得进入通用协议或表格核心。

Electron/VSCode 的跨进程插件执行面通过版本化 HostMessage 表达加载、卸载、通用调用和贡献
查询，并提供插件事件通道。所有 payload 均做 Zod 校验；平台未开放相应运行时或消费路径时
返回结构化能力错误。宿主不得仅因消息 kind 存在就宣称可执行插件完整可用，能力矩阵必须如实
反映当前实现。

## 5. 平台适配与测试

平台边界：

| 平台     | UI-safe 插件             | Host 插件 | 安装     |
| -------- | ------------------------ | --------- | -------- |
| 浏览器   | 支持                     | 不支持    | 本地上传 |
| Electron | 支持                     | 支持      | 本地文件 |
| VSCode   | 支持                     | 支持      | 本地文件 |
| Android  | 支持，运行时探测执行能力 | 不支持    | 本地上传 |

插件贡献标题优先使用插件自带翻译；缺少当前语言时回退英文，再回退应用已有的
`titleKey`。应用内建 i18n 不应成为第三方插件的唯一标题来源。

插件测试至少覆盖：

- Manifest、API 版本和权限校验；
- 未知/无效贡献点隔离；
- 启用、禁用、卸载和持久化；
- 隔离与同进程两种执行模式；
- 插件通信进入统一队列并记录 `pluginId`；
- 宿主侧同步贡献表的卸载/禁用重建；
- 宿主只加载已启用、带 entrySource 的同进程插件；
- 宿主同步幂等、entrySource 变化触发全量重建、保存失败不触发同步；
- 宿主退出或扩展停用时释放插件贡献；
- 插件失败不阻止核心应用和其他插件启动；
- 四个平台的安装、能力声明和执行路径。

## 6. 插件实现约束

必须覆盖：

- Manifest 解析；
- 插件启用和禁用；
- 平台能力声明；
- 工具栏贡献；
- 侧边栏贡献；
- 地址转换；
- 插件通信请求进入统一调度器；
- 插件异常隔离；
- Electron 和 VSCode Host 插件加载；
- 浏览器端拒绝不兼容插件；
- 插件 API 版本不兼容提示。
