# 资源释放与生命周期

## 1. 资源释放设计

### 1.1 连接释放

断开连接时必须：

1. 停止接受新请求；
2. 取消队列；
3. 停止轮询；
4. 停止自动重连；
5. 取消超时和延迟 Timer；
6. 释放串口 Reader 和 Writer；
7. 关闭串口或 Socket；
8. 删除数据和错误监听器；
9. 清空帧缓冲；
10. 更新连接状态。

close 操作必须幂等。

### 1.2 页面和窗口释放

Browser 页面关闭或隐藏时：

- 页面进入 `visibilitychange → hidden` 时调用一次幂等 `flush()`；
- 不使用页面卸载事件作为可靠保存时机，避免中断异步 IndexedDB 写入；
- 崩溃或来不及进入 hidden 时没有可靠保存时机，由自动保存 debounce 兜底；
- 释放串口；
- 页面隐藏不默认断开，但应检测后台限速；
- 页面恢复后重新计算调度时间；
- 不补发后台积压的轮询任务。

Electron 窗口关闭时：

- Renderer 请求保存；
- Main Process 停止通信；
- 等待有限时间释放资源；
- 超时后记录诊断并继续退出；
- 不允许后台残留无界请求。

VSCode Webview 关闭时：

- UI 订阅释放；
- Webview 关闭时仍由 Extension Host 管理连接；
- Extension 停用或 VSCode 关闭时必须断开；
- 重新打开 Webview 时从 Host 获取当前状态快照。

### 1.3 插件释放

停用插件时：

- 禁止创建新命令；
- 取消插件待执行任务；
- 注销 UI 贡献；
- 注销事件监听；
- 清理插件 Timer；
- 调用 dispose；
- 插件 dispose 异常不得阻止其他资源释放。

Electron Main 和 VSCode Extension Host 在启动时同步宿主插件，并在插件保存成功后同步。同步只处理已启用且已授权同进程执行的插件；集合或 entrySource 变化时，先注销旧插件，再以新建的 dataType 和 addressTransform 注册表重建。宿主退出或扩展停用时必须注销全部宿主插件并释放可重建注册表。

codec 注册表可由宿主会话长期持有，但插件条目必须按激活范围撤销。禁用、卸载、源码
更新或宿主释放时，先使旧范围失效，再执行插件收尾；核心条目保留。旧会话拒绝新请求，
已发请求按原超时完成收尾并丢弃结果，不能通过同名重装恢复旧会话。详见
[插件契约](../../ports/plugin-api/插件契约.md)和
[ProtocolCodec 扩展](../../application/communication/会话与连接.md#4-protocolcodec-扩展)。

### 1.4 释放失败与诊断

资源释放失败时：

1. 尽可能清理本地引用、订阅和计时器；
2. 记录结构化诊断错误；
3. 阻止新设备请求进入正在失败的连接；
4. 避免 UI 永久停留在 `disconnecting` 或其他中间状态；
5. 不得把部分释放伪装为成功，也不得因此删除仍然有效的工作区数据。

## 2. 启动与移动端生命周期

启动就绪必须等待：

1. Host 装配完成；
2. 工作区加载成功、失败或超时落定；
3. 已安装插件注册完成或加载结束。

就绪前显示与当前主题一致的启动骨架，避免先渲染默认空工作区再切换。超时后显示
可理解警告并保持应用可操作；插件失败不能永久阻塞 ready。`ready` 必须同时意味着
工作区和插件状态已经落定，所有后续 Store 写入要受装配取消信号保护。首帧偏好缓存、
就绪门、超时和失效 UI 指向的完整规则见
[启动偏好、首帧与就绪门](../../presentation/state/状态管理.md#2-启动偏好首帧与就绪门)。

移动端或隐藏页面进入后台时：

- 暂停轮询、Trace 和持续总线任务；
- 保留配置，不补发后台积压任务；
- 返回前台后按原配置恢复；
- 设备拔出时停止持续任务并上报消息；
- 返回键按覆盖层栈关闭最上层抽屉/对话框；
- 页面关闭和 Host 停用执行幂等释放。
