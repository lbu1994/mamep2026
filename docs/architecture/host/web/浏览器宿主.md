# 浏览器宿主

## 1. apps/web

职责：

- 装配浏览器平台能力；
- 渲染共享 React UI；
- 使用 Web Serial；Electron Renderer 复用同一 Web Serial Adapter；
- 使用 IndexedDB；
- 执行浏览器能力检测；
- 注册浏览器生命周期事件；
- 构建静态网站。

不得包含：

- Node.js 串口实现；
- Node.js TCP；
- Electron IPC；
- VSCode API；
- 厂商私有协议实现。

## 2. 平台装配

`apps/web` 同时是四端共享渲染器的组合根。`App.tsx` 只负责探测平台、创建共享
装配上下文并启动 Host 生命周期，平台差异集中到独立工厂，不能散落在 React 组件
或业务包中。

平台判定顺序固定为：

1. `window.mamepHost` 存在时，按 `bridge.platform` 选择 VSCode 或 Electron；
2. 无宿主桥且 `Capacitor.getPlatform() === "android"` 时选择 Android；
3. 其他情况选择 Browser。

宿主桥必须优先于 Capacitor 探测，防止 Electron/VSCode 内嵌 WebView 被误判为
Android。`vscode-dev-bridge.ts` 在 `createRoot().render()` 之前同步安装宿主桥，
不得改为异步加载。

平台 Host 实现按需加载：

- Browser 路径保持静态装配，并作为 Electron/Android 的共享内层能力来源；
- Electron、VSCode、Android Host 各自成为平台专属懒 chunk；
- `@capacitor/core` 及 Android Capacitor 子路径只能由 Android 工厂加载；
- Browser、Electron、VSCode 的首屏不得执行 Capacitor 全局副作用。

Host 装配编排负责“构造 → 接线 → 启动 → 释放”，使用 `AbortSignal` 保护
StrictMode 双挂载、页面卸载和重新装配。每次 `await` 后及工厂返回后都必须检查
取消状态；已取消流程不得继续写入 Store，若 Host 已构造则立即 `dispose()`，
不得接线。由装配编排注册的 `visibilitychange`、Android 前后台监听和其他订阅
必须绑定同一取消信号并在释放时退订。装配失败必须进入可操作的 `failed` 状态
并发布结构化应用消息，不能白屏。

启动状态至少包含 `assembling`、`ready`、`failed`。真实启动在首帧前进入
`assembling`；骨架可先显示平台装配过程，但 `ready` 还必须等待工作区加载和插件
注册落定，详见[启动偏好、首帧与就绪门](../../presentation/state/状态管理.md#2-启动偏好首帧与就绪门)。
