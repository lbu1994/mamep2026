# 安全边界

## 1. 安全设计

### 1.1 基础原则

1. 最小权限；
2. UI 与本地系统能力隔离；
3. 所有跨边界输入校验；
4. 插件权限可见；
5. 不自动上传数据；
6. 不自动执行未知插件；
7. 不自动连接设备；
8. 不把设备通信能力暴露给不受控脚本；
9. 日志导出由用户主动触发；
10. 开源示例不得包含私有资料。

### 1.2 写入安全边界

Mamep2026 不理解所有寄存器的业务风险，但技术上仍需要确保：

- 只有用户明确操作或已授权插件命令可以写入；
- 轮询任务不得产生写请求；
- 工作区恢复不得自动执行写入；
- 插件启用不得自动执行设备写入；
- 写入地址和实际发送地址进入日志；
- 地址插件转换必须可见；
- 禁止因重试策略对非幂等私有写入进行未经声明的重复执行；
- 标准 0x10 写入重试行为由明确策略控制。

### 1.3 内容安全策略

Browser、Electron Renderer 和 VSCode Webview 均配置 CSP。

默认要求：

- 不执行 inline script；
- 不使用 eval；
- 不从不受信任远程地址加载脚本；
- 图标和字体优先随应用打包；
- Webview 资源限制在授权 URI；
- 插件 UI 不允许注入共享页面 DOM；
- 外部链接经过 Host 确认后打开。
