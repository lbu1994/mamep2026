# 安全边界

## 1. 安全设计

### 1.1 基础原则

1. 最小权限；
2. UI 与本地系统能力隔离；
3. 所有跨边界输入校验；
4. 插件权限可见；
5. 不自动上传数据；
6. 不自动执行未知插件；
7. 不自动连接设备；
8. 不把设备通信能力暴露给不受控脚本；
9. 日志导出由用户主动触发；
10. 开源示例不得包含私有资料。

### 1.2 写入安全边界

Mamep2026 不理解所有寄存器的业务风险，但技术上仍需要确保：

- 只有用户明确操作或已授权插件命令可以写入；
- 轮询任务不得产生写请求；
- 工作区恢复不得自动执行写入；
- 插件启用不得自动执行设备写入；
- 写入地址和实际发送地址进入日志；
- 地址插件转换必须可见；
- 禁止因重试策略对非幂等私有写入进行未经声明的重复执行；
- 标准 0x10 写入重试行为由明确策略控制。

### 1.3 内容安全策略

Browser、Electron Renderer、VSCode Webview 和 Android WebView 均配置 CSP。

默认要求：

- 不执行 inline script；
- 不使用 eval；
- 不从不受信任远程地址加载脚本；
- 图标和字体优先随应用打包；
- Webview 资源限制在授权 URI；
- 插件 UI 不允许注入共享页面 DOM；
- 外部链接经过 Host 确认后打开。

Electron Renderer 和 VSCode Webview 的生产 CSP 必须在构建期随页面注入。Electron `loadFile` 加载的 `file://` 页面不触发只适用于 HTTP 请求头的 CSP 路径，不能把 `webRequest.onHeadersReceived` 作为唯一防线。

基线 CSP：

    default-src 'self';
    script-src 'self';
    style-src 'self' 'unsafe-inline';
    img-src 'self' data:;
    font-src 'self' data:;
    connect-src 'self'

其中 `style-src 'unsafe-inline'` 只服务 Ant Design CSS-in-JS，不构成放行 inline JavaScript 的依据。可执行插件需要 Blob Worker 时，再按 §1.3 增加 `blob:` 到 `worker-src` 与 `script-src`。

Electron 生产资源使用相对 `base`，加载 `apps/web/dist-electron/`；Browser 使用独立产物目录和绝对 `base`。这两个产物的目录、入口和 CSP 不得混用。

VSCode 生产 Webview 只允许加载 `localResourceRoots` 内资源，URI 必须经 `asWebviewUri()` 生成。`MAMEP_DEV_URL` iframe 仅用于开发；生产 HTML 不得包含 dev server 地址。

开发探针必须有构建门控。Electron `debug:get-state` 打包后返回禁用错误；VSCode `debug:get-state` 与面板引用命令只用于开发/e2e，不能成为 Webview 可调用的生产能力。

可执行插件经 Blob URL 加载时，生产 CSP 必须同时允许：

- `worker-src 'self' blob:`，用于 Blob Worker；
- `script-src 'self' blob:`，用于 Worker 内或文档内的插件 entry 动态 `import()`；
- VSCode Webview 使用 `webview.cspSource` 替代 `'self'`；
- 仍禁止内联脚本、`eval` 和不受信任远程脚本。

仅配置 `worker-src blob:` 不足以保证插件可执行，因为 Worker 内部动态 import 受
`script-src` 控制。dev 模式通常不注入生产 CSP，因此插件执行必须在打包产物上验证。

### 1.4 插件执行信任边界

可执行插件默认在隔离 Worker 或线程中运行。`same-process` 必须在安装确认框中由用户显式授权，其权限等同于宿主应用：

- Electron 插件在 Main Process 中运行，可获得完整 Node.js 能力；
- VSCode 插件在 Extension Host 中运行，可获得扩展宿主的 Node.js 能力；
- Android 插件在 WebView 文档上下文中运行，可获得该页面可用能力；
- Browser 不加载 Node Host 插件。

同进程加载只能隔离同步或异步抛出的异常，无法终止死循环、阻止内存耗尽或撤销插件已经取得的系统权限。当前不提供插件签名校验，因此安装确认是信任决策的一部分。Electron 和 VSCode 必须从插件存储加载已授权的同进程插件，禁止用静态 import 绕过安装与卸载语义。

Android 只允许在运行时探测确认 Blob Worker 可执行后声明可执行插件能力；探测失败或超时必须保持不支持。Android 没有 Node 宿主执行面，`hostPlugins` 维持 `false`。

## 2. 产品安全与隐私

产品不承担工业生产安全职责，但仍需满足基础软件安全要求：

1. 界面代码不得获得不必要的系统权限；
2. 所有用户输入在进入核心能力前经过校验；
3. 插件安装和执行模式选择必须有明确提示；
4. 默认不执行未知插件，不默认启用同进程执行；
5. 不记录与调试无关的敏感信息；
6. 日志导出前提示可能包含设备地址和通信数据；
7. 不自动把调试数据上传云端；
8. 不在用户不知情时建立外部网络连接；
9. Electron 遵循 Main、Preload、Renderer 安全隔离；
10. VSCode 遵循工作区信任和扩展权限约束。

默认隐私边界：

- 配置和工作区保存在本地；
- 不要求用户登录；
- 不采集设备通信内容；
- 不上传寄存器表；
- 不上传原始报文；
- 不上传插件私有数据；
- MVP 不启用默认云端遥测。

未来若增加遥测，必须说明采集字段、征得用户同意、提供关闭方式，并排除原始
设备报文和寄存器数据。日志导出与遥测边界详见
[日志应用服务](../../application/logging/日志.md)。
