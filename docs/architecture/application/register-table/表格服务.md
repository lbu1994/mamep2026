# 寄存器表应用服务

## 1. packages/register-table

包含：

- 表格应用服务；
- 行增删移动（含插入、批量移动、批量删除，`row-operations.ts`）；
- 复制和粘贴模型（含系统剪贴板 CSV 编解码与应用内剪贴板，`row-clipboard.ts`）；
- 多行选择状态（会话态 `selectedRowIds`，由 UI 层 Ant Design `rowSelection` 驱动）；
- 地址提交；
- 单元格直接编辑；
- 读取结果应用；
- 写入值解析与校验；
- 状态和错误投影；
- 工作区编辑命令与撤销/重做快照；
- 对通信服务的用例封装。

行编辑使用 Ant Design Table 的 `rowSelection`、Dropdown 和受控输入能力。插入、移动、删除、复制、剪切和粘贴的状态语义位于 `register-table`，UI 只维护 `selectedRowIds` 等会话状态。多选不依赖 AntD 内部结构，右键菜单和快捷键都经 `app-store` 的统一动作执行。

## 2. 地址提交与按表进制

地址候选文本为 `addressDraft`，已提交起始地址为 `addressValue`，范围长度由 `registerCount` 表示。提交时必须传入所属表的 `registerRadix`，不能使用全局进制：

- DEC 接受十进制整数并校验 0–65535，提交后去除前导零，不补位；
- HEX 接受 1–4 位十六进制字符，不接受 `0x` 前缀，提交后补足 4 位大写；
- 范围文本两端使用同一表级进制解析，并验证结束地址大于或等于起始地址；
- 格式错误或超范围时保留 draft 并返回 `ADDRESS_OUT_OF_RANGE` 等结构化错误，不发送请求；
- 切换 DEC/HEX 不重排已提交文本，只影响列头、后续输入和值格式化。

复制表时继承源表 `registerRadix`；老工作区缺少该字段时默认 DEC，不需要提升 Schema 版本。UI 由 `RegisterTable` 按行所属表取得进制，不能从当前活动表推断其他表的设置。

范围行的 `registerCount` 与 `dataType` 必须联合校验：

- Unsigned/Signed：1、2 或 4 个寄存器；
- float32：严格 2 个寄存器；float64：严格 4 个寄存器；两者不应用 scale；
- Binary：1 至 4 个寄存器；
- HEX 与 String：允许 1 到单次协议请求上限；
- 结束地址不得超过 `0xFFFF`，FC03/FC0x10 数量还必须满足 Modbus PDU 上限；
- 不合法时错误归属 Type/进制单元格，行读取和写入均禁用；
- 地址与类型校验在进入会话前完成，失败不发送请求。

表格服务按父行组合文本和父行 Type 解析一次写入的全部原始值，并透传
`quantity=registerCount`。子行元数据与原始值同步属于表格服务；设备请求仍由通信层一次性
发送，不由 UI 逐子行发送。

范围行子行使用以下模型与同步规则：

- 父行 `registers` 为 `RegisterSubRowMeta[] | null`，每项保存 `name`、`comment`、`dataType`，
  长度等于 `registerCount`；单寄存器行及兼容旧数据可为 `null`；
- `registerValues` 是原始值的单一事实源，子行显示值是 `registers[i]` 与
  `registerValues[i]` 的派生结果；浮点父行的缺省子行类型为 HEX，子行不允许浮点类型；
- 子行 Data 提交使用子行自己的 Type 解析单个 16 位值，写回 `registerValues[i]` 后按父行
  Type 重新格式化父行 `cellText`；缺乏原始值数组时，从父行组合文本派生基准；
- 地址范围不变时不重建元数据；范围变化时父行 Type 与原始值按新范围重新校验，旧值不得
  与新范围错位，`registers` 则按索引保留、截断或补齐；
- 父行 Data 提交、手动读取、轮询和写后回读更新原始值后，每个子行按自身 Type 重新展示；
- 子行可编辑 Name、Data、Type、Scale 和 Comment；READ、WRITE、WP、TM、地址、拖拽、多选及
  行级菜单仍只作用于父行；
- 子行 Data 校验失败不得改动父行或原始值。读取与回读不得覆盖任何子行元数据。

父行 Data 文本提交也属于“当前原始值”的合法写入方。只要文本解析成功，服务必须在
同一提交边界内同时产生规范化 `cellText` 和逐寄存器 `registerValues`：

- 范围行按父行 Type 解析全部值，单寄存器行产生长度为 1 的数组；
- 此前没有原始值（例如从未读取或由粘贴新建）时，以本次输入直接建立基准；
- 子行显示、Binary 位明细和位切换随后都必须读取这次提交后的原始值；
- 解析失败、空值或校验失败时保持原 `cellText`、`registerValues` 和子行元数据不变；
- 成功提交后不得继续保留“父行文本已更新、子行仍来自上次设备读取”的中间状态。

设备读取、轮询和写后回读仍会用设备结果整体重建当前原始值，从而使任何历史展示回到
设备事实。剪贴板粘贴新建行是明确例外：按当前粘贴语义把新行 `registerValues` 初始化为
`null`，在用户随后成功提交父行文本或发生设备读取前，子行和位明细显示未读取状态。

写后回读配置也是每表字段，随工作区持久化。写入操作使用活动表快照生成
`ReadVerifySettings`，同一行在写后回读完成前暂缓普通轮询；其他行轮询不因此停止。

## 3. 行操作

行操作统一位于 `row-operations.ts`：

1. 末尾追加或目标行之后插入空行，不继承名称、地址、类型或备注；
2. 目标行之前插入空行；
3. 按稳定 `rowId` 移动一个选择块；
4. 按稳定 `rowId` 删除一个选择块；
5. 每次结构变化后重新编号显示顺序，但不得改变 `rowId`。

多选集合 `selectedRowIds` 是会话状态，切换表或重置工作区时按 UI 规则清空，不写入持久化模型。右键菜单和键盘动作都调用同一 Store 命令，不复制业务逻辑。

删除操作不增加独立确认弹窗；现有点工具需要支持从撤销/重做栈恢复误删。删除正在轮询的行时必须取消后续轮询，并使迟到结果失效。

## 4. 剪贴板

`row-clipboard.ts` 定义平台无关的行块模型和 CSV 编解码：

- 系统剪贴板列固定为 `Name,Address,Data,Type,Comment`；
- Address 使用十进制整数，空地址留空；
- 使用 RFC4180 兼容的引号、逗号和换行转义；
- 解码按首列名兼容 `Name` 表头，新旧 CSV 均可导入；
- Address 粘贴后按目标表进制重新格式化；
- Data 非法文本原样保留，交给现有单元格解析和行级校验提示。

粘贴在目标行或最后选中行之后插入；无目标时追加表尾；空间不足时自动补空行，不静默截断。整个选择块的剪切或粘贴作为单个撤销步骤。

剪贴板不携带运行时原始值或设备读值。粘贴成功后新行的 `registerValues` 清空，
Data 文本按目标行自己的 Type 和范围长度规范化；规范化失败保留原文。整数和定点类型
不得无提示截断或舍入；float32/float64 在提交或粘贴时按 IEEE 754 最近值自动舍入，
中点取偶数，并覆盖原文，不提示或确认。地址同样按目标表进制规范化。

系统剪贴板经 `AppHost.copyTextToClipboard` / `readTextFromClipboard` 访问。写系统剪贴板失败不得清空应用内剪贴板；系统剪贴板读取失败时使用应用内最近行块。复制和剪切不修改设备状态，也不触发通信。

剪贴板来源由 [UI Store](../../../../packages/ui/src/app-store.ts) 的会话状态决定：

- **Base behavior**：粘贴总是先读系统剪贴板，仅在读取失败或内容为空时回退。
  本次复制写入失败时，系统中的旧单行内容仍会取代应用内的多行载荷。
- **Current behavior**：复制和剪切记录本次系统写入状态。写入尚未完成或失败时，
  粘贴使用应用内的完整行块；写入成功后，恢复系统剪贴板优先及读取失败回退规则。
  较早写入的完成回调不得修改较新行块的写入状态。该状态跨切表保留，不进入工作区存储。

键盘处理只通过统一快捷键注册表分发。焦点位于文本输入、Select、单元格编辑器，或存在阻塞式 Modal/Drawer 时不得执行行快捷键。

## 5. 撤销与重做

撤销栈只处理工作区编辑操作：

- 新增行；
- 删除行；
- 修改名称；
- 修改地址；
- 修改 Type；
- 修改轮询设置；
- 粘贴；
- 移动行；
- 表级配置和表结构操作。

不撤销：

- 设备读取结果；
- Data 单元格文本修改；
- 已经发送的写入；
- 连接和断开；
- 通信日志；
- 设备产生的外部状态；
- Trace 窗口与采样历史；
- 列宽、列序和标签页打开/关闭等视图状态。

写入设备后不能使用普通 UI 撤销恢复设备值。一次批量删除、移动、剪切或粘贴
整体作为一个撤销步骤。撤销/重做栈属于纯内存会话状态，不随工作区持久化；
容量上限为 100 步，加载或重置工作区时清空历史。

撤销范围进一步按以下边界划分：

- 行级操作包括新增/插入/删除、移动、复制、剪切、粘贴、改名、改地址、改 Type/Scale、
  轮询开关和范围行子行元数据；
- 表级操作包括每表地址进制、从站地址、写后回读配置，以及新增、删除、重命名、复制和移动表；
- 标签页打开/关闭、列宽、列序、当前选择、连接状态、Trace、通信日志和设备结果均不进入
  历史；
- 新编辑一旦发生，重做分支必须清空；删除某核心类型的最后一张表时，删除、同类型补建和
  活动表切换作为一个步骤。撤销恢复完整原表并移除补建表，重做复用同一补建结果；
  具体边界见[工作区删除规则](../workspace/工作区.md#222-删除最后一张同类型表)。

撤销数据在 `register-table` 中以纯函数实现。编辑项快照只保存可撤销字段；结构与增删操作
保存足以重建完整行的数据。恢复编辑字段时保留当前运行时读值，只有撤销删除这类需要重建
已消失行的情况才从完整行快照恢复。UI Store 只保存撤销栈、重做栈和当前应用动作，不把
历史写入工作区。工具栏提供可访问的撤销/重做按钮，禁用态由栈是否为空派生；`Ctrl+Z`、
`Ctrl+Shift+Z` 和 `Ctrl+Y` 调用同一动作。

## 6. 表类型与地址变换

寄存器表服务不把读写操作写死为保持寄存器。表类型元数据负责把表映射到协议
codec 和操作能力：

- `holding-register` 使用 FC03/FC0x10；
- `coil` 使用 FC01/FC0F；
- `discrete-input` 使用 FC02 且只读；
- `input-register` 使用 FC04 且只读；
- 插件表使用 `<pluginId>:<tableTypeId>`，由插件贡献的 codec 承载。

表类型只改变协议映射和允许的操作。行编辑、选择、轮询、批量读取、Trace、写后
回读和日志仍由同一服务处理，不为插件表维护第二套表格业务逻辑。读取、写入、
轮询和批量操作的守卫必须在发请求前根据表类型执行；只读表不得出现可执行的写
路径。

不同的表类型之间不得复制或粘贴行，也不能通过应用内剪贴板或系统 CSV 绕过该
限制。复制整张表时保留可持久化字段、`type` 和 `addressTransform`；表的运行时
状态不复制。

每张表可以配置一个地址变换。发送前先校验用户地址，再调用当前配置解析出的
transform：

- 未配置或关闭时不改变地址；
- 启用时由插件注册表提供 apply/validate，失败或下溢则保留用户输入并拒绝发送；
- 轮询、批量读取、单行读写和 Trace 均按目标行所属表应用变换；
- 末次发送地址、用户地址、transformId 进入请求上下文和通信日志；
- 变换不会修改用户保存的地址，协议层只接收已验证的最终发送地址。

## 7. Type 切换与位明细

### 7.1 Type/Scale 即时刷新

切换 Type 或 Scale 时，表格服务调用 `retargetRowDataType` 并写回同一当前值：

1. 用切换前的 Type 解析当前文本；
2. 用新 Type 格式化解析出的原始值；
3. 更新 `dataType` 和 `cellText`，不修改 `registerValues`；
4. 空文本或解析失败时只更新 Type 并保留原文；
5. 新 Type 无法格式化时结构化兜底，不抛到 UI；
6. 不设置脏值、不新增独立撤销项、不触发设备写入。

撤销/重做恢复 Type 时必须调用同一重定向规则。范围行先按旧父 Type 解析组合文本，
再按新父 Type 格式化；子行显示继续按各自 Type 从 `registerValues` 派生。

### 7.2 Binary 位明细

单寄存器 Binary 行可展开 16 个位行。范围行不直接展开位；其每个寄存器子行在
自身 Type 为 Binary 时可再展开 16 个位行，形成父行、寄存器子行、位行三层树。
非 Binary 行不生成位行，插件自定义类型不按名称自动参与。

位序固定为 bit 15 到 bit 0，高位在上。位行使用父行真实 `rowId`、寄存器序号和
bit 序号路由：

- Data 列只有一个 0/1 开关；未读取状态在开关内显示 `—` 而不是 `0`；
- 未读取时以父行文本派生，失败按 0 基准；开关仍可用；
- 切换位值只更新对应 `registerValues[i]` 并重算父行 `cellText`，不写设备，
  不入撤销栈，不置“已写入”状态；
- 位 Name 与 Comment 可编辑，分别写入 `bitNames` / `bitComments` 并作为工作区
  编辑进入撤销栈；
- 只读表的位明细可展开查看，但位开关、位 Name 和 Comment 不可编辑；
- 位行不进入选择集、剪贴板、拖拽、地址操作、行级菜单或设备请求计数。

位明细按需生成，不复制持久化行实体。虚拟滚动遇到范围行或 Binary 行时按既有条件
降级，位行数量不得改变父行身份或状态语义。
