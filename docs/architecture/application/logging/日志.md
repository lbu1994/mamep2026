# 日志应用服务

### 6.10 packages/logging

包含：

- 结构化消息日志；
- 通信日志；
- 日志保留上限；
- 日志导出模型（仅导出，CSV 格式；搜索/过滤不提供）；
- 敏感字段标记；
- 日志事件订阅。


## 20. 日志设计

### 20.1 日志类型

分为：

1. ApplicationMessage；
2. CommunicationLogEntry；
3. DiagnosticLog。

ApplicationMessage 面向用户。

CommunicationLogEntry 面向通信调试。

DiagnosticLog 面向开发和故障定位，不默认展示全部内部细节。

### 20.2 通信日志模型

每条通信日志建议包含：

    CommunicationLogEntry
      id
      timestamp
      connectionId
      protocol
      source
      direction
      slaveAddressOrUnitId
      transactionId
      functionCode
      registerAddress
      registerCount
      rawBytes
      attempt
      queueWaitMs
      durationMs
      status
      modbusExceptionCode
      errorCode
      errorMessage
      metadata

原始数据在内存中使用 Uint8Array，在展示和导出时转换为大写十六进制字节串。

### 20.3 请求和响应关联

每次尝试拥有独立 attemptId。

写入和回读通过 operationGroupId 关联。

全表读取通过 batchId 关联。

轮询通过 pollingCycleId 或 rowId 关联。

这些关联字段随日志一并导出（CSV），供用户在第三方软件（如 Excel）中自行筛选；本软件不提供日志搜索/过滤。

### 20.4 日志保留策略

为避免长时间运行导致内存无限增长：

- 通信日志采用环形缓冲；
- 消息日志采用独立上限；
- 上限可在设置中配置；
- 达到上限后删除最旧条目；
- 导出时只导出当前缓冲区内容；
- 后续版本可增加流式文件日志；
- Trace 数据不与普通通信日志共用无限缓冲。

### 20.5 原始报文展示

展示格式：

- 大写十六进制；
- 字节间使用空格；
- 不进行本地化；
- 对请求和响应使用不同方向标识；
- 同时展示解析后的功能码和地址；
- 插件转换地址时同时展示用户地址和实际发送地址。

### 20.6 日志隐私

导出前提示日志可能包含：

- IP 地址；
- 串口信息；
- 设备地址；
- 寄存器地址；
- 寄存器数据；
- 插件元数据。

默认不记录：

- 操作系统用户名；
- 完整个人目录；
- 与调试无关的环境变量；
- 插件私有凭据；
- 未经用户允许的任意文件内容。

## 29. 可观测性与诊断

### 29.1 内部诊断事件

系统内部发布：

- connection-state-changed；
- request-enqueued；
- request-started；
- request-retried；
- request-completed；
- request-failed；
- request-cancelled；
- polling-lagged；
- workspace-save-started；
- workspace-save-completed；
- workspace-save-failed；
- plugin-load-failed。

这些事件用于日志和测试，不直接成为 UI 状态源。

### 29.2 诊断信息导出

后续可以提供诊断包导出，包含：

- 应用版本；
- 平台；
- 工作区 Schema 版本；
- 插件列表；
- 脱敏后的错误日志；
- 最近通信错误；
- 能力矩阵。

默认不包含：

- 完整寄存器数据；
- 完整工作区；
- 原始报文；
- 设备 IP；
- 用户文件路径。

如用户主动选择包含原始通信数据，应明确提示。

### 29.3 遥测

MVP 不接入默认云端遥测。

如果未来增加遥测，应通过独立技术设计明确：

- 采集字段；
- 用户同意方式；
- 脱敏；
- 关闭方式；
- 数据保留；
- 开源部署差异。
