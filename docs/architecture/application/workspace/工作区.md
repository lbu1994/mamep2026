## 19. 持久化设计


### 19.2 自动保存

AutoSaveCoordinator 监听可持久状态变更。

策略：

1. 对连续编辑采用 debounce；
2. 关键结构操作可立即触发保存；
3. 应用关闭前尝试 flush；
4. 每次保存生成完整一致的工作区快照；
5. 不在保存过程中读取正在变化的可变对象；
6. 保存失败发布结构化错误；
7. 保存失败不得清除内存状态；
8. 自动保存不对外展示保存状态，仅手动保存场景展示保存中、已保存和失败状态；
9. 保存操作串行执行；
10. 新保存请求到来时合并中间状态，只保存最新快照。


### 19.6 数据版本和迁移

每个工作区包含 schemaVersion。

加载流程：

1. 解析 JSON；
2. 检查基础结构；
3. 读取 schemaVersion；
4. 顺序执行迁移；
5. 使用当前 Schema 校验；
6. 创建迁移后备份；
7. 返回领域对象。

迁移必须：

- 单向；
- 可重复测试；
- 不直接修改原始文件；
- 保留未知插件配置；
- 记录迁移历史；
- 遇到无法迁移数据时尽可能部分恢复。

既有/规划迁移：v1→v2（ADR-029，全局 readVerifySettings → 各表 writeVerify）；规划 v2→v3
（ADR-030：`lastKnownRawValue` → `registerValues`、补 `registerCount=1`、`dataType` 新增
"string"）。

### 19.7 损坏恢复

如果主工作区损坏：

1. 尝试读取备份；
2. 若备份有效，进入恢复模式；
3. 保留损坏原文件；
4. 提示恢复来源和时间；
5. 允许导出损坏文件；
6. 允许创建新工作区；
7. 不因单个插件配置损坏而放弃全部工作区；
8. 对无法恢复的字段采用明确默认值并记录告警。
