## 10. 连接状态机

### 10.1 状态定义

连接状态建议定义为：

- disconnected；
- selecting-device；
- connecting；
- connected；
- disconnecting；
- reconnect-waiting；
- reconnecting；
- interrupted；
- failed。

状态机必须防止非法转换。

示例合法转换：

    disconnected -> selecting-device
    disconnected -> connecting
    selecting-device -> connecting
    selecting-device -> disconnected
    connecting -> connected
    connecting -> failed
    connecting -> disconnected
    connected -> disconnecting
    connected -> interrupted
    disconnecting -> disconnected
    interrupted -> reconnect-waiting
    interrupted -> disconnected
    reconnect-waiting -> reconnecting
    reconnecting -> connected
    reconnecting -> failed
    failed -> connecting
    failed -> disconnected

### 10.2 状态机职责

1. 防止重复连接；
2. 防止重复断开；
3. 断开时取消未执行任务；
4. 连接丢失时通知轮询器停止；
5. 用户主动断开后禁止自动重连；
6. 区分连接失败和连接中断；
7. 释放底层资源；
8. 发布结构化状态事件；
9. 为 UI 提供可预测状态；
10. 不将连接句柄写入持久化状态。

### 10.3 连接配置快照

建立连接时创建不可变配置快照。

正在执行的请求使用连接建立时和请求提交时确定的配置，不读取之后被 UI 修改的可变对象。

配置修改规则：

- 串口核心参数变更后需要重新连接；
- TCP 主机和端口变更后需要重新连接；
- 从站地址或 Unit ID 对后续请求生效；
- 超时和重试可对后续请求生效；
- 已入队请求保留创建时的请求配置快照。
