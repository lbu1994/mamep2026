# 通信会话与连接

## 1. packages/communication

包含：

- CommunicationSession；
- RequestScheduler；
- RetryPolicy；
- TimeoutController；
- PollingCoordinator；
- BatchReadCoordinator；
- WriteVerifyCoordinator；
- TransportPort；
- 请求生命周期事件；
- 连接状态机；
- 取消机制；
- 延迟响应隔离；
- `ProtocolCodec` 与 `CodecRegistry`。

应用层用共享 `SessionHostCore` 组合上述能力，并由 `RtuSessionHost`、`TcpSessionHost`
声明协议差异。宿主只负责打开对应 Transport 和转发事件，不复制会话、轮询、Trace、
批量读取或写后回读编排。

Electron 与 VSCode 的活动性差异体现在 Host 边界：

- Electron RTU 仍在 Renderer 使用 Web Serial；Electron TCP 在 Main；
- VSCode RTU 与 TCP 都在 Extension Host；
- 远端 Renderer 只持有可序列化会话代理，不持有连接句柄。


## 2. 连接状态机

### 2.1 状态定义

连接状态建议定义为：

- disconnected；
- selecting-device；
- connecting；
- connected；
- disconnecting；
- reconnect-waiting；
- reconnecting；
- interrupted；
- failed。

状态机必须防止非法转换。

示例合法转换：

    disconnected -> selecting-device
    disconnected -> connecting
    selecting-device -> connecting
    selecting-device -> disconnected
    connecting -> connected
    connecting -> failed
    connecting -> disconnected
    connected -> disconnecting
    connected -> interrupted
    disconnecting -> disconnected
    interrupted -> reconnect-waiting
    interrupted -> disconnected
    reconnect-waiting -> reconnecting
    reconnecting -> connected
    reconnecting -> failed
    failed -> connecting
    failed -> disconnected

### 2.2 状态机职责

1. 防止重复连接；
2. 防止重复断开；
3. 断开时取消未执行任务；
4. 连接丢失时通知轮询器停止；
5. 用户主动断开后禁止自动重连；
6. 区分连接失败和连接中断；
7. 释放底层资源；
8. 发布结构化状态事件；
9. 为 UI 提供可预测状态；
10. 不将连接句柄写入持久化状态。

### 2.3 连接配置快照

建立连接时创建不可变配置快照。

正在执行的请求使用连接建立时和请求提交时确定的配置，不读取之后被 UI 修改的可变对象。

配置修改规则：

- 串口核心参数变更后需要重新连接；
- TCP 主机和端口变更后需要重新连接；
- RTU Slave Address 与 TCP Unit ID 均为每表设置，对活动表后续请求生效；
- 超时和重试可对后续请求生效；
- 已入队请求保留创建时的请求配置快照。

### 2.4 每表地址与 TCP Unit ID

RTU 和 TCP 共用“一表一地址”的产品语义：

- RTU 使用 `RegisterSheet.slaveAddress`，请求构造时写入 RTU Slave Address；
- TCP 使用同一表字段作为 MBAP Unit ID；
- 连接 profile 中的 `slaveAddress`/`unitId` 只提供连接初始值；
- 活动表变化或工具栏编辑后，同步到会话并对后续读、写、轮询、批量读取和 Trace 生效；
- 已提交请求保留请求创建时的地址快照，不能因之后切换表而改写目标；
- RTU 的 `setSlaveAddress` 与 TCP 的 `setUnitId` 互不影响；
- TCP 网关场景允许同一连接对不同表使用不同 Unit ID，浏览器仍不开放直接 TCP。

远程宿主使用独立 request kind `session-set-unit-id`，避免把 TCP Unit ID 伪装成 RTU
Slave Address。Webview/Renderer 按活动协议选择对应方法，宿主侧仍保留协议守卫作为
防御边界。

### 2.5 TCP 分帧与连接重建

TCP 的 MBAP 分帧和 Transaction ID 关联属于 `CommunicationSession`/`TcpFrameParser`，
不属于 Transport Port。连接建立时重置 Transaction ID 计数；每次实际尝试使用新的
16 位 ID，包括重试。连接断开时停止接收、取消等待、清空不完整帧，旧连接事件不得进入
新连接状态机。

## 3. TCP 自动重连

自动重连只适用于 Electron Main 与 VSCode Extension Host 承载的 TCP 会话。浏览器不实现
直接 Modbus TCP，RTU 不自动重连。Adapter 只报告传输中断和结构化错误，是否重连由
Application 层策略决定。

`TcpSessionHost` 装配 `ReconnectCoordinator`。协调器遵循以下规则：

- 仅当会话成功连接且 profile 的 `autoReconnect=true` 时 armed；
- 用户主动断开、重新连接或释放宿主时立即 disarm；
- 会话进入 `interrupted` 且仍 armed 时，依次发布 `reconnect-waiting`、等待退避、
  `reconnecting`，再经宿主注入的 factory 重开 TCP Transport；
- 默认最多尝试 5 次，退避为 1 秒、2 秒、4 秒、8 秒、15 秒封顶。参数来自集中配置，
  不进入 profile、表单或工作区；
- 重连成功后由 `SessionHostCore` 重建会话并恢复此前轮询和 Trace 目标；断开旧会话时取消
  待处理请求，新的 TCP 连接重置 Transaction ID，迟到响应不得污染新会话；
- 达到上限后进入 `failed` 并发布一次最终失败消息，随后停止自动重连，等待用户手动操作。

协调器使用代际计数使旧的等待和尝试失效。用户主动断开、新连接或 dispose 后，即使旧计时器
到点也不能打开新连接；任何重连计时器和 armed 状态都不持久化。应用启动和普通工作区恢复
仍保持离线。

重连中间状态通过既有 `connection-state` 事件推送给 UI，最终失败通过既有应用消息通道展示。
该能力不新增生产环境 HostMessage kind、不改变工作区 Schema、不改变平台能力矩阵。开发探针
可以模拟连接丢失，但必须受开发模式门控，不能成为生产 API。

## 4. ProtocolCodec 扩展

`CommunicationSession` 支持协议可注入。内置 `rtu` 和 `tcp` 保持既有协议实现路径；
其他 `protocolId` 通过 `CodecRegistry` 查找 codec 并委托编解码和分帧。未知 ID 必须在连接
或构造阶段返回 `CODEC_NOT_FOUND`，不得静默回退为 Modbus。

核心还注册三个基础表 RTU codec：
`modbus-basic-tables:coil`、`modbus-basic-tables:discrete-input`、
`modbus-basic-tables:input-register`。每个 codec 的协议 ID 带表类型后缀，因为通用
codec 请求不携带表类型，单一 ID 无法区分 FC01/FC02/FC04。线圈可读写，
离散输入和输入寄存器只读。基础表 TCP codec 尚未接线，能力矩阵不得提前声明。

`ProtocolCodec` 是通信层内协议无关的接口：

- 读请求包含从站/单元地址和任意有序寄存器地址列表，允许 codec 支持非连续读写；
- 写请求包含有序的 `{ address, value }` 项列表；
- 正常结果统一为 `read`、`write` 或 `exception` 判别联合；
- `FrameParser.push` 负责半包、粘包、重同步和完整帧判定；`expectedLength` 同时给出正常帧
  与异常帧的最小长度；
- codec 获得会话构造的期望描述，必须校验从站地址、功能码、字节数、个数和值顺序；
- `maxRead`/`maxWrite` 限制由 codec 声明并在发请求前校验，超限不得交给设备；
- 可选 `mapException` 把协议异常映射为结构化 `MamepError`，否则使用通用设备异常语义。

codec 路径必须复用统一调度器，因此串行、优先级、超时、重试、取消、迟到响应隔离、
请求日志和插件来源元数据与内置协议一致。codec 只能接收已经验证的地址和值并返回字节或
领域结果，不能打开 Transport、绕过通信队列或取得连接句柄。

`SessionHostCore` 接受 codec 注册表或工厂注入，并为每个会话透传；不为每种协议复制一套
Session Host。厂商专用协议和寄存器规则放在 `plugins/` 下的插件包中，核心只提供通用接口、
注册表和会话调用路径。当前安川 MEMOBUS 示例实现 67/010D 非连续读和 67/010E 非连续写，
单次读上限 120、写上限 60；协议帧、CRC、边界和异常码解释均留在插件内，异常映射为
`MEMOBUS_EXCEPTION_XX` 并按设备异常向用户呈现。该示例当前使用 RTU 类字节流承载，不扩展
为 MEMOBUS over TCP，除非后续单独确认承载格式。
