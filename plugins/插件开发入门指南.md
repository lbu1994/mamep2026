# Mamep2026 插件开发入门指南（新手版）

> 这份文档写给**完全不了解 Mamep2026 内部结构、但想给它写插件的人**。
> 只讲概念 + 一个能跑通的最小例子，尽量不依赖仓库内部细节。更权威的规范见
> `docs/插件功能设计.md` 与 `docs/AGENTS.md`（冲突时以后者为准）。

---

## 0. 一分钟理解：插件是什么

插件 = **一份「名片」（manifest）** + 可选的一小段**「能跑的业务代码」（entry / runtime）**。

主软件通过**「贡献点」（contribution point）**接收插件提供的内容。你可以把关系理解为：

- **贡献点 = 插座**（软件事先定义好：`panels`、`theme`、`toolbarAction`、`tableType`……）
- **插件 = 插头**（你写一张名片，声明「我要往哪个插座里插什么」）

软件启动后，会遍历所有已安装插件、按「贡献点」把它们声明的内容汇总到对应界面。
**插件只是声明数据，不直接改核心代码。**

---

## 1. 你需要先知道的三两件事

- 这是 **pnpm + TypeScript monorepo**；插件放在 `plugins/` 目录下，一个插件一个子目录。
- 常用命令：
  - `pnpm dev`：启动网页端（http://localhost:5173，打开后可测插件）；
  - `pnpm test` / `pnpm typecheck` / `pnpm lint`：跑这个仓库的单测 / 类型检查 / 代码检查。
- 贡献点「长什么样」由 `packages/plugin-api` 定义，插件只依赖它，**不依赖 UI 层**。

---

## 2. 两种插件

| 类型           | 需要什么                                                               | 例子                                                                        | 说明                                                                                                        |
| -------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **纯数据插件** | 一份 `manifest.json`（或单文件 JS 但不注册同步能力）                   | `example-theme`（主题色）、`example-panel`（声明式面板）                    | 只声明，不执行代码；最简单、最安全                                                                          |
| **可执行插件** | 单文件 JS（`export const manifest` + `export function activate(ctx)`） | `yaskawa-memobus-67h-010dh-010eh`、`custom-function-code`、`address-adjust` | 安装时选择执行模式；**同进程执行**（用户显式授权）才能贡献 codec / dataType / addressTransform 等同步纯函数 |

> 2026-09-12（ADR-054）：**插件一律由用户手动安装**——不再有「随包插件」与首启自动安装，
> 也没有「Restore bundled」。同进程执行不是「受信插件特权」，而是**安装时用户在安全确认框中的显式授权**。

主题色属于**纯数据插件**，所以这张「名片」就是全部。

## 3. 最小例子：主题色插件（完整复刻 example-theme）

目录长这样（**运行时只有 `manifest.json` 是必需的**，其余是开发/质检）：

```
plugins/example-theme/
├── manifest.json      # ✅ 真正被安装、被使用的
├── package.json       # 声明为 workspace 包（用于 pnpm test/typecheck）
├── tsconfig.json      # 让本包可被 typecheck
├── README.md          # 说明文档
└── src/
    ├── plugin.ts      # 用 TS 写带类型的 manifest（开发/类型检查用）
    ├── index.ts       # 包出口
    └── plugin.test.ts # 单测（不启动应用验证 manifest 合法）
```

`manifest.json` 内容（这是**整份插件**）：

```json
{
  "id": "example-theme",
  "name": "Example Theme",
  "version": "1.0.0",
  "apiVersion": "1.0",
  "description": "An example plugin that demonstrates contributing an optional theme color preset.",
  "author": "Mamep2026 Team",
  "platform": { "web": true, "node": false },
  "requiredCapabilities": [],
  "permissions": ["theme"],
  "contributes": {
    "theme": {
      "colors": [
        {
          "id": "indigo",
          "titleKey": "plugins.exampleThemeColor",
          "title": { "en-US": "Indigo", "zh-CN": "靛蓝" },
          "colorPrimary": "#4f46e5"
        }
      ]
    }
  }
}
```

### 每个字段是干嘛的

| 字段                                          | 说明                                                                                                                 | 必填              |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------- |
| `id`                                          | 插件唯一标识（全仓库不重复，用 `example-theme` 这种短横线命名）                                                      | ✅                |
| `name` / `version` / `description` / `author` | 展示信息，安装确认与插件列表显示                                                                                     | name/version 必填 |
| `apiVersion`                                  | 插件协议版本，软件用它做兼容判定（当前 `"2.0"`；major 不同即拒绝加载）                                               | ✅                |
| `platform`                                    | 运行平台：`web: true` 才可在浏览器/桌面 Webview 安装（安装时**强制要求 `web: true`**）；`node: true` 供 Host/Node 侧 | ✅                |
| `requiredCapabilities`                        | 声明需要的能力（如 `"modbus-rtu"`），本例子留空                                                                      | 默认 `[]`         |
| `permissions`                                 | 权限声明（见下方权限表）                                                                                             | 默认 `[]`         |
| `contributes`                                 | 你要贡献的内容：`{ 贡献点ID: payload }`                                                                              | ✅                |

### `contributes.theme`（主题色贡献）

```ts
{
  colors: Array<{
    id: string; // 色板内唯一（同一插件内不重复）
    titleKey: string; // 显示名 i18n 键（应用回退用）
    title?: {
      "en-US": string; // 英文显示名（必填）
      "zh-CN"?: string; // 简体中文（选填；缺失则回退英文）
    };
    colorPrimary: string; // 单一明亮模式主色（种子）；链接色跟随主色，暗色/hover/active 由 antd 算法派生
  }>;
}
```

### 权限一览（`permissions` 可用的枚举值）

`communication`、`device-write`、`workspace-read`、`workspace-write`、`file-read`、
`file-write`、`network`、`ui-contribution`、`theme`。

本例子只需 `["theme"]`（告诉软件“我要贡献主题”）。

## 4. 怎么把它装进软件（手动安装）

1. `pnpm dev` 启动网页端。
2. 打开右上角 **Settings → Plugins** 页签（2026-09-12 起插件管理并入 Settings，不再有独立入口）。
3. 点 **Install Plugin** → 选本包 `manifest.json`。
4. 在安全确认弹窗里确认（会展示名称/版本/权限/平台）。
5. 打开 **Settings → 主题色**，下拉框出现「Indigo / 靛蓝」。
6. 选用后主色/链接色切换为靛蓝；刷新后仍持久化；禁用/卸载插件后回退默认蓝。

> 注意：插件**不会自动应用**（ADR-047）。你必须主动在 Settings 里选中，它才生效。

## 5. 如果你想在仓库里正式维护它（可选）

上面只有 `manifest.json` 已经能装。但如果你想让它参与本仓库的 `pnpm test` / `pnpm typecheck` / `pnpm lint`，就再补：

- `src/plugin.ts`：用 TS 把 manifest 写成**带类型**的常量（`exampleThemeManifest`）+ 一个注册函数 `registerExampleThemePlugin(registry)`。好处：写错字段时 `tsc` 立刻报错，IDE 有补全。
- `src/index.ts`：包出口，`export * from "./plugin"`。
- `src/plugin.test.ts`：单测，模拟一个注册表验证「能注册成功、是 installed、无 runtime、贡献正确」。不启动应用即可发现错误。
- `package.json`：声明为 workspace 包（`@mamep2026/example-theme`），提供 `typecheck/test/lint` 脚本。
- `tsconfig.json`：让本包可被 `tsc` 单独检查。

**注意**：若插件不参与仓库整体构建（例如独立发给别人用），这 5 个文件可以全部不要，只留 `manifest.json`。

## 6. 进阶：贡献点有哪些、去哪看

软件已注册的**内置贡献点**（`packages/plugin-api/src/builtin-contribution-points.ts`）：

| 贡献点              | payload 要点（写明即可）                                                                 | 消费方（在哪里生效）                                  |
| ------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `panels`            | `[{ id, titleKey, title? }]`                                                             | 底部面板「插件」页签（示例：`plugins/example-panel`） |
| `theme`             | `{ colors?: [{ id, titleKey, title?, colorPrimary }] }`（`colorPrimary` 为单一明亮主色） | Settings 主题色选择器                                 |
| `toolbarAction`     | `[{ id, titleKey, icon?, scope, targetTableType?, requiresConfirm, confirmKey? }]`       | 表格工具栏按钮                                        |
| `tableType`         | `{ id, protocolId, titleKey, columns?, rowActions? }`                                    | 新建表 + 表渲染                                       |
| `protocolExtension` | `{ protocolId, titleKey }`                                                               | 通信会话 codec 注册                                   |
| `addressTransform`  | `{ id, protocol, titleKey?, defaultConfig? }`                                            | 表级地址变换（Address Adjust）                        |
| `settings`          | `{ id, titleKey }`                                                                       | Settings 弹窗分区                                     |
| `dataType`          | `{ id, titleKey }`                                                                       | 数据类型注册表                                        |
| `command`           | `[{ id, titleKey }]`                                                                     | 命令分发（快捷键/按钮）                               |
| `documentation`     | `{ id, titleKey, markdown }`                                                             | Help / 文档面板                                       |

如果你要让插件**读写设备**（寄存器读/写/批量/追踪），需要用到 `PluginCommunicationApi`
（见 `docs/插件功能设计.md` §3.4）；主题色插件不需要。

### 可执行插件：单文件 JS entry 与同步能力（ADR-054 / ADR-055）

可执行插件就是**一个自包含的 `.js`/`.mjs` 文件**（manifest 内嵌其中）：

```js
export const manifest = {
  id: "my-plugin",
  name: "My Plugin",
  version: "1.0.0",
  apiVersion: "2.0",
  description: "…",
  platform: { web: true, node: true },
  permissions: [],
  contributes: {},
};

export function activate(ctx) {
  // 同步纯函数（codec / dataType / addressTransform）经 ctx.registries 注册：
  // 函数不可 JSON 序列化，因此只能在这里注册，不能写进 manifest 的 contributes payload。
  const result = ctx.registries.addressTransform.register({
    id: "my-plugin.offset",
    protocol: "rtu",
    apply: (address) => ({ ok: true, value: address + 10 }),
  });
  if (!result.ok) throw new Error(result.error.code);
}

export function deactivate() {
  /* 可选 */
}
```

- **执行模式（安装时选择）**：`Isolated worker`（默认，Web Worker / `worker_threads`，只暴露受限通信 API）
  或 `Same process`（用户显式授权，插件与应用同进程、同权限，**贡献同步能力时必需**）。
- **同步注册面 `ctx.registries`**：`codec.register(...)` / `dataType.register(id, handlers)` /
  `addressTransform.register(transform)`——均返回 `Result`，注册失败请 `throw`（框架按
  `PLUGIN_HOOK_FAILED` 错误隔离，不影响其它插件与核心功能）。
- **宿主侧执行（ADR-055）**：Electron 主进程与 VSCode Extension Host 也会从**同一份插件存储**
  加载「已启用 + 同进程」插件并执行——所以同进程插件贡献的 codec / 地址变换在 VSCode 的
  RTU 会话（会话在 Extension Host）中真实生效；卸载 / 禁用后宿主侧同步重建，不留残留能力。
- **打包分发**：仓库内插件用 `pnpm build:plugins` 产出可安装文件到 `release/plugins/<pluginId>/`
  （`<pluginId>.mjs` + 从产物提取校验的 `manifest.json`）；纯清单插件只拷 `manifest.json`。

> 只想要主题色 / 面板这类**声明式**贡献？继续用第 3 章的 `manifest.json` 即可，不必写代码。
> 面板类贡献的完整示例见 [plugins/example-panel/README.md](../plugins/example-panel/README.md)
> （提交 `panels` 贡献 → 底部面板出现「Plugins」页签；`title` 可选，缺失时回退 `titleKey`）。

## 7. 安全与红线（务必看）

- **不得修改核心源码**，只能通过贡献点扩展（`docs/AGENTS.md` §24.1 / §32）。
- **插件一律手动安装**：插件放 `plugins/` 仅作为仓库源码组织方式，产物需用户安装；
  **禁止新增内置/随包自动安装的插件**（ADR-054，`docs/AGENTS.md` §32 ㉞）。
- **第三方代码隔离**：默认执行模式为隔离线程（Web Worker / `worker_threads`），只暴露受限 API；
  选「同进程执行」等于授予插件与应用同等权限（桌面宿主为完整 Node 环境），请只对完全信任的插件选择。
- **权限如实声明**，未知权限会被拒绝安装。

## 8. 常见问题

- **装了主题色插件，为什么界面没变色？** —— 插件只注册为「可选预设」，需在 Settings → 主题色 **手动选中**才生效（ADR-047）。
- **装了面板插件，界面哪里变化？** —— 底部面板会出现 **「Plugins」页签**（无面板贡献时不显示）；面板内目前是占位内容，插件提供交互式组件的机制属 Phase F。
- **Settings 下拉里没有我的颜色？** —— 检查 `platform.web` 是否为 `true`、`permissions` 是否含 `"theme"`、`contributes.theme.colors` 是否合法。
- **我想卸载/恢复？** —— Settings → Plugins 里对 `installed` 插件可卸载；卸载后需重新选择插件文件安装（超 2026-09-12：不再有「随包插件 / Restore bundled」，所有插件一律手动安装，ADR-054）。
- **我要多语言？** —— 在 `title` 里提供 `en-US`（必填）与 `zh-CN`（可选）；缺失语言回退英文（方案 A）。
- **可执行插件安装后不生效？** —— 贡献 codec / dataType / addressTransform 的插件必须在安装确认框里
  选 **Same process**（隔离线程无法提供同步纯函数）；装完可在 Settings → Plugins 里看到
  `Executable` / 执行模式信息，禁用/卸载即回收其能力（宿主侧同步重建，ADR-055）。
- **自己写的插件怎么试？** —— `pnpm build:plugins` 后把 `release/plugins/<pluginId>/<pluginId>.mjs`
  （或 `manifest.json`）装进应用即可。
